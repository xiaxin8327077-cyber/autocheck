# 监管智核

监管智核是一个部署在 Linux 服务器、由 Linux x86_64 单文件可执行程序提供服务、用户通过浏览器访问的 Web 应用，用于自动对数、人行全量产品导入和监管报送相关数据核对流程，并根据 FA 估值表、FA 科目余额表、AM 资产信息和 AM 合同投融资余额自动判断差异类型。

## 版本信息

- 应用界面版本：`V1.2`（顶栏与系统信息展示用月度版本；更新日志条目版本号仍按功能发布独立编号，二者分开维护）
- Python 包版本：`0.1.0`
- 当前规则版本：`logic-2026-06-12-v1`
- 运行方式：生产环境在 Linux 服务器上运行 `auto-check` x86_64 单文件可执行程序，由 systemd 管理并监听固定端口 `8765`，用户从桌面端浏览器访问；当前标准交付产物为 `dist-glibc217/auto-check`，兼容 glibc 2.17 及以上环境（包括 glibc 2.28），Windows 单文件 exe 仅作为可选兼容交付方式
- 使用范围：系统面向桌面端浏览器使用，用户通过服务器访问地址登录；建议在常规电脑屏幕或浏览器窗口宽度不低于 `900px` 的环境下操作，移动端、390px 等极窄屏不纳入本版本交付验收范围
- 数据访问原则：报表库全程只执行查询；`sql/` 目录脚本仅用于本地测试库造数
- 应用存储：系统自身配置、用户、历史记录、报送导航配置/快照、界面偏好和模块宿主状态保存到 MySQL `auto_check` 应用库；`config.json` 仅保留 `app_database` 启动连接信息和少量启动参数，动态配置、用户、自动对数历史、人行逐笔校验历史和流程链执行历史不再写回 JSON 或 SQLite；上线需依次执行 `001_init_schema.sql` 至 `014_role_capability_settings.sql` 中适用的迁移。`012_module_system.sql` 新增 3 张模块平台表，`013_report_navigation_provider_states.sql` 新增带持久注册 token 的报送导航统计提供方状态表，并为统计运行记录补充提供方失败数，`014_role_capability_settings.sql` 新增角色能力矩阵配置表（单行 JSON 快照），`019_dictionary_management.sql` 新增系统字典分类与字典项两张表并预置系统锁定的“业务系统”分类，`022_scheduled_tasks.sql` 新增统一定时任务配置与状态表并预置三项内置任务，完整应用结构为 56 张表，`app_schema_version` 仍为 `1`；旧 SQLite 数据仍可由 `scripts/export_sqlite_to_mysql.py` 只读导出，删除旧 SQLite `auto-check.db` 后应用仍应只依赖 MySQL 应用库运行。
- 应用存储增量升级：已有应用库在停机备份后，按发布顺序人工执行 `007_report_navigation_schedule_owner.sql`、`008_report_navigation_work_calendar.sql`、`009_report_navigation_manual_step_permissions.sql`、`010_pbc_template_step_seven_display_only.sql` 和 `011_report_navigation_completion_time_sources.sql`；执行 `011` 后再次确认备份可恢复，再由运维人工执行 `012_module_system.sql`、`013_report_navigation_provider_states.sql` 和 `014_role_capability_settings.sql`。`010` 将第七步调整为仅展示，`011` 将归档类完成时间统一改为仅取 `create_date`，`012` 建立模块注册和迁移状态表，`013` 建立报送导航统计提供方 token 状态表并补充运行失败提供方计数，`014` 建立角色能力矩阵配置表（单行 JSON 快照）；`021` 将原报送导航调度周期调整为 30 分钟，`022` 建立统一定时任务配置与状态表。模块业务表不加入全局 `EXPECTED_APP_SCHEMA`，由模块自己的迁移和独立 `schema_version` 管理；以后每年只需在同一日历脚本中补录当年例外日期并重新执行，不改变 `app_schema_version=1`。

## 当前功能

- 外部看板接口：看板管理模块为”金融监管报表报送大屏”和”金融监管报送流程大屏”提供 Bearer Token 认证的外部只读接口。接口只允许服务端 GET 调用，只返回 10 个固定内置区域与 22 个固定内置字段，响应通过 `data_year` 隔离年度；自定义区域、追加字段、数据源和 SQL 不会外泄；单个区域失败时其余区域继续返回，新年度未准备时返回 `data_not_ready`，截断时返回 `truncated_result`。两个接口按 TCP 来源 IP 共用认证前 10 次/60 秒限流，Token 缺失或错误同样计数；接口监控记录 401、429、认证阶段 503、精确路径 405 及认证后的调用，但不保存 Token 或 Authorization。管理员可在接口监控页面生成和更新专属 Token，该 Token 仅适用于两个精确接口，明文只展示一次；数据库仅保存 SHA-256 摘要，不保存明文。完整接口、字段映射、错误示例和后端适配建议见 [`docs/dashboard-management-external-api.zh-CN.md`](docs/dashboard-management-external-api.zh-CN.md)。

- 看板管理最新交互与权限规则：区域启用状态改为右侧区域名称后的开关，编辑弹窗只维护区域名称、数据形态和说明，保存始终绑定被点击的区域，避免跨区域误写；页面查看、配置维护与 SQL 测试三项能力均纳入“角色权限”能力树。来源、数据源或 SQL 切回已保存值后自动清除未保存状态，只有存在实际差异时切换区域或看板才提示放弃修改。自定义 SQL 即使测试因语法、连接、缺少字段、字段类型或返回行数问题失败也可保存；保存阶段只拦截明显的写入、DDL、多语句和锁表操作，“测试执行”仅用于预览和校验，失败原因会保留在按钮旁。

- 看板管理：作为可独立启停模块挂载在“系统管理”二级菜单，默认仅管理员拥有查看、维护和 SQL 测试权限。页面固定维护“金融监管报表报送大屏”和“金融监管报表报送流程大屏”两个看板，初始化 10 个内置数据区域与 22 个内置字段；管理员可在既有区域追加自定义字段，或新建自定义区域及首批字段。用户新增区域可删除，删除时同步清理字段和来源配置，系统内置区域不可删除；打开区域编辑前会读取最新版本，避免缓存版本导致误报冲突。页面在当前浏览器会话内记住最后选择的看板和各看板数据区域，刷新后恢复原选择；所选区域不存在时才回退到首个区域。顶部两个看板使用 46px 紧凑 Tabs 组件切换，当前项通过浅蓝背景、主题蓝加粗文字和 3px 底部选中线突出显示；右侧统一提供“预览当前看板”菜单，关闭预览后菜单自动收回。悬停预览菜单可选择“接口数据”和“看板页面”，两种预览以及外部接口均使用同一份固定 7+3 区域、固定字段、年度快照与错误规则；自定义区域和自定义字段仅保留在配置和来源测试能力中，不进入完整看板结果。看板页面预览使用复制到模块内部的两套独立页面，通过相同接口填入实时数据，并在接近全屏的弹窗中展示，支持关闭按钮和 Esc，点击遮罩不关闭。右侧取消重复的“基本信息”分组，改用紧凑的区域名称与状态标签，并避免配置区产生内层纵向滚动；数据源下拉与来源切换器等宽，桌面双栏布局下系统生成与自定义 SQL 编辑框均自动伸展至剩余页面高度，并禁止手动拖拽改变尺寸。三个含 `month` 字段的数据区域在字段说明中分别显示格式示例：月度信托项目数量使用 `1月`～`12月`，报表对账完成时间和报表校验问题处理使用 `YYYY-MM`。“报表对账完成时间”固定返回 `month`、`reconciliation_completed_time`（`HH:mm` 展示时分）、`reconciliation_completed_at`（完整日期时间或 `null`）三个字段。每个区域只能选择系统数据或一条自定义 SQL：系统模式按指标自动生成只读 SQL，直接查询 AutoCheck 应用数据库；来源区只展示来源功能和数据库，数据表中文名、物理表名、字段中文名与查询别名统一在生成 SQL 顶部以注释展示；数据来源编辑区测试最多展示 10 行，但该限制不得传播到完整看板预览或外部接口，完整看板使用不限行执行器。其中“报表对账完成时间”按报送期关联自动对数历史与运行摘要，取总差异为 0 的最小执行时间，每年 1 月额外允许读取上一年 12 月的迟到完成数据；“季度报表特殊处理”仅统计本年度待确认和已确认记录，排除草稿、作废及已物理删除记录；“当月报表报送时间对比”按固定流程编码排除人行大集中。自定义 SQL 必须用同一条查询返回该区域全部启用字段，支持数据库原生函数、注释、操作符、自定义类型和不带 schema 的表名；应用仅拦截非单条 `SELECT/WITH`、写入、DDL 与锁表语句，执行连接仍启用只读事务。测试失败时，顶部提示及按钮旁状态同步给出安全的具体原因，例如表或字段不存在、语法、权限、连接、超时、日期或字段类型问题，同时不回显密码、连接串和本机路径。修改数据源、SQL 或字段后必须重新测试才能保存；生产数据源应使用最小权限只读账号。“月度信托项目数量”“报表对账完成时间”“报表校验问题处理”和“季度报表特殊处理”由看板预览接口实时查询并更新本地年度快照，写入按业务所属期归属到对应年度，同周期以 SQL 或系统实时结果覆盖、未返回周期保留；接口只返回 `data_year` 对应当前自然年并按周期升序输出，实时查询失败但当年已有完整快照时回退当年快照并标记 `snapshot_status=stale`，没有当年可用快照时返回区域错误 `data_not_ready`，截断时返回区域错误 `truncated_result`；“季度报表特殊处理”仅在接口响应阶段为当前季度之后的缺失季度补 `0`，不写入快照、不覆盖已有季度值；不新增后台任务。2026 年历史基线分别初始化为：信托项目与对账完成时间 1—6 月、校验问题处理 1—8 月、特殊处理第一和第二季度；对账完成时间初始化历史仅有既时分，完整日期保持 `null`。停用模块会隐藏入口、路由和静态资源但保留四张模块表及已保存数据，重新启用或重启后可恢复读取。真实 PostgreSQL/MySQL 驱动和网络连接仍需在目标环境完成集成验证。

- 报表特殊处理录入：作为独立可启停模块挂载在顶部“数据录入”分组，该分组紧随“智能核数”显示，复用相同的无描边悬浮展开交互，父菜单不跳转，二级菜单按内容自适应紧凑宽度；按平台动态报送目录维护草稿、待确认、处理中（历史）、已完成和已作废记录；弹窗基本信息保留关联报送、所处报送期与处理人，新增所属维度（项目端/资金端/资产端/财务端）、所属业务系统（单选下拉，选项取自系统字典“业务系统”，正式保存必选，保存编码与名称快照）和数据治理负责人（按维度从「数据治理_项目资产」「数据治理_资金财务」角色联动候选人），去掉涉及报表；特殊处理内容保留处理摘要（最多 128 字）与脚本文本只存储/复制不执行，新增处理表名、处理字段名（中英双语多项：单项“中文名｜英文名”，多项用全角分号分隔，每类最多 5 项；旧记录未修改可保留原值）、修改前、修改后一组，去掉处理说明；台账主列表使用“修改字段 / 修改前 / 修改后”三个普通列，按完全相同的修改前/后值对跨表聚合并对字段显示名去重，优先显示中文字段名、中文缺失时回退英文；整条记录只有一个值对时字段逐行显示，存在多个值对时各组字段用顿号连接。列表不展示处理表、数据源或英文技术名，空值统一显示“—”，前三列水平、垂直居中并允许自然换行，不使用变更编号、标签、卡片、嵌套表格或表格内线；8 月旧手工记录按单值共享、可靠逐行对应或完整原文保留三种规则兼容展示；正式保存进入待确认，确认须经弹窗且主按钮为「源系统已确认」，确认弹窗底部可在按钮上方选填确认说明（最多 500 字）并用粘贴加入最多 3 张图片（无上传按钮），不填不贴也能确认；确认权限为 `rsp.confirm` 且当前用户为该条数据治理负责人（管理员例外）；支持乐观锁、能力码权限控制和完整审计留痕；支持按当前筛选结果导出 Excel（含处理脚本列）。模块通过 `platform.report_navigation` v1 接管“报表特殊治理”真实周/月/季/年统计，并将待确认记录经 Todo Provider 注入报送导航「我的待办」；该卡不参与定时/手工全量采集，进入报送导航页时按台账实时刷新，台账写入成功后也会 best-effort 单卡刷新；接管后旧手工维护入口自动不可点击，失败保留最近成功快照并标记过期，首次失败明确显示不可用。数据治理负责人确认完成后，系统向记录创建人发送成功通知，点击可定位到已完成记录详情。
- 报表特殊处理查看与确认：上半部分改为只读信息预览，基本信息保持三列“弱标签 + 深色文本”，处理摘要与脚本使用浅色内容块，每张处理表以配置预览卡展示数据源、表名、处理范围和修改字段；处理范围与修改字段使用轻量只读表格，长内容在单元格内自动换行且不出现横向滚动条，不再用灰色禁用输入框、下拉框或日期控件。表级数据源名称直接读取保存快照，确认页不再出现空白数据源。确认态仅底部确认说明可输入，图片粘贴与确认动作不变。报送导航“我的待办”、待确认通知和完成通知统一显示“所属维度 · 所属业务系统 · 最短字段名”，字段中文名优先、中文缺失回退英文。
- 报表特殊处理操作记录：结构化记录按“基本信息 / 特殊处理内容”分层，只突出真正变化的内容；多张处理表独立展示表信息、处理范围与修改字段变更，新增表和删除表使用业务化表达并可展开查看当前或删除前的完整配置，条件优先显示“中文名（英文字段名）”。摘要统一统计基本信息项数、特殊处理内容项数和涉及表数。处理脚本作为不计入业务变更数的次级信息按需查看 Diff，并区分自动生成与手动编辑；历史扁平记录继续兼容原三列 Diff。重开原因、作废理由和确认说明紧跟状态流显示；确认图片与记录附件继续使用各自专用的预览、下载和变更快照展示。
- 报表特殊处理记录附件：新建、保存草稿和编辑抽屉提供“附件（选填）”区域，支持点击上传多选与剪贴板直接粘贴（纯文字粘贴不受影响）；允许 PNG/JPEG/WebP、XLS/XLSX、DOC/DOCX、ZIP，每条最多 10 个、单个最大 10 MiB、总计最大 30 MiB，当前集合内相同内容自动去重、同名不同内容允许并存；图片提供缩略图与大图预览，Excel/Word/ZIP 仅下载不在线解析或执行；服务端按魔数与容器结构校验并拒绝 SVG、XLSM、DOCM、RAR、7Z 与可执行文件，不提供恶意软件扫描。附件随记录保存在同一事务内原子提交，只修改附件也递增版本并写操作记录；从当前集合移除的附件保留供历史操作记录读取，记录整体删除时才物理清理；原确认说明最多 3 张图片行为不变。

## MySQL 应用库上线准备

当前版本的系统配置、用户、认证数据、三类执行历史以及报送导航关系型配置和统计快照统一写入 MySQL 应用库 `auto_check`。DWS 数据源和报表数据源仍按业务配置支持 PostgreSQL 或 MySQL，不受应用库改造影响。config.json 仅保留 `app_database` 启动连接信息。报送导航统计任务默认每 30 分钟串行执行，使用数据库租约锁避免多实例或手工触发并行；后续统一定时任务管理可直接维护现有任务配置。

上线前需要按以下顺序处理：

1. 在 MySQL 中手工创建空库 `auto_check`，并为应用账号授予必要读写权限。
2. 执行 `sql/app_storage/mysql/001_init_schema.sql`，创建 20 张应用存储表；脚本不包含 `CREATE DATABASE`、`DROP`、`TRUNCATE` 和生产数据。
3. 如需迁移旧 `auto-check.db`，在停机备份后运行 `scripts/export_sqlite_to_mysql.py` 只读生成 schema SQL、data SQL 和迁移报告，再由运维人员人工执行数据 SQL。
4. 执行 `sql/app_storage/mysql/002_report_navigation.sql` 新增 18 张不设置数据库外键约束的报送导航表（保留主键、唯一索引、普通索引以及中文表/字段注释），再执行 `sql/app_storage/mysql/003_report_navigation_seed.sql` 写入数据源、表、字段、固定判断参数和月度报送日期配置；随后依次执行 `004_user_interface_preferences.sql`、`005_user_appearance_preferences.sql`、`006_system_interface_preferences.sql`、`007_report_navigation_schedule_owner.sql`、`008_report_navigation_work_calendar.sql`、`009_report_navigation_manual_step_permissions.sql`、`010_pbc_template_step_seven_display_only.sql` 和 `011_report_navigation_completion_time_sources.sql`。最后必须先备份生产库，再由运维人工执行 `sql/app_storage/mysql/012_module_system.sql`、`sql/app_storage/mysql/013_report_navigation_provider_states.sql` 和 `sql/app_storage/mysql/014_role_capability_settings.sql`，分别新增模块宿主 3 张平台表、报送导航统计提供方状态表和角色能力矩阵配置表（单行 JSON 快照）；随后执行 `sql/app_storage/mysql/019_dictionary_management.sql`、`020_report_period_field_dictionary.sql`、`021_report_navigation_scheduler_interval.sql` 和 `022_scheduled_tasks.sql`。`022` 幂等创建统一定时任务表并预置三项内置任务，执行后完整应用结构为 56 张表，`app_schema_version` 仍为 `1`；模块业务表不加入全局 `EXPECTED_APP_SCHEMA`，由各模块独立迁移管理。正式模块目录不得携带 demo，模块只能作为可信内置扩展发布。

## 核心规则概览

金额比较不允许误差，全部使用精确相等判断。

判断流程：

1. 读取 `zf_detail_2024` 中核对日期下的全部项目；若该日期无报表项目，提示“报表对应日期无数据”并结束本次执行，不写入核对历史。
2. 对存在报表数据的日期，筛选 `a0001 - d0000 <> 0` 的项目；若筛选后为空，返回 0 条差异并写入历史。
3. 使用估值表 `0004` 科目校验 `a0001` 是否正确。
4. 若 `a0001` 与估值表资产合计不一致，进入资产侧规则。
5. 若 `a0001` 与估值表资产合计一致，进入负债及权益侧规则。
6. 若当前规则无法定位原因，差异类型显示为 `暂无法确定`。

主要原因：

- `资产缺失`：`a0001 < 0004`，且估值表 1 开头末级科目或 `3001.XX` 正数共同类科目能匹配具体缺失资产。
- `资产重复`：`a0001 > 0004`，且估值表 1 开头末级科目或 `3001.XX` 正数共同类科目能匹配具体重复资产。
- `资产差异`：`a0001 != 0004`，但不能直接命中具体资产，或命中 1541 财产权合同投融资差异等资产端金额不一致细分。
- `负债及权益科目缺失`：资产侧正确、`c1000 = 4001`、`d0000 < a0001`，且非 1 开头估值科目能匹配具体科目；`3001.XX` 负数按绝对值作为 `应付账款_共同类` 参与匹配。
- `负债及权益科目重复`：资产侧正确、`c1000 = 4001`、`d0000 > a0001`，且非 1 开头估值科目能匹配具体科目；`3001.XX` 负数按绝对值作为 `应付账款_共同类` 参与匹配。
- `负债及权益科目差异`：资产侧正确、`c1000 = 4001`，但不能直接命中具体非 1 开头科目。
- `资产缺失/重复 + 暂无法确定`：资产缺失/重复匹配 `asset_gap` 时存在多组资产端候选科目组合均可解释差额，系统不自动选择某一组，匹配状态为 `候选不唯一`，详情最多展示按组内科目数量从少到多排序的 5 组候选，且不进入资产差异细分；资产缺失方向会额外用 AM 标的和合同投融资余额复核尝试唯一确认候选组，确认成功时仍归为 `资产缺失`。
- `负债及权益科目缺失/重复 + 暂无法确定`：资产侧正确、直接匹配 `a0001-d0000` 时存在多组非 1 开头科目组合均可解释差额，系统不自动选择某一组，匹配状态为 `候选不唯一`，详情最多展示按组内科目数量从少到多排序的 5 组候选。
- `实收本金缺失`：资产侧正确，且 `a0001 - d0000 = FA 4001`、`c1000 = 0`。
- `实收本金重复`：资产侧正确，且 `c1000` 是 `FA 4001` 的整数倍并大于 `FA 4001`，同时 `a0001 - d0000 = FA 4001 - c1000`，可识别重复计入多次的情况。
- `实收本金差异`：资产侧正确，且 `FA 4001 - c1000` 正好等于主差异；TA 汇总差异或 DM TA 客户类型为空只有在对应差额也能解释本次实收差额时才作为具体原因，否则仅作为详情核对信息展示。
- `暂无法确定`：现有规则无法命中，后续可继续接入新的排查规则。
