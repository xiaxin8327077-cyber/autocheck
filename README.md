# 监管智核

监管智核是一个可在 Windows 和 Linux 部署的本地 Web 工具，用于自动对数、人行全量产品导入和监管报送相关数据核对流程，并根据 FA 估值表、FA 科目余额表、AM 资产信息和 AM 合同投融资余额自动判断差异类型。

## 版本信息

- 应用界面版本：`v2.1`
- Python 包版本：`0.1.0`
- 当前规则版本：`logic-2026-06-12-v1`
- 运行方式：本地 Web 服务，默认固定端口 `8765`；Windows 可打包为单个 exe，Linux 可通过 Python 服务部署
- 使用范围：系统面向桌面端浏览器使用，建议在常规电脑屏幕或浏览器窗口宽度不低于 `900px` 的环境下操作；移动端、390px 等极窄屏不纳入本版本交付验收范围
- 数据访问原则：报表库全程只执行查询；`sql/` 目录脚本仅用于本地测试库造数
- 应用存储：系统自身配置、用户、历史记录、报送导航配置/快照和界面偏好保存到 MySQL `auto_check` 应用库；`config.json` 仅保留 `app_database` 启动连接信息和少量启动参数，动态配置、用户、自动对数历史、人行逐笔校验历史和流程链执行历史不再写回 JSON 或 SQLite；上线需按顺序执行 `001_init_schema.sql`、`002_report_navigation.sql`、`003_report_navigation_seed.sql`、`004_user_interface_preferences.sql`、`005_user_appearance_preferences.sql` 和 `006_system_interface_preferences.sql`，完整应用结构共 37 张表；旧 SQLite 数据仍可由 `scripts/export_sqlite_to_mysql.py` 只读导出，删除旧 SQLite `auto-check.db` 后应用仍应只依赖 MySQL 应用库运行

## MySQL 应用库上线准备

当前版本的系统配置、用户、认证数据、三类执行历史以及报送导航关系型配置和统计快照统一写入 MySQL 应用库 `auto_check`。DWS 数据源和报表数据源仍按业务配置支持 PostgreSQL 或 MySQL，不受应用库改造影响。config.json 仅保留 `app_database` 启动连接信息。报送导航统计任务默认每 10 分钟串行执行，使用数据库租约锁避免多实例或手工触发并行。

上线前需要按以下顺序处理：

1. 在 MySQL 中手工创建空库 `auto_check`，并为应用账号授予必要读写权限。
2. 执行 `sql/app_storage/mysql/001_init_schema.sql`，创建 20 张应用存储表；脚本不包含 `CREATE DATABASE`、`DROP`、`TRUNCATE` 和生产数据。
3. 如需迁移旧 `auto-check.db`，在停机备份后运行 `scripts/export_sqlite_to_mysql.py` 只读生成 schema SQL、data SQL 和迁移报告，再由运维人员人工执行数据 SQL。
4. 执行 `sql/app_storage/mysql/002_report_navigation.sql` 新增 15 张不设置数据库外键约束的报送导航表（保留主键、唯一索引、普通索引以及中文表/字段注释），再执行 `sql/app_storage/mysql/003_report_navigation_seed.sql` 写入数据源、表、字段、固定判断参数和月度报送日期配置；随后依次执行 `sql/app_storage/mysql/004_user_interface_preferences.sql`、`sql/app_storage/mysql/005_user_appearance_preferences.sql` 和 `sql/app_storage/mysql/006_system_interface_preferences.sql`。最终 `user_interface_preferences` 按每个用户保存圆角、折线图风格，并保留两个可空的历史兼容主题色字段；`system_interface_preferences` 作为独立的历史兼容表保留。当前前端固定使用 Logo 蓝渐变且不读取这些兼容字段，也不提供自定义主题色入口。完整应用结构共 37 张表，未调整原 20 张表结构。用户偏好表不设置外键，删除用户后的孤儿偏好由应用清理；主题色绝不写入 `app_settings`。
5. 在现有 `config.json` 中配置 `app_database`，`config.json` 仅保留 `app_database` 启动连接信息，不再承载动态配置、用户、历史数据或报送导航规则配置。
6. 保持 `AUTO_CHECK_SECRET_KEY` 与旧环境一致，否则旧数据源加密密码可能无法解密。
7. 导入后核对迁移报告中的原 20 张迁移目标表、导出行数、SQLite 完整性和外键异常数，并确认 15 张报送导航表、种子配置及第 36 张用户界面偏好表、第 37 张系统界面偏好表已就绪；删除旧 SQLite `auto-check.db` 后应用仍应只依赖 MySQL 应用库运行。

示例：

```json
{
  "app_database": {
    "backend": "mysql",
    "host": "127.0.0.1",
    "port": 3306,
    "database": "auto_check",
    "username": "auto_check_app",
    "password": "<set-by-operations>",
    "charset": "utf8mb4"
  }
}
```

## 数据源与固定表

界面维护两类数据源：

- DWS 数据源：用于包含 `_dws` 的表以及同库 DM/固定 schema 表，例如 `fa_valuationreport_dws`、`fa_accountbalance_dws`、`am_pactasset_dws`、`am_projinvest_dws`、`ta_pact_detail_dws`、`dm.ta_pact_survamt_day_zgxg_dm`、`dm.fa_security_balance_zgxg_dm`、`dm.am_projinvest_zgxg_dm`、`dm.am_projinvest_spv_zgxg_dm`、`zgxg_zhbs.ccqxx`。
- 报表数据源：用于非 `_dws` 表，目前主要是 `zf_detail_2024`。

两类数据源都支持 PostgreSQL 或 MySQL。表名和字段名当前按业务规则固定。

系统设置中的“对账业务设置”会展示当前对数逻辑涉及的表、字段、业务含义和当前用途。后续表名或字段调整时，需要同步更新该页面中的字段清单。

核心表：

- `zf_detail_2024`：主差异来源，按 `caldate` 取数；对应日期无报表项目时提示“报表对应日期无数据”且不写入历史，对应日期有报表项目时再使用 `a0001 - d0000` 判断是否存在差异。
- `fa_valuationreport_dws`：估值表，按 `d_valuationdate` 和项目编号匹配，使用 `0004` 科目校验资产合计，并用 `f_marketvalue` 排查差异科目。
- `fa_accountbalance_dws`：科目余额表，使用 `4001` 科目核对实收信托。
- `dm.ta_pact_survamt_day_zgxg_dm`：DM TA 存续金额表，实收本金差异时用 `tpm_htincome + tpm_shareamt` 与 DWS TA 表核对，并检查客户类型依赖字段是否为空。
- `ta_pact_detail_dws`：DWS TA 明细表，实收本金差异时用 `f_shareamt + f_alltincom` 与 DM TA 表核对。
- `am_pactasset_dws`：AM 资产信息表，使用资产名称、标的代码、合同代码、SPV 类型和资产类型做复核。
- `am_projinvest_dws`：AM 合同投融资余额表，使用合同代码核对 `f_acbalance`。
- `dm.fa_security_balance_zgxg_dm`：资产缺失细分时核查债券、股票、公募基金、私募基金基础信息；资产差异细分时核对债券本金 FA 科目余额与 DM 证券余额。
- `dm.am_projinvest_zgxg_dm`：资产缺失细分时核查贷款和股权投资合同余额及股权投资类别。
- `dm.am_projinvest_spv_zgxg_dm`：资产缺失细分时核查特定目的载体和信托计划收益权余额及资产类型。
- `zgxg_zhbs.ccqxx`：资产缺失细分时核查资产收益权合同余额。
- `ass_man_reg.ex_pledge_back`：资产缺失细分时核查逆回购回购金额和佣金空值。
- `currency_report_24.currency_detail_project_2_1_*`：资产缺失细分时核查资负子系统相关明细表是否生成。
- `currency_report_duration`：本地测试保留表，便于后续扩展 TA 规则。

## 核心规则概览

金额比较不允许误差，全部使用精确相等判断。

判断流程：

1. 读取 `zf_detail_2024` 中核对日期下的全部项目；若该日期无报表项目，提示“报表对应日期无数据”并结束本次执行，不写入核对历史。
2. 对存在报表数据的日期，筛选 `a0001 - d0000 <> 0` 的项目；若筛选后为空，返回 0 条差异并写入历史。
3. 使用估值表 `0004` 科目校验 `a0001` 是否正确。
4. 若 `a0001` 与估值表资产合计不一致，进入资产侧规则。
5. 若 `a0001` 与估值表资产合计一致，进入负债及权益侧规则。
6. 若当前规则无法定位原因，差异类型显示为 `暂无法确定`。

主要原因：

- `资产缺失`：`a0001 < 0004`，且估值表 1 开头末级科目或 `3001.XX` 正数共同类科目能匹配具体缺失资产。
- `资产重复`：`a0001 > 0004`，且估值表 1 开头末级科目或 `3001.XX` 正数共同类科目能匹配具体重复资产。
- `资产差异`：`a0001 != 0004`，但不能直接命中具体资产，或命中 1541 财产权合同投融资差异等资产端金额不一致细分。
- `负债及权益科目缺失`：资产侧正确、`c1000 = 4001`、`d0000 < a0001`，且非 1 开头估值科目能匹配具体科目；`3001.XX` 负数按绝对值作为 `应付账款_共同类` 参与匹配。
- `负债及权益科目重复`：资产侧正确、`c1000 = 4001`、`d0000 > a0001`，且非 1 开头估值科目能匹配具体科目；`3001.XX` 负数按绝对值作为 `应付账款_共同类` 参与匹配。
- `负债及权益科目差异`：资产侧正确、`c1000 = 4001`，但不能直接命中具体非 1 开头科目。
- `资产缺失/重复 + 暂无法确定`：资产缺失/重复匹配 `asset_gap` 时存在多组资产端候选科目组合均可解释差额，系统不自动选择某一组，匹配状态为 `候选不唯一`，详情最多展示按组内科目数量从少到多排序的 5 组候选，且不进入资产差异细分；资产缺失方向会额外用 AM 标的和合同投融资余额复核尝试唯一确认候选组，确认成功时仍归为 `资产缺失`。
- `负债及权益科目缺失/重复 + 暂无法确定`：资产侧正确、直接匹配 `a0001-d0000` 时存在多组非 1 开头科目组合均可解释差额，系统不自动选择某一组，匹配状态为 `候选不唯一`，详情最多展示按组内科目数量从少到多排序的 5 组候选。
- `实收本金缺失`：资产侧正确，且 `a0001 - d0000 = FA 4001`、`c1000 = 0`。
- `实收本金重复`：资产侧正确，且 `c1000` 是 `FA 4001` 的整数倍并大于 `FA 4001`，同时 `a0001 - d0000 = FA 4001 - c1000`，可识别重复计入多次的情况。
- `实收本金差异`：资产侧正确，且 `FA 4001 - c1000` 正好等于主差异；TA 汇总差异或 DM TA 客户类型为空只有在对应差额也能解释本次实收差额时才作为具体原因，否则仅作为详情核对信息展示。
- `暂无法确定`：现有规则无法命中，后续可继续接入新的排查规则。
