# 报表特殊处理录入模块

该可选内置模块维护报送期特殊处理台账，并向 `special_governance` 卡片提供真实统计。模块只保存脚本文本及 SHA-256 留痕，永不解析、试运行或执行脚本。

## 后端边界

### 台账导出格式

Excel 按台账样式展示并保留处理表名，共九列：处理表名、修改字段、修改前、修改后、所属业务系统、关联报送、状态、处理人、处理时间（不含操作列）。页面与导出共用 `ledger_display.py` 的只读展示数据：中文字段名优先、英文回退，列表按完全相同的修改前/后跨表分组并按显示名去重；导出先按表保留归属，表内复用同值分组规则，字段逐项换行，多组每组一行，公共信息在 Excel 中纵向合并。字段组和关联名称按视觉宽度升序，同宽保持原序。旧记录无法逐字段对应时保留完整值，不猜测归属。关联名保留原始报送快照，不替换为统计标签“人行报送”。

导出按当前筛选、排序读取最多 5000 条记录，补齐列宽、自动换行、行高和冻结表头；表头及内容统一四边框、水平及垂直居中；零、前导零、长编号及以等号开头的业务值均以文本保留。没有配置或数据库迁移变化。

### 扩展关联报送配置

台账中的“人行大集中报送”和“资管产品模板、逐笔报送”合并为“人行报送”页签，列表和导出同时匹配两类，统计按记录去重。录入目录仍保留两个原始报送，合并页签不代表新的可保存报送，也不影响导航目录。

1. 管理员进入“系统管理 / 字典管理”，创建并启用分类：编码 `rsp_extra_report_process`，名称“特殊处理扩展报送”。
2. 添加原有 7 个报送以外的字典项：编码用于保存关联，名称用于展示，排序控制追加顺序。分类和项都需启用；无需配置报送导航流程。
3. 重新进入特殊处理页面，新建/编辑的关联报送多选和台账筛选即可使用新增项。原有 7 个编码、名称与顺序优先保留；与原目录同编码或同名的扩展项不生效。

原目录编码比较忽略首尾空格和大小写，名称比较忽略首尾空格；合并统计标签名“人行报送”也保留，不允许扩展项产生同名页签。字典分类缺失或暂时不可用时，原报送目录继续可用。

排序固定为原有报送在前、字典新增项在后；普通新增项保持字典原有排序，名称为“其他报送”的启用项固定最后，不受其排序值影响。“更多报送”菜单和录入多选沿用该顺序，不因收纳或点击而重排。

例如新增编码 `custom_report_a`、名称“自定义报送A”的启用项，即可在特殊处理中选择该项。字典项继续使用平台既有编码/名称长度规则；单条特殊处理记录最多关联 20 项，沿用现有上限。无需把原有七项重复录入字典。

顶部页签按真实可用宽度保持单行，排不下的项目收纳到“更多报送”，下拉支持名称搜索、数量和细滚动条；选中隐藏项时入口显示该名称并高亮。新建/编辑多选列表限高滚动。字典改名不改写旧记录快照，停用或删除不丢失旧关联，旧记录可保留原关联编辑其他字段，也可移除；不可新选停用项。

顶部标签最多显示前 15 个字符、不加省略号，悬停可看全名；各标签保留自身所需宽度，长名称只减少后续可见标签数量，不能压缩其他名称。少量标签仍伸展填满行宽。

该字典仅由本模块消费，不改写平台报送目录、不生成报送导航流程；现有统计、待办和通知联动口径不变。复用现有关联表，无数据库迁移。撤销配置可停用分类或相应字典项，历史记录继续保留。

### 现有接口与业务规则

页签较少时，各项自适应分配可用空间并铺满整行；溢出时可见项继续填满剩余区域，“更多报送”保持在右侧，不因项目数量减少留下大片空白。

- API：`/api/modules/report-special-processing`，普通请求体最大 1 MiB；确认完成接口最大 10 MiB，以容纳选填说明与最多 3 张粘贴图片；新建/修改记录接口最大 45 MiB，以容纳随记录原子提交的附件 Base64（低于平台 50 MiB 硬上限）。
- 权限：按角色能力矩阵 `rsp.view/create/edit/confirm/void/reopen/delete` 判定；标准用户遵循“谁创建谁处理”（仅创建人可编辑/作废/重开，处理人不可单独操作）；`rsp.confirm` 控制完成确认，且确认人须为该条「数据治理负责人」（管理员例外可确认任意条）；`rsp.delete` 控制任意状态物理删除。管理员默认拥有全部能力。
- 状态：`draft → pending(待确认) → completed`；界面不再主动进入 `processing`（历史数据仍可显示）；具备作废能力可将 `draft/pending/processing` 作废；具备重开能力可将 `completed/voided` 重开为 `pending`；具备删除能力可对任意状态记录物理删除（二次确认，不可恢复）。
- 字段：基本信息含关联报送、所处报送期、处理人、所属维度、所属业务系统、数据治理负责人；特殊处理内容为“数据源 → 处理表 → 处理字段 → 修改前/修改后”结构，另含公共的处理摘要（≤128 字）；界面已去掉涉及报表与处理说明。处理编号不占用表单行，改为“基本信息”标题行右侧只读元信息（标签次级灰、编号深色加粗、附“复制”按钮），仅记录已有编号时渲染，新建/无编号时整块不出现。所属业务系统为单选下拉，选项来自平台只读字典服务 `platform.dictionary` v1 的启用分类 `business_system`；正式保存必选、草稿可为空；记录保存字典项编码与名称快照，字典改名/停用不影响历史记录显示；已停用项不能新选，但旧记录未改选时仍可编辑其他字段。结构化内容（1.2.15 起，仅新建记录与已结构化记录）：数据源仅能从系统已配置数据源中选择（新增/编辑需选数据源；已选表或字段后切换数据源需二次确认并清空表、字段及修改前/后）；表与字段通过“选择处理表/选择字段”弹窗从真实数据库元数据读取（后端搜索 + 后端分页，支持中英文名模糊匹配，已添加项置灰不可重复选择），物理表名/字段名永远只读，不允许手工输入；中文名称读取数据库 comment/remark：有注释时只读展示（来源 DATABASE），无注释时允许在表卡片标题/字段行内补充中文名（来源 MANUAL，仅保存到业务记录，不反写数据库）；每张表一张分组卡片，添加表自动生成字段选择区，字段区永远保留一行“请选择字段”（最后一个字段删除后恢复空选状态，页面不出现“暂无关联字段”），卡片支持折叠/展开，标题显示“中文名（物理名） · N个已选字段”；字段行为固定列：中文字段名/英文字段名/修改前/修改后/操作（列宽 24%/24%/20%/20%/自适应，表头固定列标题始终可见），新字段的修改前/修改后默认留空，与上一字段值相等时显示“同上”标签且可修改；删除含已选字段的表需二次确认（提示同时删除关联字段及修改前/后）。每张表最多 5 字段、最多 5 张表；每张表至少 1 个已选字段（草稿也要求）；中文表名/中文字段名（MANUAL 来源）必填；正式保存时每个字段的修改前/修改后必填，错误定位到具体字段（如“客户状态：请输入修改前内容”）；草稿可留空。元数据能力仅支持 PostgreSQL / MySQL 类型数据源（不支持 GBase）；连接失败/读取失败统一提示“数据源连接失败，请检查数据源配置”“表/字段信息获取失败，请稍后重试”，不泄露驱动信息；数据源类型与名称以后端解析系统配置为准，防前端伪造，记录同时保存 `datasource_id`、`datasource_name_snapshot`、`datasource_type` 快照。存储层以 `structured_content_json` 为结构化内容唯一事实来源，并派生既有兼容串：`table_name`（`中文名｜物理名；…` 规范串）、`field_name`（按表分组，组间 `；；`）、`value_before`/`value_after`（按字段顺序每字段一行 `\n` 聚合），台账、导出、通知、审计继续消费派生串。历史手工录入记录（`structured_content` 为空）保留原“表-字段分组卡片 + 全局修改前/后”的录入方式编辑（方案 A 兼容）：双语规范串单项 `中文名｜英文名`、多项 `；` 分隔、每类最多 5 项；非规范旧值未修改时原样保存，一旦修改必须升级格式。所属维度枚举为项目端/资金端/资产端/财务端；数据治理负责人下拉为全部启用用户。选维度或改维度时，从对应治理角色启用用户中自动带出（项目端、资产端 →「数据治理_项目资产」；资金端、财务端 →「数据治理_资金财务」；多人则随机一人），改维度会覆盖当前选择，也可改选其他人。确认仍仅该条「数据治理负责人」可操作（管理员例外）。
- 列表：使用“修改字段 / 修改前 / 修改后”三个普通列，其余为所属业务系统、关联报送、状态、处理人、处理时间、操作，不展示处理摘要、处理表、数据源或英文技术名。结构化记录先按原始修改前/后完整值对跨表聚合，再在每组内提取字段显示名并去重：优先中文字段名，中文缺失时回退英文字段名，双名缺失时显示非空占位；整条记录只有一个值对时，去重字段按原顺序逐行显示；存在多个值对时，每个值对占一行、组内字段按原顺序用顿号连接，各行再按整行字段文字长度从短到长排列。null、undefined 和空字符串统一为空值并显示“—”。一条业务记录只占一个主表行，前三列在同一网格中同步排列，避免 `rowspan` 撑高产生空档；内容水平、垂直居中并允许自然换行，不使用变更编号、标签、卡片、嵌套表格或表格内线。`structured_content` 为空的 8 月旧手工记录走保守兼容：单组修改值应用于全部字段，逐行数量一致时按索引对应，无法可靠对应时保留字段及修改前/后完整原文。所属业务系统显示保存时名称快照，旧记录缺失时显示“—”；确认经弹窗完成，主按钮「源系统已确认」。确认弹窗底部可在按钮上方选填确认说明（最多 500 字），并用粘贴加入最多 3 张 PNG/JPEG/WebP 图片；不填不贴也能确认。系统只保存展示，不解析或执行说明与图片内容。
- 查看/确认：不可编辑的查看态和确认态使用只读预览，不渲染灰色禁用输入框、下拉框或日期控件。所处报送期、处理人、所属维度、所属业务系统和数据治理负责人保持三列“弱标签 + 深色文本”，关联报送固定移到短字段网格之后独占全宽并自然换行，处理摘要继续在其下方全宽展示，处理脚本使用浅色内容块；每张处理表使用独立配置预览卡，表信息为三列纯文本，处理范围和修改字段为浅色表头、细分隔线的只读表格，长英文名、中文名和修改值在单元格内自动换行，不出现横向滚动条。表级数据源优先显示结构化内容内保存的名称快照，避免确认页空白；确认态只有底部“确认说明（选填）”保留可输入文本框，图片粘贴、取消和“源系统已确认”动作保持不变。
- 记录附件：新建、保存草稿和编辑抽屉提供「附件（选填）」区域，支持点击上传多选与剪贴板粘贴（仅当剪贴板包含文件时拦截，纯文字粘贴不受影响；从资源管理器复制文件依赖浏览器暴露剪贴板文件，上传按钮为稳定兜底）。允许 PNG/JPEG/WebP、XLS/XLSX、DOC/DOCX、ZIP；拒绝 SVG、XLSM、DOCM、RAR、7Z 与可执行文件。每条记录当前最多 10 个附件、单个最大 10 MiB、原始字节总计最大 30 MiB；当前集合内相同 SHA-256 内容拒绝，同名不同内容允许。服务端按魔数与容器结构校验：旧 `.xls/.doc` 只校验 OLE 容器并统一保存为 `application/x-ole-storage`（无法区分具体 Office 类型或保证无宏，属明确限制）；`.xlsx/.docx` 校验 ZIP 容器与 `xl/`、`word/` 标识并拒绝宏内容；ZIP 只校验容器结构。图片提供缩略图和大图预览，Excel/Word/ZIP 只下载，不在线解析、渲染或执行；不提供恶意软件扫描，只有具备详情权限的用户主动下载后才由本机软件处理。附件与记录在同一事务原子提交：新文件以 Base64 随 JSON 提交，保留附件只提交 ID；内容与元数据不可覆盖，从当前集合移除仅软删除（历史操作记录仍可预览/下载），记录整体删除时才物理清理。只修改附件也递增 `row_version` 并写 update 审计，摘要显示「修改附件（新增 N 个，移除 M 个）」。查看、预览和下载当前或历史附件沿用 `rsp.detail` 且校验记录归属，跨记录统一 not found。记录附件与确认说明图片附件（最多 3 张）分表分流程管理，互不混用。
- 元数据接口：`GET /datasources`（系统已配置数据源列表，仅返回 id/名称/类型/库/架构，不含主机、端口、账号、密码）、`GET /datasources/{id}/tables`（keyword/page/page_size，返回 table_name/table_comment/schema）、`GET /datasources/{id}/tables/{table}/columns`（返回 column_name/column_comment/data_type），均需 `rsp.view`；表/字段查询仅读 information_schema / pg_catalog 目录视图，参数全部绑定，不接受用户传入连接信息；数据源配置读取复用平台 `storage_config.load_data_sources`，连接复用 `app.db.DatabaseClient`，不修改平台内核。
- 待办与处理记录：`pending` 且治理负责人为当前用户时，经平台 Todo Provider 注入报送导航「我的待办」；当前用户确认完成的记录进入「我的处理记录」。两者摘要统一为“所属维度 · 所属业务系统 · 最短字段名”，多个字段时在最短字段名后保留“等 N 字段”总数提示；字段显示中文优先、英文回退，再按视觉宽度选择最短一项。系统名称缺失时回退系统编码；旧记录名称和编码均缺失时保持原“所属维度 · 字段摘要”格式，不显示“未填系统”；「处理」或「查看」跳转台账并定位该条。
- 通知：正式记录进入待确认或重新产生待确认关系时，通知当前数据治理负责人；数据治理负责人成功确认完成后，通知记录创建人（`creator_user_id`），即使表单处理人不同也不改发处理人。待确认通知和完成通知与待办、处理记录共用上述摘要规则；点击完成通知打开已完成记录详情，不再次进入确认模式；通知发布失败不回滚已成功的业务状态和审计。
- 数据：主表与关联报送、关联流程、审计日志、确认图片附件、记录附件共六张表由独立迁移管理；删除接口会同步清除该记录的明细、审计、确认附件与全部当前/历史记录附件；停用模块不删除数据。
- 操作记录：按创建、修改、完成、重开、作废等简洁操作名和语义展示；创建和保存草稿仅显示操作名，不重复展示服务端摘要。有字段变更时可从摘要行展开查看完整的字段、修改前、修改后对照。字段列使用较窄固定宽度，修改前、修改后始终均分剩余空间；长值自动换行且不截断，不使用横向滚动条。处理脚本对照界面显示开头预览（最多 400 字、8 行），超出以省略号截断，鼠标悬停可查看预览；修改前/修改后一键复制完整脚本。仅有字数、没有正文的历史记录仍显示字数。重开原因、作废理由和确认说明紧跟状态流显示为未编号说明；确认时粘贴的图片在完成详情中显示缩略图，点击后查看大图。附件集合变化的修改记录展开后以「修改前 / 修改后」双栏展示当次完整附件快照，标注新增/移除/保留（标签只按该条审计自身的 ID 集合计算，与附件后来的移除状态无关），双栏内图片均可预览、全部附件均可下载；附件集合未变化时不显示附件字段。
- 新版结构化操作记录将基本信息与特殊处理内容分层；特殊处理内容按处理表独立展示表信息、处理范围和修改字段的真实变化，新增/删除使用业务化表达，展开后分别展示当前完整配置或删除前完整配置。处理表、条件、修改字段使用内部稳定 `item_id` 匹配同一对象，条件保留中文字段名快照并优先以“中文名（英文字段名）”展示；处理脚本作为次级信息默认折叠且不计入业务变更数，并区分“自动生成”和“手动编辑”，仅修改手动脚本时仍使用结构化操作记录；历史扁平审计继续兼容展示。录入弹窗中的 `summary` 字段统一显示为“处理摘要”，并归入基本信息区。
- 关联报送：支持多选；主表保留首项编码，名称快照为分号拼接；页签筛选与按报送统计走关联表；台账按报送逐行展示。
- 并发：所有修改携带 `row_version`，冲突返回 409；业务写入和审计处于同一数据库事务。
- 目录：处理人和报送流程分别来自 owner-bound `platform.user_directory` v1 与 `platform.report_navigation` v1，所属业务系统选项来自 `platform.dictionary` v1，不在模块硬编码人员、报送或业务系统。
- 统计：按平台传入的 Asia/Shanghai 左闭右开周期，以 `special_handling_at` 汇总；草稿和作废排除。
- 统计刷新：注册为 `include_in_collect=False` + `refresh_on_dashboard=True`。定时/手工 `collect_once` 均不采集本卡；进入报送导航读取 dashboard 时按台账实时刷新；台账写入成功后仍 best-effort 调用 owner 作用域 `refresh_card_provider`；刷新失败不影响业务写入与页面读取。

## 运维

上线前备份应用库。模块迁移不提供 down migration；出现问题时优先禁用模块，保留业务表、迁移历史和报送导航最后成功快照。后续结构变化只能新增迁移，不得修改已发布的 `001_initial.sql`。当前 schema_version=9（`006_record_attachments.sql` 新增记录附件表 `report_special_processing_record_attachments`；`007_business_system_and_bilingual_names.sql` 新增 `business_system_code`、`business_system_name_snapshot` 两列并把 `table_name`/`field_name` 放宽为 TEXT 以承载双语多项规范串；`008_datasource_structured_content.sql` 新增 `datasource_id`、`datasource_name_snapshot`、`datasource_type`、`structured_content_json` 四列并把 `value_before`/`value_after` 放宽为 TEXT 以承载字段级逐行聚合；`009_field_mappings_and_scope.sql` 新增字段映射表及结构化处理范围配置；历史旧记录新列保持 NULL，按历史手工录入模式编辑，无需数据回填）。回滚附件功能需通过后续补偿迁移删除该表，且表中附件数据不可恢复，回滚前按数据备份流程处理；MySQL 的 `DROP TABLE` 无法安全回滚，升级说明中须明确备份与恢复步骤。

## 1.2.16 变更

- 处理范围升级：固定"项目/合同"升级为通用"条件字段 + 条件值"结构（`conditions` 数组），每张表至少一条有效条件。条件字段从当前表真实字段搜索选择，条件值支持单值/多值（"、""；"分隔，去空去重），单值自动匹配 `=`、多值自动匹配 `IN`；用户主动选择运算符后进入 MANUAL 模式不再被自动覆盖。
- 处理脚本渐进式自动生成：选择处理表后由前端 debounce 400ms 直接拼接预览；选表即出现 UPDATE，选择修改字段/条件字段即分别出现 SET/WHERE，空值先按 `''` 展示并随后实时替换。多表独立生成，未选择条件字段时不生成 WHERE；此预览不调用或放宽正式保存校验。
- 手动编辑模式：点击"手动编辑"后保留当前脚本、解锁 textarea、在输入框上方显示“手动编辑模式，自动生成已暂停”，且处理内容变化不再覆盖用户输入；按钮切换为“恢复自动生成”，手工内容已变化时恢复前确认覆盖。
- 保留 `POST /script/generate` 路由（`report_special_processing.edit` 权限）作为兼容接口，前端实时预览不再调用；接口与记录保存的完整性校验保持不变。
- `sql_builder.py` 的报送期字面量统一为 `YYYY-MM-DD`；IN、LIKE、IS NULL/IS NOT NULL 和字段类型感知字面量继续保持既有规则。
- `StructuredTable` 新增 `datasource_name` 字段；`parse_structured_content` 兼容旧 `projects/contracts`（历史记录回显）。
- 新增迁移 `009_field_mappings_and_scope.sql`（field_mappings 表与结构化内容处理范围字段）。
- 界面栅格对齐：处理范围标题行与条件行复用同一套四列 Grid（含 `var(--action-width)` 操作列、`column-gap: 12px`）并铺满卡片宽度，使“指定数据日期”开启但自动识别失败/不唯一时显示的数据日期字段选择器与“条件值”列左右边界、宽度完全一致（高度同为 32px），隐藏时不占位且列宽与标题行位置不变，不使用 margin/transform/absolute 手工偏移；窄屏（≤900px）回退为两列时选择器仍与条件值同列。
- 行级操作图标语义色：加号仅最后一行显示、默认主题蓝（悬浮浅蓝底）；删除减号保留 Minus 图标并默认使用 `var(--action-danger)`，悬浮加深并配极浅红背景、不描边；仅剩一条条件/字段时的禁用态仍用危险色并以 `opacity: 0.45` 表达不可用；两枚图标固定 28px 双槽位，圆角统一 `var(--ui-radius)`。
