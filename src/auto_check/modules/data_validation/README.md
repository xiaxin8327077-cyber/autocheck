# 数据校验模块

## 角色权限

管理员可在「系统管理 → 角色权限 → 角色授权」的「数据质量」分组为角色配置校验页面、规则维护、AI 生成、测试、启用、执行、结果查看及导出权限。「校验设置」为管理员专属。规则和结果仍按资源归属及已有可见范围校验。

## 规则编辑

从列表进入已有规则时，使用精简纵向弹窗，仅展示规则名称、数据源、报送分类、相关表、规则说明、只读 SQL 和状态开关。主键、比较关系、筛选与关联、缺值及相等策略等内部定义仍完整保留。修改开关后点击“保存”才生效；开启时对刚保存的版本执行原有样本校验并核对版本哈希，全部通过才启用，不执行真实业务校验任务。未改动的已有草稿保持原状态，启用失败可重试，不重复生成版本。

编辑写入携带可选 `expected_rule`（版本号、内容哈希、启停状态和当前启用版本）。服务端在写事务中验证该上下文，发现其他窗口更新时拒绝覆盖。旧版客户端、AI 新建和手工新建仍可沿用原协议；SQL 不增加直接编辑或执行入口。

异常明细中的 SQL 查询列直接以实际返回列名／`AS` 别名作为表头，不在结果页查询文档、字段备注或调用模型转换名称。例如 `cldate AS "数据日期"` 显示“数据日期”，`cldate AS data_date` 显示 `data_date`。新生成规则依据已核验字段输出中文别名，并保存可信的内部角色映射，供执行器读取业务键与校验值；历史版本保留原 SQL 和哈希。中文别名同时保留到明细快照、CSV 和 XLSX。无中文名、不安全的特殊名称回退物理名；重复名称及过长名称按两种数据库的标识符限制处理。

## 校验规则列表

- 列表表头、文字、状态和操作统一居中。目标数据表显示为“中文表名（表英文名）”，去掉文档名称中的 `.ktr` 文件名，不重复显示英文名；按数据源、物理表名和报送分类匹配，文档缺失或命名有歧义时只显示物理表名，不调用模型或查询业务数据。
- 操作列保持紧凑，剩余空间优先给规则名称；名称最多展示两行，超出省略，悬停查看完整名称和说明。行内操作为无边框文字按钮，删除及停用保持红色；点击空白或按 Esc 收起“更多”菜单，键盘操作保留焦点提示。
- 勾选框提供全选、半选、键盘焦点和选中行反馈，全选只作用于当前页；翻页沿用已有勾选范围，筛选或调整页容量清空勾选。
- 行内“删除”和“批量删除”沿用已注册的规则维护权限 `dv.manage` / `data_validation.manage`，并在前后端限制为规则创建人操作，管理员不越过创建人约束。批量删除仅在所选项全部归本人时可用，确认后逐条执行；中途失败会报告已删除数量并保留其余勾选，便于重试。
- `DELETE /rules/{rule_id}` 将规则状态设为 `deleted`，从列表、分类与状态统计中移除，保留版本、用例、确认记录、任务快照和异常明细；重复删除不重复记审计。删除历史包含操作者、时间及前后状态，历史接口继续按原有权限提供查询。
- 已删除规则不能修改、复制、测试、启用、导出规则包或用于新任务。删除和规则写入使用同一事务锁，任务受理时再次检查启用状态及版本；历史失败任务重试也会在同一事务检查规则，拒绝时保留原结果。删除前已受理的任务按其独立快照完成，历史结果仍可查询和导出。复用现有状态字段，无数据库结构迁移。

## 信托业务知识

在「校验设置 → 信托业务知识」可预览、保存和显式启用知识摘要。默认未启用，保存草稿不改变当前启用快照。分析前按来源、期间和主题匹配少量摘要，同用户、同数据源、同活动文档、同启用版本的知识摘要可缓存 10 分钟。模型接口仍接收匹配摘要。知识设置由模块迁移 011 管理。

初始草稿含实收映射。监管报表按项目查 `proj_info_dtl_pboc.f_equity_total_4001_bal`，募集层查 `raise_info_dtl_pboc` 或 `raise_info_mid_pboc` 的 `f_end_share`；后者是份额与待结转收益分别空补0后的和，募集金额 `f_end_amt` 还乘单位净值。监管报送集市按项目查 `reg_pub_project_info.f_endp_amt`，资金端合同明细依裸份额或含收益实收信托规模选择 `reg_pub_ta_pact_info.f_shareamt` 或 `f_actual_trust_scale`。条目按来源匹配，各次模型分析均接收已启用的相关摘要，后端按实际文档核对字段、粒度和期间。

2026-11-19 的本地知识核查以 JSC 当前 KTR/SQL 为取数依据，指引用于解释概念。获批修正包括 C1000 实收与 C0000 权益、资产收益权余额 `f_end_bal`、汇总与关联粒度、空值和报送范围；币种处理仍遵循可编辑的通用口径。24 条原知识的保留、合并、拆分及补充见[确认清单](../../../../outputs/trust-knowledge-audit-20261119/confirmation-list.md)。本地启用记录与字段文档补充属于配置数据，不代表其他部署环境已同步。

## AI 新增规则

需求输入区已移除推理开关，AI 新建、修改需求和采纳建议统一关闭推理；载入旧草稿也不会恢复为开启。数据源和模型下拉使用紧凑字号及足够宽度，避免名称挤压换行。

输出预算为简单校验每轮最多 3072 token，文档核实的多个独立检查按需扩至 6144 / 9216，且同一提问所有模型轮次累计不得超过 10000 token。重试及文档更新后的重分析共用剩余额度；缺失或矛盾用量按本轮额度保守计数。输出被截断时明确提示，残缺结果不进入预览。

多选筛选字段后分别生成方案时，规则名称使用所选表的字段中文名，区分当前和原始口径；缺少中文元数据时保留选项说明。

金额字段在文档未特定标注单位时按元；文档明确标注万元、亿元等单位时按文档换算。份额、数量、净值和比例不套用金额单位约定。

文档上下文补充已登记的业务别名、明确修饰词对应的完整字段字典及可核实直取来源。词段或字典命中仅作为模型复核的线索，完整证据给出后不强制逐编号生成方案或排除报告；保留原始需求和用户实际补答的条件，允许纠正尚未确认的模型草稿。空范围可在补证后细化，同一 AND/OR 的分支调整顺序不会导致误拦。

测试运行弹窗采用单行日期操作区与独立结果区，运行状态、返回条数和截断提示统一展示。无数据时显示带查询日期的完整空状态，不保留空表头及横向滚动条；加载、日期待运行和失败分别展示。结果表格保留中文列名、粘性表头和细滚动条，沿用系统主题及全局圆角。

校验 SQL 右侧的「测试运行」会打开二级结果弹窗，按默认上月底的报送日期执行只读查询，可修改日期后重新运行。表格保留 SQL 列名及中文别名，最多返回前 10 条，超过时提示截断；空结果、超时和执行失败分别提示。弹窗仅通过关闭按钮关闭，关闭后忽略迟到响应。接口 `POST /ai/sql-test` 同时校验现有的测试、执行校验、查看结果权限，后端核对当前文档与预览 hash、重新编译 SQL，再沿用执行器的真实表结构和只读检查；固定 30 秒超时、最多 2 个并发，客户端不能放大行数或覆盖编译参数。此次试运行不保存规则、任务或测试证据，不替代「生成并运行测试用例」及启用门禁，无数据库迁移。

AI 新建暂时隐藏「监管报送集市」并默认选择「监管报表」。这一限制仅作用于新建界面，不改变手工表单、已有规则或后端数据源配置。

文档导入以工作表名「校验页分类名称_表名」标注归属，例如 `人行报送_项目明细`、`1104报送_贷款明细`。「人行大集中报送」和「资管产品模板、逐笔」在校验模块统一为「人行报送」，旧规则同组显示和统计。`人行_`、`人行明细表_`、`人行底稿_`、`人行结果表_` 等已有名称继续兼容。

1. 在系统设置启用模型，并在校验设置导入、激活文档快照。
2. 选择数据源并填写需求。AI 依据当前文档选表、核对字段并生成候选。相同需求及文档、配置可直接复用已保存的原始分析，保留待确认口径。相似需求仍由模型判断适用性、更新条件并生成候选。模型使用文档元数据，不读取业务数据行。
3. 模型解释指标、比较关系和筛选范围，系统核对文档字段与字典码值。待确认口径按组竖排，码值与含义一致时合并展示，存在差异时跟随各自字段。建议标签统一为「模型建议」，首次展示默认勾选，可手动取消或改选。文档核实的分类筛选字段与指标可多选，每个字段组合分别生成方案并沿用各自字典。确认全部口径后查看方案与只读 SQL，随后可点击「生成并运行测试用例」。尚无已生成用例时隐藏「测试用例」标题，生成后再显示。
4. 方案卡以待保存的规则名称为标题。模型结合适用范围、指标与检查要求组织完整业务名称，存在单个多字段指标时可同时给出各候选的名称，选定后沿用。卡片列出检查对象、已有依据的粒度和适用范围，展开详情可查看关联、日期和空值处理，物理字段、字典码值和完整取数说明收在「原始证据」中。
5. 当前用例全部通过且业务口径已明确后保存并启用。AI 新建不提供单独保存草稿的入口；多方案主按钮显示“保存并启动以上X个方案”，按实际勾选数量分别保存校验并启用。最终启用先保存真实版本，再由后端重验所选用例和版本哈希；不自动创建校验任务。生成成功不表示已测试或启用。

## 分析结果与未保存测试

后台为所有用户积累共享分析记忆。模块迁移 012 保存需求与紧凑的规则结构。修改当前需求时可点「应用修改」，新开弹窗或换账号也能检索相同上下文中的历史口径。模型对照当前需求和活动文档决定沿用、调整或重新分析。修改阈值后，以新阈值编译 SQL，测试从未运行开始。

模块迁移 013 增加原始分析结果缓存。新分析完成并核对依据仍有效后，保存原始选表结果与结构化草稿。相同需求、数据源、模型、活动文档及提示词、报送分类、来源映射、启用知识等配置一致时，直接在本地还原候选，重新核对当前文档与本用户已有规则，模型调用为零。待确认字段、独立问题和多方案完整保留；测试从未运行开始，用户的后续确认独立处理。显式提交新的口径选择时按该选择继续分析。旧共享记忆仍用于相似需求，升级后首次成功分析会建立完整缓存。

AI 分析遇到不同业务维度、原始/当前或其他指标口径时，补充相关证据再核实选择。未核对完整时保持待确认，不把首轮推荐当作唯一结论。修改需求前尚未确认的默认选项不作为旧选择提交；带个人选择的修订结果不写入共享分析记忆。提示词协议更新后，旧的单口径结果不会命中新协议缓存。

缓存仅保存模型结构，不保存预览 SQL、测试成绩或用户确认结果，重启后仍可使用。显式修订请求继续核对用户本轮选择。模型目录提供兼容的配置摘要，修改接口地址或密钥也会使缓存失效。配置或文档指纹变化、结构无法重新核实则重新分析。回退应用版本时可保留缓存表，既有规则与任务数据继续使用原表。

用户手动选择的字段和范围仅用于本人本次修订，不写入共享分析基线；下一位用户仍须看到原始需求中有依据的不同口径。界面的建议勾选和此前选择提示不等于当前用户已经确认。

活动文档的内容或版本、报送分类、启用的业务知识或通用校验口径改变后，按新依据分析。字典改码时使用当前码值。其他分类新增同名字段时，依据本次需求判断目标分类和表，多个合理口径供用户选择。分析期间依据变化会自动重算。选字段期间依据变化，可以点「按最新口径重新分析」保留需求原文。历史 SQL、测试成绩及业务数据行不进入共享记忆。

- AI 分析等待态采用方案 A：顶部两层只读需求卡展示实际数据源、模型配置名和需求原文，中间为双层呼吸星光、一位小数的真实等待时间和不定进度线，底部可取消。仅等待期间隐藏下拉和编辑框；不复制原型切换按钮、示例数据或模拟进度。分析完成后结果、口径选择、SQL 和保存前测试布局不变。手动新建和编辑不受影响。
- 候选生成与口径复核期间的行内等待提示采用三个蓝色圆点依次轻跳，完成或失败后随当前状态移除。动画不增加模型调用或计时器，按用户要求在系统开启减少动态效果时也保持跳动。
- 测试入口带 AI 星芒图标，点击后保留约 3 秒生成动效，实际测试未返回时继续等待，随后统一展示用例和后端计算的结果。生成期间隐藏用例标题和结果表；动效不受系统减少动态效果设置影响，不新增模型调用。所有所选方案沿用同一张清爽表格，保留场景、预期、实际判断和测试结果，完整样本折叠在「查看样本」。可只看未通过项，统计与启用校验仍覆盖全部当前用例；修改预期后须重新测试。样本继续由字段类型与规则合成，不读取业务数据。
- 后端按各方案自己的表和字典核实模型建议。例如「项目原始运行方式为净值型时，累计净值不得为空」，若当前表字典把开放式、封闭式净值型分别映射到两个码值，两个码值均用于筛选。同一字段有多个合理解释或字典缺少映射时，页面先展示需要用户决定的事项。「模型判断」保留模型原始判断，便于与最终采用的条件对照。
- 「净值型项目的累计净值不得为空」省略了运行方式的字段口径。如果当前表的运行方式和原始运行方式都能表达这项分类，页面列出两个字段及各自字典取值，模型建议会标在对应选项上。只输入「净值型项目」时，可以先定位检查范围，再补充要检查的字段和异常条件。
- 分类无法确定时可保持未分类并继续分析；不得伪造分类。仅有“一般/通常/原则上”而没有明确自动排除要求时，保留合理例外、提示人工核实；具体例外排除和额外状态筛选仍不能静默省略。
- `POST /ai/preview` 按当前激活文档校验数据源、表和字段。补充答案引出后续问题时，响应只给出待确认项和字段信息。所有口径确认后才编译 SQL 并生成参数、哈希及样本。`POST /ai/tests` 对同一规则重新校验并运行合成样本。两个接口均不写入规则或测试记录，也不读取业务数据行。
- SQL 使用所选数据源的方言和参数绑定。数据源的数据库类型变更后，已有版本需按新方言重新预览、保存和测试。发现明确的范围、条件或阈值遗漏时，预览前提示核对。
- SQL 预览与复制按查询子句排版。新预览 SQL 的数据日期、校验值和本表比较值使用各自字段中文别名，内部 `data_date`、`checked_value`、`comparison_value` 角色由可信映射保留。预览、保存与执行使用同一投影，已有规则继续按其已保存版本校验。
- 多候选各自以校验字段所在表为主表，并核对需求所指的筛选维度。本表有对应状态时直接筛选。筛选依据位于其他表且活动文档明确同维度业务键、同一数据日期时，使用 `EXISTS` 关联筛选。已核实的跨粒度方案可分别运行，分析结果给出对应的核查建议。
- 「通用校验口径」提示词同时用于选表、规则生成和补充建议。系统默认按忽略币种处理，可在校验设置编辑，保存后用于下一次分析。
- Excel 在导入时解析为版本化的表、字段元数据，分析读取当前活动版本的数据库记录，再按需提供文档证据给模型。已确认的业务约定可写入「通用校验口径」供模型判断，无需改变元数据表结构；同一报送日期等值条件的等价写法不会被误判为跨轮口径变更。
- 模型可给出业务指标字段选项和推荐项。输入「净值不得为空」时，如果当前表只有单位净值一个符合条件的字段，系统直接采用；有多个合理字段时才显示字段选择和「全部都要」。全选后每个字段形成一条独立规则。只输入「净值」时，还需先选定检查要求或补充需求。
- 范围候选按需求和文档业务含义判断。共用字典只复用码值说明，不强制逐项审阅或解释无关字段；真实字段歧义及所选字段的完整字典校验继续保留。
- 当前分析沿用已选模型的供应商默认参数；调用选项仅通过模型平台v2白名单传递。快速实验参数未默认启用，几秒返回但字段、结构或范围错误不算通过。
- 默认用例按文档类型生成正常、异常、边界和空值样本。需求、通用校验口径或字段定义明确 NULL 按 0 比较时，模型可选择 `null_policy="zero"`，系统核验真实数值类型后保留到 SQL、用例及保存执行；其他常量校验维持原有数值与缺值处理。汇总中的金额 NULL 可按 0 相加；普通比较仅匹配已有明细，没有对应明细不能当作金额 0，缺明细核查按有依据的业务范围作为独立建议。独立的字段缺失检查、非数值字段和关联键不受该策略替代。策略变化必须重存新版本和重测。
- 单次预览测试限 1–100 个用例，只接受比较涉及字段、有限数值/短字符串/空值与 0/1 预期；客户端提供的通过状态或实际结果不会被信任。
- 修改需求/数据源/模型会使旧分析与测试失效；修改预期判断、字段选择或空值处理会清除旧测试证据。最终确认仅接受最新保存版本、匹配哈希、非空且全为 passed 的服务端用例；失败、未运行或未知状态均拒绝。
- 这是进程内合成样本测试，不是在业务库执行预览 SQL；通过不证明真实表范围、业务数据或数据库执行结果正确，SQL 日期等参数仍需在正式任务运行时绑定。

“测试可用性”只检查短对话能否得到非空响应，不保证正式规则生成耗时或内容正确。
页面按实际后台阶段显示等待。超过 60 秒提示耗时较长；单次模型调用最多 120 秒，同步和异步分析均为整轮最多 180 秒、最多 4 次模型调用，超出后明确结束并提供错误编号。上述限制控制等待边界，不保证当前网关在一分钟内生成正确结果。

## 真实分析进度与取消等待

- `POST /ai/analyses` 创建进程内临时分析，`GET /ai/analyses/{analysis_id}` 读取真实阶段、模型轮次、最近状态时间和总预算，不延长总截止时间。`DELETE` 通知同一任务和已建立的模型连接结束。三个接口都校验 AI 使用权限和任务所有者。同步 `/ai/parse-rule` 使用相同整轮预算，外部取消信号不会延长预算。
- 页面创建任务时带上 `await_first_poll: true`。后台收到任务所有者对该 ID 的首次查询后才发送模型请求，创建响应遗失时不会产生模型调用。发起分析、结束和提交预览前，页面通过宿主核对当前登录账号并同步其会话令牌。
- 前端仍串行轮询真实阶段，读屏动态提示当前阶段和已返回的文档事实；等待界面不展示步骤清单或完成百分比。单调时钟每 100ms 只更新计时数值，流逝时间不改变阶段；慢响应单独提示。活动进度线是必要状态反馈，星光呼吸和计时蓝点属于可减弱的装饰。
- 点击结束会断开本系统到模型接口的连接，阻止后续阶段并丢弃迟到结果。后台清理期间任务为 `cancelling`，退出后为 `cancelled`。供应商收到断连后何时停止推理及如何计费，取决于其接口实现。
- 临时任务最多缓存 64 个，每用户 8 个，同时运行上限分别为 8 个和 2 个。完成态保留 900 秒。原 1800 秒无轮询期限仅用于放弃任务的清理，180 秒整轮截止始终优先，配置变化重跑也共用该预算。终止后停止后续模型轮次并禁止发布迟到结果；已进入原子提交的结果会完成提交。模块停用时也会终止在途分析，进程重启后可重新分析。平台系统 DNS/TCP 建连阻塞无法立即强制退出，已建立连接的取消与超时会关闭实际连接。

## 集市项目并列检查

- 集市层明确以项目为粒度、按同一个数值常量对 2–3 个项目字段分别比较时，先在活动文档的 `reg_pub_project_info` 查字段。能确定表达式结构时不调用模型选表或生成；不把费用实收当作实收信托，也不把并列字段当作跨表比较。无法按该受限结构识别、或存在关联/汇总/例外时仍走原分析流程。
- 例如「存续项目的资产和实收不得小于 0」拆为两项，实收取本表文档的实收信托；简称“资产”只在该项确认具体字段。存续字典选择对同一分析的并列检查共用，不跨分析自动确认。每项分别编译预览、分别进行不落库合成测试；不会自动保存或启用。

## 低打扰的多口径候选

- 同一业务词在当前活动文档中对应多个合理目标时，完整展示有据的候选方案，单次支持最多 8 个独立方案。每个方案列出检查对象、真实字段、数据粒度和推荐依据，完成本方案的全部确认后展示 SQL。需求指向项目且文档提供项目级证据时，优先推荐项目级方案。
- 分析覆盖当前来源的完整字段目录，优先发送相关详细证据，保留真实歧义。证据充分时同一次回复给出目标表与规则草稿；引用尚未展开的字段时补充相关文档。相关候选逐条按完整文档核验并编译。换表时重新核对主键、日期与筛选范围。非零阈值涉及不同单位时保留具体问题，各方案独立确认。
- 用户可勾选一条或多条，固定底部显示“保存并启动以上X个方案”；勾选不保存。查看与合成测试按方案隔离，切换使旧请求失效，不能把 A 的通过证据用于 B。推荐不等于已确认或已测试。
- 当前展开的方案已有 SQL 预览时可随所选方案一同测试，方案勾选保持原样。主按钮按勾选范围保存并启用，不要求展开，不包含未勾选方案；任一所选方案不满足版本与测试条件时禁用并提示原因。卡内只提供查看入口。
- `POST /ai/candidates/batch-save` 复用管理权限，接收 `{request_key:UUID,definitions:[...]}`（含字段多选和补充规则最多 26 条）。全部按当前文档规范化编译，规则/版本/历史与请求回执在同一事务提交；MySQL 锁定唯一活动文档行后检查 owner/key/hash，重复请求返回既有结果，key 重用不同内容或文档漂移拒绝。不存在/多个活动文档不保存；批量保存本身不新增表。编号按自增主键生成，避免单/批保存碰撞。
- 较长的补充方案说明可随主方案一起保存。规则列表保留前 1,000 个字符，版本和详情仍保留完整说明。
- 批量保存接口只保存独立待启用版本，不确认、不启用。AI 主按钮在保存后读取并复测全部所选版本，全部通过后逐条确认启用；不创建或执行业务任务。保存回执未知时保留原请求键并锁定勾选和口径，重试读取同一次保存结果。部分启用失败可重试，已启用且版本未变的方案跳过重复确认。同一方案保存后不重复创建；若修改已保存方案，明确引导编辑原规则。单方案启用仍须先通过当前预览测试，再保存/复用实际版本并在后端重验非空全部 passed、最新版本与 hash。
- 批量保存的未知异常返回关联错误编号，并在模块日志记录脱敏的异常类型、驱动错误码和代码位置，便于定位；不将未知回执当作确定未保存，也不在日志记录完整 SQL、请求体或连接凭据。
- 有证据的目标选择歧义转为方案差异；真实的范围、关联、单位、例外及不支持要求不能被顺带清除。只有确实缺证据、无法提供可靠选项时才要求具体补充，已确定日期与其他口径保留。
- 跨维度的一致性核对由同次回复中的模型建议提出，系统核实引用和实际能力。不同粒度可能 1:N；期间、单位、币种及业务口径未证实前标为待确认，不默认认定两个指标应相等，也不以逐行 EXISTS 代替汇总一致性。

## 项目定位、缺值核查与独立 AI 建议

- 点击方案卡片在卡内展开 SQL 与业务说明，卡内的文档和模型判断可单独展开。收起卡片即收起详情。独立测试区用一张表展示所选方案的全部用例，测试证据按各自规则版本保存。
- 卡片只保留「查看此方案」，不提供单条保存启用按钮；勾选一条或多条方案均通过底部统一入口保存并启用，沿用测试、版本与重复保存检查。状态标签完整横排，空间不足时整组换行。展开和切换详情有 160ms 的轻微过渡，独立于系统动画开关；普通重绘不重播，收起取消动画。
- AI 补充建议只在方案生成阶段显示，口径确认阶段不显示。卡片只提供「采纳」，分析进度、真实业务澄清、取消与重试均留在该建议卡片内，原方案保持可见，不显示内部提示词或结构化上下文。采纳生成的方案加入现有列表，沿用所选范围并默认勾选，可与原方案一起测试和保存；原方案已完成的测试保留，失败或取消不改原方案。采纳分析不递归生成新建议，原列表中的其他建议继续保留。
- 采纳使用当前已勾选且已预览的父方案收据，保留筛选、关联与数据日期。可移植的期间单指标检查沿用原上下界、等号与空值口径；汇总建议使用建议自身的指标、SUM 及差额判定，不继承主方案的单值阈值。不同父条件和范围成对保留，不交叉组合；无法保持关联含义时明确询问。执行条件和范围相同的方案合并，不同范围通过活动文档字段中文名及必要字典含义区分。新增期间适用范围须有文档和已确认口径依据。
- 建议明确更换已有筛选范围时，模型用 `scope_replacements` 声明真实表字段和新谓词，系统按活动文档及当前已选方案核实，保留其余条件。相应单指标检查用 `check_target` 沿用已有比较表达式声明建议自身的异常条件，后续生成不能再采用主方案的旧比较方向。建议缺少必要声明时先补核，仅未解决的建议保留待核实；首次解析与缓存恢复采用相同的规范化结果。
- 采纳方案与已有方案的已核实执行定义一致时，复用原卡片、已有测试和保存版本；不同字段、范围、阈值、空值、日期、关联、汇总或业务定位键仍独立保留。字段比较复核保留已声明的操作数类型和表角色。
- 模型草稿中的合法项目驱动提示选错侧时，仅在活动文档能唯一证明关联关系的情况下纠正；缺少来源或存在多个候选时仍需核实。正式预览及保存继续校验实际项目角色，不因模型提示而省略范围、关联或日期检查。
- 模型推理控制按实际模型标识适配：`LongCat-2.5` 使用 `thinking.type`，DeepSeek 和其他模型保留原有 `reasoning_effort` 参数；分析上下文和实际请求使用同一组选项，动态输出预算及单题总预算不变。
- 已确认的期间指标适用范围可在「通用校验口径」另起一行登记 `PERIOD_APPLICABILITY`，其后为 JSON 对象：`source_id`、`table`、`field` 指明实际数据源、表和指标，`filters` 使用现有筛选字段、操作和取值。系统按活动文档核对字段类型及完整字典后，按实际检查指标将该范围传递到采纳分析、预览和保存；建议附带编号、日期等引用时仍保留适用范围。已确认的取值不因模型误写排除码而重复询问，新增或冲突的范围仍须核实。登记内容必须已有明确业务依据，不能按字段名相似度猜测；换环境须核对实际数据源 ID。
- 项目相关校验在实际 SQL 和异常结果中输出项目编号与名称。识别本表字段的中文名，或与结构化来源一致的完整直取说明，例如人行项目明细的 TCMP 编号与产品名称。需要同源项目维表时，核对键、日期和唯一性证据，再确认关联口径。
- 文档缺少项目编号或名称时，预览入口说明具体缺少的字段以及从「校验设置 → 文档快照」更新文档的步骤。
- `reg_pub_project_info` 固定用活动文档中的 `c_projname` 作为「项目名全称」，不再询问 `c_proj_name`；缺列时提示文档缺口，不用其他列代替。其他表沿用原有文档判断。
- 旧版定位规则保留原有名称查询与历史定义。新 v2 项目规则直接取项目表名称，不附加编号为空、重复项目等检查，不为定位增加相关计数子查询或额外异常分支。仍最多两张不同物理业务表，不能夹带第三表或跨源。
- 结果逐行登记业务键、项目码名、项目定位状态、核查类型与原因，规则状态/异常行/截断在同一事务提交；重复或取消后的迟到结果不得覆盖。界面及 CSV/XLSX 均保留这些字段，数字 0、文本前导零不丢；导出字符串避免公式执行。历史占位明细无法恢复，明确标记项目身份或类型未采集。
- 目前项目输出支持结构化 field_compare（包括一元、筛选与两表规格）。旧项目规则缺映射、或复杂类型无法安全补出项目身份时明确拒绝，不能悄悄继续只查合同，也不任意改 GROUP BY/判定粒度；需重核并保存受支持的新版本。
- 末尾 AI 补充建议由模型提出，后端逐条核实真实文档引用和执行能力。主方案完成后，以精简的独立请求核对已有建议及与当前指标匹配的已确认补充口径，不重写主方案，继续共用本次输出预算。完整修订清单替换旧建议，明确为原请求和已预览字段的重复项不另列。没有适用依据或主案已经覆盖时可返回空数组；已有待核实建议或明确相关口径却未说明空清单原因时，标记建议尚未完成。该轮超过 20 秒或响应无效时保留主方案并提示未完成，总时限与用户取消仍终止整次分析。不由程序扫描主键、字典或不同粒度后拼接通用建议。
- 已通过引用核实的模型建议在方案生成阶段完整展示，包含待确认和暂不支持的提案；不因建议自身尚无 SQL 或涉及其他候选字段而遗漏。页面说明模型来源、业务依据、待核实条件和执行限制；主需求过期时旧建议随之失效。内容按既有去重与容量边界处理，不把建议倒灌成主规则待确认项。
- 模型提出的两表数值求和核对可标为待确认，须另行核实对应键、数据日期、汇总范围、单位及差额判定。跨源、超过两表或当前不支持的运算保留显示并说明限制，不笼统声称引擎不支持汇总。模型提供的 SQL、执行定义和 supported 自述不能直接采用；建议不自动保存、启用或执行。
- 历史参考与本人修订均复用紧凑文档目录，并在字段证据充分时合并选表和生成。历史涉及表不无条件完整附加；新阈值、活动文档归属、字段和范围仍独立核对，缺证据时保留扩展与澄清路径。
- 多方案回复兼容各方案独立携带选表和草稿，直接保留有据的不同维度。补取证可纠正尚未确认的模型草稿，不把首稿误当成用户已经确认的业务口径；原始需求和用户明确补答的条件仍须完整保留。协议升级使旧分析缓存重新核实。
- 常规执行与结果定位策略写在「通用校验口径」，由模型根据本次文档确定关联、缺记录处理及真实定位编号，不再无条件追加三项确认；系统保留真实表列、类型、日期字段与SQL结构校验，不添加具体表/字段的业务选择规则。模型未解决的关系或实质业务歧义仍可询问。普通关联缺信息时的“暂不检查、需另核”是结果说明，不当作通过，也不冒充已经列出缺记录清单。模型给出的合法DATE字段不依赖固定中文列名；选择数据所属期间的业务知识在可编辑口径中维护。协议8及原始结构缓存保留各方案的定位列；未决执行选择可在补证后完成，原关联键、日期、汇总、筛选和已确定策略不得被无关修复改变。现有完成结果仅在用户主动重新分析时更新。

## 数值常量比较

表单的比较目标可选字段或数值常量。比如“金额不得为 0”，违规触发条件应为“金额 = 数值常量 0”，不是“金额 ≠ 0”。

- 旧规则的 `expression: {left, op, right}` 仍表示两字段比较。
- 常量规则使用 `expression: {left, op, right_type: "value", right: 0}`；支持有限整数与小数，不接受字符串、布尔、空值和 NaN/Infinity。
- 日期映射采用 `report_date_field`；旧规则仍默认 `report_date`。后端按真实文档判断期间语义，只有一个明确的数据/业务/余额/报送等 DATE 日期时自动采用并在摘要中说明；多个合理候选、缺少语义证据或只有事件日期时才给具体选项，不因仅有一个 DATE 就使用项目事件日或采集时间；没有日期字段时明确提示补充文档。SQL 只替换受核验的列标识符，运行期日期仍绑定 `:report_date`，映射计入版本哈希和变更历史。日期选择及预览重试不调用模型；预览失败保留候选、已选口径及可重试选项，不用全局错误遮掉结果。SQL/测试证据仍须重新生成，未确认事项或未全部通过的用例不能启用。
- 常量使用 SQL 绑定参数 `right_value`，不会被当作列名；生成、编辑、保存、样本测试和实际查询使用相同语义。常量模式严格按异常触发运算符判断相等，不套用字段比较的“相等放行”口径。
- “一般不为 0”以命中后人工核实提醒保留合理例外，不自动猜测或排除具体例外。常量目前不支持字符串或日期。

## 基础完整性、复合筛选与两表关联

- 一条字段比较规则可保留 2 至 8 项违规条件。`expression.logic` 为 `any` 时任一项命中即可，为 `all` 时需全部命中。`conditions` 中每项分别指定字段及比较方式。范围筛选和业务日期约束作用于整组，同一组的关联条件在同一条关联记录上核对。单项规则继续使用原字段格式。
- 例如“净值不得大于 1 或小于 0”命中上下限以外的记录，0 和 1 均合规。“截止日同时早于发行日和入账日”只有两项比较都成立才命中。选定一个指标后，同一指标的所有比较一起更新。勾选多个指标时，每个指标按完整条件生成规则。
- 生成规则时以活动文档核对模型提出的字段和字典。多个有依据的选择会在 SQL 生成前展示。真实文档缺少指标、计量单位或关联依据时，保留对应的问题供补充。
- 选完指标和筛选口径后，页面提交当前选择核对。后端按活动文档重新验证选择及字典码集，已经由选择解决的模型疑问归入模型判断。若确有另一个日期、单位或状态条件需要确认，页面只展示剩余问题。此步骤沿用当前候选。
- 生成方案后可用底栏「重新选择口径」返回本次原始选项，保留上次已确认的勾选。重新确认沿用当前分析进行文档复核与 SQL 编译，清空旧方案测试证据，启用前须重新测试。保存、测试和启用期间禁止返回；输入已修改时须先应用修改。已保存规则不随重选改变，相同定义继续识别已保存状态，变更后的口径可另存草稿。

- 日期字段“不能为空/必须有值”使用一元 `expression: {left, op: "is_null"}`，编译为查找 `IS NULL` 的记录；“必须为空”使用 `is_not_null`。无右值；`null_policy="violate"`、`equality_policy="allow_equal"`，不能追加 skip 过滤目标空值。字符串空串/空白不自动等同 NULL，不能把日期列伪造成空串测试。
- `filters` 支持最多 8 项 AND：`{table:"base"|"related",field,op,value,confirmed}`。运算符为 eq/neq/lt/lte/gt/gte/in/not_in/is_null/is_not_null；列表最多 50 项、字符串最多 200 字。值始终绑定参数；IS NULL 运算符不接收任意表达式。文档同名状态存在不同码时展示各自字典选项，用户明确选择，不硬编码“1=存续”。
- 集市层明确为项目维度时，主表使用当前授权文档的 `reg_pub_project_info`，不改用合同、账户或汇总表；粒度不明时保留澄清或真实多候选流程。识别项目状态、存续和是否完结相关字段，但只有明确的存续或未完结需求才补存续筛选。
- 报送取数范围说明表中已有的数据，用于选表和判断覆盖。校验筛选根据需求和当前表的字典确定，模型带入的上游取数条件不会重复执行。明确的范围可按同类字段的字典标签或「是否…」字段的肯定值匹配，例如存续项目、当期终止项目、已复核客户。字段和值唯一时直接采用，存在多个口径时供用户选择，明确提出的条件缺少取值时提示补充。
- 存续口径记录在当前浏览器，按登录用户、数据源和表隔离。下一次存在同字段、同操作符、同值和同字典含义的选项时预勾选并标「上次」；可改选，必须显式继续才生成预览。不是审批、自动保存或启用，清除本地浏览器数据后失效。
- 可选 `join` 仅支持同一授权数据源中第二张真实文档表：`{table_name,on:[{left,right}],report_date_field,relationship_confirmed,unmatched_policy}`。最多 4 对等值键；左键属于主表、右键属于关联表，类型须兼容，两表分别选择真实 DATE 业务日期并绑定同一期。主表字段可通过 `expression.right_table="related"` 与关联表字段比较。
- 后端生成固定 EXISTS 半连接，不开放任意 JOIN/SQL，右表重复不会放大主表异常条数。同名字段或两边都有主键不等于业务关系已证实，关联含义仍需明确确认。`unmatched_policy` 缺省 unresolved；用户明确选择 exclude 才只检查同日有对应记录的范围，无关联记录不代表正确，完整性需单独检查。
- 模型确认标记不作为用户确认。筛选确认、关联含义和未匹配策略未解决时不能启用；新结构的样本包含主表行、关联行列表和校验日期，实际计算筛选/键匹配/同日关系，覆盖范围外、无关联、错期及重复关联，不会只测原金额谓词冒充联表测试。
- 新规则保存时重新按活动文档规范化，忽略客户端元数据/SQL，绑定文档版本；保存后测试核验实际两表元数据但不读取业务行。确认启用仍要求最新版本、匹配 hash 和非空全 passed 用例；文档变更要求重新核对。执行期检查两表全部引用字段与日期类型漂移，外部任务参数不能覆盖规则中的状态值或比较常量。
- 旧平面样本与非项目、无筛选/关联的历史比较规则保持兼容。筛选/关联结构本身不新增表；回滚到旧代码前必须停用使用新筛选、关联或一元运算符的规则，不能让旧编译器忽略新口径。

## 提示词、选表与人工复核

- 选表和规则生成统一使用 `uncertainties`、`unsupported_requirements` 字符串数组。旧自定义模板的 `uncertainty` 字符串或数组会转换并合并；选表阶段的问题必须传入下一阶段，模型不能自行删除。
- 当前 AI 分析保留授权来源的完整字段目录，按需求相关性、字段稀有度和未覆盖义项展开详细证据，完整字典按引用去重。证据不足时扩大相关范围，后端始终用完整文档核对。字段数量仅作提示，页面直接列出确实缺少的字段、日期或范围。对同一指标的非空与限值要求合并生成一条规则；文档可确定分类字段和完整码值时自动采用，带“一般”的阈值命中后提示人工核实。完整文档能唯一核实需求全文的单表范围和零值比较时，模型附带的说明保留在「模型判断」。「当期结束」和「当期终止」以同一期间的实际终止字典核对，缺少证据时暂停生成预览。
- 内置模板给出完整 JSON 示例，明确正常条件与违规条件相反；不得把近似金额字段互相替代，缺乏语义、类型、单位或取数逻辑证据时须留下待确认项。“存续”“一般”“通常”和例外限定不能静默省略。
- `uncertainties` 及对齐的 `uncertainty_resolutions` 复核证据仍随版本保存；真实字段选择会记录相应选择证据，不能把其他未决事项一并放行。AI 页不展示泛化的逐项说明输入；目标有多个真实解释时直接选择候选方案，有真实字段/字典选项时就地选择，只有确实缺证据或不支持的要求才需具体补充；手动编辑仍保留说明输入。待确认事项缺少对应证据时，前后端均拒绝确认；修改事项或比较上下文（数据源、表、校验日期映射、表达式、复合筛选、关联、空值/相等口径、需求描述）会使旧说明失效，重新生成也会清空旧说明。执行阶段同样拒绝尚未复核或含不支持要求的定义，不查询业务数据。
- 当前支持的 AND 筛选、基础空值检查、同源两表关联和按键及日期汇总的两表 SUM 核对不能仅因规则类型而判为不支持。超过两表、跨源、任意嵌套的 OR 筛选、COUNT/AVG 等未实现的汇总运算、复杂派生公式、自动例外排除等仍放入 `unsupported_requirements`，仅填写说明不能放行。未唯一命中但存在有依据的多个目标时提供候选选择；缺少可确认的真实对象或字段时才返回“需要澄清”，不伪造候选、不写规则。优先使用能满足需求的单表；证据充分时合并选表与生成，结构缺项修复优先补交对应片段，再运行完整校验。仅共用字典不会触发无关字段审阅或修复。
- 规则阶段只输出结构化定义，不再要求模型生成 SQL；即使旧模板仍返回 SQL，也会丢弃，执行 SQL 由后端编译。独立 SQL 模板保留，但不在当前 AI 新增流程中调用。
- 已保存的模板正文不会自动覆盖。运行时在其后追加版本化输出约束，可在“校验设置 → 生成提示词”展开查看；选择“恢复默认”才会将新默认模板保存为新版本。
- 复核证据使用现有定义字段，不改变平台协议；非项目旧规则缺少复核字段时保持兼容。历史规则中此前已被丢弃的未决口径无法自动恢复，应重新生成或人工补录。回滚到不支持复核字段的旧代码前，应先停用尚有未决口径或不支持要求的相关规则。

## 错误与运维

模型调用错误只返回脱敏错误码、阶段和错误编号；日志用相同编号检索，不记录地址、密钥、提示词、模型全文或业务行。

语义分析只接收完整 JSON 对象或单个合法 JSON 代码围栏，不裁切截断数组、多个片段或重复键。初轮格式错误最多重新请求一次，沿用本次原始需求与文档快照，继续计入整轮预算；不猜补缺失字段或异常条件。

模块启动后，诊断文件位于应用配置文件同目录的 `logs/data_validation/analysis.log`。可按页面的错误编号查找失败类别，并按分析编号查看各轮阶段、耗时及模型返回的 token 用量。单文件上限为 1 MiB，保留最近 3 个备份。模块停止时关闭文件；日志目录不可写时由宿主记录告警，分析功能仍可运行。

如需更换目录，可在启动服务前将环境变量 `AUTO_CHECK_ANALYSIS_LOG_DIR` 设置为可写的绝对目录，模块会在该目录写入 `analysis.log`。

| 错误码 | 含义及处理 |
| --- | --- |
| `MODEL_TIMEOUT` | 当前阶段超时；稍后重试或选择更快的模型。 |
| `MODEL_REQUEST_FAILED` | 模型服务返回 HTTP 错误；管理员检查限流、服务状态和配置。 |
| `MODEL_RESPONSE_INVALID` | 响应结构或规则格式不正确；可重试或转手工。JSON 对象和 Markdown JSON 代码块均受支持。 |
| `MODEL_UNAVAILABLE` | 模型缺失、停用或连接不可用；检查配置。 |
| `ANALYSIS_LIMIT_REACHED` | 临时分析缓存或并发已达上限；等待现有请求结束或稍后重试。 |
| `ANALYSIS_FAILED` | 临时分析未完成；用安全错误编号查询模块日志，不返回上游异常文本。 |
| `ANALYSIS_UNAVAILABLE` | 分析服务已停止或重载；刷新后重新分析。 |

后端源码变更需要以原启动方式和原 `AUTO_CHECK_SECRET_KEY` 重启服务；前端刷新加载最新资源。不要更换密钥或重导配置来修复超时。异常项目身份由模块迁移 010 增加项目编号、项目名称、项目定位状态和核查类型四列，不重写历史业务行；当前执行迁移见前文。由原启动流程应用模块迁移；旧占位明细不可恢复。重载必须继续使用原环境与密钥；旧项目规则需补真实身份并重存重测，不能宣称兼容执行不完整 SQL。回滚前必须停用旧版不能理解的常量/复合规格/项目映射/新空值策略规则，不能只回退界面继续执行。

## 验证

当前工作台使用语义分析协议 2。新生成或主动重新生成的项目规则记录 `project_driver`，按项目表的数据日期与 TCMP 编号匹配明细；项目条件取项目表，明细自身的筛选条件正常保留。项目表包含公司全部产品，不代表每个项目都有各类合同或明细。v3 比较仅检查同项目、同日期下实际匹配且符合范围的明细；无明细、只有其他期间明细、明细全部在范围外时不自动列异常。存在的金额 NULL 仍按已确认口径参与比较，不能把没有合同与合同金额为空混为一谈。测试样本用一个 `project` 和零至多条 `details` 表达，多条违规明细按实际条数测试。

项目驱动标记、两侧字段归属及范围进入版本哈希。未带标记的已存版本和历史分析协议保持原 SQL；当前工作台新规则无法核实项目驱动时保留待确认，不退回明细取数。项目来源和字段缺失、多个项目实体及需要三张物理表的比较明确保留问题，不自动汇总或删去原条件。

SQL 展示和复制仅保留 `:report_date`，其他已校验静态值按数据库方言安全内联，展示参数也只列数据日期。实际执行、版本保存与哈希仍使用参数绑定 SQL。

新生成项目规则采用 v3 SQL 模板，不自行检查项目编号为空或重复，也不以编号非空或唯一性筛选排除记录。单表校验仅包含数据日期、用户要求的范围和异常条件；跨表比较使用 INNER JOIN，汇总先按业务键汇总实际明细，再与项目比较，日期关联不重复添加。用户明确提出的编号为空或重复校验仍可独立生成。已有 v1、v2 版本及历史执行快照保持原 SQL；编辑保存或重新生成时产生新版本，重新测试后才切换启用。

缺明细只作为独立补充建议，不混入字段比较。该建议必须核实“哪些项目应有这类明细”；没有业务范围依据时保留在建议的待确认前提中，不默认要求全部产品项目都有该类合同，也不阻塞当前比较。

### 文本与四则公式

关键词范围及异常表达式支持 `contains_any` / `not_contains_any`，值为字符串数组。包含组任一词命中即可纳入，排除组任一词命中即跳过；严格区分大小写，`%`、`_` 等字符按普通文字匹配。数值列按数据库文本投影检查，提示其类型约束，样本不塞入无法入库的文字。模型返回的纯词表正则可无损转为关键词组，复杂正则会说明尚需明确的匹配能力，不伪造校验。文本列支持字符串相等、不等比较，保留 `02` 等原始码值；`skip` 下跳过 NULL 和空字符串。用户明确指名字典分类且文档映射唯一时，核实对应码值；同名多码保留可辨识的选择。

同一行的四则公式使用结构化运算树，支持字段、有限数值常量、加减乘除、括号以及比较两侧均为算式。已有上期字段直接参与本行计算，不自行关联上一期。明确成文且能由文档唯一绑定的等式按原式核实运算项、符号和异常方向；真实字段歧义只影响相应运算位置。候选与简化编辑器只读展示复杂公式，测试、保存、重新打开均保留完整树；修改业务公式可重新描述需求。

执行时除数为 0 的记录单独输出 `calculation_error`，说明为“公式无法计算：除数为 0”，其余记录正常继续。原始字段缺值仍按本条 `zero`、`skip` 或 `review` 口径处理；已知为 0 的除数不会被其他字段缺值掩盖。整数中间运算先按精确数值提升，避免加乘溢出或整除截断。展示及复制 SQL 仍只保留数据日期变量。
