# 数据校验模块

## 信托业务知识

在「校验设置 → 信托业务知识」可预览、保存和显式启用知识摘要。默认未启用；保存草稿不改变当前启用快照。分析前按来源、期间和主题匹配少量摘要，连续配置在 10 分钟内复用同用户、同数据源、同活动文档和同启用版本的结果，不额外调用模型，也不保留上一条业务请求。模型接口仍接收匹配摘要，不保证供应商输入缓存。勿填入未经授权外发的内部资料、业务行或凭据。部署由独立模块迁移 011 管理，回退前先停用，保留知识表即可。

## AI 新增规则

AI 新建暂时隐藏「监管报送集市」并默认选择「监管报表」。这一限制仅作用于新建界面，不改变手工表单、已有规则或后端数据源配置。

后续文档导入以工作表名「已启用的校验报表分类名称_表名」标注归属，如 `1104报送_贷款明细`、`East5报送_表名`。前缀明确时，分析按文档分类，不采用模型的不同分类；`人行_` 是「人行大集中报送」与「资管产品模板、逐笔」的公共前缀，无法判定具体项时给出两项确认。兼容既有 `人行明细表_`、`人行底稿_`、`人行结果表_` 前缀；未知前缀保留原分析流程。前缀识别与数据源映射是两件事，不更改已有规则。

1. 在系统设置启用模型，并在校验设置导入、激活文档快照。
2. 选择数据源，填写需求；AI 先按文档选表，再按字段生成候选，不读取或发送业务数据行。
3. 直接查看业务结论、后端编译的只读 SQL 和测试用例，无需先保存草稿即可检查预期判断并运行样本测试。
4. 根据结果选择保存草稿，或在当前用例全部通过且业务口径已明确后“保存并启用”。最终启用先保存真实版本，再由后端重验所选用例和版本哈希；不自动创建校验任务。生成成功不表示已测试或启用。

## 分析结果与未保存测试

- AI 分析等待态采用方案 A：顶部两层只读需求卡展示实际数据源、模型配置名和需求原文，中间为双层呼吸星光、一位小数的真实等待时间和不定进度线，底部可取消。仅等待期间隐藏下拉和编辑框；不复制原型切换按钮、示例数据或模拟进度。分析完成后结果、口径选择、SQL 和保存前测试布局不变。手动新建和编辑不受影响。
- 只有真实文档字段可被选择。字段有多个候选或业务标识未定时，逐个展示具体问题与真实选项；选择直接重编译预览，不再次调用模型。其他证据不足或不支持的条件需修改需求，不提供笼统的“已确认”放行按钮。
- 分类无法确定时可保持未分类并继续分析；不得伪造分类。仅有“一般/通常/原则上”而没有明确自动排除要求时，保留合理例外、提示人工核实；具体例外排除和额外状态筛选仍不能静默省略。
- `POST /ai/preview` 按当前激活文档校验数据源、表和字段，忽略客户端 SQL/列清单，编译 SQL、绑定参数及定义哈希；`POST /ai/tests` 使用同一已校验定义运行合成样本，二者均不写规则/版本/测试记录，不读取业务数据行。复用 AI 使用/规则测试权限及平台登录、CSRF 防护，无新增权限码；项目结果扩展见下文的模块升级说明。
- 默认用例按真实文档类型生成正常、异常、边界、空值等合成样本。新数值比较由系统自动绑定策略：缺少无条件且确定的本字段 NULL=0 定义时，原值 NULL 单列“缺值待核实”，不静默跳过或一律零化，不要求业务补讲技术口径；明确文档证据才对相应操作数零化。`issue_kind=missing_value` 与真实数值命中 `numeric` 分开，专项回归验证命中原因及类型；日期、文本、一元空值、筛选与关联键不套用数值零化。策略变化必须重存新版本和重测，不能用旧哈希测试新 SQL。
- 单次预览测试限 1–100 个用例，只接受比较涉及字段、有限数值/短字符串/空值与 0/1 预期；客户端提供的通过状态或实际结果不会被信任。
- 修改需求/数据源/模型会使旧分析与测试失效；修改预期判断、字段选择或空值处理会清除旧测试证据。最终确认仅接受最新保存版本、匹配哈希、非空且全为 passed 的服务端用例；失败、未运行或未知状态均拒绝。
- 这是进程内合成样本测试，不是在业务库执行预览 SQL；通过不证明真实表范围、业务数据或数据库执行结果正确，SQL 日期等参数仍需在正式任务运行时绑定。

“测试可用性”只检查短对话能否得到非空响应，不保证正式规则生成耗时或内容正确。
正式生成的选表、规则生成阶段各等待最多 120 秒（原为 60 秒），两段模型调用合计最多约 240 秒，不自动重试；网络、网关及反向代理仍可能提前中断。

## 真实分析进度与取消等待

- `POST /ai/analyses` 创建进程内临时分析，`GET /ai/analyses/{analysis_id}` 读取真实阶段快照，`DELETE` 合作取消；三个接口均复用既有 AI 使用权限，严格按用户隔离，不新增规则或业务任务。旧同步解析接口保留兼容。
- 前端仍串行轮询真实阶段，读屏动态提示当前阶段和已返回的文档事实；等待界面不展示步骤清单或完成百分比。单调时钟每 100ms 只更新计时数值，流逝时间不改变阶段；慢响应单独提示。活动进度线是必要状态反馈，星光呼吸和计时蓝点属于可减弱的装饰。
- 点击「取消」停止轮询并尽力通知后端，不跳转到完成页，不承诺立即中止进行中的模型请求。重新分析、修改需求、取消和离开都会使旧响应失效。
- 临时任务总缓存 64、每用户 8，全局并发 8、每用户并发 2；完成态保留 900 秒，运行期限 1800 秒（合作取消，不强杀上游 HTTP）。缓存与读取均检查期限；未结束的取消请求仍占用并发，不能通过反复取消绕过限额。模块停用协作取消，进程重启后临时任务失效，需要重新分析，不恢复假进度。
- 此改动提供真实等待反馈，不是模型推理提速：仍最多两次模型调用，每阶段预算保持 120 秒，不自动重试，不更换模型配置。

## 集市项目并列检查

- 集市层明确以项目为粒度、按同一个数值常量对 2–3 个项目字段分别比较时，先在活动文档的 `reg_pub_project_info` 查字段。能确定表达式结构时不调用模型选表或生成；不把费用实收当作实收信托，也不把并列字段当作跨表比较。无法按该受限结构识别、或存在关联/汇总/例外时仍走原分析流程。
- 例如「存续项目的资产和实收不得小于 0」拆为两项，实收取本表文档的实收信托；简称“资产”只在该项确认具体字段。存续字典选择对同一分析的并列检查共用，不跨分析自动确认。每项分别编译预览、分别进行不落库合成测试；不会自动保存或启用。

## 低打扰的多口径候选

- 同一业务词在当前授权来源的活动文档中有多个合理字段时，返回最多 3 个完整 `candidate_options`，不是随意选表后要求重写需求。每项独立展示检查对象、真实字段、文档粒度、依据、差异与后端 SQL；项目主语有明确项目级证据时优先推荐。实收信托、合同实收规模与余额是不同解释，不声明等价。
- 仍是一轮选表与一轮生成；有界相关候选基于真实文档发现并逐条重新核验、编译，不为每张表重启模型。换表不能沿用旧主键、日期或默认范围；不能安全表达的复合筛选/关联不自动跨表替换。非零阈值涉及不同单位时保留具体问题，不把确认一张卡视为其他卡已确认。
- 用户可勾选一条或多条，固定底部明确“保存所选 N 条草稿”；勾选不保存。查看/完善与合成测试按方案隔离，切换使旧请求失效，不能把 A 的通过证据用于 B。推荐不等于已确认或已测试。
- `POST /ai/candidates/batch-save` 复用管理权限，接收 `{request_key:UUID,definitions:[...]}`（最多 3 条）。全部按当前文档规范化编译，规则/版本/历史与请求回执在同一事务提交；MySQL 锁定唯一活动文档行后检查 owner/key/hash，重复请求返回既有结果，key 重用不同内容或文档漂移拒绝。不存在/多个活动文档不保存；批量保存本身不新增表。编号按自增主键生成，避免单/批保存碰撞。
- 批量仅保存独立草稿，不确认、不启用、不创建或执行业务任务。同一方案保存后不重复创建；若修改已保存方案，明确引导编辑原规则。单方案启用仍须先通过当前预览测试，再保存/复用实际版本并在后端重验非空全部 passed、最新版本与 hash。
- 有证据的目标选择歧义转为方案差异；真实的范围、关联、单位、例外及不支持要求不能被顺带清除。只有确实缺证据、无法提供可靠选项时才要求具体补充，已确定日期与其他口径保留。
- `comparison_suggestions` 仅展示进一步核实建议，无自动创建按钮。不同粒度可能 1:N；期间、单位、币种及业务口径未证实不能直接相等比较，需要聚合时当前不支持，不能用逐行 EXISTS 冒充汇总一致性。

## 项目定位、缺值核查与独立 AI 建议

- 点击方案卡片在该卡内展开，一次只展开一张；勾选与当前查看独立，全部已选卡蓝框。展开、收起、切换不丢各自输入/测试/哈希，迟到响应不得覆盖别的方案；不把细节挪到整个列表下方。
- 项目相关校验必须在实际 SQL 和每条异常中输出真实项目编号与名称，合同键只作明细辅助。本表唯一明确字段直接投影；需要同源项目维表时只接受真实映射与完整唯一性证据，明确确认关联口径。多个表/字段/期间给真实选择，不照物理名字猜。不能证明名称时阻止不完整执行。
- `reg_pub_project_info` 固定用活动文档中的 `c_projname` 作为「项目名全称」，不再询问 `c_proj_name`；缺列时提示文档缺口，不用其他列代替。其他表沿用原有文档判断。
- 名称查找使用保留异常的相关子查询：仅唯一匹配取真实名称，缺码、缺名、无匹配或多匹配单独标识；不使用 INNER JOIN 丢异常，不裸 JOIN 放大，不任取 first/MIN/MAX 掩盖歧义。仍最多两张不同物理业务表，不能夹带第三表或跨源。
- 结果逐行登记业务键、项目码名、项目定位状态、核查类型与原因，规则状态/异常行/截断在同一事务提交；重复或取消后的迟到结果不得覆盖。界面及 CSV/XLSX 均保留这些字段，数字 0、文本前导零不丢；导出字符串避免公式执行。历史占位明细无法恢复，明确标记项目身份或类型未采集。
- 目前项目输出支持结构化 field_compare（包括一元、筛选与两表规格）。旧项目规则缺映射、或复杂类型无法安全补出项目身份时明确拒绝，不能悄悄继续只查合同，也不任意改 GROUP BY/判定粒度；需重核并保存受支持的新版本。
- 末尾 AI 补充建议由当前文档事实、用户可见已有规则摘要与现有第二轮生成共同形成，再由后端逐条验证真实引用/能力/去重；事实包有界，已有 SQL 和固定条件值不上传。不增加第三轮、不绑定实收等业务词、无依据不凑数。
- AI 补充建议独立于主定义、SQL、哈希、测试与保存。当前后端预览已生成且口径全确认后，只显示后端认定可进一步检查、直接引用校验主字段的建议；无合格项不显示该区域。不用无关主键或筛选字典凑数，也不把建议倒灌成主规则待确认项。
- 有同源文档证实同粒度、同期间、对应键及同字段取数依据时，可建议跨表核对对应字段值。项目实收只能与同项目同期间的可比合同合计核对，不能与单笔合同直接比较；已有可核对的项目级合同汇总字段可作为对应列，只有合同明细时不把逐笔关联当作汇总，也不新增运行时聚合能力。建议不自动保存、启用或归入业务任务。

## 数值常量比较

表单的比较目标可选字段或数值常量。比如“金额不得为 0”，违规触发条件应为“金额 = 数值常量 0”，不是“金额 ≠ 0”。

- 旧规则的 `expression: {left, op, right}` 仍表示两字段比较。
- 常量规则使用 `expression: {left, op, right_type: "value", right: 0}`；支持有限整数与小数，不接受字符串、布尔、空值和 NaN/Infinity。
- 日期映射采用 `report_date_field`；旧规则仍默认 `report_date`。后端按真实文档判断期间语义，只有一个明确的数据/业务/余额/报送等 DATE 日期时自动采用并在摘要中说明；多个合理候选、缺少语义证据或只有事件日期时才给具体选项，不因仅有一个 DATE 就使用项目事件日或采集时间；没有日期字段时明确提示补充文档。SQL 只替换受核验的列标识符，运行期日期仍绑定 `:report_date`，映射计入版本哈希和变更历史。日期选择及预览重试不调用模型；预览失败保留候选、已选口径及可重试选项，不用全局错误遮掉结果。SQL/测试证据仍须重新生成，未确认事项或未全部通过的用例不能启用。
- 常量使用 SQL 绑定参数 `right_value`，不会被当作列名；生成、编辑、保存、样本测试和实际查询使用相同语义。常量模式严格按异常触发运算符判断相等，不套用字段比较的“相等放行”口径。
- “一般不为 0”以命中后人工核实提醒保留合理例外，不自动猜测或排除具体例外。常量目前不支持字符串或日期。

## 基础完整性、复合筛选与两表关联

- 日期字段“不能为空/必须有值”使用一元 `expression: {left, op: "is_null"}`，编译为查找 `IS NULL` 的记录；“必须为空”使用 `is_not_null`。无右值；`null_policy="violate"`、`equality_policy="allow_equal"`，不能追加 skip 过滤目标空值。字符串空串/空白不自动等同 NULL，不能把日期列伪造成空串测试。
- `filters` 支持最多 8 项 AND：`{table:"base"|"related",field,op,value,confirmed}`。运算符为 eq/neq/lt/lte/gt/gte/in/not_in/is_null/is_not_null；列表最多 50 项、字符串最多 200 字。值始终绑定参数；IS NULL 运算符不接收任意表达式。文档同名状态存在不同码时展示各自字典选项，用户明确选择，不硬编码“1=存续”。
- 集市层明确为项目维度时，主表使用当前授权文档的 `reg_pub_project_info`，不改用合同、账户或汇总表；粒度不明时保留澄清或真实多候选流程。识别项目状态、存续和是否完结相关字段，但只有明确的存续或未完结需求才补存续筛选。
- 存续筛选候选由当前表的真实字典按文档顺序枚举，不由模型先提到的列决定。用户选择后后端只绑定所选列和值；独立关联或日期问题单独保留。候选逻辑中连续编号的步骤分行展示。
- 存续口径记录在当前浏览器，按登录用户、数据源和表隔离。下一次存在同字段、同操作符、同值和同字典含义的选项时预勾选并标「上次」；可改选，必须显式继续才生成预览。不是审批、自动保存或启用，清除本地浏览器数据后失效。
- 可选 `join` 仅支持同一授权数据源中第二张真实文档表：`{table_name,on:[{left,right}],report_date_field,relationship_confirmed,unmatched_policy}`。最多 4 对等值键；左键属于主表、右键属于关联表，类型须兼容，两表分别选择真实 DATE 业务日期并绑定同一期。主表字段可通过 `expression.right_table="related"` 与关联表字段比较。
- 后端生成固定 EXISTS 半连接，不开放任意 JOIN/SQL，右表重复不会放大主表异常条数。同名字段或两边都有主键不等于业务关系已证实，关联含义仍需明确确认。`unmatched_policy` 缺省 unresolved；用户明确选择 exclude 才只检查同日有对应记录的范围，无关联记录不代表正确，完整性需单独检查。
- 模型确认标记不作为用户确认。筛选确认、关联含义和未匹配策略未解决时不能启用；新结构的样本包含主表行、关联行列表和校验日期，实际计算筛选/键匹配/同日关系，覆盖范围外、无关联、错期及重复关联，不会只测原金额谓词冒充联表测试。
- 新规则保存时重新按活动文档规范化，忽略客户端元数据/SQL，绑定文档版本；保存后测试核验实际两表元数据但不读取业务行。确认启用仍要求最新版本、匹配 hash 和非空全 passed 用例；文档变更要求重新核对。执行期检查两表全部引用字段与日期类型漂移，外部任务参数不能覆盖规则中的状态值或比较常量。
- 旧平面样本与非项目、无筛选/关联的历史比较规则保持兼容。筛选/关联结构本身不新增表；回滚到旧代码前必须停用使用新筛选、关联或一元运算符的规则，不能让旧编译器忽略新口径。

## 提示词、选表与人工复核

- 选表和规则生成统一使用 `uncertainties`、`unsupported_requirements` 字符串数组。旧自定义模板的 `uncertainty` 字符串或数组会转换并合并；选表阶段的问题必须传入下一阶段，模型不能自行删除。
- 表数量超过 80 时按需求与表英文名、中文名、来源描述、数据范围的相关性排序后截取，而非固定取前 80 张；仍会提示覆盖范围有限。大表字段也按相关性选取，相关字段附取数逻辑和字典证据。没有读取业务数据行。
- 内置模板给出完整 JSON 示例，明确正常条件与违规条件相反；不得把近似金额字段互相替代，缺乏语义、类型、单位或取数逻辑证据时须留下待确认项。“存续”“一般”“通常”和例外限定不能静默省略。
- `uncertainties` 及对齐的 `uncertainty_resolutions` 复核证据仍随版本保存；真实字段选择会记录相应选择证据，不能把其他未决事项一并放行。AI 页不展示泛化的逐项说明输入；目标有多个真实解释时直接选择候选方案，有真实字段/字典选项时就地选择，只有确实缺证据或不支持的要求才需具体补充；手动编辑仍保留说明输入。待确认事项缺少对应证据时，前后端均拒绝确认；修改事项或比较上下文（数据源、表、校验日期映射、表达式、复合筛选、关联、空值/相等口径、需求描述）会使旧说明失效，重新生成也会清空旧说明。执行阶段同样拒绝尚未复核或含不支持要求的定义，不查询业务数据。
- 当前支持的 AND 筛选、基础空值检查和同源两表关联不能再仅因规则类型而判为不支持。三表以上、跨源、OR 树、聚合/派生公式、自动例外排除等仍放入 `unsupported_requirements`，仅填写说明不能放行。未唯一命中但存在有依据的多个目标时提供候选选择；缺少可确认的真实对象或字段时才返回“需要澄清”，不伪造候选、不写规则。选表附带有界相关字段/字典线索，优先使用能满足需求的单表；选择/生成仍两次调用，不因每个口径问题再次调模型。
- 规则阶段只输出结构化定义，不再要求模型生成 SQL；即使旧模板仍返回 SQL，也会丢弃，执行 SQL 由后端编译。独立 SQL 模板保留，但不在当前 AI 新增流程中调用。
- 已保存的模板正文不会自动覆盖。运行时在其后追加版本化输出约束，可在“校验设置 → 生成提示词”展开查看；选择“恢复默认”才会将新默认模板保存为新版本。
- 复核证据使用现有定义字段，不改变平台协议；非项目旧规则缺少复核字段时保持兼容。历史规则中此前已被丢弃的未决口径无法自动恢复，应重新生成或人工补录。回滚到不支持复核字段的旧代码前，应先停用尚有未决口径或不支持要求的相关规则。

## 错误与运维

模型调用错误只返回脱敏错误码、阶段和错误编号；日志用相同编号检索，不记录地址、密钥、提示词、模型全文或业务行。

| 错误码 | 含义及处理 |
| --- | --- |
| `MODEL_TIMEOUT` | 当前阶段超时；稍后重试或选择更快的模型。 |
| `MODEL_REQUEST_FAILED` | 模型服务返回 HTTP 错误；管理员检查限流、服务状态和配置。 |
| `MODEL_RESPONSE_INVALID` | 响应结构或规则格式不正确；可重试或转手工。JSON 对象和 Markdown JSON 代码块均受支持。 |
| `MODEL_UNAVAILABLE` | 模型缺失、停用或连接不可用；检查配置。 |
| `ANALYSIS_LIMIT_REACHED` | 临时分析缓存或并发已达上限；等待现有请求结束或稍后重试。 |
| `ANALYSIS_FAILED` | 临时分析未完成；用安全错误编号查询模块日志，不返回上游异常文本。 |
| `ANALYSIS_UNAVAILABLE` | 分析服务已停止或重载；刷新后重新分析。 |

后端源码变更需要以原启动方式和原 `AUTO_CHECK_SECRET_KEY` 重启服务；前端刷新加载最新资源。不要更换密钥或重导配置来修复超时。本次不变更平台接口；模块 schema 升至 10，仅在异常明细表增加项目编号、项目名称、项目定位状态和核查类型四列，不重写历史业务行。由原启动流程应用模块迁移；旧占位明细不可恢复。重载必须继续使用原环境与密钥；旧项目规则需补真实身份并重存重测，不能宣称兼容执行不完整 SQL。回滚前必须停用旧版不能理解的常量/复合规格/项目映射/新空值策略规则，不能只回退界面继续执行。
