# 看板管理模块

“看板管理”用于维护两个固定看板的数据来源，不能新建第三个看板：

- 金融监管报表报送大屏：7 个内置数据区域。
- 金融监管报送流程大屏：3 个内置数据区域。

页面使用浏览器会话存储分别记住当前看板及各看板最后选择的数据区域，刷新浏览器后恢复原选择；区域已不存在或不可用时才回退到当前看板第一个区域。

顶部两个看板使用完整的紧凑 Tabs 组件切换，当前项通过浅蓝背景、主题色加粗文字和 3px 底部选中线突出显示。切换区右侧使用统一操作组放置“预览当前看板”菜单和“接口监控”入口，避免操作项被分散到页签中部。悬停预览菜单后可选择“接口数据”或“看板页面”；关闭预览后焦点返回当前看板 Tab，下拉菜单随即收回。接口数据预览和看板页面预览均读取固定 7+3 内置区域和固定字段，与外部接口使用同一份业务结果；自定义区域和自定义字段仅保留在配置和来源测试能力中，不进入完整看板结果。预览使用接近全屏的弹窗展示，支持右上角“关闭”和 Esc 关闭，点击遮罩空白处不会关闭。

“月度信托项目数量”“报表对账完成时间”“报表校验问题处理”和“季度报表特殊处理”四个内置趋势区域使用年度快照。每次看板预览先执行当前已保存的 SQL 或系统查询，查询返回的周期按业务所属期写入对应年度快照，未返回的旧周期继续保留；接口最终按周期升序返回当前自然年的合并快照，响应通过 `data_year` 隔离年度；实时查询失败但当年已有完整快照时返回旧快照并标记 `snapshot_status=stale`，没有当年可用快照时返回区域错误 `data_not_ready`，顶层为 `partial`。每年 1 月，新年度没有可用年度趋势数据时返回 `data_not_ready`；“报表对账完成时间”来源返回的上一年 12 月迟到记录写入上一年度快照，但不进入本年度响应。“季度报表特殊处理”的对外预览接口会为当前季度之后尚无数据的季度临时返回 `0`，该补零只存在于接口响应中，不写入年度快照，也不覆盖已有季度值。数据来源编辑区测试继续最多展示 10 行，但该调试上限不得传播到完整看板预览或外部接口；完整看板使用不限行执行器读取全部业务行，成功列表必须满足 `has_more=false` 且 `returned_count` 等于 `rows` 长度。不新增后台任务或额外轮询。

2026 年初始化基线中，“月度信托项目数量”和“报表对账完成时间”为 1—6 月，“报表校验问题处理”为 1—8 月，“季度报表特殊处理”为第一、第二季度。“报表对账完成时间”的初始化历史仅有既时分，完整日期保持 `null`，不推算或伪造历史完成日期。初始化只补缺失周期，不覆盖接口已经采集的数据；7 月及以后的其他数据由看板预览接口查询后生成。

模块迁移初始化上述 10 个内置区域和 22 个内置字段。管理员可以在现有区域追加自定义字段，也可以在任一固定看板内新建自定义区域并一次定义首批字段。内置编码、字段别名和字段类型是后续契约，不能修改；自定义区域和字段支持调整显示名、说明及启用状态。用户创建的区域支持删除，删除时会同时物理删除其字段和来源配置；系统内置区域禁止删除。区域启用状态在右侧区域名称后通过开关直接维护，编辑弹窗只维护区域名称、数据形态和说明，其中区域名称与数据形态按两列同行展示。编辑区域前页面会重新读取最新版本，保存时始终绑定被点击的区域，不受左侧当前选中项影响，避免缓存冲突或跨区域误写。

三个内置 `month` 字段的展示格式直接写入字段说明：“月度信托项目数量”使用 `1月`～`12月`（例如 `8月`）；“报表对账完成时间”和“报表校验问题处理”使用 `YYYY-MM`（例如 `2026-08`）。打开对应字段的管理弹窗即可查看；该说明仅描述看板展示契约，不改变 SQL 校验或接口返回逻辑。

## 外部只读接口

模块通过两个精确外部 GET 路由对外提供 `report_submission` 和 `reporting_process` 两个固定看板的只读数据：

- `/api/external/v1/dashboard-management/boards/report_submission/preview`
- `/api/external/v1/dashboard-management/boards/reporting_process/preview`

外部路由使用看板专属 Bearer Token 认证（由管理员在接口监控页面生成或更新），只返回 catalog 中的 10 个内置区域及其固定内置字段；用户新增区域、追加字段、数据源、SQL 和其他管理信息均不外泄。单区域失败时其余区域继续返回，顶层 `status` 为 `partial`。该 Token 仅适用于这两个精确接口，不得访问第三个看板、其他外部接口、内部模块接口或任何非 GET 请求。完整认证、请求约束、响应、字段映射、错误示例、联调清单和对方系统后端适配建议见 [`docs/dashboard-management-external-api.zh-CN.md`](../../../../docs/dashboard-management-external-api.zh-CN.md)。

### 接口监控

"系统管理 → 看板管理"内提供"接口监控"子页面（受 `dashboard_management.external_api_monitor` 能力控制，默认仅管理员），展示：

- 接口启用状态、Token 来源与系统生成时间、两个固定接口地址。
- 近 24 小时调用、成功、部分成功、失败、平均耗时。
- 分页查看认证通过并命中路由的调用记录，含调用方 TCP 对端 IP、request_id、错误摘要。

监控页沿用系统管理列表布局：状态和 Token 以语义标识展示，两个接口在桌面端同一行并列展示，开始/结束日期复用系统日期选择组件并覆盖所选自然日，查询与重置均使用统一空心按钮，表头与内容统一居中，分页复用系统标准箭头按钮。业务状态使用成功、警告和失败语义色；调用方 IP 和 request_id 只使用等宽文本展示，不提供单独复制按钮。

仅认证通过并命中路由的调用才会被记录；401、503、错误方法、未命中路由和内部预览不记录。调用记录滚动保留 30 天。

## 数据来源和保存规则

每个数据区域只能选用一种来源：可用时选择系统数据，或选择自定义 SQL。一个区域只能保存一条 SQL，这条 SQL 应在执行时返回该区域全部启用字段；系统数据区域追加自定义字段后必须改用自定义 SQL。自定义 SQL 保存不以测试成功为前提，语法错误、连接失败、查询结果缺少字段、字段类型不匹配或单值区域返回多行时仍可保存；保存阶段只拦截明显的写入、DDL、多语句和锁表操作。若最近一次测试失败或保存时发现语句不符合可执行的只读查询结构，“测试执行”旁持续显示“当前 SQL 有问题”及具体原因。“测试执行”仅用于连接、语法、返回字段和类型的提前预览校验。SQL 或数据源变更、字段新增/停用/恢复后仍会使上次测试状态失效，但不会禁用保存。

系统数据模式由模块按内置指标自动生成只读 SQL，并直接在当前 AutoCheck 应用数据库连接中执行。页面来源区只展示来源功能和应用数据库名，数据表中文名、物理表名、字段中文名与查询别名改在系统生成 SQL 顶部以注释展示，并支持返回前 10 行预览；预览表头使用区域字段配置中的中文名，表头与内容统一居中，`datetime` 字段把接口 ISO 8601 值显示为 `YYYY-MM-DD HH:mm:ss`，但不改写接口返回。右侧使用紧凑的区域名称与状态标签代替重复的“基本信息”分组，配置内容由页面统一滚动，不生成内层纵向滚动条；数据源下拉与来源切换器等宽，桌面双栏布局下系统生成与自定义 SQL 编辑框均自动占用剩余页面高度，并禁止手动拖拽改变尺寸。当前系统口径分别来自报送导航统计快照、核对历史、报表特殊处理记录以及报送导航流程/月度报送计划；系统表尚未初始化或没有数据时不会生成模拟结果。

“报表对账完成时间”以 `run_headers.run_date` 作为报送期，关联 `reconcile_runs.total_count`，筛选总差异为 0 的自动对数历史，并取最小的 `run_at`；每年 1 月额外允许读取上一年 12 月的迟到完成数据，但该记录只写入上一年度快照。接口同时返回 `reconciliation_completed_time`（页面展示的 `HH:mm` 时分）与 `reconciliation_completed_at`（完整日期时间或 `null`），并从中派生展示时分。

“季度报表特殊处理”按特殊处理时间统计本年度 `pending`（待确认）与 `completed`（已确认）记录；草稿和作废状态不统计。删除操作会物理删除主记录，因此已删除记录自然不会进入统计。

“当月报表报送时间对比”读取启用的报送导航流程、当月完成快照和月度报送计划，并按流程名称排除“人行大集中”。

执行与预览仅接受任意单条 `SELECT`，或最终返回 `SELECT` 的 `WITH` 查询，支持行注释、块注释、数据库原生函数、自定义函数、操作符、自定义类型及不带 schema 的表名；语法与对象是否有效交由目标数据库判断。保存允许暂存尚未通过上述执行校验的 SQL，但应用仍禁止保存或执行明显的写入、DDL、授权、锁定及多语句；查询连接启用只读事务。成功执行的结果需覆盖全部字段，标量区域至多一行，预览最多展示 10 行。切换来源、数据源或 SQL 后，页面会将当前值与已保存快照比较；切回原值即自动清除未保存状态，只有存在实际差异时切换区域或看板才提示放弃修改。测试失败时，顶部提示和按钮旁状态会同步显示安全的具体原因，包括数据表或字段不存在、SQL 语法、权限、连接、超时、日期或字段类型问题；保存不会清除该失败状态，修改数据源或 SQL 后才会清除旧失败原因。系统不会存储数据源密码到模块表，错误响应也不会回显连接串、密码、SQL 原文、驱动堆栈或本地路径。

## 运维与验证

看板管理的页面查看、配置维护、SQL 测试、外部接口监控和 Token 管理能力均列入“系统管理 / 角色权限”的能力树，可分别授权；Token 管理默认仅管理员拥有。为数据源创建专用、最小权限的只读账号，并按实际使用的 PostgreSQL 或 MySQL 数据库完成连通性、超时和权限集成验证；单元与集成测试中的 SQL 执行器替身不会覆盖真实网络驱动验证。停用 `dashboard_management` 会移除入口、内部/外部模块 API 和静态资源，但不会删除模块的区域、字段、来源配置、年度快照、外部调用记录和外部凭据表或其中的数据；重新启用后相关配置和记录会恢复可读。页面生成或更新的数据库管理 Token 写入成功后立即生效，无需重启；只有使用环境变量兼容回退并变更部署配置时才通常需要重启进程。
