# 2026-07-10 验收测试数据说明

## 口径

本轮自动对数测试不要求单独准备 MySQL 报表库。当前版本自动对数以“自动对账表字段配置”中每张逻辑表绑定的数据源为准；只要测试库中存在对应物理表，并在页面配置到这些表，即可覆盖业务闭环。

## 自动对数

脚本：`sql/append_20260710_acceptance_reconcile_scenarios.postgres.sql`

执行后，报告日期选择 `2026-07-10`。测试数据项目编号均以 `AC20260710` 开头，另有一条 `AC20260709DATE01` 用于验证日期边界。

覆盖场景：

- `AC20260710MATCH01`：完全匹配，不应出现在差异结果中。
- `AC20260710AMOUNT01`：金额差异，预期进入实收本金差异链路。
- `AC20260710BIZMISS01`：业务缺失，估值表缺少 `0004` 资产合计，预期暂无法确定。
- `AC20260710ASSETMISS01`：资产缺失，单个资产科目命中。
- `AC20260710AMB01`：候选不唯一，两组候选组合均可解释资产差额。
- `AC20260709DATE01`：日期边界，运行 `2026-07-10` 时不应出现。
- `AC20260710NULL01`：空值场景，估值科目名称为空但不应导致执行失败。
- `AC20260710DUP01`：重复记录场景，同一项目编号存在两条主表记录，用于验证重复数据处理和展示。

如果所有自动对账逻辑表都放在同一个 PostgreSQL 测试 schema，页面中的各表数据源可以都指向该数据源；不需要为了“报表库”额外准备 MySQL。

执行后，报告期选择 `2026-07-10`。建议勾选 `ZG01`、`ZG05`、`ZG07`、`ZG09`、`ZG10`、`ZG12`，并同时开启公开信息校验和模板校验。

- 字段映射刷新能读到元数据。
- 逐笔校验任务能完成并生成 Excel。
