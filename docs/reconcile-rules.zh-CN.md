# 自动对数规则说明

本文档说明当前程序已经实现的自动对数判断规则，便于后续核对代码和继续追加规则。

## 一、参与数据表

主差异来源：`zf_detail_2024`

- 按 `caldate` 筛选日期。
- 项目编号使用 `projinnercode`。
- 项目名称使用 `projname`。
- 资产合计使用 `a0001`。
- 负债及权益合计使用 `d0000`。
- 实收本金余额使用 `c1000`。
- 只有 `a0001 - d0000 <> 0` 的项目会进入对数结果。

估值表：`fa_valuationreport_dws`

- 按 `d_valuationdate` 筛选日期。
- 项目编号使用 `c_projcode`，与主表 `projinnercode` 对应。
- 科目代码使用 `c_accountcode`。
- 科目名称使用 `c_accountname`。
- 市值金额使用 `f_marketvalue`。
- 科目代码 `0004` 代表估值表资产合计。

科目余额表：`fa_accountbalance_dws`

- 按 `d_balancedate` 筛选日期。
- 项目编号使用 `c_projcode`。
- 科目代码 `4001` 代表 FA 实收信托。
- 余额使用 `f_balance`，同项目同日期会汇总。

DM TA 存续金额表：`dm.ta_pact_survamt_day_zgxg_dm`

- 按 `tpm_date` 筛选日期。
- 项目编号使用 `tpm_tcmpcode`。
- 待结转收益使用 `tpm_htincome`。
- 份额余额使用 `tpm_shareamt`。
- 客户类型主字段使用 `tpm_clientkind_tusp`。
- 客户类型明细字段使用 `tpm_clientkindex`。
- SPV 类型字段使用 `tpm_spvtype`。
- 合同编号使用 `tpm_pactid`。
- 客户名称使用 `tpm_clientname`。

DWS TA 明细表：`ta_pact_detail_dws`

- 按 `d_cldate` 筛选日期。
- 项目编号使用 `c_projcode`。
- 份额余额使用 `f_shareamt`。
- 待结转收益使用 `f_alltincom`。

AM 资产表：`am_pactasset_dws`

- 按 `d_cldate` 筛选日期。
- 项目编号使用 `c_projcode`。
- 资产名称使用 `c_udlyasset`。
- 标的代码使用 `c_stockcode`。

AM 合同投融资表：`am_projinvest_dws`

- 按 `d_cldate` 筛选日期。
- 项目编号使用 `c_projcode`。
- 合同代码使用 `c_pactid`。
- 投融资余额使用 `f_acbalance`，同项目同日期同合同会汇总。

资产细分核查表：

- `dm.fa_security_balance_zgxg_dm`：债券、股票、公募基金、私募基金缺失细分；按项目、日期、证券代码、证券名称查。
- `dm.am_projinvest_zgxg_dm`：贷款、股权投资缺失细分，以及资产差异中的贷款合同逐一核对；按项目、日期、合同代码查。
- `dm.am_projinvest_spv_zgxg_dm`：特定目的载体和信托计划收益权缺失细分；按项目、日期、合同代码查。
- `zgxg_zhbs.ccqxx`：资产收益权缺失细分；按项目、合同代码查，不加日期条件。
- `assman_reg.ex_pledge_back`：逆回购缺失细分和逆/正回购金额差异细分；按 `project_code` 过滤项目，逆回购使用 `subcode LIKE '7%'`，正回购使用 `subcode LIKE '8%'`，不加日期条件。
- `currency_report_24.currency_detail_project_2_1_2`：除回购和拆借外贷款明细表。
- `currency_report_24.currency_detail_project_2_1_4`：债务证券明细表。
- `currency_report_24.currency_detail_project_2_1_5`：股票股权明细表。
- `currency_report_24.currency_detail_project_2_1_5_2`：股权明细表。
- `currency_report_24.currency_detail_project_2_1_6`：特定目的载体明细表。
- `currency_report_24.currency_detail_project_2_1_8`：实收本金明细表。
- `currency_report_24.currency_detail_project_2_1_9`：其他债权明细表。

说明：当前所有 `currency_report_24.currency_detail_project_2_1_*` 报表明细表均只按 `caldate` 判断有无数据，不按项目编号过滤。

## 二、金额比较规则

- 所有金额都用精确相等判断，不允许误差。
- 主差异金额为 `a0001 - d0000`。
- 主差异大于 0 表示“资产大于负债及权益”。
- 主差异小于 0 表示“资产小于负债及权益”。

## 三、整体判断流程

程序按以下顺序判断，前面的规则命中后不再进入后面的规则。

1. 先读取主表中 `a0001 - d0000 <> 0` 的项目。
2. 用估值表科目 `0004` 的 `f_marketvalue` 校验主表 `a0001`。
3. 如果 `a0001` 与估值表资产合计不一致，进入资产端规则。
4. 如果 `a0001` 与估值表资产合计一致，进入负债及权益端规则。
5. 如果能定位到一级原因但不能直接命中具体明细，保留对应“差异”类原因，后续细分对比继续写入详情。
6. 如果所有规则都无法解释差异，差异类型为“暂无法确定”。

## 四、资产缺失

触发条件：

- `a0001` 小于估值表 `0004` 资产合计。

判断含义：

- 估值表资产更大，说明 `zf_detail_2024.a0001` 可能少计资产。
- 能命中具体资产明细时，差异类型展示为“资产缺失”。
- 如果不能命中具体资产明细，差异类型展示为“资产差异”。

排查范围：

- 只查估值表 `1` 开头的实际末级科目，不要求科目代码必须包含四个点。
- 实际末级科目指当前项目估值表中没有下级科目的科目，例如存在 `1541.01.CC8250MX` 时，`1541.01` 不作为资产缺失候选。
- 使用 `f_marketvalue` 与资产差异金额匹配。
- 全末级组合优先；只有全末级组合返回 `combination_overflow` 时，才按科目前四段自然分组组合。
- 前四段分组组合仍只使用该分组下的实际末级科目，不做上一层聚合。
- 命中科目会继续细分资产类型并写入 `具体原因` 列，格式为 `①资产类型缺失：资产名称；原因：具体原因`；没有最终原因时省略 `；原因：...`。
- 多个资产共同命中时，按 `①②③` 换行拼接，并在展开详情中展示“资产缺失细分”表格。

资产类型按科目编码前缀识别：

- 特定目的载体：FA 科目前四段为 `1101.05.01.01`、`1101.05.02.01`、`1101.05.03.01`、`1101.05.04.01`、`1101.05.05.01`、`1101.05.07.01`，或满足 `1501.03.XX.01`。
- 债券：以 `1501.01` 或 `1101.02` 开头。
- 股票：以 `1101.01` 开头。
- 公募基金：以 `1101.04` 开头。
- 私募基金：以 `1101.05.06` 开头。
- 逆回购：前四段满足 `1111.xx.xx.01`，后续可带尾段。
- 贷款：以 `1303.01.01` 或 `1501.04.05.01` 开头。
- 股权投资：以 `1511.01.01` 开头。
- 信托计划收益权：以 `1541.01` 开头，且科目名称满足 `LIKE '江苏信托%信托产品%'` 或 `LIKE '江苏信托%资金信托计划%'`。
- 资产收益权：以 `1541.01` 开头，且不满足信托计划收益权名称条件。
- 其他资产：不做分类，使用 `科目代码 + 科目名称` 作为资产名称。

细分核查补充：

- 债券、股票、公募基金、私募基金先查 DWS 数据源 `dm.fa_security_balance_zgxg_dm`，再按资产类型检查人行字段或报表明细表。
- 贷款、股权投资查 DWS 数据源 `dm.am_projinvest_zgxg_dm`，再检查对应报表明细表；股权投资额外检查 `pin_gqtype_h`。
- 特定目的载体保留 AM 标的缺失、FA/AM 标的不一致、合同投融资余额为 0 判断；合同投融资余额非 0 后继续查 `dm.am_projinvest_spv_zgxg_dm` 和对应报表明细表；`1101.05.06*` 仍单独作为私募基金。
- 信托计划收益权查 `dm.am_projinvest_spv_zgxg_dm` 和 `currency_report_24.currency_detail_project_2_1_6`。
- 资产收益权查 `zgxg_zhbs.ccqxx` 和 `currency_report_24.currency_detail_project_2_1_9`，`zgxg_zhbs.ccqxx` 不加日期条件。
- 逆回购查业务报表数据源 `assman_reg.ex_pledge_back`，按 `project_code` 过滤项目，`subcode` 以 `7` 开头，不按日期过滤，只检查 `buyback_money` 或 `expenses` 为空。

详情展示：

- 展示 `zf_detail` 资产合计、估值表资产合计、资产差异金额。
- 展示命中的估值表科目代码、科目名称、科目尾码、金额。
- 如果同时发现 AM 标的缺失、FA/AM 标的代码不一致、合同投融资余额异常等细分原因，会在详情中展示“具体原因”。

## 五、资产重复

触发条件：

- `a0001` 大于估值表 `0004` 资产合计。

判断含义：

- 主表资产更大，说明 `zf_detail_2024.a0001` 可能多计资产。
- 能命中具体资产明细时，差异类型展示为“资产重复”。
- 如果不能命中具体资产明细，差异类型展示为“资产差异”。

排查范围：

- 只查估值表 `1` 开头的实际末级科目，不要求科目代码必须包含四个点。
- 实际末级科目指当前项目估值表中没有下级科目的科目，例如存在 `1541.01.CC8250MX` 时，`1541.01` 不作为资产重复候选。
- 使用 `f_marketvalue` 与资产差异金额匹配。
- 全末级组合优先；只有全末级组合返回 `combination_overflow` 时，才按科目前四段自然分组组合。
- 前四段分组组合仍只使用该分组下的实际末级科目，不做上一层聚合。
- 能命中具体资产明细时，具体原因按 `①资产类型重复：资产名称；原因：具体原因` 展示；没有最终原因时省略 `；原因：...`。
- 若命中科目不是 `1101.05.06.01` 开头，资产名称使用 `科目代码 + 科目名称`。
- 若命中科目以 `1101.05.06.01` 开头，用科目最后一个点后的尾段匹配同项目、同日期 `am_pactasset_dws.c_stockcode`。如果查到 AM 标的，且 `c_spv_type <> 11`，并且 `c_assettype` 属于 `31、32、34、35、37、33、38`，原因展示为“该资产在证券信息表中为私募产品但在AM中不为私募产品”；否则原因留空。

详情展示：

- 展示资产合计差异。
- 展示命中的估值表资产科目。
- 展开详情中展示“资产重复细分”表。资产重复只对 `1101.05.06.01` 私募证券信息表口径做 AM 标的字段复核，不进入资产缺失的 FA/AM 标的代码修正链路。

## 六、资产差异债券、合同及逆回购金额核对

该规则只在无法明确命中某一或某几个资产缺失/重复后进入。命中时一级原因展示为“资产差异”，具体原因按债券本金 DM 证券余额、贷款合同、财产权合同和逆回购金额差异展示。

触发前提：

- `a0001` 与估值表 `0004` 资产合计不一致。
- 已尝试用估值表 `1` 开头实际末级科目匹配资产缺失/资产重复，但不能明确命中某一或某几个资产。

核对逻辑：

- 债券本金：只在全末级组合超限，且前四段自然分组后的债券本金分组仍超限时触发；FA 科目仅限 `1501.01.XX.01*` 或 `1101.02.XX.01*`，用 `科目尾段 + 科目名称` 匹配 DM `sbm_stockcode + sbm_sename`。
- 债券 DM 金额：查 DWS 数据源 `dm.fa_security_balance_zgxg_dm`，按项目和日期过滤，按 `sbm_stockcode + sbm_sename` 汇总 `sbm_balamoney_cost + sbm_balamoney_fair + sbm_balamoney_inte`。
- 债券双边补零：DM 缺少某债券时 DM 金额按 0；FA 缺少某债券时 FA 科目金额按 0；逐项计算 `DM证券余额 - FA债券本金科目余额`。
- 贷款合同：估值表实际末级科目以 `1303.01.01` 或 `1501.04.05.01` 开头，且最后一个点后的尾段以 `DK` 或 `ZQ` 开头；尾段作为合同代码，查 `dm.am_projinvest_zgxg_dm.pin_acbalance`。
- 财产权合同：估值表实际末级科目以 `1541` 开头；尾段作为合同代码，查 `am_projinvest_dws.f_acbalance`。
- 逆回购：汇总估值表实际末级科目中满足 `1111.xx.xx.01*` 的 FA 科目余额；再查业务报表数据源 `assman_reg.ex_pledge_back`，按 `project_code = 项目编号`、`subcode LIKE '7%'` 汇总 `buyback_money + expenses`。
- 债券逐项计算 `DM证券余额 - FA债券本金科目余额`；贷款和财产权逐项计算 `AM投融资余额 - FA科目余额`；逆回购计算 `存续回购业务表逆回购金额 - FA逆回购科目余额`；再汇总为资产差异合计。

命中后：

- 如果资产差异合计等于 `a0001 - 估值表0004`，说明资产端已完整解释，具体原因按 `①②③` 逐条展示。单只债券展示 `①XX债券：FA债券本金科目余额与DM证券余额有差异，债券代码XXX，差异值XXX`；多只债券在主列汇总为 `①多个债券：FA债券本金科目余额与DM证券余额有差异，差异值XXX`，逐债券名称和证券代码放入详情表；贷款、逆回购示例为 `①XX贷款合同：FA科目余额与AM投融资余额有差异，差异值XXX`、`①逆回购：FA科目余额与存续回购业务表逆回购金额有差异，差异值XXX`。
- 资产端完整解释后，继续计算 `remaining = (a0001 - d0000) - (a0001 - 估值表0004) = 估值表0004 - d0000`。
- 如果 `remaining = 0`，全局匹配状态为“已解释”，差异类型保持“资产差异”。
- 如果 `remaining <> 0`，继续把 `remaining` 送入实收本金和负债及权益科目规则。只要进入后续链路，不管后续是否完整解释，差异类型都按链路拼接，例如 `资产差异 + 实收本金差异`、`资产差异 + 负债及权益科目差异`、`资产差异 + 实收本金差异 + 负债及权益科目差异`；具体原因继续从资产原因后的下一个序号开始展示，匹配状态则由后续链路是否完整解释决定。
- 如果资产差异合计不为 0 但不等于 `a0001 - 估值表0004`，资产端未完整解释，匹配状态为“未解释”或“组合候选过多”，差异类型保持“资产差异”。债券部分解释时，单只债券展示 `暂不明确具体资产差异，但XX债券，FA债券本金科目余额与DM证券余额有差异，差异值XXX`，多只债券展示 `暂不明确具体资产差异，但多个债券，FA债券本金科目余额与DM证券余额有差异，差异值XXX`。贷款、财产权、逆回购仍按实际资产类型动态展示。
- 如果没有债券、贷款、财产权、逆回购差异，匹配状态为“未解释”，具体原因展示为：`暂不明确具体资产差异`。
- 展开详情展示“资产差异细分”表，列出序号、资产类型、资产名称、FA科目编码、合同代码或证券代码、FA科目余额、DM证券余额/AM投融资余额/存续回购业务表金额、差异值、核查表和原因。

## 七、特定目的载体缺失链路

该规则只在“资产缺失”已经命中特定目的载体实际末级科目后继续判断；“资产重复”不进入该链路，`1101.05.06*` 私募基金也不进入该链路。

触发条件：

- 已判定为“资产缺失”。
- 资产缺失金额能命中估值表 `1` 开头实际末级科目。
- 命中的 FA 科目前四段属于特定目的载体范围：`1101.05.01.01`、`1101.05.02.01`、`1101.05.03.01`、`1101.05.04.01`、`1101.05.05.01`、`1101.05.07.01`，或满足 `1501.03.XX.01`。
- FA 科目名称 `c_accountname` 用于展示 `①特定目的载体缺失：XX` 中的 `XX`。

AM 标的匹配逻辑：

- 读取同项目、同日期 `am_pactasset_dws`。
- 用 FA 科目名称匹配 AM 资产名称 `c_udlyasset`。
- 名称标准化时去掉空白、统一全角半角，并忽略末尾 `_XXX` / `＿XXX` 这类后缀；括号中的内容保留并参与匹配。
- 标准化后完全一致时认为名称匹配；括号内容不一致时认为名称不匹配；否则按相似度判断，相似度不低于 `0.90` 视为匹配。
- 如果同一 FA 科目命中多个 AM 资产，优先使用匹配度最高的 AM 资产继续复核。
- 取 FA 科目代码最后一个点后的尾段，与 AM 标的代码 `c_stockcode` 比较。

具体原因：

- 找不到 AM 标的：`①特定目的载体缺失：FA科目名称；原因：AM标的缺失`。
- AM 名称可匹配但 `c_stockcode` 与 FA 尾段不一致：`①特定目的载体缺失：FA科目名称；原因：FA和AM标的不一致`。
- AM 标的一致后，用 AM 合同代码 `c_pactid` 查 `am_projinvest_dws` 同项目、同日期、同合同 `f_acbalance`；如果余额为 0：`①特定目的载体缺失：FA科目名称；原因：合同投融资余额为0但FA科目余额不为0`。
- 如果合同投融资余额非 0，用 AM 合同代码查 DWS 数据源 `dm.am_projinvest_spv_zgxg_dm`，条件为 `svd_projcode = 项目编号`、`svd_mpactid = AM合同代码`、`svd_cldate = 核对日期`，且 `svd_balamoney_cost + svd_balamoney_inte + svd_balamoney_fair <> 0`。
- 若 SPV DM 表查不到：`①特定目的载体缺失：FA科目名称；原因：该特定目的载体在dm.am_projinvest_spv_zgxg_dm不存在或余额为0`。
- 若 AM 资产名称包含 `收益凭证`，直接查业务报表数据源 `currency_report_24.currency_detail_project_2_1_9`，只按 `caldate` 过滤；无数据时：`①特定目的载体缺失：FA科目名称；原因：该收益凭证在资负数据子系统-其他债权明细表无数据`。
- 若 AM 资产名称不包含 `收益凭证`，先检查 `dm.am_projinvest_spv_zgxg_dm.svd_assettype` 是否属于 `31、32、34、35、37、33、38`；为空或不在范围内时：`①特定目的载体缺失：FA科目名称；原因：该特定目的载体资产类型为空或资产类型有误`。
- 资产类型正常后查业务报表数据源 `currency_report_24.currency_detail_project_2_1_6`，只按 `caldate` 过滤；无数据时：`①特定目的载体缺失：FA科目名称；原因：资负数据子系统-特定目的载体明细表无数据`。
- 上述检查都未发现问题时，具体原因仅展示 `①特定目的载体缺失：FA科目名称`，省略 `；原因：...`。

展开详情会同时展示 AM 标的、合同代码、核查表、关键字段和具体原因；AM 标的缺失详情中的“需复核四级科目”展示实际命中的 FA 前四段。

## 八、实收本金差异、缺失、重复

触发前提：

- `a0001` 与估值表 `0004` 资产合计一致。
- 这表示资产端正确，问题优先看负债及权益端。

一级原因判断：

- 如果 `a0001 - d0000 = FA 4001`，差异类型展示为“实收本金缺失”。
- 如果 `a0001 - d0000 = -FA 4001`，差异类型展示为“实收本金重复”。
- 如果主表 `c1000` 与 FA 科目余额表 `4001` 不一致，并且 `FA 4001 - c1000` 与主差异 `a0001 - d0000` 完全相等，差异类型展示为“实收本金差异”。
- 如果 `c1000` 与 FA `4001` 不一致，但 `FA 4001 - c1000` 不能单独解释主差异，则计算剩余差额：`a0001 - d0000 - (FA 4001 - c1000)`，继续进入负债及权益科目规则。

判断含义：

- “实收本金缺失/重复”表示主差异正好等于整笔 FA `4001` 科目余额。
- “实收本金差异”表示主差异可以由 `c1000` 与 FA `4001` 的差异解释。
- “实收本金差异 + 其他负债权益差异”混合场景不会直接归为暂无法确定，会把实收差额从主差异中扣除后，用剩余差额继续匹配非 `1` 开头估值科目。
- 细分规则命中后，一级原因仍为“实收本金差异”，更具体原因进入详情。

具体原因格式：

- 实收本金缺失：默认展示 `①实收本金缺失：FA 4001科目余额XXX`；如果 `currency_report_24.currency_detail_project_2_1_8` 按 `caldate` 无数据，追加 `；原因：资负数据子系统-实收本金明细表无数据`。
- 实收本金重复：展示 `①实收本金重复：FA 4001科目余额XXX`。
- 实收本金差异：默认展示 `①实收本金差异：FA 4001与c1000存在差异，差异值XXX`。
- 如果 TA 细分能解释实收本金差异，在默认原因后追加 `；原因：DM表TA份额余额错误` 或 `；原因：dm.ta_pact_survamt_day_zgxg_dm表中客户类型为空导致实收信托有误`。
- 如果 TA 细分不能解释实收本金差异，不再输出“实收信托有误”，保留默认实收本金差异原因。

细分规则：

1. 到 `dm.ta_pact_survamt_day_zgxg_dm` 按同日期、同项目汇总 `tpm_htincome + tpm_shareamt`。
2. 到 `ta_pact_detail_dws` 按同日期、同项目汇总 `f_shareamt + f_alltincom`。
3. 如果两个汇总值不一致，先展示 TA 汇总核对详情；只有 `DM-DWS` 差额绝对值等于 `FA 4001 - c1000` 时，具体原因才追加“DM表TA份额余额错误”。
4. 如果两个汇总值一致，继续在 `dm.ta_pact_survamt_day_zgxg_dm` 中查同日期、同项目、`tpm_htincome + tpm_shareamt <> 0` 且客户类型为空的记录。
5. 客户类型为空包括三类情况：`tpm_clientkind_tusp` 为空；`tpm_clientkind_tusp = 4` 且 `tpm_clientkindex` 为空；`tpm_clientkind_tusp = 5` 且 `tpm_spvtype` 为空。
6. 如果客户类型为空记录的 `tpm_htincome + tpm_shareamt` 合计等于 `FA 4001 - c1000`，具体原因追加“dm.ta_pact_survamt_day_zgxg_dm表中客户类型为空导致实收信托有误”。
7. 如果上述细分规则都不能解释差异，具体原因保留默认实收本金差异原因。

详情展示：

- 展示 `c1000` 实收本金余额。
- 展示 FA `4001` 科目余额。
- 展示 `4001-c1000` 差异。
- 展开详情新增“实收本金细分”表，展示序号、类型、FA 4001 科目余额、c1000 实收本金余额、差异值、核查表、核查结果和原因。
- 混合场景的具体原因按编号拼接：`①实收本金差异：FA 4001与c1000存在差异，差异值XXX`，再从 `②` 起展示剩余差额命中的负债及权益科目；如果剩余差额未命中，第二行展示 `②暂不明确具体负债及权益科目差异`。详情会额外展示主差异、实收差额、剩余差额，以及后续负债及权益科目的核对范围、命中方式和命中金额。
- DM/DWS TA 表汇总不一致时，展示 DM 汇总、DWS 汇总和差异。
- DM TA 客户类型为空时，展示空客户类型金额合计，以及合同编号、客户名称、客户类型主字段、客户类型明细字段、SPV 类型、待结转收益、份额余额和单行合计。

## 九、负债及权益科目差异、缺失、重复

触发前提：

- `a0001` 与估值表 `0004` 资产合计一致；或资产差异细分已完整解释 `a0001 - 估值表0004`，修正后继续用 `remaining = 估值表0004 - d0000` 核对。
- `c1000 = FA 4001`，实收本金正确，直接进入负债及权益科目核对；或 `c1000 <> FA 4001`，但 `FA 4001 - c1000` 不能单独解释主差异，需要继续核对剩余差额。

排查范围：

- 查估值表非 `1` 开头的科目。
- 匹配前剔除 `0` 开头的四位科目，例如 `0001`、`0002`、`0004`、`0033`；这些属于估值表汇总或指标类科目，不参与负债及权益科目金额匹配。该剔除只影响本步骤，不影响前置的 `0004` 资产合计读取。
- 单行精确匹配和同科目汇总匹配不限制最末级科目，因为负债及权益类差异可能直接体现在上级科目。
- 多科目组合匹配只使用实际末级科目，并剔除正回购利息科目 `2111.xx.xx.02.*`，避免上级和下级重复参与组合，或用正回购利息凑数。

匹配目标：

- 优先用当前待解释差额匹配；资产一开始正确时为主差异 `a0001 - d0000`，资产差异已完整解释时为 `估值表0004 - d0000`。
- 混合场景使用扣除实收差额后的剩余差额匹配，例如 `a0001 - d0000 - (FA 4001 - c1000)`，或资产差异已完整解释后的 `估值表0004 - d0000 - (FA 4001 - c1000)`。
- 如果主差异为负数且未命中，再尝试用主差异绝对值匹配。

命中后：

- 如果 `d0000 < a0001`，且能命中具体非 `1` 开头科目，差异类型展示为“负债及权益科目缺失”。
- 如果 `d0000 > a0001`，且能命中具体非 `1` 开头科目，差异类型展示为“负债及权益科目重复”。
- 如果不能命中具体非 `1` 开头科目，差异类型展示为“负债及权益科目差异”。
- 命中普通非 `1` 科目时，具体原因按 `①负债及权益科目缺失：科目名称` 或 `①负债及权益科目重复：科目名称` 展示，多条命中按 `①②③` 换行拼接。
- 命中科目前四段满足 `2111.xx.xx.01` 时，具体原因按 `①正回购缺失：科目名称；原因：正回购差异` 或 `①正回购重复：科目名称；原因：正回购差异` 展示，后续可带尾段。
- 未命中具体非 `1` 科目时，继续做正回购金额比对：汇总估值表满足 `2111.xx.xx.01*` 的 FA 科目余额；查 `assman_reg.ex_pledge_back`，按 `project_code = 项目编号`、`subcode LIKE '8%'` 汇总 `buyback_money - expenses`；计算 `FA正回购科目余额 - 业务表正回购金额`。
- 如果正回购金额差异等于当前匹配目标，差异类型仍展示为“负债及权益科目差异”，匹配状态为“已解释”，具体原因展示为 `①正回购：FA科目余额与存续回购业务表正回购金额有差异，差异值XXX`；混合场景中从 `②` 开始展示。
- 如果正回购金额差异不为 0 但不能解释当前匹配目标，匹配状态为“未解释”，具体原因展示为 `暂不明确具体负债及权益科目差异，但正回购，FA科目余额与存续回购业务表正回购金额有差异，差异值XXX`；混合场景中作为第二行展示。
- 如果未命中具体非 `1` 科目且正回购金额也无差异，具体原因展示为 `暂不明确具体负债及权益科目差异`；混合场景中作为第二行展示。
- 详情展示匹配范围、命中方式、命中金额、具体估值表科目，并新增“负债及权益科目细分”表，展示序号、科目类型、科目名称、FA 科目编码、科目尾段、FA 科目金额、存续回购业务表金额、差异方向、核查结果和原因。

## 十、结果页、历史页和 Excel 下载统一口径

结果展示统一使用同一份核对结果：

- 后端在 `display_details` 的“最终判断结果”中写入 `差异类型` 和 `具体原因`。
- 结果页列表展示 `差异类型`；点击展开后展示完整 `display_details`，同一时间只展开一条结果详情。
- 历史页详情表展示 `差异类型` 和 `具体原因`，其中 `具体原因` 从 `display_details` 的“最终判断结果”中读取。
- 下载 Excel 时展示 `差异类型` 和 `具体原因` 两列，`具体原因` 同样从 `display_details` 的“最终判断结果”中读取。
- 处理脚本和差异原因详情仍使用完整详情生成，不再把更细原因塞进一级 `差异类型`。

## 十一、估值表金额匹配优先级

无论资产端还是负债及权益端，估值表科目金额匹配都按以下顺序执行：

1. 单行命中：某一行 `f_marketvalue` 与目标差异完全相等。
2. 同科目汇总命中：同一个科目代码下多行 `f_marketvalue` 汇总后与目标差异完全相等。
3. 全末级多科目组合命中：多个实际末级科目组合汇总后与目标差异完全相等。负债及权益端进入组合前会把候选收敛为实际末级科目，并剔除正回购利息科目 `2111.xx.xx.02.*`；资产端本身已使用实际末级科目。
4. 前四段分类组合命中：只有全末级组合返回 `combination_overflow` 时才触发，按科目前四段自然分组，每组内部仍只用实际末级科目。
5. 组合候选过多：全末级组合和前四段分类组合的候选行数超过程序上限，或组合过程中的状态数超过安全上限时停止组合匹配，避免大数据量下卡死。
6. 未命中：以上方式都无法匹配。

匹配状态说明：

- 单行命中、同科目汇总命中、多科目组合命中：状态为“已解释”。
- 组合候选过多：状态为“组合候选过多”。
- 未命中：状态为“未解释”。

## 十二、暂无法确定

以下情况会展示为“暂无法确定”：

- 估值表缺少当前项目的 `0004` 资产合计，无法判断 `a0001` 是否正确。
- 组合候选过多，程序为避免卡死没有继续组合匹配；详情中的“匹配说明”会显示是候选行数超过上限还是组合状态数超过上限。
- 资产端、实收本金、负债及权益科目规则均无法归类时，才保留“暂无法确定”。

导出 Excel 时，“暂无法确定”的差异详情列保持为空。

## 十三、当前不再单独使用的旧规则

早期讨论过 `fa_accountbalance_dws.4001` 与 `currency_report_duration.f_assetshare` 的 FA/TA 实收差异短路规则。

当前实现已按新的完整流程处理：

- 不再在估值表判断之前单独用 FA/TA 规则直接短路。
- 实收类问题统一在“资产端正确后”通过 `c1000` 与 FA `4001` 判断。
- `currency_report_duration` 的本地 DDL 和查询接口仍保留，方便后续如果要恢复或扩展 TA 规则时继续使用。
