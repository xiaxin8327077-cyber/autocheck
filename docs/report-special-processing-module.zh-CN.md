# 报表特殊处理录入模块设计说明

## 架构

模块 ID 为 `report_special_processing`，是 `required=false` 的独立业务模块。`module.py` 仅组装路由、仓储、业务服务与统计 provider；字段校验、资源权限、状态机、SQL 和统计口径分别位于 `validator.py`、`permissions.py`、`service.py`、`storage.py`、`statistics.py`。模块不修改公共入口、平台内核或其他业务模块。

## 数据和一致性

### 台账与导出共用展示数据

`ledger_display.py` 将记录转换为字段值分组、关联名称列表和处理时间；列表服务以只读 `ledger_display` 返回，前端优先使用，旧接口数据保留原渲染回退。导出直接复用相同转换，避免两套分组格式继续分叉。分组使用原始修改前/后组成元组，不 trim 后合并；同组显示名去重。按视觉宽度排序，同宽稳定保留原顺序，不依赖操作系统语言。关联名称仍读取保存快照，不受统计标签合并影响。

Excel 按台账样式保留处理表名，共九个数据列，移除旧模板的报送期、维度、摘要和治理负责人列；导出先按表拆分，表内复用列表同值分组，字段逐项换行，防止跨表合并后丢失归属。历史表字段可可靠对应时按组拆分，否则保留完整原文。一条记录有多个值分组时按行展开，业务系统至处理时间五列纵向合并；表头和正文均使用四边框、水平及垂直居中。文本格式保护前导零和公式样式原文，自动换行及行高用于展示完整分组。保持现有筛选、记录排序、权限和 5000 条上限，无数据库迁移。

### 2026-09-21：扩展关联报送与单行页签

页签的自然宽度测量与最终布局分离：测量用于决定可见项数量，显示时将剩余空间分配给可见页签，保证少量项和溢出场景均铺满可用行宽，更多入口保持在最右侧。

标签文案按 Unicode 字符最多取前 15 个，不加省略号，完整名放在 title；测量和显示使用相同文案，禁止 flex 压缩标签文字，超出宽度的尾部标签进入更多菜单，原顺序不变。

目录顺序不因伸展或收纳改变：原目录优先保留，扩展项按字典返回顺序稳定追加；其中名称去首尾空格后为“其他报送”的启用项稳定移至扩展末尾，再生成递增展示顺序。统计页签及更多菜单沿用该顺序。
台账目录 `report_process_tabs` 将 `pbc_central` 与 `pbc_template` 合并为名称“人行报送”、编码 `group:pbc` 的虚拟筛选项；录入目录 `report_processes` 不合并。列表和导出对虚拟项执行两类关联的 OR 条件，摘要统计按记录 ID 去重，不直接相加两项数量；虚拟编码不能保存为关联报送，从合并页签新建时由用户选择真实报送。

模块只读消费 `platform.dictionary` v1 的 `rsp_extra_report_process` 分类，将启用项追加到 `platform.report_navigation` v1 原有报送目录后。原目录编码、名称、顺序保持不变，冲突项（同编码或同名称）不加入扩展目录；目录展示与保存校验共用相同解析规则。分类由管理员在现有字典管理中创建，中文名建议为“特殊处理扩展报送”，未配置时无需额外初始化即可使用原有七项。

记录继续使用模块自己的关联表及名称快照，不新增平台表、模块表或迁移，不写入导航报送目录和流程配置。新选项必须在启用目录中；更新时未移除的已有关联保留原名称快照，字典项改名、停用、删除都不妨碍编辑其他字段。旧记录的停用项在多选中保留展示并允许移除，不允许新选；展示、导出仍使用保存快照。现有特殊治理统计与待办、通知联动继续沿用原口径。

顶部“全部”及报送页签使用真实元素宽度分配单行空间，尾部溢出项收进“更多报送”。下拉显示名称和数量，提供名称搜索、限高细滚动条与键盘操作；隐藏项被选中时入口显示当前名称并高亮。窗口宽度变化自动重排，页面重渲染、离开和销毁时清理观察器和事件监听。页面样式限定模块作用域，复用全局主题、表面与圆角变量。

模块拥有记录、涉及报表、关联报送、审计日志、确认图片附件、记录附件六张表。自 1.2.14（schema 7）起：基本信息新增“所属业务系统”，单选下拉取自平台只读字典服务 `platform.dictionary` v1 的启用分类 `business_system`，正式保存必选、草稿可为空，记录保存字典项编码与名称快照（字典改名/停用不影响历史显示，停用项不可新选但旧记录未改选时仍可编辑其他字段）；处理表名、处理字段名改为中英双语多项规范串（单项 `中文名｜英文名`，全角竖线分隔中英名；多项用全角分号 `；` 分隔；每类最多 5 项、单个名称最多 100 字、整段最多 4096 字），自 1.2.15 起字段名支持表-字段关联分组格式（组间用双全角分号 `；；` 分隔，第 N 组对应第 N 张表，允许空组；分组数必须与表数一致，无分隔符的历史扁平值按单组兼容）：录入弹窗内每张表一张分组卡片，表名行为一级信息、卡内关联字段为二级信息，顶部添加表、卡内添加字段，表/字段可单独删除且删除含字段的表需二次确认，字段较多时卡片可折叠并在标题显示字段数量；修改前/修改后左右并排对比，处理摘要保留在最下方且默认高度缩小；台账首列保持“修改字段名”，双语与分组字段均按条目分行，历史字段名不附加表名或标签。待办、处理记录与通知摘要统一显示“所属维度 · 所属业务系统 · 最短字段名”：字段显示名中文优先、英文回退，再按近似视觉宽度选择最短一项；多个字段时在最短字段名后保留“等 N 字段”总数提示。系统名称快照缺失时回退系统编码；旧记录名称和编码均缺失时保持原“所属维度 · 字段摘要”格式，不显示“未填系统”。Excel 导出两列按项换行、字段分组间以空行分隔；旧记录非规范原值以普通输入行展示，未修改时继续保存，一旦修改必须整体升级为双语/分组格式（无自动回滚，回滚前备份，保留新增列不删数据）。草稿允许报表、摘要、内容、报送期、特殊处理时间和处理人暂缺，因此迁移中这些业务列允许 NULL；正式保存或完成前由服务执行完整校验。

自 1.2.15（schema 8）起，特殊处理内容升级为“数据源 → 处理表 → 处理字段 → 修改前/修改后”关联结构：新建记录与已结构化记录在录入弹窗内先选择系统已配置数据源（不提供手工填写 IP/端口/账号/密码入口），处理表和处理字段通过“选择处理表/选择字段”弹窗调用模块元数据接口 `GET /datasources`、`GET /datasources/{id}/tables`、`GET /datasources/{id}/tables/{table}/columns` 从真实数据库读取；元数据 SQL 差异由模块内 `metadata.py` 适配层统一处理（当前支持 PostgreSQL 与 MySQL，表/字段均后端搜索 + 后端分页，中文名称取 comment/remark），前端不区分数据库类型编写业务逻辑。物理表名/字段名永远只读；数据库存在中文注释时中文名只读（来源 DATABASE），不存在时允许用户补充中文名（来源 MANUAL，仅保存到业务记录，不反写数据库 comment）。每张表一张分组卡片：添加表后自动生成字段选择区，字段区永远保留“请选择字段”空行（最后一个字段删除后恢复空选态，不出现“暂无关联字段”），卡片可折叠/展开，标题显示“中文名（物理名） · N个已选字段”；字段行为固定列布局（中文字段名/英文字段名/修改前/修改后/操作），修改前/修改后归属具体字段，新字段默认留空，与上一字段值相等时显示“同上”标记，可修改。删除含已选字段的表需二次确认（同时删除其关联字段及修改前/后信息）；已选表/字段存在时切换数据源需二次确认并清空表、字段及修改数据。校验逐条定位：数据源必选、至少一张处理表、每张表至少一个已选字段（草稿同规则）、MANUAL 中文名必填、正式保存时每个字段的修改前/修改后必填。数据模型：迁移 `008_datasource_structured_content.sql` 新增 `datasource_id`、`datasource_name_snapshot`、`datasource_type`、`structured_content_json` 列并将 `value_before`/`value_after` 放宽为 TEXT；`structured_content_json` 为结构化内容唯一事实来源（保存时后端按系统数据源配置钉牢类型与名称快照，防止前端伪造），同时派生既有兼容串——`table_name`（`中文名｜物理名；…`）、`field_name`（按表分组、组间 `；；`）、`value_before`/`value_after`（按字段顺序每字段一行 `
` 聚合）——导出、通知、待办和审计继续消费派生串。台账主列表使用“修改字段 / 修改前 / 修改后”三个普通列，右侧所属业务系统、关联报送、状态、处理人、处理时间、操作保持不变，不展示处理摘要、处理表、数据源或英文技术名；结构化记录先按原始修改前/后完整值对跨表聚合，再在组内提取字段显示名并去重，字段显示名优先中文、中文缺失时回退英文、双名缺失时显示占位。整条记录只有一个值对时，去重字段按原顺序逐行显示；存在多个值对时，每个值对占一行、组内字段按原顺序使用顿号连接，各行按整行字段文字长度从短到长排列。null、undefined 和空字符串归一为空值并显示“—”。一条业务记录只占一个主表行，前三列在同一网格中同步排列，避免合并单元格撑高产生空档；内容水平、垂直居中并允许自然换行，不显示变更编号、标签、卡片、嵌套表格或表格内线。历史手工录入记录（`structured_content` 为 NULL）保留原“表-字段分组卡片 + 记录级修改前/后”模式编辑（方案 A 兼容），无需数据回填；台账对旧记录仅在单值共享或行数完全一致时建立字段和值的对应关系，其他情况保留完整原文，不推测、不丢失。记录升级为结构化模式保存后新列写入、旧列按派生规则同步。关联报送支持多选：子表存多项，主表保留首项编码与顿号拼接名称快照。台账筛选栏提供导出按钮，按当前报送 Tab、报送期与筛选条件导出 Excel，列顺序为所属报送期、关联报送、涉及报表、处理摘要、处理说明、处理脚本、处理时间、处理人、状态。

不可编辑的查看态与确认态使用独立只读预览组件，不复用禁用表单控件。基本信息中的所处报送期、处理人、所属维度、所属业务系统和数据治理负责人保持三列布局，并以小号灰色标签配深色文本值；关联报送不按内容长度动态换位，固定放在短字段网格之后独占全宽并自然换行；处理摘要继续在关联报送之后独占全宽，处理脚本使用浅色内容块。每张处理表使用独立预览卡，卡头显示处理表序号及“数据源 / 英文表名”，卡内表信息为三列纯文本，处理范围与修改字段使用浅色表头、细分隔线的只读表格。表格固定占满卡片宽度，长英文名、中文名和修改值在单元格内自动换行，外层隐藏横向溢出且不提供滚动条。数据源优先读取每张表保存的 `datasource_name`，再回退记录级 `datasource_name_snapshot` 和数据源 ID，确认时不依赖元数据目录请求。确认态仅底部确认说明保留可输入文本框，图片粘贴、取消与确认动作保持原逻辑。

更新语句同时匹配 `id` 与 `row_version` 并原子递增版本；主表、子表全量替换和审计写入共享一个事务。删除记录时同步删除明细、审计、确认附件与全部当前/历史记录附件。结构化记录的审计按“基本信息 / 特殊处理内容”分层：特殊处理内容按处理表隔离，表内依次展示表信息、处理范围和修改字段；修改对象只记录变化属性，新增/删除对象使用业务化快照，新增或删除整表各计一项。新增表展开后展示当前完整配置，删除表展开后展示删除前完整配置，均包含表信息、指定数据日期与日期字段、全部条件和全部修改字段。处理表、条件和修改字段保存内部稳定 `item_id` 以识别同一对象；条件同时保留可选的中文字段名快照，操作记录优先显示“中文名（英文字段名）”；历史无标识内容按唯一物理身份保守匹配，无法确定时按新增加删除展示。摘要显示业务变更总数、基本信息项数、特殊处理内容项数和涉及表数；处理脚本作为次级证据默认折叠且不计入业务变更数，自动生成脚本标记为“自动生成”，手动脚本标记为“手动编辑”，仅修改手动脚本时仍进入结构化操作记录并显示“手动脚本已修改”。历史扁平审计继续使用原三列 Diff。重开原因、作废理由、确认说明、确认图片和记录附件维持既有专用展示。

### 记录附件（006 迁移）

`report_special_processing_record_attachments` 保存记录级附件的不可变内容与元数据（原文件名、扩展名、服务端确认 MIME、字节数、SHA-256、添加人快照、添加时间、移除人快照与移除时间）。新文件以 Base64 随新建/修改 JSON 在同一数据库事务内原子提交，保留附件只提交 ID；任何一步失败整体回滚，不留孤立附件或半保存记录。请求省略 `record_attachments` 字段时附件集合保持不变；提供时必须显式给出 `retained_ids` 与 `new_files` 两个数组，`([], [])` 表示清空。附件行内容与元数据不可覆盖，重新添加创建新行；从当前集合移除只写移除人与移除时间（软删除），历史操作记录仍可预览或下载。

审计只保存 `old_ids/new_ids/added_ids/removed_ids` 集合，不复制文件字节或可变文件名；查询审计时按当前页收集全部 ID 一次性批量补全不可变元数据（无 N+1），“新增/移除/保留”标签只按该条审计自身的集合差计算，与附件行当前 `removed_at` 无关。只修改附件也递增 `row_version` 并写 update 审计，摘要显示“修改附件（新增 N 个，移除 M 个）”；集合未变化时不计为附件修改。列表接口只返回 `record_attachment_count`，详情返回当前附件元数据（不含字节）；文件读取路由校验详情权限与 `record_id` 归属，当前与历史附件均可下载，跨记录统一 not found。POST/PUT 记录路由请求体上限为独立的 45 MiB（约 30 MiB 原始字节 Base64 后加元数据），低于平台 50 MiB 硬上限，其他路由上限不变。

## 平台集成

模块通过 manifest 精确声明并解析 `platform.user_directory` v1 和 `platform.report_navigation` v1。用户目录用于校验启用用户并保存处理人、创建人和操作人快照；报送目录动态提供稳定代码、名称、顺序和启用状态，模块不复制七类报送。

启动时模块以 owner-bound facade 注册 `special_governance`、口径版本 1 的统计提供者，停止时关闭 handle。provider 直接使用平台给出的周/月/季/年边界，按 `[start, end)` 查询 `special_handling_at`；有效总数只含待处理、处理中和已完成。失败由平台保留最近成功快照，模块不写零或手工值。

## 安全和回滚

处理脚本仅作为 UTF-8 文本保存，限制 512 KiB；代码不存在脚本执行器、shell、子进程或数据库脚本执行入口。未知异常返回固定 500 文案和错误 ID，不回显 SQL、脚本、路径或驱动错误。上线失败时禁用可选模块即可隐藏导航、关闭 API 并注销 provider，数据和审计继续保留。

记录附件只受控存储与回传下载，不在服务端解析、渲染或执行任何附件内容：图片按魔数核对 PNG/JPEG/WebP（拒绝 SVG）；旧 `.xls/.doc` 只校验 OLE 复合文档容器头并统一保存为 `application/x-ole-storage`，服务端无法区分具体 Office 类型或保证无宏，属允许旧格式的明确限制；`.xlsx/.docx` 在不解压成员正文的前提下校验 ZIP 中央目录、`[Content_Types].xml` 与 `xl/`、`word/` 标识，限制条目数量并拒绝 `vbaProject.bin` 与宏启用内容类型，显式 `.xlsm/.docm` 一律拒绝；`.zip` 只校验容器结构。本功能不提供恶意软件扫描，附件只有经具备详情权限的用户主动下载后才由本机软件处理。文件名做 basename 清理并限制长度；下载响应使用服务端确认 MIME、平台统一 `nosniff` 与 UTF-8 编码的 `Content-Disposition`。附件内容、Base64 与密码不写入应用日志。

附件功能回滚：代码回滚恢复模块前后端、manifest 与测试后，需通过新的补偿迁移删除 `report_special_processing_record_attachments` 表，不得修改或回放已发布的 `006_record_attachments.sql`；该表数据删除后不可恢复，回滚前按数据备份流程处理。若迁移尚未在任何环境执行，可直接撤销未发布的迁移文件。

## 1.2.16 变更（schema 9）

### 处理范围升级：通用条件结构

固定"项目/合同"输入升级为通用"条件字段 + 条件值"结构（`conditions` 数组），每张表至少一条有效条件：

- 条件字段从当前表真实字段搜索选择（combo，不走二级弹窗，候选在当前弹窗内展开）。
- 条件值支持单值/多值（"、""；"分隔，去空去重），单值自动匹配 `=`、多值自动匹配 `IN`。
- 条件运算符 10 种（等于/不等于/大于/大于等于/小于/小于等于/模糊匹配/属于多个值/为空/不为空），AUTO 模式下智能匹配，用户主动选择后进入 MANUAL 模式不再被自动覆盖。
- 校验逐条定位：空行忽略，有效条件必须填字段和值（IS NULL/IS NOT NULL 除外）。

### 处理脚本实时自动生成

选择处理表后，前端纯函数 debounce 400ms 渐进拼接 UPDATE SQL 预览，不等待整张表或其他表全部填写完成：

- 选择物理表即生成 `UPDATE`；选择修改字段即生成 `SET 字段 = ''`，后续随“修改后”实时替换；选择条件字段即生成 `WHERE 字段 运算符 ''`，后续随条件值实时替换。
- 每张表独立生成；未完整的表不阻塞其他表。未选择条件字段时不生成 `WHERE`，允许形成无 WHERE 的全表更新脚本。
- WHERE 顺序：报送期 → 处理范围条件；报送期不区分字段类型，统一使用 `YYYY-MM-DD`。
- SQL 字符串保留单引号转义；IN、LIKE、IS NULL、IS NOT NULL 和数值条件保持既有生成语义。
- 脚本预览不调用正式保存校验，也不放宽修改内容区域前端 `validate()`、后端 create/update 和结构化内容必填校验。
- 脚本只读展示（textarea readOnly），提供"复制脚本"按钮。

### 手动编辑模式

- 点击"手动编辑"解锁脚本 textarea 并暂停自动生成，按钮文案切换为"恢复自动生成"。
- 输入框上方显示“手动编辑模式，自动生成已暂停”；切换时保留已生成内容，处理内容后续变化不再覆盖用户输入。
- 恢复自动生成前若脚本已被修改需确认覆盖（确认文案："恢复自动生成后，当前手工修改的脚本将被覆盖，是否继续？"）。
- 确认后回到 AUTO 模式，脚本恢复只读并重新触发生成。
