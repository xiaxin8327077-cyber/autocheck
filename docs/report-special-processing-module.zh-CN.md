# 报表特殊处理录入模块设计说明

## 架构

模块 ID 为 `report_special_processing`，是 `required=false` 的独立业务模块。`module.py` 仅组装路由、仓储、业务服务与统计 provider；字段校验、资源权限、状态机、SQL 和统计口径分别位于 `validator.py`、`permissions.py`、`service.py`、`storage.py`、`statistics.py`。模块不修改公共入口、平台内核或其他业务模块。

## 数据和一致性

模块拥有记录、涉及报表、关联报送、审计日志、确认图片附件、记录附件六张表。草稿允许报表、摘要、内容、报送期、特殊处理时间和处理人暂缺，因此迁移中这些业务列允许 NULL；正式保存或完成前由服务执行完整校验。关联报送支持多选：子表存多项，主表保留首项编码与顿号拼接名称快照。台账筛选栏提供导出按钮，按当前报送 Tab、报送期与筛选条件导出 Excel，列顺序为所属报送期、关联报送、涉及报表、处理摘要、处理说明、处理脚本、处理时间、处理人、状态。

更新语句同时匹配 `id` 与 `row_version` 并原子递增版本；主表、子表全量替换和审计写入共享一个事务。删除记录时同步删除明细、审计、确认附件与全部当前/历史记录附件。审计保存结构化字段变化；前端按创建、修改、完成、重开、作废等简洁语义在摘要行展示。创建和保存草稿仅显示操作名，不重复服务端摘要；其他记录可展开完整的字段、修改前、修改后对照。字段列使用较窄固定宽度，修改前、修改后始终均分剩余空间；长值保留全文并自动换行，不使用横向滚动条。重开原因、作废理由和确认说明作为未编号补充说明紧跟状态流显示；确认时粘贴的图片在完成详情中显示缩略图。处理脚本对照显示开头预览，完整脚本可一键复制。

### 记录附件（006 迁移）

`report_special_processing_record_attachments` 保存记录级附件的不可变内容与元数据（原文件名、扩展名、服务端确认 MIME、字节数、SHA-256、添加人快照、添加时间、移除人快照与移除时间）。新文件以 Base64 随新建/修改 JSON 在同一数据库事务内原子提交，保留附件只提交 ID；任何一步失败整体回滚，不留孤立附件或半保存记录。请求省略 `record_attachments` 字段时附件集合保持不变；提供时必须显式给出 `retained_ids` 与 `new_files` 两个数组，`([], [])` 表示清空。附件行内容与元数据不可覆盖，重新添加创建新行；从当前集合移除只写移除人与移除时间（软删除），历史操作记录仍可预览或下载。

审计只保存 `old_ids/new_ids/added_ids/removed_ids` 集合，不复制文件字节或可变文件名；查询审计时按当前页收集全部 ID 一次性批量补全不可变元数据（无 N+1），“新增/移除/保留”标签只按该条审计自身的集合差计算，与附件行当前 `removed_at` 无关。只修改附件也递增 `row_version` 并写 update 审计，摘要显示“修改附件（新增 N 个，移除 M 个）”；集合未变化时不计为附件修改。列表接口只返回 `record_attachment_count`，详情返回当前附件元数据（不含字节）；文件读取路由校验详情权限与 `record_id` 归属，当前与历史附件均可下载，跨记录统一 not found。POST/PUT 记录路由请求体上限为独立的 45 MiB（约 30 MiB 原始字节 Base64 后加元数据），低于平台 50 MiB 硬上限，其他路由上限不变。

## 平台集成

模块通过 manifest 精确声明并解析 `platform.user_directory` v1 和 `platform.report_navigation` v1。用户目录用于校验启用用户并保存处理人、创建人和操作人快照；报送目录动态提供稳定代码、名称、顺序和启用状态，模块不复制七类报送。

启动时模块以 owner-bound facade 注册 `special_governance`、口径版本 1 的统计提供者，停止时关闭 handle。provider 直接使用平台给出的周/月/季/年边界，按 `[start, end)` 查询 `special_handling_at`；有效总数只含待处理、处理中和已完成。失败由平台保留最近成功快照，模块不写零或手工值。

## 安全和回滚

处理脚本仅作为 UTF-8 文本保存，限制 512 KiB；代码不存在脚本执行器、shell、子进程或数据库脚本执行入口。未知异常返回固定 500 文案和错误 ID，不回显 SQL、脚本、路径或驱动错误。上线失败时禁用可选模块即可隐藏导航、关闭 API 并注销 provider，数据和审计继续保留。

记录附件只受控存储与回传下载，不在服务端解析、渲染或执行任何附件内容：图片按魔数核对 PNG/JPEG/WebP（拒绝 SVG）；旧 `.xls/.doc` 只校验 OLE 复合文档容器头并统一保存为 `application/x-ole-storage`，服务端无法区分具体 Office 类型或保证无宏，属允许旧格式的明确限制；`.xlsx/.docx` 在不解压成员正文的前提下校验 ZIP 中央目录、`[Content_Types].xml` 与 `xl/`、`word/` 标识，限制条目数量并拒绝 `vbaProject.bin` 与宏启用内容类型，显式 `.xlsm/.docm` 一律拒绝；`.zip` 只校验容器结构。本功能不提供恶意软件扫描，附件只有经具备详情权限的用户主动下载后才由本机软件处理。文件名做 basename 清理并限制长度；下载响应使用服务端确认 MIME、平台统一 `nosniff` 与 UTF-8 编码的 `Content-Disposition`。附件内容、Base64 与密码不写入应用日志。

附件功能回滚：代码回滚恢复模块前后端、manifest 与测试后，需通过新的补偿迁移删除 `report_special_processing_record_attachments` 表，不得修改或回放已发布的 `006_record_attachments.sql`；该表数据删除后不可恢复，回滚前按数据备份流程处理。若迁移尚未在任何环境执行，可直接撤销未发布的迁移文件。
