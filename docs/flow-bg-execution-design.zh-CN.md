# 流程执行工具后台执行设计

## 一、目标

将流程执行工具改为后台执行模式，让用户触发流程后可以关闭弹窗，流程在后台继续执行，完成后通过浮动提示条通知。

## 二、现状

- 后端：流程执行已在后台线程运行（`threading.Thread(daemon=True)`），关闭弹窗不会中断执行。
- 前端：进度面板嵌在流程执行弹窗内，必须保持弹窗打开才能看到进度，且同一时间只允许一个流程任务。
- 限制：同一时间只允许一个活跃的流程链任务。

## 三、设计方案

### 3.1 后端（少量改动）

1. 已有 `_start_flow_chain_job` 后台线程机制，无需重构。
2. 保留现有的"同一时间只允许一个活跃任务"限制。
3. 新增轻量接口 `GET /api/flow-chain/status`，返回当前活跃任务状态（无需 job_id），无活跃任务时返回 `job: null`，方便全局轮询且避免前端 404 噪声。

#### 接口定义

```
GET /api/flow-chain/status

响应（有活跃任务）：
{
  "job": {
    "id": "hex",
    "chain_id": "chain-zgxg-1",
    "chain_name": "资管新规1",
    "trigger_type": "manual",
    "status": "running",
    "progress": 30,
    "step": "正在执行：流程B",
    "steps": [...],
    "logs": [...],
    "error": "",
    "started_at": "2026-06-18 19:32:01",
    "finished_at": ""
  }
}

响应（无活跃任务）：
HTTP 200 { "job": null }
```

### 3.2 前端

#### 流程执行弹窗

- 触发执行后，弹窗底部显示"已提交，流程在后台运行中，关闭弹窗不影响执行"，允许用户随时关闭。
- 再次打开流程执行弹窗时，如果有活跃任务，自动切换为"查看进度"模式而非"新建执行"模式，显示当前进度、日志和操作按钮。
- 弹窗关闭时不停止后台轮询，浮动提示条继续独立更新。
- 点击停止时，前端按后台任务 `job_id` 调用取消接口并立即禁用停止按钮，后端设置本地 `cancel_event`，停止继续等待当前任务或提交后续流程。该操作不强杀申报平台已经提交的 `sp_task`，已提交任务由平台自身继续处理。

关键函数：

| 函数 | 说明 |
|------|------|
| `openFlowModal()` | 打开弹窗，检测活跃任务并自动切换模式 |
| `showFlowModalProgressMode(job)` | 将弹窗切换为查看进度模式 |
| `startFlowModalBackgroundPoll(jobId)` | 弹窗内轮询后台任务状态 |
| `closeFlowModal()` | 关闭弹窗，不停止后台执行 |

#### 浮动提示条

位置：页面右下角，固定定位。

结构：

```
┌──────────────────────────────────────────────┐
│  ⚙  资管新规1 - 流程链执行中       3/10  展开 │
│      正在执行：流程B                          │
│  ████████░░░░░░░░░░░░░░░░░░ 30%              │
├──────────────────────────────────────────────┤
│  19:32:01  准备执行流程：流程A                │
│  19:32:05  流程已启动：流程A / sp_task.id=101 │
│  19:35:10  流程执行结束：流程A                │
│  19:35:12  准备执行流程：流程B                │
│  19:35:18  流程已启动：流程B / sp_task.id=102 │
└──────────────────────────────────────────────┘
```

组成元素：

| 元素 | 说明 |
|------|------|
| 图标 | 运行中显示齿轮图标，完成后显示 ✓，失败显示 ✗ |
| 标题 | 流程链名称 + 状态（执行中 / 执行完成 / 执行失败） |
| 副标题 | 当前执行的流程名称，或完成用时，或失败原因 |
| 步骤编号 | `当前/总数` 形式，如 `3/10`，适合多步骤场景 |
| 操作按钮 | 运行中显示"展开/收起"，完成后/失败后显示关闭 × |
| 进度条 | 细进度条，颜色跟随状态变化 |
| 日志面板 | 点击展开后显示，可滚动查看执行日志 |

状态与颜色：

| 状态 | 颜色 | 说明 |
|------|------|------|
| 运行中 | 蓝色渐变（活力）/ 青绿色渐变（沉稳） | 图标脉冲动画 |
| 已完成 | 绿色渐变 | 无动画 |
| 失败 | 红色渐变 | 无动画 |

交互行为：

| 操作 | 行为 |
|------|------|
| 点击"展开" | 向下展开日志面板，最多显示 220px 高度 |
| 点击"收起" | 收起日志面板 |
| 点击 ×（完成/失败后） | 关闭提示条 |
| 完成后 | 不自动关闭，需手动关闭，避免用户在其他页面时错过结果 |

#### 主题适配

- 活力主题（太空蓝）：蓝色运行态、绿色完成态、红色失败态。
- 沉稳主题（青绿色）：青绿色运行态、绿色完成态、红色失败态。
- 暗色模式：背景加深，对比度调整。
- 毛玻璃效果：头部栏使用 `backdrop-filter: blur(16px)`。

### 3.3 流程链配置选择增强

- `GET /api/tools/flow/definitions` 返回流程列表时保留 500 条展示上限，并在响应中返回 `limit` 和 `truncated`，前端据此提示“仅展示前 500 条”。
- 流程链配置弹窗的搜索框支持按流程名称或 `flow_id` 后端查询，超过初始 500 条的流程可通过搜索定位后加入。
- 弹窗保留手工 `flow_id` 添加入口；当流程表排序或过滤导致目标流程不在当前列表中时，可直接输入 `flow_id` 加入链路，保存后仍按原流程链执行逻辑调用。

### 3.4 不需要改的部分

- `flow_tool.py` 核心逻辑不变。
- 执行、轮询、超时、取消机制不变。
- 流程链执行记录的对外 payload 和 API 结构不变；当前版本通过 `DatabaseHistoryStore` 写入 MySQL 应用库中的 `flow_chain_runs`、`flow_chain_run_steps`、`flow_chain_run_logs` 和 `flow_chain_run_details`，并在 `run_headers.payload_json` 保留完整快照，不再维护旧 `history_runs(kind='flow_chain')` 兼容快照。
