# 业务表字段配置化迭代建议

本文记录“表名和字段可能配置化或动态获取”的设计建议和当前落地状态，方便后续迭代继续推进。

## 背景

当前系统设置中的“业务设置”已经展示对数逻辑涉及的表、字段、业务含义和当前用途，但这些内容仍由前端静态维护。后续如果生产环境表名或字段名变化，继续写死在代码里会带来两个问题：

- 字段调整需要改代码、重新测试、重新打包。
- 业务规则和物理字段耦合，后续规则增多后维护成本会持续上升。

## 推荐方向

后续建议采用“配置文件驱动 + 元数据校验”的方式推进，不建议一开始做成完全动态识别。

核心原则：

- 对数规则只识别稳定的业务字段编码，例如 `main.asset_total`、`valuation.market_value`、`am_asset.stock_code`。
- 具体库、schema、表名、字段名由业务设置维护。
- 数据库元数据只用于辅助校验表字段是否存在、类型是否合理，不要完全依赖动态识别业务含义。

## 当前落地状态

当前版本已完成后端查询层配置化：

- 新增 `reconcile_schema` 配置模型，支持按逻辑表维护数据源、表名和字段名；当前自动对数逻辑会用到的字段均按必填校验。
- 系统设置页面新增自动对账表字段配置表单，可按逻辑表选择数据源、填写物理表名、读取数据库字段，并按字段英文名和中文备注模糊搜索选择/手工填写字段映射，同时提供“根据配置文件初始化配置”按钮，可从数据目录下的 `reconcile-schema.yaml` 导入并保存到系统配置；生产二进制部署目录为 `/home/autocheck/data/reconcile-schema.yaml`。
- 自动对数仓储查询已通过逻辑表映射生成 SQL，运行时以系统页面保存的配置为准；未保存页面配置时继续使用内置默认映射，保持兼容。
- 页面保存后的配置按严格模式执行，缺少逻辑表、必填字段、表名或数据源时直接报配置错误，不再自动补默认字段。
- 表名支持单段表名，也支持 `schema.table` / `database.table` 形式；字段名仍限制为普通标识符，不允许配置 SQL 表达式。

尚未完成的内容：

- 系统设置页面已提供 JSON 编辑和按 YAML 文件初始化能力，但还未提供可视化字段选择与元数据检测能力。
- 运行历史暂未保存当次字段配置版本。
- 数据库元数据校验接口尚未落地。

## 分阶段方案

### 第一阶段：配置文件驱动展示

新增类似 `config/business-schema.json` 的业务字段配置文件，内容包括：

- 业务对象：主差异、估值表、科目余额、AM 资产、AM 合同投融资、TA 预留表。
- 业务字段编码：例如 `main.project_code`、`main.asset_total`。
- 业务含义：项目编号、资产合计、估值表金额等。
- 当前物理位置：数据源、schema、表名、字段名。
- 当前用途：主差异计算、资产侧校验、AM 标的校验、合同余额判断等。
- 是否必填：缺少后是否阻断对数。

系统设置中的“业务设置”从该配置读取，不再写死在 `app.js`。这一阶段可以先不改变对数 SQL。

当前状态：后端已具备配置模型，前端“业务设置”已能以表单方式保存/初始化运行配置；下方字段清单展示仍是静态说明，后续可继续改为读取同一份配置。

### 第二阶段：对数查询使用业务映射

后端增加 `BusinessSchema` 或同类模块，把业务字段编码映射为真实表字段。核心规则中不直接写 `a0001`、`d0000`、`f_marketvalue`，而是使用业务字段含义。

示例：

```text
main.asset_total       -> zf_detail_2024.a0001
main.liability_total   -> zf_detail_2024.d0000
valuation.market_value -> fa_valuationreport_dws.f_marketvalue
am_asset.stock_code    -> am_pactasset_dws.c_stockcode
```

这样后续字段名变化时，只调整业务配置，不调整核心规则。

当前状态：已以 `ReconcileSchemaSettings` / `AutoCheckRepository` 方式落地到自动对数仓储层。

### 第三阶段：动态获取用于校验

在系统设置里增加“检测配置”能力，通过 PostgreSQL/MySQL 元数据读取当前连接下的表字段：

- 表是否存在。
- 字段是否存在。
- 日期、金额、文本字段类型是否大体合理。
- 当前账号是否具备查询权限。

动态获取只做校验和辅助选择，不负责自动判断业务含义。原因是字段名无法可靠推断“资产合计”“负债及权益合计”等业务概念，完全自动识别风险较高。

## 历史记录要求

后续如果字段配置化，需要给字段映射增加字段配置版本，并在每次核对历史记录中保存当次使用的字段配置版本。

这样后续字段名调整后，回看历史记录时仍能知道当时使用的是哪一版表字段映射，避免历史结果解释不清。

## 推荐落地顺序

1. 先把当前业务设置字段清单抽成配置文件。
2. 页面从配置文件读取并展示。
3. 增加配置格式测试和必填字段测试。
4. 后端查询层逐步改为读取业务字段映射。
5. 增加元数据校验接口。
6. 核对历史保存字段配置版本。

## 当前版本边界

本版本已调整自动对数仓储查询的表名、字段名解析方式，但不改变业务判断顺序、金额口径、差异类型和导出规则。当前仍不引入动态表字段查询，也不提供页面可视化编辑。
