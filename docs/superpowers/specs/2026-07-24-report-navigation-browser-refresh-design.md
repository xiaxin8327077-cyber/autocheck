# 报送导航浏览器刷新体验优化设计

## 目标

浏览器刷新报送导航页面时，不再短暂展示空白统计区、空鱼骨图和空日程。页面优先恢复本标签页最近一次成功数据，同时后台读取最新数据；新数据返回后一次性替换旧画面。

## 交互设计

1. 每次成功渲染报送导航后，将接口 payload 缓存到 `sessionStorage`。
2. 缓存按当前用户和统计周期隔离，避免不同用户或“本周/本月/本季度/本年”之间串用数据。
3. 浏览器刷新后：
   - 有有效缓存：立即渲染缓存画面，刷新按钮显示旋转状态，后台读取最新数据。
   - 无有效缓存：显示轻量加载骨架，不展示空白鱼骨图。
4. 最新数据返回成功后，完整渲染一次并更新缓存。
5. 最新数据读取失败时：
   - 已显示缓存：保留缓存画面，并显示读取失败提示。
   - 无缓存：保留加载失败状态，不伪造业务数据。
6. 用户主动切换统计周期时，只读取该周期对应缓存，不继续显示上一周期内容。

## 缓存有效性

- 使用 `sessionStorage`，仅在当前浏览器标签页生命周期内有效。
- 缓存内容包含用户 ID、统计周期、业务报告期、保存时间和 dashboard payload。
- 用户 ID 或统计周期不一致时不读取。
- 缓存业务报告期必须与当前月份对应的上月月末一致；跨月后自动忽略旧缓存。
- 缓存解析失败或字段不完整时直接忽略，不影响接口正常加载。
- 退出登录时清理报送导航缓存。

## 页面状态

- `initial-loading`：首次访问且无缓存，显示骨架。
- `refreshing-with-cache`：已显示缓存，页面内容保持稳定，仅刷新按钮旋转并提供“正在更新”语义。
- `ready`：最新数据已渲染。
- `error-with-cache`：保留缓存，提示最新数据读取失败。
- `error-empty`：无可展示数据，显示明确失败状态。

## 实现范围

- `src/auto_check/web/app.js`

  - 调整 `loadReportNavigation()`，先恢复缓存再后台请求。
  - 只缓存成功返回且结构有效的 dashboard payload。
- `src/auto_check/web/index.html`

- `src/auto_check/web/styles.css`
  - 增加轻量骨架和刷新中状态样式，沿用现有主题色与圆角变量。
- `tests/test_web_static.py`
  - 验证缓存按用户/周期隔离、跨月失效、错误保留缓存及首次加载骨架结构。

## 验收标准

1. 同一用户在同一标签页按 F5 后，接口返回前仍能看到上次成功画面。
2. 刷新期间不出现空鱼骨图、空统计区或空日程。
3. 新数据返回后，页面完整更新且缓存同步更新。
4. 接口失败时不清空已显示的缓存数据。
5. 切换用户、统计周期或进入新月份时不显示不匹配的缓存。
6. 首次访问无缓存时显示加载骨架。
7. 不改变报送导航统计、刷新冷却和权限逻辑。
