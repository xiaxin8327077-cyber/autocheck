# 用户界面圆角自定义设计

## 1. 背景

监管智核当前使用 MySQL `auto_check` 应用库保存系统配置、用户、历史记录和报送导航数据。运行时不再使用 SQLite，应用启动时只连接并校验既有 MySQL 结构，不自动建表或升级。

当前前端支持活力、沉稳和暗色模式，但导航、卡片、弹窗、按钮及表单控件的圆角分散硬编码在 `styles.css` 中。不同组件目前使用 6px、8px、12px、16px 等不同值，用户无法统一调整。

本功能为每个登录用户提供跨浏览器、跨设备同步的圆角偏好，并在系统设置中提供所见即所得的滑块预览和显式保存。

## 2. 已确认需求

- 本次调整只能影响界面显示，不得影响系统任何业务功能、数据结果、权限判断或操作流程。
- 系统设置新增“界面设置”卡片，管理员和普通用户均可见。
- 使用一个全局滑块控制目标组件的圆角。
- 滑块范围为 1–15px，步长为 1px，默认值为 4px。
- 所有目标组件精确使用同一个滑块值，不按组件设置不同上限。
- 拖动滑块时立即预览，但不自动保存。
- 只有点击“保存界面设置”后才写入服务端。
- “恢复默认”把当前预览改为 4px，仍需点击保存才持久化。
- 未保存时离开系统设置页面，界面恢复为上次已保存值。
- 偏好按用户保存在 MySQL，同一账号跨浏览器、跨设备同步。
- 弹窗外壳以及弹窗中的按钮、输入框、日期框、数字框和下拉框纳入覆盖范围。

## 3. 目标与非目标

### 3.1 目标

- 为当前用户持久化一个 `radius_px` 整数偏好。
- 在应用显示前应用服务端偏好，避免页面圆角闪变。
- 用单一 CSS 自定义属性统一控制明确列出的组件。
- 圆角覆盖只修改目标组件的 `border-radius`，不改变尺寸、定位、层级、点击区域或交互事件。
- 保持活力、沉稳和暗色模式的颜色、阴影、背景及动效不变。
- 与当前 MySQL 人工升级、启动只校验的部署模式一致。

### 3.2 非目标

- 不修改自动对数、报送导航、人行导入、逐笔校验、流程工具、历史记录、用户管理等业务逻辑及请求参数。
- 不修改权限判断、按钮可用状态、表单值、焦点逻辑、键盘操作、页面切换和弹窗开关行为。
- 不修改登录页圆角。
- 不把圆形头像、状态点、图表节点改成普通圆角矩形。
- 不修改胶囊徽标、进度条、复选框、单选框、滑块轨道和手柄。
- 不调整颜色、阴影、间距、字体或主题切换逻辑。
- 不把偏好写入 `app_settings`、`config.json`、SQLite 或浏览器本地存储作为权威来源。
- 不提供管理员代替其他用户修改圆角的入口。

## 4. 数据库设计

### 4.1 增量 SQL

新增 `sql/app_storage/mysql/004_user_interface_preferences.sql`。现有 `001`、`002`、`003` 保持不变，新部署和升级部署均按顺序执行到 `004`。

新增第 36 张应用表：

```sql
CREATE TABLE IF NOT EXISTS `user_interface_preferences` (
  `user_id` VARCHAR(64) NOT NULL COMMENT '用户 ID',
  `radius_px` TINYINT UNSIGNED NOT NULL DEFAULT 4 COMMENT '界面圆角像素值，范围 1 至 15',
  `updated_at` DATETIME(6) NOT NULL COMMENT '更新时间',
  PRIMARY KEY (`user_id`),
  CONSTRAINT `chk_user_interface_radius_px` CHECK (`radius_px` BETWEEN 1 AND 15)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='用户界面偏好表：保存每个用户的界面圆角设置。';
```

### 4.2 不设置用户外键

当前 `storage_users.replace_users()` 在保存用户时先删除 `users` 全表，再整体插入现有用户。如果偏好表使用 `ON DELETE CASCADE`，登录时间更新等普通用户写入也会级联删除全部偏好。

因此本功能不为 `user_id` 创建数据库外键。数据完整性由应用维护：每次用户列表保存完成后，在同一事务中删除 `user_interface_preferences.user_id` 不在当前用户 ID 集合中的孤立记录。

这样既保持现有认证存储行为，又能在真实删除用户后清理偏好，不扩大到用户仓储重构。

### 4.3 结构校验与版本

- 将 `user_interface_preferences` 及其三个字段加入 `EXPECTED_APP_SCHEMA`。
- 应用期望表数从 35 调整为 36。
- 延续报送导航增量表的现行约定，`CURRENT_APP_SCHEMA_VERSION` 保持 1。
- 未执行 `004` 时，新程序启动应明确报告缺少 `user_interface_preferences` 表。

## 5. 后端仓储与接口

### 5.1 仓储边界

新增独立仓储模块 `storage_user_interface_preferences.py`，提供：

- `load_user_interface_preferences(connection, user_id)`：读取当前用户偏好；无记录或值非法时返回默认 4。
- `save_user_interface_preferences(connection, user_id, radius_px)`：使用 MySQL upsert 保存并更新时间。
- `prune_user_interface_preferences(connection, active_user_ids)`：清理不存在用户的偏好。

偏好保存不经过 `AuthSession`，也不修改用户公开资料结构。

### 5.2 API

新增当前用户接口：

- `GET /api/settings/interface`
- `POST /api/settings/interface`

统一响应：

```json
{
  "settings": {
    "radius_px": 4
  }
}
```

保存请求：

```json
{
  "radius_px": 4
}
```

规则：

- 仅允许已登录用户访问。
- 用户 ID 只取当前认证会话，不接受请求传入其他用户 ID。
- `radius_px` 必须是 1–15 的整数；布尔值、浮点数、空值、字符串越界值均返回 400。
- POST 继续使用现有 CSRF 校验。
- 成功保存后返回数据库中的规范化结果。

## 6. 前端设计

### 6.1 启动顺序

应用保持 `auth-pending` 隐藏状态，按以下顺序启动：

1. 获取认证状态并建立当前用户上下文。
2. 读取 `/api/settings/interface`。
3. 把结果写入根节点 CSS 属性 `--ui-radius`。
4. 继续应用主题和暗色状态。
5. 解除 `auth-pending`，显示主界面。

偏好读取失败不阻塞登录，应用默认 4px，并保留加载失败状态，进入系统设置后可提示用户重试。

### 6.2 界面设置卡片

“界面设置”卡片放在“系统信息”之后，不添加 `admin-only`：

- 标题：界面设置
- 说明：自定义当前账号的系统圆角
- 滑块：最小 1、最大 15、步长 1
- 当前值：实时显示 `Npx`
- 状态：区分“已保存”“正在预览，尚未保存”“保存成功”“保存失败”
- 操作：保存界面设置、恢复默认

普通用户原本只看到系统信息和关于系统；加入界面设置后显示三张卡片。管理员的现有设置卡片按网格自然后移，不改变各管理员专属卡片权限。

### 6.3 状态模型

前端维护两个整数：

- `savedRadiusPx`：最近一次从服务端读取或成功保存的值。
- `draftRadiusPx`：当前滑块预览值。

交互规则：

- 滑块 `input` 事件只更新 `draftRadiusPx` 和 CSS 属性。
- 点击保存后提交 `draftRadiusPx`；成功时同步更新 `savedRadiusPx`。
- 点击恢复默认只把 `draftRadiusPx` 设为 4。
- 从系统设置切换到其他页面时，如果两者不同，则用 `savedRadiusPx` 恢复界面。
- 保存失败时保留预览值和未保存状态，用户可重试；离开页面时仍恢复保存值。
- 多设备并发保存采用最后一次成功写入结果。

## 7. 样式覆盖范围

### 7.1 实现方式

在根节点定义：

```css
:root {
  --ui-radius: 4px;
}
```

在 `styles.css` 末尾增加集中式“用户圆角偏好覆盖层”。使用明确的选择器列表，不使用 `[class*=card]`、全局 `button` 等宽泛匹配。由于现有主题和页面规则存在较高 specificity，覆盖层可以只对 `border-radius` 使用集中、受控的 `!important`，确保用户偏好优先于组件和主题默认值。

### 7.2 纳入覆盖

- 导航：活力主题顶部导航外壳、顶部导航项和二级菜单；沉稳主题导航项、导航组按钮和二级菜单。
- 内容：通用卡片、首页统计卡、报送导航卡、工具卡、系统设置卡、用户管理卡、列表和详情主面板。
- 弹窗：确认、输入、信息、用户编辑、导入配置及其他矩形弹窗外壳。
- 按钮：矩形主按钮、次按钮、危险按钮、确认按钮、用户菜单按钮及弹窗内矩形按钮。
- 表单：文本框、数字框、日期框、原生选择框、自定义输入外壳、自定义选择触发器、下拉面板和日期选择面板。
- 主题：活力、沉稳、浅色和暗色模式共同读取 `--ui-radius`。

### 7.3 明确排除

- 登录页。
- 圆形头像、状态点、图表节点和圆形刷新按钮。
- 胶囊徽标、标签、进度条及用于完整胶囊形态的 `999px` 圆角。
- 复选框、单选框、滑块轨道和滑块手柄。
- SVG、CSS 图标内部形状。
- 弹窗遮罩。

## 8. 异常处理

- 启动读取失败：使用 4px，主界面继续加载。
- 保存网络失败或服务端错误：保留预览，显示失败信息，不修改保存基线。
- 圆角偏好接口异常不得阻断或延迟业务接口、页面切换和业务操作。
- 非法请求值：后端返回 400，不写数据库。
- 数据库中存在非法值：读取时回退 4px；后续正常保存覆盖异常值。
- 偏好表缺失：应用启动结构校验失败并明确提示先执行 `004`。
- 用户删除：用户保存事务结束前清理孤立偏好。

## 9. 测试设计

### 9.1 数据库与仓储

- 校验第 36 张表和三个必需字段。
- 校验增量 SQL 包含中文表注释、字段注释、主键、默认值和范围约束。
- 测试无记录返回 4。
- 测试同一用户重复保存执行更新而非新增。
- 测试不同用户互不影响。
- 测试用户删除后孤立偏好被清理。

### 9.2 API

- 未登录访问被拒绝。
- 普通用户和管理员均可读取、保存自己的设置。
- 请求不能指定其他用户 ID。
- 接受边界值 1 和 15。
- 拒绝 0、16、浮点数、布尔值、空值及不可解析字符串。
- CSRF 校验继续生效。

### 9.3 前端静态与行为

- 界面设置卡片不带 `admin-only`。
- 滑块包含 `min=1`、`max=15`、`step=1`、默认 4。
- 启动时在解除 `auth-pending` 前应用用户偏好。
- 拖动不调用保存接口。
- 保存按钮调用 POST，成功后更新基线。
- 恢复默认只修改预览。
- 离开页面撤销未保存预览。
- CSS 覆盖层包含导航、主卡片、弹窗、矩形按钮、输入和选择控件。
- 圆形和胶囊组件不进入覆盖选择器。
- 代表性按钮、输入框、下拉框和弹窗在不同圆角值下仍保持原事件绑定、可点击区域、表单值和键盘操作。

### 9.4 功能无影响回归

- 圆角值分别设为 1、4、15 时，验证页面切换、主题切换、暗色切换和弹窗开关行为不变。
- 验证自动对数、报送导航、历史查看、工具入口和系统设置原有 API 调用参数不因圆角变化而改变。
- 验证普通用户和管理员的原有权限边界不变；新增权限仅限所有已登录用户可管理自己的界面偏好。
- 验证偏好读取或保存失败时，其他页面和业务功能仍可正常使用。

### 9.5 全量验证

- 运行 `python -m pytest -q`。
- 运行 `git diff --check` 并修复真实 whitespace error。
- 检查活力、沉稳和暗色模式下的系统设置及代表性业务页面。
- 需要交付应用时运行 Windows 打包脚本并刷新 `dist/auto-check.exe`。

## 11. 验收标准

- 除圆角显示和界面设置卡片外，系统业务行为、数据结果、权限、操作流程和接口参数与改动前一致。
- 任意登录用户都能在系统设置看到界面设置卡片。
- 默认圆角为 4px，滑块可在 1–15px 之间逐像素调整。
- 导航、内容卡片、弹窗、矩形按钮、输入和选择控件同步变化且数值完全一致。
- 圆形、胶囊、进度和图标内部形状保持原样。
- 未保存预览不会写库，离开设置页后恢复。
- 保存后刷新、重新登录和换浏览器仍保持该账号偏好。
- 不同账号使用不同值时互不影响。
- 偏好读取或保存失败不会阻塞主要业务功能。
- 圆角值为 1px 或 15px 时，按钮、表单、下拉面板和弹窗仍能正常点击、输入、选择和关闭。
- MySQL 结构校验、全量测试和必要打包均通过。
