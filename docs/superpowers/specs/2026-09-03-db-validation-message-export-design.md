# 人行逐笔与模板报文一键下载设计

状态：用户已确认

## 1. 目标

在人行逐笔校验引擎弹窗标题区域、“执行历史”按钮右侧增加“下载报文”按钮。用户选择报告期后，一键生成并下载完整的逐笔报文和模板报文压缩包。

本功能的首要验收条件是：压缩包中的文件数量、文件格式、目录、文件名、工作表名称与顺序、列顺序、中文列名、单元格数据类型和格式必须与用户提供的参考压缩包一致。不能用近似格式、字段别名或 `.xlsx` 替代 `.xls`。

## 4. 数据来源与字段契约

### 4.1 动态映射

- 表映射继续使用现有 `db_validation_mapping_tables`，字段映射继续使用现有 `db_validation_mapping_fields`；不为报文功能建立第二套重复的映射、覆盖和审计表。
- ZG01 新增及 ZG02—ZG13继续使用当前人行逐笔校验的动态表映射快照。
- 新增 `detail:ZG01_CHANGE` 表映射，初始化物理表为 `zg01_change`；通过新的应用存储迁移添加种子关系，不修改已发布的 `017_db_validation_mapping.sql`。
- `db_validation_mapping_fields` 保留现有 `is_required` 作为“校验必需”标记，并新增 `is_export_required` 作为“报文必需”标记。一个中文字段同时用于校验和报文时只保存一条映射记录，两个标记同时为真。
- 刷新映射时，每张表的字段集合为“校验必需字段、校验可选字段、报文完整列集合”的并集。现有元数据加载器继续从 `xt_reg_table_baseinfo` 和 `xt_reg_table_field_info` 取得完整中文名到物理字段关系，再对并集逐项解析并验证物理列。
- 校验启动前只检查 `is_required`；报文启动前只检查 `is_export_required`。仅供报文使用的字段缺失不会阻断正常逐笔校验，仅供校验使用的字段也不会被错误加入输出列。
- 人工修改、恢复自动映射和审计记录继续复用 `db_validation_mapping_overrides` 及现有审计表。相同表、相同中文字段只有一个有效物理字段，不分别维护“校验映射值”和“报文映射值”。
- ZG01 变更表在新表映射下保存自己的字段映射状态和人工覆盖；自动映射默认继承同一份 ZG01 中文字段到物理字段关系，然后验证 `zg01_change` 的实际物理列，不按列位置猜测。
- 报文生成任务开始时取得一个不可变的映射快照，同一任务内不得因后台刷新映射而切换表或字段。
- 数据库标识符只能来自已验证的映射快照，并按 PostgreSQL/MySQL 方言引用，不能从请求参数直接拼接。

### 4.2 列和格式

逐笔文件不能使用数据库 `SELECT *` 返回顺序作为输出顺序。每个 ZG 文件必须使用版本化输出契约逐列投影：

- 完整中文列名和顺序来自参考包；不允许别名、简写、大小写替换或自动排序。
- 每个中文列名通过同一映射存储中的“报文必需”字段记录解析到物理字段；数据库新增列不会自动进入报文。
- 任一必需列无法唯一映射时，整个导出失败，并指出 ZG 编号和缺失中文列名。
- 标识符、代码、可能包含前导零的值保持文本类型；日期、数值、金额和比例按参考文件的单元格类型、精度及数字格式写入。
- 空值、零值和空字符串按参考契约区分，不能统一转换为字符串或统一填零。
- 空表仍写入完整表头、列宽、样式、冻结窗格及参考文件已有的其他工作表设置。

### 4.3 报告期和机构信息

- 报告日取自弹窗现有“报告期”控件，并继续使用现有逐笔校验的报告期表解析规则定位当期或历史表。
- ZG01 变更文件名使用报告日前一自然日；其他 13 个逐笔文件和 2 个模板文件使用报告日。
- 机构代码和机构名称从本次报文数据及模板元数据中提取并交叉校验。
- 无法确定机构信息、出现多个不一致机构代码或机构名称时不猜测，整个任务失败并返回脱敏错误。

## 5. 架构与代码边界

本需求扩展现有核心“人行逐笔校验”工具，不新建一个重复配置和数据源的普通业务模块，也不新增通用平台协议。业务实现集中在新的 `src/auto_check/db_validation/message_export/` 子包中，按以下职责拆分：

- `contracts.py`：16 个文件的命名、工作表、有序字段、类型及格式契约。
- `source.py`：从同一映射快照读取“报文必需”字段，完成数据读取与字段投影。
- `xlsx_writer.py`：14 个逐笔 `.xlsx` 文件写入。
- `xls_writer.py`：基于脱敏结构骨架写入 2 个 BIFF8 `.xls` 模板。
- `service.py`：机构信息校验、16 个文件编排、结构校验和 ZIP 封装。
- `jobs.py`：后台任务状态、互斥、超时、归属、临时目录及清理。
- `resources/`：只保存脱敏后的 `.xls` 结构骨架和必要的结构清单，不包含参考包业务明细。

公共文件只做最小接线：

- `server.py` 注册启动、状态和下载接口，完成登录、CSRF、能力码及任务归属校验；不承载报文业务逻辑。
- `capabilities.py` 注册 `db_validation.message_export` 并补全默认角色矩阵。
- `index.html`、`app.js`、`styles.css` 只增加按钮、状态轮询、下载和现有主题范围内的样式。
- 新迁移文件为现有字段映射表增加 `is_export_required` 标记，并新增 `detail:ZG01_CHANGE` 种子映射；不新建重复映射表，不修改其他模块的数据表或迁移。

## 6. 交互、权限与任务流程

### 6.1 界面

- “下载报文”位于弹窗标题区域、“执行历史”右侧，与截图红框位置一致。
- 使用中性空心按钮样式、现有全局圆角和主题变量，不使用渐变或主题光晕。
- 按钮只使用当前报告期，不读取“公开信息”“模板”或 ZG01—ZG13 勾选状态；每次始终生成完整 16 个文件。
- 生成期间按钮显示“报文生成中…”，并禁用重复点击。
- 成功后浏览器自动下载 ZIP；失败时恢复按钮并显示具体错误。
- 现有“查看最新映射关系”弹窗默认继续显示校验字段，并增加“报文字段”筛选及用途标签；报文字段数量不影响现有校验字段统计。字段同时服务两种用途时显示“校验、报文”。

### 6.2 权限

- 新增能力码 `db_validation.message_export`。
- 管理员和普通用户默认允许，角色权限页面可单独关闭普通角色权限。
- 前端按能力码控制按钮显隐，后端所有启动、状态和下载接口均再次鉴权。
- 状态和下载接口还必须校验任务归属；只有任务发起人和管理员能够访问。

### 6.3 后台任务与资源限制

1. 启动接口校验报告日、会话、CSRF、能力码、数据库设置和互斥状态，成功后返回任务 ID。
2. 后台任务取得数据源配置与映射快照，在任务专属临时目录生成 16 个文件。
3. 服务逐个验证文件结构；全部通过后才封装 ZIP，并将任务状态改为可下载。
4. 前端轮询状态；任务成功时请求下载接口，失败时展示错误。
5. 下载完成或任务过期后清理临时目录；应用退出时清理未完成任务资源。

报文生成和人行逐笔校验共用互斥控制，任一任务运行时均不得启动另一类任务。应用同一时刻最多运行一个报文生成任务；单任务超时 60 分钟，生成文件及解压后总大小上限 2 GiB。达到限制时任务失败并清理临时文件，不提供残缺下载。

## 7. API 契约

沿用现有 `/api/tools/db-validation` 命名空间：

- `POST /api/tools/db-validation/message-export/start`
  - 输入：`report_date`。
  - 输出：任务 ID、初始状态。
- `GET /api/tools/db-validation/message-export/status?task_id=...`
  - 输出：`queued/running/succeeded/failed/expired`、阶段、进度、可下载状态及脱敏错误。
- `GET /api/tools/db-validation/message-export/download?task_id=...`
  - 仅成功且未过期的任务返回 ZIP；其他状态返回明确错误码。

接口不得返回数据库连接串、密码、原始 SQL、驱动堆栈或本地绝对路径。下载响应使用经过清理的固定文件名；任务 ID 不能用于任意文件路径拼接。

## 8. 错误处理与原子性

以下任一情况均使整个任务失败：

- 数据源、表映射或任一必需字段映射缺失或冲突。
- `detail:ZG01` 或 `detail:ZG01_CHANGE` 指向同一有效物理表。
- 机构代码、机构名称或报告期无法唯一确定。
- 文件数量不是 16，文件名、扩展名、工作表、列、列名、数据类型或格式与契约不符。
- `.xls` 模板骨架缺失、损坏或写入后结构校验失败。
- 查询、写入、压缩、超时或容量限制失败。

失败任务只保留脱敏错误状态，不保留可下载的部分 ZIP；服务清理全部中间文件。错误信息应尽量定位到 ZG 编号、模板类型、工作表或中文字段，但不能暴露敏感连接和文件系统信息。

## 9. 测试与验收

### 9.1 自动化测试

- 契约测试：正好 16 个文件、目录和文件名规则正确；逐项断言完整有序中文列名，不只断言列数。
- ZG01 双表测试：新增从 `detail:ZG01` 读取，变更只从 `detail:ZG01_CHANGE -> zg01_change` 读取；不执行“信息类型”拆分；日期分别为报告日和前一自然日。
- `.xlsx` 测试：工作表名称、列顺序、中文列名、数据类型、数字格式、空值行为和空表表头均与结构契约一致。
- `.xls` 测试：文件签名为 BIFF8 `.xls`，两类文件各有 16 个工作表，并逐项比较工作表顺序、合并区域、隐藏行列、行列尺寸、关键样式、静态文字和填充值。
- 服务测试：机构信息交叉校验、映射快照固定、全部文件验证后才压缩、任一文件失败即无 ZIP。
- 任务测试：互斥、重复启动、超时、容量限制、任务归属、过期和清理。
- API 测试：登录、CSRF、能力码、管理员访问、普通用户跨用户访问拒绝、错误脱敏和下载头。
- 前端静态测试：按钮位置、能力码、报告日请求、忽略勾选状态、生成中禁用、轮询、成功下载和失败恢复。
- 数据库映射测试：新迁移增加 `is_export_required` 和 `detail:ZG01_CHANGE`，不新增第二套字段映射表；既有 `detail:ZG01` 及其他映射、覆盖和审计数据保持不变。
- 映射范围测试：刷新结果是校验字段与完整报文字段的去重并集；校验预检只受 `is_required` 影响，报文预检只受 `is_export_required` 影响；映射页面可分别筛选两类字段。

### 9.2 参考包对照

使用脱敏的 2026-08-31 固定夹具生成一份测试 ZIP，并与参考结构清单逐项比较：

## 11. 回滚与兼容性

- 新功能通过独立能力码和独立接口接入，关闭能力码即可隐藏入口并拒绝调用，不影响现有逐笔校验。
- 新迁移只增加带默认值的用途标记和映射种子，不删除或改写既有映射；旧字段记录默认保持“非报文必需”，既有校验行为不变。回滚应用版本时新列和种子记录不会改变旧版本的校验预检。
- 导出失败不写入校验历史，不改变逐笔校验结果、规则或现有下载结果。
- 不恢复暗色模式、沉稳主题或主题切换入口。
