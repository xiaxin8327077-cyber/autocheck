# 报送导航与智能核数多级菜单设计

## 目标

将现有首页位置替换为“报送导航”，并把现有自动对数相关页面收拢到一级菜单“智能核数”下，同时保持现有自动对数业务逻辑、历史逻辑和主题体系不变。

## 导航结构

- 一级页签“报送导航”作为登录后的默认页面，对应新路由 `#report-navigation`。
- 一级菜单“智能核数”包含三个子菜单：
  - “对数总览”：复用现有 `#home` 页面和首页统计逻辑。
  - “对数执行”：复用现有 `#auto-check` 页面和执行逻辑。
  - “对数历史”：复用现有 `#history` 页面和历史逻辑。
- “工具”“系统设置”“用户管理”等既有一级入口保持不变。
- 侧栏主题使用点击展开/收起的纵向子菜单；太空主题顶部导航使用点击展开的下拉子菜单。
- 任一子页面激活时，“智能核数”一级菜单保持激活状态；点击一级菜单时展开菜单，不直接切换页面。

## 报送导航页面

新增 `page-report-navigation` 页面，复刻 `监管智核-报送导航设计稿.html` 的主体内容：

- 统计周期选择栏。
- 报送报表、补录任务、数据治理流程、报表特殊治理四张统计卡片。
- “报送流程进度”鱼骨式流程图及人行、金监批次说明。
- 人行大集中完成状态、其他报送分支及核对要点。
- “注意事项”卡片和三条示例任务。

页面数据按设计稿静态展示，不新增后端接口。设计稿自身的顶部导航、品牌区、主题按钮和页脚不重复复制，继续使用项目现有应用外壳。页面样式统一增加报送导航作用域，避免污染现有首页卡片、按钮和流程工具样式。

## 路由与兼容

- 应用无 hash 启动时默认进入 `#report-navigation`。
- 原 `#home` 继续有效，表示“对数总览”，从而保留现有首页刷新、统计弹框和跳转逻辑。
- `#auto-check`、`#history` 等既有 hash 不变，避免影响已有内部跳转。
- 普通用户误入用户管理时回退到“报送导航”。

## 主题与交互

- 报送导航沿用设计稿的太空科技玻璃拟态表现，并为现有侧栏主题和两种暗色模式提供可读样式。
- 多级菜单支持鼠标点击、键盘焦点、`aria-expanded` 和 Escape/点击外部关闭。
- 菜单文字和页面标题统一改为“对数总览”“对数执行”“对数历史”。

## 测试与文档

- 在 `tests/test_web_static.py` 增加多级菜单、默认路由、页面结构、样式作用域、暗色兼容和文案断言。
- 先运行新增静态测试观察失败，再实现最小改动并回归完整测试。
- 同步更新 `README.md` 的详细变更说明和 `src/auto_check/web/app.js` 的应用内更新日志。
- 完整运行 `python -m pytest -q`、`git diff --check`，随后刷新 `dist/auto-check.exe`。

## 非目标

- 不新增报送导航后端数据接口。
- 不修改自动对数规则、仓储查询、导出、人行导入或逐笔校验逻辑。
- 不重构现有大型前端文件，也不修改应用版本号。
