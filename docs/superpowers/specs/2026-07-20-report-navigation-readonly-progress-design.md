# 报送导航只读流程全景与步骤详情设计

## 背景

现有“报送导航”使用鱼骨图表达各类监管报送流程，能够展示流程之间的整体关系，但霓虹色、发光效果、悬浮卡片和较大的空白使页面显得杂乱。新的设计继续保留图形化流程全景，不把页面改成任务处理台或操作表格。

该页面面向经理和管理人员，用于查看本月报送完成度、当前步骤、截止时间和风险。报送操作仍在各业务功能中完成，报送导航只读取统计快照并展示状态。

## 目标

- 保留“从月初准备到月末完成”的图形化流程表达。
- 默认状态下快速看清每条报送的总体进度、当前阶段和风险。
- 在不离开页面的情况下查看某条报送的全部具体步骤。
- 删除流程区域中的处理入口，避免管理看板与业务操作混杂。
- 所有新增表面、强调色和交互状态兼容系统圆角与主题色设置。

## 非目标

- 不修改报送状态计算、步骤依赖、数据库结构或统计接口。
- 不在页面中新增开始处理、继续处理、立即处理、查看结果、手工完成或撤销完成入口。
- 不在本次设计中重做顶部导航、其他业务页面或系统设置。
- 独立 HTML 预览使用模拟快照，不连接真实业务数据源。

## 选定方案

采用“两层只读展示”：流程全景负责总览，流程卡片下方的详情区负责具体步骤。

### 第一层：流程全景

流程卡片包含以下信息：

- 报送名称。
- 总体状态：已完成、进行中、有风险或未开始。
- 已完成步骤数与总步骤数，例如 `4/7`。
- 由步骤数量生成的微型分段进度条。
- 当前步骤的简短名称；全部完成时显示完成时间。
- 截止日期和负责人。

卡片通过细线连接到“月初准备—月末完成”主轴。连接线、当前步骤和选中态使用系统主题色；已完成、预警、逾期分别使用语义绿、橙、红；未开始使用中性灰。

主轴和卡片不依赖固定蓝色渐变或发光效果。用户更换主题色后，结构和信息层级保持不变。

### 第二层：步骤详情

默认选中第一条未完成或有风险的流程。点击任意流程卡片后，在流程图下方就地更新一个只读详情区，不打开新页面，也不触发业务动作。

详情区包含：

- 流程名称、总体状态、完成比例、截止日期和负责人。
- 按顺序排列的完整步骤清单。
- 每一步的序号、名称、状态、说明和完成时间或最近更新时间。
- 当前步骤使用系统主题色和“当前”标记。
- 已完成步骤使用绿色勾选状态。
- 异常步骤使用红色状态，并展示快照返回的异常原因。
- 未开始步骤使用灰色空心节点。

步骤名称较长时允许在详情区自然换行；流程卡片中的当前步骤名称最多显示两行，超出部分省略并通过只读提示展示完整内容。

详情区一次只展示一条流程。再次点击已选中的卡片保持展开，不折叠详情，避免用户误以为详情数据消失。

### 单步骤流程

21、23 版全要素、East5 和五篇大文章只有一个内部判断步骤：

- 流程卡片仍显示一段进度条和 `0/1` 或 `1/1`。
- 点击后详情区展示唯一的“归档并上传”步骤、状态和完成时间。
- 不为了视觉一致性虚构额外步骤。
- 五篇大文章仅在 1、4、7、10 月展示，延续现有规则。

## 页面结构

1. 顶部应用导航：沿用现有品牌和菜单结构。
2. 页面标题栏：报送导航、统计周期、最近更新时间和只读刷新状态。
3. 四张统计卡：保持现有四类统计数据，降低装饰，使用统一表面样式。
4. 报送流程全景：主轴、七条报送分支、流程概览卡和图例。
5. 步骤详情区：随选中流程更新的只读步骤列表。
6. 底部摘要：风险与提醒、关键日期，均不提供处理按钮。

## 交互规则

- 鼠标点击流程卡片：切换选中流程并更新详情区。
- 键盘聚焦卡片后按 Enter 或 Space：执行相同的只读选择行为。
- 鼠标悬浮卡片：仅加强边框和轻微上移，不增加光晕。
- 选中卡片：使用主题色边框、浅色主题表面和清晰焦点环。
- 统计周期切换：独立 HTML 预览在本月、本季度之间切换模拟数据；正式实现继续使用现有接口和统计周期逻辑。
- 刷新按钮：独立预览只演示更新时间变化和短暂加载状态；正式实现沿用当前刷新、冷却和错误提示逻辑。
- 所有流程、步骤、风险和日期区域均不出现业务处理按钮。

## 圆角与主题色

原型使用统一 CSS 变量：

- `--ui-radius`：卡片、按钮、输入框、详情区、状态容器和提示层的公共圆角。
- `--theme-color`：激活导航、主轴进度、当前步骤、选中态、焦点环和链接颜色。
- `--theme-color-soft`：选中表面和弱强调背景，由主题色计算得到。

圆形流程节点、状态点和头像仍保持圆形，不跟随矩形控件圆角。语义红、橙、绿不跟随主题色变化。

独立 HTML 预览提供一个明确标注为“原型预览”的小型设置面板，用来切换几种主题色并调整圆角，验证设计令牌生效。该面板不属于正式报送导航页面。

## 数据映射

继续使用当前报送导航快照结构：

- `processes[]` 生成流程卡片和主轴状态。
- `completed_steps / total_steps` 生成完成比例和分段进度。
- `steps[]` 生成只读步骤详情。
- `status`、`status_message`、`error_message` 和 `completed_at` 分别用于状态、说明、异常原因和完成时间。
- `report_date` 和责任人字段用于卡片与详情摘要；独立预览使用固定模拟值。

正式实现不改变步骤判断器、步骤依赖、人工覆盖记录或定时统计流程。

## 状态与异常

- 无统计快照：保留现有加载或无快照提示，不展示伪造进度。
- 最近统计失败：保留上次成功快照，并在页面顶部展示失败提示。
- 单步骤异常：流程卡标记为有风险，详情区定位并展开异常步骤。
- 步骤数量为零：显示“暂无可展示步骤”，总体状态仍按快照返回值展示。
- 长文本：详情区换行，流程卡限制两行，不能溢出卡片。

## 响应式与可访问性

- 桌面宽屏保持图形主轴和上下分支布局。
- 窄屏改为纵向时间线，流程顺序和详情选择逻辑不变。
- 流程卡片具备可见焦点态和明确的只读选择语义。
- 状态不能只依赖颜色，同时显示文字、图标或节点形态。
- 支持减少动态效果偏好；悬浮位移和详情切换动画可被关闭。

## 独立 HTML 预览验收标准

- 打开单个 HTML 文件即可查看完整页面，不依赖后端服务。
- 能点击或用键盘选择七条流程，并看到对应的真实步骤名称。
- 人行大集中显示 4 步，资管产品模板、逐笔显示 7 步，1104 显示 4 步，中信登显示 5 步；其余流程各显示 1 步。
- 页面不包含任何报送处理按钮或操作列。
- 能切换原型主题色和圆角，并同步影响所有目标组件。
- 风险色、预警色和完成色不随主题色切换。
- 1440×1024 下主体信息完整、无裁切、无横向滚动；窄屏布局仍可阅读。

## 正式实现影响范围

设计获批并完成独立预览确认后，正式实现预计修改：

- `src/auto_check/web/index.html`：调整报送导航流程区域和增加只读详情容器。
- `src/auto_check/web/app.js`：增加流程选择和详情渲染，移除流程步骤的手工操作绑定。
- `src/auto_check/web/styles.css`：重做流程全景、步骤详情、响应式及主题/圆角适配。
- `tests/test_web_static.py`：更新静态结构、只读交互和主题/圆角覆盖断言。
- `README.md` 与应用内更新日志：按仓库约定同步可见 UI 变更。

独立 HTML 预览放在 `docs/prototypes/`，不属于正式产物，不改变应用运行行为。
