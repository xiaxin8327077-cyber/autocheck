# 自定义报表设计、查看与导出功能设计

状态：方案已确认，已按模块化扩展架构修订

日期：2026-07-31
交互原型：`docs/prototypes/custom-report-designer-preview.html`

前置架构：`docs/superpowers/specs/2026-07-31-modular-extension-architecture-design.md`

## 1. 背景

当前系统已经具备单条数据源管理、MySQL/PostgreSQL 连接、数据库字段读取、查询结果展示和 Excel 导出等基础能力，但尚未提供面向业务用户的通用报表设计工具。

本功能需要让用户在不编写 SQL 的情况下，从一个数据源中选择一张或多张表，配置表之间的关联关系，选择展示字段和查询条件，预览拼接后的数据，并将整套配置保存为可重复查看和导出的报表模板。

## 2. 目标

- 从系统现有数据源读取 schema、表、字段、注释、类型、主键和索引信息。
- 支持选择一张主表和多张关联表。
- 通过可视化方式配置表关联字段、连接类型和预期关联基数。
- 支持选择展示字段、调整列名、顺序和数据格式。
- 支持固定筛选条件、运行时查询参数和多字段排序。
- 支持在保存前预览数据并诊断关联结果。
- 将报表配置保存为模板，后续可直接查看、复制、发布和导出。
- 支持 Excel 和 CSV 导出，并记录模板版本、查询条件和执行结果。
- 保证所有查询只读、参数化、可限制、可审计。

## 3. 非目标

第一期不包含：

- 不同数据源之间的直接关联查询。
- 用户直接编写或执行任意 SQL。
- 存储过程、数据库函数或写入类语句。
- 多对多关系的自动去重。
- 复杂窗口函数、任意嵌套子查询和自由 SQL 表达式。
- 定时报表、邮件订阅和消息推送。
- 图表、仪表盘和大屏设计。
- 为每个模板创建数据库物理表。
- 自动推断字段的业务含义。

## 4. 核心决策

### 4.1 采用结构化可视化设计器

用户通过选择表、字段、关联方式和筛选条件完成设计。系统保存结构化配置，并在运行时生成参数化 SQL。

不采用 SQL 编辑器作为普通用户入口，原因是任意 SQL 难以控制字段权限、查询规模、数据库兼容性和安全风险。

### 4.2 模板保存查询定义，不保存数据副本

报表模板保存表、字段、关联、筛选、排序和展示格式等定义。查看或导出时重新查询数据源，以保证结果使用最新数据。

如后续出现固定时点留痕需求，应单独增加“报表快照”，不与模板定义混为一体。

### 4.3 第一期仅支持同一数据源内多表关联

普通数据库 JOIN 只能在同一数据库连接可访问的范围内执行。跨数据源拼接涉及数据搬运、缓存、类型转换和一致性控制，应作为后续独立能力建设。

### 4.4 主表驱动关联图

每个报表必须指定且只能指定一张主表。每张新增关联表必须与已经加入的表建立至少一条有效关联，整个关联图必须连通。

### 4.5 作为标准业务模块交付

自定义报表是模块化扩展宿主的首个正式业务模块，全部业务代码、前端资源、数据库迁移和模块测试放在：

```text
src/auto_check/modules/custom_reports/
tests/modules/custom_reports/
```

模块通过 `manifest.json` 自动注册导航、权限、API 前缀、前端入口和 schema 版本。报表业务实现不得写入 `server.py`、`app.js`、`styles.css`、`index.html`，也不得修改其他业务模块内部代码。

自定义报表模块开发必须以模块宿主通过验收为前置条件。平台协议存在缺口时，先形成独立的平台变更，不把公共入口修改混入报表业务提交。

## 5. 用户角色与权限

系统现有管理员/普通用户身份保持不变。报表模块在自己的权限表中为普通用户附加 `design`、`publish`、`export`、`admin` 能力；系统管理员自动拥有全部能力，所有已登录普通用户默认只有已发布报表的 `view` 能力。这样既不修改现有用户模块，也能支持报表设计人员和查看人员的职责分离。

### 5.1 报表设计人员

- 创建、编辑和复制自己的报表模板。
- 读取有权限的数据源元数据。
- 执行数据预览。
- 保存草稿并申请或执行发布。

### 5.2 报表查看人员

- 查看有权限的已发布模板。
- 输入运行参数并查询数据。
- 调整页面显示列和排序。
- 在权限允许时导出数据。

### 5.3 系统管理员

- 管理所有报表模板。
- 设置模板可见范围。
- 停用、恢复和回退模板版本。
- 配置表级、字段级和导出权限。
- 查看查询及导出审计记录。

## 7. 报表设计流程

### 7.1 第一步：基本信息

配置内容：

- 报表名称
- 报表编码
- 报表分类
- 报表说明
- 数据源
- 可见范围
- 默认导出文件名

报表编码在系统内唯一，模板创建后不允许随意修改，以便执行历史稳定引用。

### 7.2 第二步：选择数据表

系统从数据源读取：

- schema 或 database
- 表名
- 表注释
- 字段数量
- 主键和唯一索引

用户首先选择主表，再增加关联表。每张表生成唯一别名，后续配置只引用表节点 ID 和字段 ID，不依赖用户可见名称。

### 7.3 第三步：配置关联关系

每条关联配置包含：

- 左表
- 左字段
- 连接类型
- 右表
- 右字段
- 多字段关联条件
- 预期关联基数

第一期允许：

- `LEFT JOIN`：默认方式，保留左表全部数据。
- `INNER JOIN`：只保留匹配数据。

第一期不允许：

- 无关联条件的交叉连接。
- `RIGHT JOIN`。
- `FULL JOIN`。
- 关联条件中的任意 SQL 表达式。

多个关联字段之间统一使用 `AND`。

普通模式采用线性配置方式：选择左表、连接类型、右表和关联字段。关系图用于展示三张及以上表的整体连接关系，并作为高级编辑入口，不作为第一期唯一操作方式。

### 7.4 第四步：选择展示字段

字段配置包括：

- 来源表和来源字段
- 展示名称
- 显示顺序
- 是否默认显示
- 是否允许筛选
- 是否允许排序
- 是否导出
- 列宽
- 空值显示方式
- 数据格式

第一期数据格式包括：

- 文本
- 整数
- 金额
- 小数
- 百分比
- 日期
- 日期时间

第一期只允许选择数据源中的直接字段，不实现计算字段和聚合字段。模板定义保留未来扩展版本号，但第一期接口拒绝字符串拼接、日期表达式、数值运算、`CASE WHEN`、`SUM`、`COUNT`、`MAX`、`MIN` 和 `AVG`。

结构化计算字段和分组汇总放入后续增强阶段，并继续禁止自由 SQL。

### 7.5 第五步：筛选与排序

筛选条件分为：

- 固定条件：设计模板时确定，运行时不可移除。
- 默认条件：设计模板时提供默认值，运行时允许修改。
- 运行参数：每次查询时由用户输入。

支持的操作符：

- 等于、不等于
- 大于、小于、大于等于、小于等于
- 包含、开头匹配
- 区间
- 包含于多个值
- 为空、不为空

每个运行参数需要配置：

- 参数编码
- 参数名称
- 数据类型
- 是否必填
- 默认值
- 可选值来源

排序支持多个字段，并保存明确的优先级和升降序。

### 7.6 第六步：预览与保存

预览默认返回前 100 行，并显示：

- 查询耗时
- 结果总数或估算数量
- 主表抽样行数
- 关联后行数
- 行数增长倍数
- 未匹配数量
- 重复匹配数量

模板保存前必须完成：

- 数据源有效性检查
- 表和字段存在性检查
- 关联图连通性检查
- 字段类型兼容性检查
- 查询语法检查
- 预览查询检查

## 8. 表关联规则

### 8.1 连通性

- 所有表节点必须从主表可达。
- 新增表时必须同时配置与已有表的关联。
- 删除表时同步删除相关关联，并检查展示字段和筛选条件引用。
- 不允许形成无连接的孤立表。

### 8.2 字段类型

系统按类型族检查关联字段兼容性：

- 文本与文本兼容。
- 整数、浮点和定点数属于数值族，但精度变化需要提示。
- 日期与日期兼容。
- 日期时间与日期时间兼容。
- 日期与日期时间允许关联，但需要明确转换规则。
- 文本与数值默认不兼容。

### 8.3 关联基数

用户需要声明预期基数：

- 一对一
- 一对多
- 多对一
- 多对多

系统可通过主键、唯一索引和抽样数据提出建议，但最终以用户确认的业务关系为准。

检测到多对多时，系统必须展示强警告，并阻止直接发布，除非管理员明确确认该关系符合业务预期。

### 8.4 结果膨胀

预览阶段计算：

```text
增长倍数 = 关联后行数 / 主表抽样行数
```

当增长倍数超过配置阈值时提示可能存在：

- 关联字段不唯一
- 关联条件缺失
- 多对多关系
- 日期或版本条件遗漏

## 10. 模块内部结构

建议新增：

- `manifest.json`：模块、导航、权限、版本和资源声明。
- `module.py`：实现模块生命周期并注册路由、schema 和后台任务。
- `contracts.py`：定义模板、表节点、关联、字段、筛选和排序对象。
- `metadata.py`：读取表、字段、注释、主键、唯一索引和外键。
- `validator.py`：校验模板结构、权限、类型和关联图。
- `sql_compiler.py`：生成 MySQL/PostgreSQL 参数化 SQL。
- `executor.py`：分页读取、流式读取、查询超时、取消和结果列类型。
- `storage.py`：模板、版本、执行记录和导出任务持久化。
- `service.py`：负责模板保存、版本、发布、复制和运行编排。
- `export_jobs.py`：负责 CSV、XLSX 和后台导出。
- `api.py`：注册模块相对 API。
- `web/`：模板列表、六步设计器、查看页面和执行记录。
- `migrations/`：模块独立数据库迁移。

模块可以复用 `DataSourceConfig`、数据源存储和数据库驱动等平台能力，但不得调用 `DatabaseClient._connect()` 等私有接口。自定义报表的分页、流式读取、超时和数据库级取消由模块自己的 `executor.py` 实现，避免为了报表功能修改现有数据库客户端行为。

## 12. 查询生成与执行

### 12.1 生成过程

1. 读取模板指定版本。
2. 解析数据源。
3. 校验用户、表和字段权限。
4. 实时检查表和字段是否存在。
5. 校验关联图和字段类型。
6. 根据数据库类型引用标识符。
7. 生成 `SELECT`、`JOIN`、`WHERE` 和 `ORDER BY`。
8. 将筛选值作为参数传入数据库驱动。
9. 对预览追加行数限制。
10. 执行查询并记录执行信息。

### 12.2 SQL 安全

- 表名和字段名只能来自已验证的元数据。
- 标识符必须通过合法性检查和数据库方言引用。
- 所有值使用参数化查询。
- 后端最终仍执行只读 SQL 检查。
- 数据源账号原则上使用只读账号。
- 不向前端返回完整生成 SQL，只返回可读的查询摘要。

### 12.3 分页

- MySQL 和 PostgreSQL 使用各自兼容的 `LIMIT/OFFSET`。
- 页面默认每页 50 行。
- 预览最多返回 100 行。
- 结果总数较大时允许使用估算数量，避免每次执行高成本 `COUNT(*)`。

## 13. 查看功能

打开已发布模板后：

1. 检查模板和当前版本状态。
2. 检查数据源及元数据。
3. 展示运行参数。
4. 执行分页查询。
5. 显示结果总数、耗时和模板版本。
6. 根据权限开放导出。

查看页面支持：

- 查询和重置
- 条件区域展开与收起
- 分页
- 多字段排序
- 列显示控制
- 列冻结
- 结果横向滚动
- 当前查询条件摘要
- 导出 Excel 或 CSV

查看页面临时调整列显示和排序时，不修改已发布模板。

## 14. 导出设计

### 14.1 格式

- Excel `.xlsx`
- CSV `.csv`

### 14.2 行为

- 后端根据模板版本和本次参数重新执行完整查询。
- 只导出被标记为允许导出的字段。
- 表头使用字段展示名称。
- 保留日期、日期时间、金额和数字格式。
- 文件名包含报表名称和导出时间。
- 导出记录关联模板版本和执行记录。

### 14.3 大数据量

- 小数据量同步导出。
- 大数据量进入后台导出任务。
- CSV 使用流式输出。
- Excel 使用只写模式分批写入。
- 超过 Excel 单工作表容量时自动拆分工作表。
- 单次最大导出行数由系统配置控制。
- 导出文件到期后由清理任务删除。

## 15. 权限、安全与审计

- 数据源访问权限。
- 表级查看权限。
- 字段级查看权限。
- 字段级导出权限。
- 敏感字段脱敏规则。
- 模板所有者和可见范围。
- 发布、停用和回退权限。
- 查询超时和并发限制。
- 预览和导出行数限制。
- 查询取消能力。
- 模板变更审计。
- 查看和导出审计。

数据库错误返回时需要移除：

- 数据库密码
- 完整连接串
- 未脱敏参数
- 数据库驱动堆栈

## 16. 错误处理

- 数据源不存在：阻止运行并提示重新选择数据源。
- 数据源连接失败：提示数据源名称和连接失败摘要。
- 表不存在：模板进入“配置异常”状态，标记具体表。
- 字段不存在：标记受影响的展示字段、条件和关联。
- 字段类型变化：重新执行兼容性校验。
- 关联图不连通：阻止保存和预览。
- 关联结果膨胀：显示诊断并阻止直接发布。
- 查询超时：终止查询并建议增加筛选条件。
- 导出超过限制：提示缩小范围或选择 CSV。
- 模板版本已变化：运行继续使用已加载版本，页面提示刷新获取新版本。

## 17. 界面规范

- 使用当前系统亮色活力主题。
- Logo 和实心主操作按钮使用 `#3466D9` 到 `#6AA4FF` 的固定渐变。
- 卡片、面板、按钮、输入框和选择框使用现有全局圆角规范。
- 空心按钮、文字操作和标签使用纯主题色，不使用渐变文字。
- 删除、停用使用危险色；警告使用警告色；校验成功使用成功色。
- 卡片和按钮悬浮仅使用主题色描边和轻微位移，不使用主题光晕。
- 关联画布通过清晰的表卡片、连接线和关联标签表达关系。
- 多对多和结果膨胀必须使用明显的警告提示，不能只依赖颜色表达。
- 所有 DOM 查询限制在 `.auto-check-module[data-module="custom_reports"]` 根节点内。
- 所有模块样式使用根节点作用域，不定义无作用域的通用按钮、输入框、表格和卡片规则。

## 20. 验收标准

- 用户可以从系统数据源中读取表和字段。
- 用户可以选择一张主表和至少一张关联表。
- 每张关联表都必须配置有效关联条件。
- 系统可以识别不连通关联、字段类型不兼容和结果膨胀。
- 用户可以选择展示字段并设置列名、顺序和格式。
- 用户可以配置固定筛选、运行参数和排序。
- 预览最多返回前 100 行，并展示关联诊断信息。
- 报表可以保存为草稿并发布为可查看模板。
- 模板修改后形成新版本，历史运行继续引用原版本。
- 用户可以按权限查看模板并导出 Excel 或 CSV。
- 查询和导出均有超时、行数限制和审计记录。
- 普通用户不能提交或执行任意 SQL。
- 第一期不允许不同数据源之间直接关联。
- 报表模块可以通过目录自动发现、启停和打包。
- 禁用报表模块后，现有功能、页面和数据均不受影响。
- 报表业务代码不进入现有公共入口和其他业务模块。
