# 人行逐笔校验执行历史分页与表格布局设计

## 目标

为“人行逐笔校验引擎”的执行历史弹窗增加分页，并压缩“执行时间”与“执行人”列的视觉间距，使表格在弹窗可用宽度内完整展示，不再出现左右滚动条。

## 范围

- 仅调整人行逐笔校验执行历史弹窗的前端结构、状态、渲染和样式。
- 继续使用现有 `GET /api/tools/db-validation/history` 接口，不修改后端数据结构或存储。
- 分页条数沿用“系统设置 → 每页条数”，默认 10 条。
- 不新增菜单、入口、按钮能力码或后端权限。
- 不修改展示用大版本号，不打包 `dist/auto-check.exe`。

## 交互设计

1. 打开执行历史弹窗时加载全部历史记录，继续按真实执行时间倒序排列，并将当前页重置为第 1 页。
2. 前端缓存已排序的历史记录，只渲染当前页切片。
3. 表格下方复用现有标准分页组件，展示总条数、当前页和总页数，并提供上一页、下一页和跳页。
4. 没有数据时显示“暂无历史记录”，分页显示“暂无数据”；加载失败时保留现有错误提示并禁用翻页。
5. 当系统设置的每页条数变化后，再次打开弹窗时使用最新配置。

## 布局设计

- 表格宽度固定为容器可用宽度，容器关闭横向滚动，只保留必要的纵向滚动。
- 七列使用合计为 100% 的明确比例，避免浏览器把剩余宽度平均扩散到各列。
- “执行时间”列保持完整日期时间所需宽度；“执行人”列明显缩窄，从而缩短两列内容之间的视觉空隙。
- 其余“报告期、结果条数、公开信息、模板、表单数”按内容长度分配宽度。
- 表头及七列所有数据单元格均强制单行展示，不允许任何列内容换行。
- 正常日期、时间、数字和“是/否”等内容应完整显示；异常过长的执行人名称使用单行省略号，并通过 `title` 提供完整文本，不得通过折行容纳。
- 分页控件使用现有全局圆角、主题色与分页样式，不引入新的颜色或圆角值体系。

## 数据流与状态

- 新增执行历史列表缓存和当前页状态。
- `loadDbValidationHistory()` 负责加载、排序、保存缓存并调用分页渲染。
- 分页渲染函数负责校正当前页、计算总页数、切片记录、更新表格和分页控件状态。
- 上一页、下一页和跳页事件只更新当前页并重新渲染，不重复请求接口。

## 验证

- 在 `tests/test_web_static.py` 增加或调整静态测试，覆盖分页结构、分页状态与切片逻辑、使用全局每页条数、执行人完整文本以及禁止横向滚动的样式。
- 静态样式测试明确检查执行历史表头和全部数据单元格使用 `white-space: nowrap`，且不存在会使这些单元格重新换行的局部覆盖。
- 运行相关前端静态测试，再运行完整 `python -m pytest -q`。
- 由测试子代理执行验证，主会话检查结果并处理必要修正。
- 运行 `git diff --check`，确认没有实际空白错误。
- 更新 `README.md` 的详细变更说明，并在 `src/auto_check/web/app.js` 当前更新日志版本中增加精简条目“系统优化及BUG修复”。

## 验收标准

- 执行历史按系统设置的每页条数分页，可正常上一页、下一页和跳页。
- 表格在弹窗可用宽度内完整显示，不出现左右滚动条。
- “执行时间”与“执行人”之间的空隙较当前界面明显缩短。
- 七列表头和每一列数据内容均不得换行；正常业务值完整可读，异常超长执行人名称以单行省略号显示并可悬浮查看完整内容。

## 非目标

- 不实现后端分页、筛选、搜索或分页条数独立配置。
- 不修改历史记录下载行为、排序规则、数据内容或权限。
- 不恢复暗色模式、沉稳主题或主题切换入口。
