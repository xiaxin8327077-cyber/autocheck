# 字段映射必需与可选状态设计

## 目标

字段映射同时管理校验必需字段和业务可选字段，并严格区分两类字段的缺失状态：

- 必需字段无法映射时，状态为 `required_missing`，计入“必须缺失”，并参与运行前阻断。
- 可选字段无法映射时，状态为 `unmapped`，计入“未映射”，但不阻断校验。
- 两类字段映射成功后状态均为 `mapped`，均支持人工修改和恢复自动映射。

## 字段范围

现有 `REQUIRED_CHINESE_FIELDS_BY_SCOPE` 继续作为校验必需字段的唯一清单。

新增可选映射字段清单，首批字段为：

- ZG06：数据管理机构
- ZG08：发行机构代码
- ZG09：数据管理机构、法人金融机构名称
- ZG10：数据管理机构、法人金融机构名称
- ZG13：数据管理机构

不从元数据自动扩张可选字段范围，避免把与校验无关的元数据字段重新带入弹窗。

## 刷新流程

每张逻辑表刷新时分别解析必需字段和可选字段，再按中文字段名去重合并：

1. 必需字段优先；同名字段同时出现在两张清单时按必需字段处理。
2. 对每个字段执行现有的精确匹配、受控语义匹配、物理列存在性检查和人工覆盖合并。
3. 必需字段无法映射时生成 `required_missing`，`is_required=true`。
4. 可选字段无法映射时生成 `unmapped`，`is_required=false`。
5. 快捷筛选、标题统计和按钮圆点继续依据已有状态字段计算，无需增加前端特殊判断。

## 运行行为

运行前缺失检查只查询 `is_required=true` 且状态为 `required_missing` 的记录。可选字段缺失不会阻止校验；规则读取不到可选字段时沿用现有空值或默认输出行为。

## 测试

- 可选字段无元数据映射时出现在字段列表，状态为 `unmapped`，且 `is_required=false`。
- 可选字段存在元数据映射时状态为 `mapped`。
- 必需字段缺失仍为 `required_missing`。
- 同名字段同时配置为必需和可选时按必需处理。
- 运行前缺失检查不返回可选未映射字段。
- 现有字段映射与规则引擎相关测试全部通过。
