# 看板外部接口专属 Token 管理设计

日期：2026-09-16
状态：已确认

## 1. 目标

由 AutoCheck 管理员在“系统管理 → 看板管理 → 接口监控”页面生成或轮换 Bearer Token，供 Kanban 后端调用以下两个固定只读接口：

- `GET /api/external/v1/dashboard-management/boards/report_submission/preview`
- `GET /api/external/v1/dashboard-management/boards/reporting_process/preview`

该 Token 不是平台全局 Token，不得访问其他看板、其他外部路由、普通模块 API、网页登录接口或管理接口。

开发环境与生产环境分别由各自管理员生成 Token。生产上线后重新生成并提供给生产 Kanban，不提供“录入已有 Token”，不复用开发环境 Token。

## 2. 方案选择

采用“模块持有凭据、平台只提供通用的外部路由认证挂钩”方案。

### 2.1 选定方案

- 看板管理模块拥有 Token 摘要、生成、轮换、状态查询和验证逻辑。
- 模块只发布两个精确外部 GET 路由，并为这两个路由登记模块专属认证器。
- 模块宿主新增可复用的外部路由认证挂钩，但平台内核不写入看板编码、路径或业务规则。
- HTTP 入口先解析已登记的精确外部路由，再调用该路由自己的认证器，最后分发模块处理器。

这样既能把 Token 限制在两个接口，又不会在 `server.py` 中硬编码看板业务。

### 2.2 未采用方案

1. 全平台共享 Token：会使凭据天然拥有未来其他外部路由的访问能力，违反本次最小权限要求。
2. 模块自己绕过平台直接解析 `Authorization`：会复制 HTTP 安全逻辑，并破坏模块宿主统一的 401、405、缓存头和响应限制。
3. 管理页面写 Windows 环境变量并要求重启：平台相关、不可移植、无法做到即时轮换，也难以保证生产 Linux 环境一致。

## 3. 路由与权限边界

### 3.1 外部路由

外部发布改为两个精确路由，不再用可匹配任意 `board_code` 的外部动态路径：

- `/boards/report_submission/preview`
- `/boards/reporting_process/preview`

内部登录态接口仍可保留参数化路由，由原有业务校验约束固定看板。

以下请求不得被该 Token 授权：

- 任何第三个或未知看板编码；
- `/api/modules/dashboard-management/**` 内部接口；
- 其他模块的 `/api/external/v1/**` 路由；
- 登录、用户、配置、SQL、监控查询和 Token 管理接口；
- 非 GET 方法和带请求体的调用。

### 3.2 管理权限

新增能力码：

```text
dashboard_management.external_api_token_manage
```

- 默认仅管理员拥有；普通用户和自定义角色默认关闭。
- 后端生成接口必须执行登录、CSRF、能力码和请求体大小校验。
- 前端按钮按能力码显隐，但后端鉴权是最终边界。
- 原 `dashboard_management.external_api_monitor` 只允许查看监控，不自动获得 Token 管理权。

## 4. Token 生命周期

### 4.1 生成与轮换

- 使用 `secrets.token_urlsafe(32)` 生成至少 256 位随机 Token。
- 首次生成与后续轮换使用同一管理接口。
- 已存在 Token 时必须先显示二次确认，明确“旧 Token 将立即失效”。
- 新 Token 成功持久化后立即生效，不需要重启 AutoCheck。
- 轮换采用单事务更新；持久化失败时旧 Token 继续有效，不返回未生效的新 Token。

### 4.2 一次性展示

- 生成接口只在本次成功响应中返回一次明文 Token。
- 前端使用遮罩弹窗展示，并提供复制操作和“我已保存”关闭按钮。
- 关闭弹窗、切换页面、退出模块或刷新浏览器后清除前端状态。
- 状态查询、监控接口、日志、数据库和后续页面均不得再次返回明文。

### 4.3 存储与校验

新增模块表：

```text
dashboard_management_external_api_credentials
```

仅保存：

- 固定凭据作用域；
- SHA-256 摘要；
- 非敏感指纹；
- 创建/轮换时间；
- 操作管理员标识。

不保存明文 Token。由于 Token 本身具有至少 256 位随机熵，外部请求到达时对候选 Token 计算 SHA-256，并使用 `secrets.compare_digest` 比较摘要。

### 4.4 管理接口

新增内部登录态接口：

```text
POST /api/modules/dashboard-management/external-api/token/generate
```

- 请求体固定为 `{}`，不接受调用方提供的 Token。
- 首次生成和轮换共用该接口；响应只在成功时返回 `token`、`generated_at` 和 `rotated`。
- 监控摘要继续只返回 `token_configured`，并新增非敏感 `token_source=managed|environment|none`。
- 接口未返回成功时，前端不得展示或保留任何候选 Token。

## 5. 环境变量兼容

现有 `AUTO_CHECK_EXTERNAL_API_TOKEN` 仅作为数据库尚无模块 Token 时的过渡兼容来源，并且只能由看板管理模块的两个专属路由认证器使用。

- 数据库 Token 一旦生成，立即优先并完全取代环境变量 Token。
- 数据库 Token 存在时，环境变量 Token 必须认证失败。
- 其他模块和其他外部路由不得复用该环境变量。
- 页面状态需区分“管理员生成”与“兼容环境变量”，但不显示 Token 内容、长度或摘要。

后续部署流程为：启动 AutoCheck → 管理员登录 → 在接口监控页面生成 Token → 将一次性明文安全提供给 Kanban → 配置并验证两个接口。生产环境重新生成，不录入开发 Token。

## 6. 模块与平台改动边界

### 6.1 独立平台兼容层

平台宿主只新增通用能力：

- 外部路由可登记认证回调；
- 外部预检结果能标识匹配到的认证策略；
- HTTP 入口统一解析 Bearer 头、调用认证回调并输出安全的 401/404/405；
- 认证回调不可读取请求体，不接收网页登录会话，不返回敏感信息。

平台层不得出现 `dashboard_management`、两个看板编码或模块表名。

### 6.2 看板管理模块

模块内新增：

- `004` 迁移及模块自有凭据表；
- Token 仓储和服务；
- 两个精确外部路由的认证器；
- 管理员生成/轮换 API；
- 接口监控页的生成/轮换按钮和一次性展示弹窗；
- 模块清单权限、schema 版本和 release note。

不修改其他业务模块，不修改其他看板页面，不恢复主题切换，不新建通用全局样式。

## 7. 页面规范

- 入口继续位于现有“接口监控”状态区域，不新增顶级菜单或独立页面。
- 未配置时显示“生成 Token”，已配置时显示“轮换 Token”。
- 按钮沿用现有管理页尺寸、圆角和主题色；轮换确认使用警告语义，不创建独立视觉体系。
- 一次性 Token 使用等宽只读区域；复制按钮只用于本次 Token，不影响调用记录“不提供复制按钮”的既有规范。
- 弹窗明确提示：仅适用于两个监管看板接口、关闭后无法再次查看、生产环境应重新生成。
- 页面不得显示摘要、环境变量值、数据库字段或内部错误。

## 8. 错误与审计

- 生成失败返回统一脱敏错误和 `request_id`，不返回 SQL、堆栈、数据库连接信息或旧摘要。
- 认证失败继续返回 401 和 `WWW-Authenticate: Bearer`，不说明 Token 是否存在或来自何处。
- Token 未配置时返回 503 `external_api_disabled`。
- 未知外部路由和第三个看板返回 404；错误方法返回 405。
- 401、503、未知路由和错误方法继续不写业务调用记录。
- 生成/轮换操作记录管理员标识和时间，但不记录明文、摘要或候选 Token。

## 9. 测试与验收

### 9.1 平台兼容层

- 只有显式登记认证器的外部路由才会调用对应认证器。
- 一个路由的 Token 不能访问另一个模块或另一个认证作用域。
- 未知路由、错误方法、缺失/重复/格式错误的 Authorization 均返回既定状态。
- 内部模块路由、登录会话路由和现有模块生命周期不受影响。

### 9.2 模块后端

- 首次生成只返回一次明文，数据库只保存摘要。
- 同一明文可以通过两个固定看板接口认证。
- 未知看板、其他模块路由和内部接口不能使用该 Token。
- 轮换后旧 Token 立即失效，新 Token 生效。
- 数据库写入失败时旧 Token 保持有效，失败响应不泄露新 Token。
- 数据库 Token 存在时环境变量 Token 失效；不存在时兼容值只服务两个固定路由。
- 普通用户、只有监控权限的用户和无 CSRF 请求不能生成或轮换。

### 9.3 前端

- 生成/轮换按钮只在拥有新能力码时出现。
- 首次与轮换文案、二次确认、一次性展示和清理行为正确。
- Token 不进入 URL、`localStorage`、`sessionStorage`、调用记录或普通页面状态快照。
- 页面布局、按钮、弹窗和响应式行为沿用现有系统规范。

### 9.4 回归范围

- 看板管理模块定向测试；
- 模块宿主路由、运行时、权限和服务测试；
- 外部接口及监控测试；
- 前端静态与行为测试；
- 全量 `python -m pytest -q`；
- `git diff --check`。

本次不自动打包，不提交、不推送。

## 10. 回滚

- 回滚模块代码时保留凭据表，不自动删除数据。
- 回滚到旧版本前，可继续用环境变量配置原外部接口 Token。
- 若新 Token 已提供给 Kanban，回滚前必须协调恢复旧环境变量 Token，否则 Kanban 调用会收到 401/503。
- 平台认证挂钩保持向后兼容：未登记模块专属认证器的旧外部路由不自动获得看板 Token。
