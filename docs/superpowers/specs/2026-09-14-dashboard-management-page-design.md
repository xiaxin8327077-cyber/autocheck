# 看板管理一期页面与数据来源配置设计

日期：2026-09-14
状态：已实施
范围：系统管理中的看板管理页面、配置持久化、自定义 SQL 测试与结果预览；不包含对外 API 和 API Key

## 1. 目标

在“系统管理”下新增“看板管理”，用于维护两个金融监管看板的数据来源：

1. 金融监管报表报送大屏。
2. 金融监管报送流程大屏。

两个看板必须分开展示。每个数据区域独立选择系统数据或自定义 SQL；一个数据区域只配置一条 SQL，并由该 SQL 一次返回区域内全部字段。

看板本身固定为上述两个，不支持用户新建第三个看板。管理员可以在现有两个看板中：

- 给已有数据区域追加自定义字段。
- 新建完整的数据区域，并为该区域定义一个或多个字段。
- 调整自定义数据区域和自定义字段的名称、顺序、启用状态和说明。

Excel 中只有黄色填充的业务字段属于一期范围。公共元信息、数组包装字段、流程编码、展示顺序、日期来源等未标黄字段不进入一期配置页面。

## 2. 页面结构

页面沿用系统当前亮色活力主题、统一圆角和固定 Logo 蓝色，不新增主题或配色开关。

### 2.1 导航

- 顶部“系统管理”菜单内新增“看板管理”。
- 页面默认仅管理员可见和可操作。
- 后续可以通过角色权限矩阵分别授予查看、编辑和 SQL 测试权限。

### 2.2 看板切换

页面标题为“看板管理”，标题下方使用两个一级页签：

- 金融监管报表报送大屏（7 个数据区域）。
- 金融监管报送流程大屏（3 个数据区域）。

切换页签时保留各看板最近一次选中的数据区域。两个看板的数据区域、编辑状态和测试结果互不混用。

### 2.3 主工作区

页面主体使用左右两栏：

- 左栏：当前看板的数据区域列表，展示序号、区域名称、来源类型和配置状态，并提供“新增数据区域”。
- 右栏：选中区域的字段、来源模式、数据源、SQL、测试状态和结果预览。

右栏字段区展示当前区域全部启用字段，并提供“新增字段”和“管理字段”。内置字段与自定义字段使用一致的字段标签展示，但自定义字段额外显示“自定义”标记。

来源状态统一显示为：

- 系统数据。
- 自定义 SQL。
- 未配置。
- 配置异常。

系统数据可用的区域提供“系统数据 / 自定义 SQL”切换，默认选择系统数据。系统没有直接来源的区域只允许自定义 SQL，并在系统数据选项处说明“该数据区域暂不支持系统数据”。

## 3. 一期数据区域

### 3.1 金融监管报表报送大屏

| 数据区域 | 返回字段 | 一期默认来源 |
| --- | --- | --- |
| 本年度完成补录任务 | 完成补录任务数 | 系统数据，可切换自定义 SQL |
| 当月报表检验还剩 | 剩余校验数量 | 系统数据，可切换自定义 SQL |
| 月度信托项目数量 | 月份、单一信托项目数量、集合信托项目数量、财产权信托项目数量 | 仅自定义 SQL |
| 报表对账完成时间 | 月份、对账完成时间 | 系统数据，可切换自定义 SQL |
| 报表校验问题处理 | 月份、校验问题数量 | 仅自定义 SQL |
| 季度报表特殊处理 | 季度、特殊处理数量 | 系统数据，可切换自定义 SQL |
| 当月报表报送时间对比 | 报表类型、实际出表日期、要求报送日期 | 系统数据，可切换自定义 SQL |

### 3.2 金融监管报送流程大屏

| 数据区域 | 返回字段 | 一期默认来源 |
| --- | --- | --- |
| 监管报送报表数量 | 报表类型、报表数量 | 仅自定义 SQL |
| 当月监管报送报表时间 | 报表类型、报送日期 | 系统数据，可切换自定义 SQL |
| 报表校验统计 | 报表类型、校验数量 | 仅自定义 SQL |

系统数据来源的预期口径：

- 本年度完成补录任务：报送导航“补录任务”年度统计的已完成数量。
- 当月报表检验还剩：报送导航“报表校验”月度统计的未完成数量。
- 报表对账完成时间：按月份汇总报送导航流程快照的整体完成时间。
- 季度报表特殊处理：报表特殊处理模块按季度统计的已完成数量。
- 当月报表报送时间对比：报送导航的流程完成时间与月度报送计划日期。
- 当月监管报送报表时间：报送导航的月度报送计划日期。

“报表校验问题处理”“监管报送报表数量”“报表校验统计”现有数据缺少与目标口径完全一致的直接结果，因此一期不伪造系统默认口径，直接采用自定义 SQL。

系统数据实现采用固定只读 SQL：由看板管理模块按区域编码生成，并使用 AutoCheck 应用数据库的现有连接执行。页面同时展示来源功能、应用数据库名、数据表中文名与物理表名和生成 SQL。补录任务与报表校验读取 `report_nav_card_snapshots`；报表对账完成时间读取 `run_headers` 中的自动对数历史；季度特殊处理读取 `report_special_processing_records`；报送时间对比与当月报送时间读取 `report_nav_processes`、`report_nav_process_months`、`report_nav_process_snapshots` 和 `report_nav_monthly_schedules`。该方式不新增平台服务接口，不保存第二份系统 SQL 配置，也不返回模拟数据。

## 4. 数据区域与字段扩展

### 4.1 固定看板与内置目录

两个看板编码由程序固定。Excel 标黄内容作为内置数据区域和内置字段，通过模块迁移写入目录表。内置编码用于后续 API 契约，不允许删除或修改；管理员可以调整其显示顺序和启用状态。

### 4.2 新增数据区域

管理员在当前看板页签中点击“新增数据区域”，填写：

- 数据区域名称。
- 数据形态：单值或列表。
- 数据区域说明。
- 至少一个字段。

自定义数据区域的稳定编码由后端生成，创建后不可修改。自定义数据区域一期只支持自定义 SQL，不提供系统数据来源。

自定义数据区域允许修改名称、说明、顺序和启用状态。删除采用二次确认；删除后区域与字段做逻辑停用，保留历史配置，不直接物理删除。

### 4.3 新增和管理字段

字段定义包含：

- 中文显示名。
- 稳定字段别名：小写字母开头，只允许小写字母、数字和下划线。
- 类型：字符串、整数、小数、布尔、日期、日期时间。
- 是否允许空值。
- 字段说明。
- 展示顺序。

内置字段的稳定别名、类型和数据形态不可修改。自定义字段创建后别名不可修改，但可以修改显示名、说明、顺序、是否允许空值和启用状态。

给已有系统数据区域增加自定义字段时，系统默认来源无法保证返回该字段，因此该区域必须切换为自定义 SQL，并由一条 SQL 同时返回全部启用字段。页面切换前明确提示这一影响，不自动拼接第二条 SQL。

新增、停用或恢复字段后，原 SQL 测试通过状态立即失效，必须重新测试并保存。

## 5. 自定义 SQL 配置

### 5.1 配置项

每个数据区域保存：

- 看板编码。
- 数据区域编码。
- 来源模式：`system` 或 `sql`。
- 系统数据源标识；仅 SQL 模式需要。
- SQL 文本；仅 SQL 模式需要。
- 配置版本号。
- 最后修改人和最后修改时间。

字段清单由内置字段和管理员新增字段共同组成。后续 API 使用稳定字段别名输出；显示名变化不影响字段别名。

### 5.2 SQL 返回约束

- 一个数据区域一条 SQL。
- SQL 只允许单条 `SELECT`，或以 `WITH` 开头并最终返回 `SELECT` 结果的查询。
- 禁止新增、修改、删除、建表、授权、存储过程和多语句执行。
- 查询结果列必须覆盖当前数据区域要求的全部字段。
- 允许额外返回列，但保存配置和后续输出时忽略额外列。
- 标量区域必须返回零或一行；列表区域允许多行。
- 测试预览最多读取 11 行：页面展示前 10 行，第 11 行只用于判断是否还有更多数据。
- 测试执行设置连接超时和查询超时，错误响应不得回显数据库密码、连接串、完整驱动堆栈或本地路径。

页面在 SQL 编辑器上方展示当前区域的全部启用输出字段标签，并提供可复制的字段别名示例。测试通过必须同时满足：查询成功、必需列齐全、值类型可转换、标量/列表行数符合约束。

### 5.3 保存规则

- SQL 模式只有在数据源已选择、SQL 非空且最近一次测试通过后才能保存。
- SQL 或数据源发生修改后，立即清除原测试通过状态，必须重新测试。
- 系统数据模式显示来源说明及只读的系统生成 SQL，并可直接执行前 10 行预览；系统 SQL 不允许在页面修改。
- 切换来源模式但未保存时，离开区域或页面需要提示是否放弃修改。

## 6. 后端与模块边界

一期采用“平台小扩展 + 独立业务模块”。

### 6.1 平台导航扩展

现有模块宿主只能把模块菜单渲染为独立顶级入口，不能合并到已有“系统管理”菜单。平台增加通用的同名导航组挂载能力：当模块清单声明 `group_id=system-management` 时，宿主把模块入口挂到已有系统管理子菜单；模块停用或会话刷新时清理动态入口。

该改动只扩展通用导航协议，不包含看板业务逻辑，并单独测试和提交差异。

### 6.2 看板管理模块

新增独立模块 `dashboard_management`：

```text
src/auto_check/modules/dashboard_management/
├── __init__.py
├── manifest.json
├── module.py
├── api.py
├── contracts.py
├── catalog.py
├── service.py
├── sql_executor.py
├── storage.py
├── migrations/
│   └── 001_initial.sql
└── web/
    ├── index.js
    ├── styles.css
    ├── api.js
    ├── state.js
    ├── pages/
    └── components/
```

模块 API 只提供已登录管理页面所需能力：

- 读取两个看板及数据区域目录。
- 新建、修改、停用和恢复自定义数据区域。
- 给内置或自定义数据区域新增、修改、停用和恢复自定义字段。
- 读取某数据区域的当前配置。
- 测试自定义 SQL 并返回字段检查与前 10 行预览。
- 执行系统生成 SQL并返回系统来源说明与前 10 行预览。
- 保存某数据区域的来源配置。

本期不增加外部匿名接口、不生成 API Key、不组装最终看板 JSON。

## 7. 数据库存储

模块迁移创建本模块命名空间内的数据区域目录表、字段目录表和来源配置表，表名统一使用 `dashboard_management_` 前缀：

- 数据区域目录一行对应一个内置或自定义数据区域。
- 字段目录一行对应一个内置或自定义字段。
- 来源配置一行对应一个数据区域，并使用看板编码与区域编码唯一约束。
- 迁移初始化两个固定看板、10 个内置数据区域；初版 21 个内置字段，2026-09-16 对账完成时间契约修正后为 22 个。

SQL 文本属于敏感配置：

- 只向具备管理权限的登录用户返回。
- 操作日志和异常日志不记录完整 SQL。
- 页面测试错误只返回脱敏错误编号与可理解的失败原因。
- 数据源密码继续复用系统已有加密存储，不复制到模块表。

## 8. 权限

模块声明：

- `dashboard_management.view`：进入页面并查看非敏感配置摘要。
- `dashboard_management.manage`：维护数据区域和字段、切换来源、编辑并保存配置。
- `dashboard_management.test_sql`：执行 SQL 测试并查看预览。

管理员默认拥有全部权限；普通用户和新增角色默认不拥有。即使前端隐藏按钮，后端仍逐接口校验权限。

## 9. 错误与状态处理

- 数据源不存在或已删除：区域显示“配置异常”，禁止沿用旧测试结果保存。
- 数据库无法连接：保留编辑内容，显示脱敏连接失败信息。
- 查询超时：主动终止或关闭查询连接，提示缩小查询范围。
- 返回列缺失：逐项列出缺少的固定字段别名。
- 数据区域没有启用字段：禁止测试和保存，并提示先新增或恢复字段。
- 系统数据区域新增自定义字段：提示切换为自定义 SQL，不把缺失字段当成空值静默输出。
- 类型不匹配：指出字段和期望类型，不展示敏感原始值。
- 模块加载失败：只禁用看板管理，不影响核心系统和其他模块。

## 10. 测试与验收

### 10.1 后端

- 清单、导航组、权限和命名空间契约测试。
- 模块迁移与配置仓储测试。
- 两个固定看板、10 个内置区域和当前 22 个内置字段的初始化测试。
- 自定义区域和字段的创建、修改、排序、停用、恢复、稳定别名和逻辑删除测试。
- 配置读取、保存、并发版本冲突测试。
- SQL 只读校验、必需列、类型、行数、超时、行数上限和错误脱敏测试。
- PostgreSQL 与 MySQL 数据源的查询测试。

### 10.2 前端

- 两个看板页签严格分离。
- 数据区域切换、来源切换、未保存提示和配置状态展示。
- 新增数据区域、追加字段、字段管理，以及内置/自定义标记展示。
- SQL 修改后测试状态失效。
- 测试预览最多 10 行。
- 权限控制、模块生命周期和 CSS 作用域测试。
- 页面遵守亮色主题、固定主题色、统一圆角和无光晕悬浮规范。

### 10.3 验收场景

1. 管理员进入“系统管理 → 看板管理”，默认看到“金融监管报表报送大屏”的 7 个区域。
2. 切换到“金融监管报送流程大屏”，只显示该看板的 3 个区域。
3. “月度信托项目数量”只允许 SQL 模式；一条 SQL 返回四个要求字段并成功预览。
4. 系统数据可用的区域默认选择系统数据，并可切换为 SQL。
5. SQL 缺少必需列、返回多行标量、执行超时或数据源失效时不能保存。
6. 离开页面、停用模块或退出登录后，未完成请求和事件监听被正确清理。
7. 管理员可以在任一固定看板中新增数据区域并为其定义多个字段；新区域只允许自定义 SQL。
8. 管理员可以给已有区域追加字段；若该区域原来使用系统数据，页面要求切换为一条覆盖全部字段的自定义 SQL。
9. 自定义字段显示名可以修改，但稳定别名不可修改；停用字段后原 SQL 测试状态失效。

## 11. 非一期范围

- 对外看板 API。
- Bearer API Key 的生成、轮换、撤销和调用审计。
- 最终 API JSON 的公共元信息。
- 数据缓存、历史快照和定时刷新。
- 看板图表或大屏页面本身。
- 新建第三个看板或修改两个固定看板的稳定编码。
- 每个字段单独配置 SQL，或在同一数据区域内组合多条 SQL。
- SQL 参数模板、可视化 SQL 设计器和跨数据源联合查询。

## 12. 回滚

- 停用 `dashboard_management` 模块即可移除页面和管理 API，配置数据保留。
- 平台导航扩展回滚后，其他模块仍按原方式渲染；看板管理入口不再挂入系统管理。
- 模块迁移不自动删除配置表，避免误删已经维护的 SQL。
