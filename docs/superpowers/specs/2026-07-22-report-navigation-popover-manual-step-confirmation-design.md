# 报送步骤浮窗人工确认设计

## 目标

管理员可直接在报送日程“查看步骤”的全部步骤浮窗中确认允许人工维护的步骤状态；当前仅开放“资管产品模板、逐笔报送”的第 7 步，同时保留以后通过数据库配置开放更多步骤的能力。

## 操作位置与样式

- 操作入口只位于全部步骤浮窗内，不在日程展开详情栏增加按钮。
- 可人工确认且未完成的步骤直接将右侧“未完成”状态文字变为可点击操作，不增加独立按钮。
- 已人工确认的步骤直接将右侧“已完成”状态文字变为可点击撤销操作。
- 自动判断为已完成的步骤只显示“已完成”，不得提供撤销人工确认按钮。
- 不允许人工维护的步骤及普通用户仍只显示原状态文字。
- 可操作状态文字使用主题色、下横线和手型光标，悬浮时颜色加深，键盘聚焦时显示焦点框。
- 浮窗宽度、步骤名称列和现有换行布局保持不变。

## 权限与配置

- 只有管理员可以人工确认或撤销确认。
- 只允许维护当前报送月，其他月份不显示操作按钮。
- 是否允许操作继续由流程表 `allow_manual_step_completion` 与步骤表 `manual_completion_allowed` 两级开关共同决定，不在前后端写死步骤编码。
- 当前数据配置仅将 `pbc_template_7` 的 `manual_completion_allowed` 设为 `1`，其他启用步骤设为 `0`。
- 新增可重复执行的增量 SQL 修正已有应用库；以后需要开放其他步骤时，只修改数据库开关即可，无需改前端或后端代码。

## 数据流

1. 报送导航接口为管理员返回每一步的 `manual_completion_allowed` 和 `manual_completed`。
2. 浮窗根据管理员身份、当前报送月、两级配置以及自动状态决定是否显示确认或撤销按钮。
3. “确认完成”调用已有 `manual-complete` 接口；“撤销确认”调用已有 `manual-cancel` 接口。
4. 成功后重新加载报送导航数据，但不重建日程或浮窗 DOM；在原浮窗内更新步骤状态，并立即原位同步当前日程行的完成比例、展开详情进度和下一步，直到鼠标移出或焦点离开后再完整重绘日程，避免浮窗先关闭再打开；失败时保留现状并显示错误提示。
5. 请求处理中禁用当前状态操作，避免重复提交。

## 后端约束

- 人工操作接口除管理员和当前月份校验外，还必须同时校验流程级与步骤级开关。
- 撤销操作只移除人工覆盖记录，不修改自动判断结果。
- 人工确认完成后沿用现有流程快照重算逻辑。

## 验证

- 后端测试覆盖管理员权限、当前月限制、两级开关和人工确认/撤销。
- 前端静态测试覆盖浮窗可操作状态文字、接口调用、刷新后持续打开浮窗和普通用户只读。
- 数据库脚本测试确认当前仅 `pbc_template_7` 开放人工确认，且增量脚本可重复执行。
