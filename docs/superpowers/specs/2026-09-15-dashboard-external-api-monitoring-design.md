# 看板外部接口监控设计

日期：2026-09-15  
状态：已确认  
适用模块：`dashboard_management`

## 1. 背景

AutoCheck 已为两个固定监管看板提供 Bearer Token 认证的只读接口：

- `GET /api/external/v1/dashboard-management/boards/report_submission/preview`
- `GET /api/external/v1/dashboard-management/boards/reporting_process/preview`

管理员需要在 AutoCheck 内查看接口是否可用、近期调用概况和逐次调用记录。本功能只服务于看板管理模块，不把看板业务字段、统计规则或监控页面写入平台内核。

## 2. 已确认范围

### 2.1 包含

- 在“系统管理 → 看板管理”内增加“接口监控”入口。
- 展示外部接口启用状态、Token 是否已配置、两个固定接口地址、最近调用时间和最近成功时间。
- 展示近 24 小时调用数、成功数、部分成功数、失败数和平均耗时。
- 分页查看认证通过并命中看板预览路由的调用记录。
- 记录并展示调用方 TCP 对端 IP 地址。
- 调用记录滚动保留 30 天，并自动删除更早数据。
- 从接口监控页返回看板管理主界面，并恢复进入前的看板、区域和未保存草稿。
- 新增独立监控能力码，默认只授予管理员。

### 2.2 不包含

- 不记录 Token 缺失或错误产生的 401。
- 不记录未配置外部 Token 时产生的 503。
- 不记录错误请求方法、未命中看板预览路由的路径或其他模块接口。
- 不展示、不持久化、不写入日志任何明文或脱敏 Token、`Authorization` 请求头、查询结果明细和 SQL。
- 不提供手动删除、导出、修改留存期限、实时推送或告警通知。
- 不新增全局一级或二级菜单，不建设跨模块的通用接口审计中心。

## 3. 方案选择

### 3.1 采用：模块内持久化记录

认证由现有平台外部接口入口完成。认证通过且请求命中看板外部预览路由后，看板模块负责计时、生成响应并写入模块自有调用记录表；看板模块再通过内部管理 API 提供状态、统计和分页数据。

该方案让调用记录和看板业务结果保持在 `dashboard_management` 内，改动范围小，也符合本次不记录 401/503 的决定。

### 3.2 未采用：平台统一审计

平台统一审计可以覆盖 401、503 和未来其他模块，但需要定义全局事件协议、共享审计表和更多权限边界。本次明确不需要认证失败记录，因此暂不引入。

### 3.3 未采用：解析应用日志

文件日志不适合作为可分页、可筛选、可统计的数据源；日志轮转和异常退出也会降低记录完整性，因此不采用。

## 4. 模块与平台边界

### 4.1 平台职责

- 继续执行外部接口 Token 配置读取和 Bearer Token 认证。
- 提供只读、可撤销、版本化的 `platform.external_api_status` v1 服务。
- 服务只向已声明依赖的模块返回 `token_configured: bool`，不暴露 Token 内容、长度、摘要或环境变量值。
- 复用同一个外部接口配置读取函数供认证入口和状态服务使用，避免两处判断规则漂移。
- 从 HTTP 连接读取并规范化 TCP 对端 IP，通过通用 `ModuleRequest.client_ip` 请求元数据传给模块。默认不读取 `X-Forwarded-For`、`Forwarded` 等可由客户端伪造的请求头。

### 4.2 看板模块职责

- 在 manifest 中声明 `platform.external_api_status` v1 依赖。
- 维护调用记录表、30 天清理、统计和分页查询。
- 仅在外部预览处理器中记录调用；内部预览不记录。
- 提供内部监控 API 和前端监控子页面。
- 维护看板名称、业务状态和失败区域数等业务含义。

平台内核不解析看板编码，不计算成功/部分成功，不读写看板调用记录表。

## 5. 调用记录模型

新增模块迁移 `003_external_api_call_logs.sql`，schema version 从 2 升至 3，并新增表 `dashboard_management_external_api_calls`：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | BIGINT | 自增主键 |
| `called_at` | DATETIME(6) | UTC 调用开始时间，必填 |
| `board_code` | VARCHAR(64) | 固定看板编码，必填 |
| `http_status` | INT | 最终 HTTP 状态码，必填 |
| `result_status` | VARCHAR(16) | `success`、`partial` 或 `error` |
| `failed_region_count` | INT | 状态为 `error` 的区域数量，默认 0 |
| `duration_ms` | BIGINT | 单调时钟计算的总耗时，向上取整且不小于 0 |
| `request_id` | VARCHAR(64) | 与接口响应 `meta.request_id` 一致，唯一且必填 |
| `caller_ip` | VARCHAR(45) | 规范化后的 IPv4 或 IPv6 TCP 对端地址，必填 |
| `error_code` | VARCHAR(64) | 顶层错误码，可空 |
| `error_message` | VARCHAR(500) | 对外安全错误摘要，可空 |

按 `called_at` 建立索引，并为看板与时间组合建立查询索引。调用方 IP 保存完整地址并与整条记录一起在 30 天后清理；记录中不保存响应数据、地区结果、SQL、数据源信息、Token 或请求头。

### 5.1 状态归类

- HTTP 200 且顶层 `status=success`：`success`。
- HTTP 200 且顶层 `status=partial`：`partial`。
- 认证通过、命中路由，但产生 4xx 或 5xx：`error`。
- `failed_region_count` 为外部响应中 `region.status=error` 的区域数量；顶层错误响应记为 0。

### 5.2 一致性策略

接口主响应优先于审计记录。调用记录写入失败时，外部接口仍返回原业务响应，同时记录服务端错误日志；不能因为监控表异常让监管看板不可用。

每次写入调用记录时，在同一仓储操作中删除 `called_at < 当前时间 - 30 天` 的记录。打开监控页查询时也执行一次相同清理，确保接口长期无人调用后再次查看时不会显示过期数据。清理失败只影响本次监控查询或记录写入，不改变外部接口的业务结果。

## 6. 请求数据流

1. 外部调用进入 `/api/external/v1/...`，平台按现有规则检查 Token。
2. 401 或 503 在平台层结束，不产生调用记录。
3. 认证通过后，平台读取并规范化 TCP 对端 IP，预检并连同通用请求元数据分发到看板外部预览处理器。
4. 处理器生成唯一 `request_id`，记录开始时间，调用 `preview_external_board_data()`。
5. 处理器根据成功、部分成功或异常构造最终响应。
6. 在返回响应前，以 `finally` 等价路径写入一次调用记录，耗时由单调时钟计算。
7. 写入失败仅写服务端日志，仍返回第 5 步的原响应。

同一个外部请求最多写入一条记录；内部 `/api/modules/.../preview` 请求永不写入。

## 7. 内部管理 API

所有监控 API 都要求 `dashboard_management.external_api_monitor` 权限；无权限返回 403。

### 7.1 状态与统计

`GET /api/modules/dashboard-management/external-api/monitor/summary`

返回：

- `enabled`：当前模块运行且 Token 已配置时为 `true`。
- `token_configured`：来自平台只读状态服务。
- `endpoints`：两个固定接口的相对路径和看板名称。
- `last_called_at`、`last_success_at`：没有记录时为 `null`。
- `last_24_hours`：`total`、`success`、`partial`、`failed`、`average_duration_ms`。
- `retention_days`：固定为 30。

### 7.2 调用记录列表

`GET /api/modules/dashboard-management/external-api/monitor/calls`

查询参数：

- `page`：从 1 开始。
- `page_size`：默认 10，最大 100；沿用系统管理列表默认容量，不新增专用设置。
- `board_code`：空值或两个固定看板编码。
- `result_status`：空值、`success`、`partial` 或 `error`。
- `caller_ip`：可选完整 IP 精确匹配；不做模糊匹配。
- `started_at`、`ended_at`：可选 ISO 8601 时间；最大查询范围受 30 天留存自然限制。

返回 `items`、`page`、`page_size`、`total` 和 `total_pages`。排序固定为 `called_at DESC, id DESC`。页码越界时收敛到最后一个有效页；无数据时页码按 1、总页数按 1 返回，便于前端始终展示分页栏。

## 8. 页面设计与返回行为

### 8.1 入口

看板管理主界面标题栏增加空心次要按钮“接口监控”。按钮受 `sys.dashboard_management.external_api_monitor` 能力控制，无权限时不显示。

点击后在同一个模块容器内切换到监控子页面，不打开弹窗、不离开“看板管理”导航项，也不新增浏览器顶层路由。

### 8.2 返回

监控页标题栏左侧提供清晰的“返回看板管理”按钮。点击后恢复进入监控页前的：

- 当前看板页签；
- 当前选中区域；
- 本次模块生命周期内尚未保存的编辑草稿、测试状态和预览结果；
- 看板管理页面原有滚动位置（可安全恢复时）。

进入监控页不会触发放弃修改确认，因为草稿不会被清除。模块停用、离开看板管理导航或浏览器刷新仍按现有生命周期处理，不承诺跨刷新保留未保存草稿。

### 8.3 监控内容与统一排版

- 整个监控页使用一个与现有看板管理、角色权限管理一致的整页外框，内部严格按“标题栏 → 状态区 → 统计条 → 筛选栏 → 表格 → 底部分页”纵向排列，不使用多个漂浮卡片拼接页面。
- 状态区展示启用/未启用、Token 已配置/未配置、30 天留存说明和两个接口地址；字段采用统一标签宽度和左对齐内容，不设计独立英雄区或装饰性插画。
- 统计条展示近 24 小时调用、成功、部分成功、失败、平均耗时；桌面宽度下五项等宽、等高、文字基线一致，以分隔线组织，不使用大小不一的指标卡或夸张字号。
- 列表筛选：看板、结果状态、开始时间、结束时间、查询、清除。
- 表格列：调用时间、调用方 IP、看板、HTTP 状态、业务状态、失败区域数、耗时、`request_id`、错误摘要。
- 调用方 IP 与 `request_id` 使用等宽字体并支持复制；错误摘要为空时显示 `-`。

标题栏高度、内容内边距、筛选控件高度、表头、数据行、状态标签、按钮尺寸与间距均复用“系统管理 / 角色权限”的现有结构和样式，不为监控页另建一套密度。表格各列在同类数据上统一对齐：文本左对齐，HTTP 状态、业务状态、失败区域数和耗时居中，数字使用等宽或表格数字；同一行不得因按钮或标签高度产生错位。

列表主体占满剩余高度，复用 `.result-table`、`.management-list-table`、`.pagination`、`.pagination-info`、`.pagination-controls`、`.page-btn`、`.page-current`、`.pagination-jump`。空数据和单页时分页仍显示，文案分别为“暂无数据”或“共 N 条，第 P / T 页”。

页面仅使用现有亮色活力主题、`--ui-radius`、主题色和语义色；主操作使用 Logo 蓝渐变，返回、筛选和复制等次要操作使用纯色，不增加暗色或主题切换。

禁止使用与现有管理页不同的巨型圆角、彩色投影、光晕、玻璃拟态、悬浮卡片、胶囊式导航、超大指标数字或独立图标语言。响应式变化只调整列数和换行，不改变组件视觉语义和顺序。

## 9. 权限

新增模块权限：

- `dashboard_management.external_api_monitor`

映射平台能力：

- `sys.dashboard_management.external_api_monitor`

能力类型为功能权限，名称为“查看看板外部接口监控”。默认角色矩阵只为管理员启用；其他角色默认关闭，但管理员可在角色权限页授权。

前端入口按能力码显隐，两个内部监控 API 同时在后端校验模块权限，不能只依赖前端隐藏。

## 10. 错误处理

- Token 未配置：状态卡显示“未启用 / Token 未配置”，接口本身仍按既有协议返回 503；该 503 不进入调用记录。
- 调用方 IP 始终取 TCP 对端地址；即使请求携带 `X-Forwarded-For` 或 `Forwarded` 也忽略，避免伪造审计来源。受信任反向代理识别不在本次范围内。
- 状态平台服务不可用：监控 summary 返回安全的 503 模块错误，不猜测 Token 状态。
- 监控列表参数无效：返回 400 和字段级错误信息。
- 调用记录写入失败：外部接口响应不受影响，服务端记录异常。
- 监控查询失败：页面保留筛选条件，显示错误提示和可重试按钮，不伪造空统计。
- 记录中的错误消息只使用已经允许返回给外部调用方的安全摘要，不保存异常堆栈或数据库原始错误。

## 11. 验证范围

### 11.1 后端

- 平台状态服务只返回布尔状态，关闭后拒绝访问，且模块未声明依赖时不可解析。
- Token 配置读取由认证入口和状态服务共享。
- 200 success、200 partial、认证后 404 和处理器 500 各写一条正确记录。
- IPv4、IPv6 对端地址能够规范化、持久化、精确筛选和展示；伪造的转发请求头不会覆盖 TCP 对端 IP。
- 401、503、错误方法、未命中路由和内部预览不写记录。
- 写记录失败不改变外部响应。
- 30 天边界清理、统计、平均耗时、筛选、稳定排序、分页和越界收敛正确。
- 监控 API 权限分别覆盖管理员、已授权普通角色和未授权角色。

### 11.2 前端

- 无能力时入口不可见，有能力时可进入监控页。
- 返回按钮恢复看板、区域和未保存草稿。
- 状态、统计、筛选、清除、加载、错误、空数据和复制反馈正确。
- 筛选变化与清除后回到第一页，上一页、下一页、跳页和越界收敛正确。
- 满高布局、公共分页类名、单页/空数据分页常显和统一文案符合管理列表规范。

### 11.3 回归与运行验证

- 运行看板模块、模块系统和服务端外部接口相关测试。
- 运行完整 `python -m pytest -q`。
- 运行 `git diff --check` 并处理实际 whitespace error。
- 重启 AutoCheck 开发环境，验证 8765 端口、401、503、两个接口成功/部分成功、监控记录新增、summary 更新和返回看板管理状态恢复。
- 不打包 `dist/auto-check.exe`，除非用户另行明确要求。
