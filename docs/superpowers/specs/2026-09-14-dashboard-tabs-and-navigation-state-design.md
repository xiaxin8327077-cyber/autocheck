# 看板切换栏与菜单状态修复设计

## 目标

修复看板管理页面刷新及预览菜单状态问题，并将两个看板的切换入口调整为参考图中的独立按钮样式。

## 平台导航修复

模块页面刷新后，“系统管理”保持当前分组高亮，但不得自动添加 `open` 状态，`aria-expanded` 保持 `false`。用户主动点击或悬浮时仍按现有规则展开。该改动属于模块宿主的通用导航状态修复，对所有合并到平台分组的模块入口一致生效。

## 看板切换与预览

- 左侧两个看板名称组成一个紧凑、完整的 Tabs / Segmented Control，不零散占用大面积白色区域；每个 Tab 的整个区域均可点击。
- 当前看板使用浅蓝背景、主题蓝加粗文字、轻微圆角和 3px 底部选中线；非当前看板使用透明或白色背景与深灰文字，悬浮时显示轻微浅灰蓝背景。
- 右侧仅显示一个“预览当前看板”按钮，包含眼睛图标、文字和下拉箭头。
- 悬浮或键盘聚焦预览按钮时显示“接口数据 / 看板页面”。
- 关闭预览弹窗后，焦点回到当前看板切换按钮，不回到预览按钮，因此下拉菜单立即收回。
- 预览弹窗原有关闭按钮、Esc 关闭和点击遮罩不关闭行为保持不变。

## 布局

切换栏使用左右分布的 flex 布局，总高度为 46px；切换按钮组紧凑排列。预览文字和箭头使用 `inline-flex` 垂直居中，箭头与文字间距固定为 4px。

## 当月报表报送时间对比口径

该系统数据区域继续读取报送导航流程、完成快照和月度计划，但生成 SQL 在已启用流程基础上增加 `process.process_name <> '人行大集中'` 条件。“人行大集中”不进入接口结果、配置页预览和看板页面，其余流程保持原排序与口径。

- 看板前端静态测试确认单一预览按钮、图标结构、焦点回退目标及对齐样式。
- 系统数据目录测试确认“当月报表报送时间对比”明确排除“人行大集中”。
