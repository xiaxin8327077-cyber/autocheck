# 角色轻量可配权限与报表特殊处理流程设计

日期：2026-08-07  
状态：已确认（2026-08-07）  
范围：系统角色/权限框架 + 导航「系统管理」重组 + 报表特殊处理状态流转

## 1. 目标

1. 预留多角色身份，默认权限可配置、可扩展，避免业务代码写死 `role === "xxx"`（管理员行除外锁定）。
2. 报表特殊处理状态收敛为：草稿 / 待确认 / 已确认 / 已作废，并明确提交确认、治理确认、作废、重开、删除。
3. 顶栏将「系统设置」升级为「系统管理」分组，下挂系统设置、角色权限、用户管理。

## 2. 非目标

- 不支持管理员自定义新增/删除角色码（首期角色固定预留）。
- 不做完整企业级 RBAC（自定义权限树、数据范围、字段级权限）。
- 不在本期把系统设置页内各卡片拆成细能力码（继续沿用现网「页内管理员专属区块」区分）。
- 不在本期改其它业务模块的细权限（除进入「标准用户」默认档、以及下文显式纳入的「对数历史删除」外，行为与现网普通用户一致）。

## 2.1 现网约束（必须兼容）

1. **系统设置页已有管理员 / 普通用户内容区分**  
   - 普通用户可进入「系统设置」，可见如系统信息、界面设置等个人向内容。  
   - 默认设置、数据源、业务字段、流程链、人行校验相关等卡片为 `admin-only`，普通用户不可见/不可改。  
   - 本期导航改名后，**不得**把整个「系统设置」收成仅管理员入口；页内现有区分继续保留。

2. **对数历史记录删除目前仅管理员可删**  
   - 前端：`canManageHistory()` 仅 `role === "admin"` 显示删除按钮。  
   - 后端：`DELETE /api/history` 非管理员返回 403。  
   - 本期纳入能力码 `history.delete`，默认仅管理员；行为与现网一致，便于日后可配。

## 3. 角色（身份层）

| 角色码 | 显示名 | 说明 |
|---|---|---|
| `admin` | 管理员 | 系统最高权限；权限矩阵中该列锁定不可改 |
| `governance` | 数据治理 | 报表特殊处理可「确认」；其余默认同标准用户 |
| `user` | 普通用户 | 兼容现网账号 |
| `regulatory_report` | 监管报表 | 预留；默认同标准用户 |
| `data_middle` | 数据中台 | 预留；默认同标准用户 |
| `fund_custody` | 资金托管部 | 预留；默认同标准用户 |

兼容：已有 `role=user` 账号继续有效；登录与用户管理可选择上述角色。

## 3.1 RSP 人员术语（统一口径）

**谁创建谁处理**：不再单独维护「处理人」。

| 术语 | 字段 | 含义 |
|---|---|---|
| **创建人** | `creator_user_id` | 新建该条记录的用户；同时即处理责任人。标准用户对编辑 / 作废 / 重开均以创建人为唯一主体 |
| **管理员** | 具备管理员身份（`admin`）或等效最高权限 | 不受创建人范围限制 |

废弃约定：

- 界面去掉「处理人」选择框、筛选、列表列与导出列。
- 权限判断**不再**使用 `handler_user_id`。
- 存量库字段 `handler_*` 可保留但不再展示、不再参与鉴权；新建/更新时若仍写库，一律回填为创建人（兼容旧表结构），或随模块迁移停写。
- 文档与文案**不再使用**「发起人」「处理人」。

## 4. 能力（权限点，可扩展）

业务代码统一通过 `has_capability(user, code)` 判断。

### 4.1 首期能力码

系统：

- `sys.settings`：进入系统设置页（**默认全角色开放**；页内管理员专属卡片仍按现网 `admin-only` / 管理员能力控制，首期不拆卡片级能力码）
- `sys.settings.admin`：系统设置页内管理员专属配置（默认设置、数据源、业务字段、流程链等；对齐现网 admin-only 区块）
- `sys.users`：用户管理
- `sys.role_permissions`：角色权限配置页

核对历史：

- `history.delete`：删除对数历史记录（对齐现网仅管理员可删）

报表特殊处理（RSP）：

- `rsp.view`：查看台账/详情
- `rsp.create`：新建/保存草稿/提交确认
- `rsp.edit`：编辑未终态记录（另受「仅创建人 / 管理员」范围约束，见第 6 节）
- `rsp.confirm`：待确认 → 已确认
- `rsp.void`：作废（另受「仅创建人」范围约束，见第 6 节）
- `rsp.reopen`：重开为待确认（另受「仅创建人」范围约束，见第 6 节）
- `rsp.delete`：物理删除

### 4.2 扩展方式

新功能上线时：

1. 在能力注册表增加新 `code` + 中文名 + 默认矩阵；
2. 启动或迁移时合并进已保存配置（只补缺失项，不覆盖管理员已改项）；
3. 业务侧调用 `has_capability`，不再写死角色。

## 5. 默认矩阵（可被管理员修改，admin 列锁定）

「标准档」= `user` / `regulatory_report` / `data_middle` / `fund_custody`。

| 能力 | admin | governance | 标准档 |
|---|---|---|---|
| `sys.settings` | ✓ 锁 | ✓ | ✓ |
| `sys.settings.admin` | ✓ 锁 | ✗ | ✗ |
| `sys.users` | ✓ 锁 | ✗ | ✗ |
| `sys.role_permissions` | ✓ 锁 | ✗ | ✗ |
| `history.delete` | ✓ 锁 | ✗ | ✗ |
| `rsp.view` | ✓ 锁 | ✓ | ✓ |
| `rsp.create` | ✓ 锁 | ✗ | ✓ |
| `rsp.edit` | ✓ 锁 | ✗ | ✓ |
| `rsp.confirm` | ✓ 锁 | ✓ | ✗ |
| `rsp.void` | ✓ 锁 | ✗ | ✓ |
| `rsp.reopen` | ✓ 锁 | ✗ | ✓ |
| `rsp.delete` | ✓ 锁 | ✗ | ✗ |

规则：

- 管理员不可修改「管理员」列的任何勾选（UI 禁用 + 后端拒绝）。
- 其它角色列可改；保存到应用库。
- 无配置记录时使用上表默认值。

## 6. 业务附加规则（配置矩阵之外）

即使矩阵勾选了能力，仍受业务规则约束：

| 规则 | 说明 |
|---|---|
| 编辑 | 未终态（草稿/待确认）才可编辑；标准用户仅**创建人**；管理员不受此限 |
| 作废 | 需具备 `rsp.void`；标准用户仅**创建人**可作废；管理员不限 |
| 重开 | 需具备 `rsp.reopen`；标准用户仅**创建人**可对已确认/已作废重开为待确认；管理员不限 |
| 确认 | 需具备 `rsp.confirm`；仅「待确认」可确认 |
| 删除 | 需具备 `rsp.delete`；任意状态；二次确认；物理删除 |

数据治理用户：矩阵默认仅 `rsp.view` + `rsp.confirm`（及系统侧无管理项），不能作废/重开/删除/新建。

## 7. 报表特殊处理状态机

### 7.1 状态

| 状态码（建议） | 显示名 | 对应旧状态 |
|---|---|---|
| `draft` | 草稿 | draft |
| `pending_confirm` | 待确认 | 替代 pending / processing |
| `confirmed` | 已确认 | 替代 completed |
| `voided` | 已作废 | voided |

迁移：库内 `pending`/`processing` → `pending_confirm`；`completed` → `confirmed`。统计与导航卡片口径同步改名/改过滤。

### 7.2 流转

```text
草稿 --提交确认--> 待确认 --确认--> 已确认
 |                   |
 +--------作废-------+--------作废--------> 已作废

已确认 --重开--> 待确认
已作废 --重开--> 待确认

任意状态 --删除-->（物理删除，需 rsp.delete）
```

操作入口：

- 草稿：保存草稿；提交确认（必填项校验同现「保存记录」）；具备 `rsp.delete` 时可删除
- 待确认：确认；作废（权限见上）；可编辑（权限见上）；具备 `rsp.delete` 时可删除
- 已确认 / 已作废：重开；具备 `rsp.delete` 时可删除
- **删除口径（与第 6 节、上方状态机一致）**：草稿 / 待确认 / 已确认 / 已作废 **均可删**；不限终态；二次确认后物理删除；默认仅管理员具备 `rsp.delete`
- 列表不再使用「处理中」「完成」文案

## 8. 导航改版

```text
系统管理（原一级「系统设置」改名，悬浮二级）
  ├─ 系统设置     ← 现有系统设置页内容，顺序第 1（普通用户可见入口）
  ├─ 角色权限     ← 新建配置页，顺序第 2（默认仅管理员）
  └─ 用户管理     ← 现有用户管理页挪入，顺序第 3（默认仅管理员）
```

- 二级菜单按能力显隐：`sys.settings` / `sys.role_permissions` / `sys.users`。
- 「系统设置」页进入后，**继续保留现网管理员与普通用户内容区分**（页内 `admin-only` / `sys.settings.admin`）；不得因导航改版改变普通用户可见卡片范围。
- 「角色权限」页：角色×能力矩阵；管理员列只读；保存写应用库。
- 无任一「系统管理」子项权限时，不显示该一级分组（极端情况；默认标准用户至少有「系统设置」）。

## 9. 存储建议

- 应用库新增配置表（或等价键值）：如 `role_capability_settings`（`role_code`, `capability_code`, `allowed`, `updated_at`, `updated_by`），或以 JSON 整表存储一版矩阵快照。
- 推荐：**矩阵快照 JSON**（简单）+ 版本号；启动时与代码内默认矩阵做「缺省能力合并」。
- 模块迁移与全局 `app_schema` 按现有规范处理（全局应用库用 `sql/app_storage` 增量脚本）。

## 10. 实现分期（边界明确）

### 一期：平台能力框架（**不改 RSP 业务行为**）

交付：

- 角色预留（用户管理可选新角色码）
- 能力注册表 + 默认矩阵 + 应用库持久化 + `has_capability`
- 「系统管理」导航重组 +「角色权限」配置页 + admin 列锁定
- **非 RSP** 现网权限迁到能力码（行为不变）：
  - `sys.settings` / `sys.settings.admin` / `sys.users` / `sys.role_permissions`
  - `history.delete`（对数历史删除）

明确不做：

- **不改** RSP 状态码、状态机、按钮文案与可见性
- **不改** RSP 模块内现有 `is_admin` / 创建人 / 处理人等业务鉴权
- 一期矩阵里虽可展示 `rsp.*` 能力码（便于管理员提前配置），但 **RSP 运行时暂不读取**；改矩阵不影响 RSP，直到二期接通

### 二期：RSP 流程与权限落地（一次性接通）

交付：

1. **接通** `has_capability`：RSP 全部按钮与 API 改为读 `rsp.*`（含一期已配矩阵）
2. **状态迁移**：`pending`/`processing` → `pending_confirm`；`completed` → `confirmed`；文案改为草稿 / 待确认 / 已确认 / 已作废
3. **新流程按钮**：提交确认、确认、作废、重开、删除等按第 6～7 节
4. **去掉处理人**：界面 / 筛选 / 鉴权只认创建人

二期「按钮与权限按新流程改造」= 上列 1～4 的合体，不是与「接通 has_capability」重复的另一件事。

### 为何这样切

| 若一期就改 RSP | 问题 |
|---|---|
| 只换 `has_capability`、状态仍旧 | 矩阵改了，按钮仍是旧流程语义，验收口径混乱 |
| 连状态一起改 | 一期范围膨胀，与「先搭框架」目标冲突 |

因此：**一期验证框架用系统导航 + 对数历史删除即可；RSP 等二期整包切换。**

## 11. 测试要点

### 一期

- 角色权限页可改非 admin 列并持久化；改 admin 列前后端拒绝。
- 新能力注册后旧配置自动补默认勾选。
- 导航：系统管理下三项顺序正确；普通用户可见「系统设置」，不可见「角色权限」「用户管理」。
- 系统设置页：普通用户仍只能看到现网开放卡片；管理员专属卡片不可见。
- 对数历史：非管理员无删除按钮且 `DELETE /api/history` 返回 403；管理员可删。
- **回归**：RSP 台账/按钮/状态与改前一致（一期未接通）。

### 二期

- 默认矩阵下：标准用户/治理/管理员在 RSP 的按钮可见性与 API 403 一致。
- 历史 `pending`/`completed` 迁移后列表与筛选正确；处理人 UI/筛选已移除，鉴权仅认创建人。
- 改 `rsp.*` 矩阵后 RSP 立即生效（与一期「改了也不影响」形成对照）。

## 12. 已确认决策摘要

- 轻量可配：固定角色 + 可扩展能力矩阵。
- 管理员列不可改。
- 入口：系统设置升级为系统管理；二级为系统设置、角色权限、用户管理。
- 系统设置页保留现网管理员/普通用户内容区分；不得整页收成仅管理员。
- 对数历史删除纳入 `history.delete`，默认仅管理员（与现网一致）。
- **分期**：一期只搭平台框架（RSP 不接通）；二期 RSP 一次性接通 `has_capability` + 状态迁移 + 新流程按钮 + 去掉处理人。
- RSP：草稿→待确认→已确认；治理确认；**谁创建谁处理**——仅创建人可编辑/作废/重开；去掉独立处理人；管理员全权限；治理默认仅查看+确认。
- 人员术语只保留「创建人」；不再使用「发起人」「处理人」。
- 预留部门角色默认等同普通用户，身份分开存便于日后拆权。
