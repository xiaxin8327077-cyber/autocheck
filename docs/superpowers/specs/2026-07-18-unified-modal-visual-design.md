# 系统弹窗统一视觉设计

## 1. 背景

监管智核当前存在两套主要弹窗结构：通用 `.modal` 弹窗，以及人行导入、逐笔校验、流程工具使用的 `.pbc-modal` 弹窗。两套结构在遮罩、标题栏、图标、内容留白、底部操作区、阴影和暗色模式表现上差异较大，用户管理弹窗又叠加了一套独立装饰，导致系统内弹窗缺少统一视觉语言。

本次以 `C:\Users\jh832\WorkBuddy\2026-06-03-23-21-40\history-detail-A-balanced.html` 的“平衡版”历史详情为视觉参考，吸收其克制的纯色表面、细分隔线、轻阴影、轻量标题栏、独立滚动内容区和固定操作区风格。参考稿只决定视觉语言，不强制决定各弹窗尺寸、业务结构或表格对齐方式。

本设计直接基于 worktree `D:\trae\autocheck\.worktrees\user-interface-radius-preferences` 和分支 `codex/user-interface-radius-preferences`。该分支已经完成用户界面圆角设置及全局 `--ui-radius` 覆盖，本次不重复实现圆角存储、接口或设置控件。

## 2. 已确认需求

- 所有系统弹窗统一为参考稿的轻量、平衡视觉风格，整体外观需要有明显变化。
- 弹窗及其矩形控件的圆角继续跟随现有界面设置，通过 `--ui-radius` 实时生效。
- 弹窗尺寸不要求与参考稿一致；确认框、历史详情、用户编辑、人行导入和流程编辑器等继续保留适合自身内容的现有尺寸。
- 历史详情的内容层级参照参考稿重排，但表头和单元格继续使用系统当前的居中对齐方式，不采用参考稿的左对齐和金额右对齐。
- 不改变任何业务功能、数据结构、权限判断、接口参数或操作流程。
- 人行全量产品一键导入继续保持“上传文件、字段映射、开始导入、完成”四步流程。
- 默认太空主题、沉稳主题和暗色模式都必须具有一致且清晰的弹窗风格。

## 3. 目标与非目标

### 3.1 目标

- 建立一套通用弹窗外壳视觉规范，覆盖遮罩、容器、标题栏、关闭按钮、内容区、底部操作区和按钮层级。
- 在不重构业务事件的前提下，让 `.modal` 与 `.pbc-modal` 两套现有结构呈现同一视觉语言。
- 将对数历史详情调整为参考稿的轻量信息结构和分组表格风格。
- 保留不同弹窗为业务可读性设置的宽度、高度、内部网格和滚动策略。
- 继续服从用户圆角设置，同时保留状态胶囊、圆形进度、开关等组件的语义形态。

### 3.2 非目标

- 不把所有弹窗重写为新的 JavaScript 组件或统一创建函数。
- 不调整弹窗打开、关闭、遮罩点击、键盘焦点、加载、提交或错误处理逻辑。
- 不改变历史数据、历史比较口径、差异类型、匹配状态或“恢复到结果页”的行为。
- 不调整人行导入字段映射、逐笔校验、流程链定义或后台执行逻辑。
- 不因视觉统一强制缩小大型表格或复杂表单弹窗。
- 不在本次修改中调整应用版本号。

## 4. 覆盖范围

统一视觉层覆盖以下现有弹窗：

1. 确认弹窗 `confirmModal`。
2. 输入弹窗 `promptModal`。
3. 通用信息弹窗 `infoModal`，包括更新日志、帮助、首页统计详情、对账结构错误和对数历史详情。
4. 报送导航卡片维护弹窗 `reportNavCardMaintenanceModal`。
5. 用户新建/编辑弹窗 `userModal`。
6. 数据源新建/编辑弹窗 `configModal`。
7. 人行全量产品导入弹窗 `pbcModalOverlay`。
8. 人行逐笔校验执行与历史弹窗。
9. 流程执行、流程历史和流程链编辑弹窗。

下拉面板、日期选择器、提示气泡、悬浮执行提示和普通 Toast 不属于弹窗外壳，不纳入本次统一范围；它们继续由现有界面圆角设置和各自组件规则控制。

## 5. 统一弹窗视觉规范

### 5.1 遮罩与容器

- 通用与工具弹窗使用一致的主题化半透明遮罩。浅色模式保持柔和，不把背景压成纯黑；暗色模式适当增加遮罩不透明度以保证聚焦。
- 弹窗容器使用纯色主题表面、细边框和克制阴影，取消弹窗外壳上的玻璃感、强渐变和大范围发光。
- 容器 `border-radius` 使用 `var(--ui-radius)`，不得重新写死 12px、14px 或 16px。
- 保留现有层级和动画入口，动画只做轻量淡入与位移/缩放，不改变关闭时序。

### 5.2 标题栏

- 标题栏统一采用清晰的水平布局、细底部分隔线和稳定内边距。
- 主标题使用约 16px 中等字重，避免现有部分弹窗过粗或过强的标题层级。
- 工具弹窗需要说明文字时，允许在标题下保留一行弱化副标题；副标题不改变标题栏整体高度策略。
- 用户、人行和流程弹窗标题旁现有的大色块图标移除，不再以图标卡片区分弹窗家族。
- 关闭按钮统一为弱化的 `×` 控件，默认低对比度，悬浮时使用轻背景反馈；按钮矩形圆角读取 `--ui-radius`。

### 5.3 内容区

- 内容区使用一致的水平留白和垂直节奏，复杂弹窗可根据现有布局保留更紧凑的内部间距。
- 弹窗内容在自身区域滚动，标题栏与底部操作区保持可见。
- 表格、表单、步骤条、进度、错误详情等业务内容继续使用各自组件结构，不用统一外壳规则覆盖其必要宽度和滚动行为。
- 空状态、加载状态和错误状态继续使用现有语义与事件，只调整视觉层级以适配新外壳。

### 5.4 底部操作区与按钮

- 底部操作区统一使用细顶部分隔线、纯色主题表面和右对齐操作组；存在状态文本时，状态文本占用左侧剩余空间。
- 主操作按钮使用纯色主题强调色，不使用强渐变或大阴影；次操作按钮使用中性描边或弱背景。
- 保留危险操作的错误色语义、禁用状态、加载状态和原按钮文案。
- 矩形按钮读取 `--ui-radius`；状态胶囊、开关、进度圆环等继续保留完整胶囊或圆形。

## 6. 对数历史详情专项设计

### 6.1 弹窗尺寸与滚动

- 保留当前历史详情的宽屏尺寸策略：`min(1240px, 94vw)` 与现有最大高度约束，不复制参考稿的 920px 宽度。
- 标题栏与底部操作区固定，详情主体独立滚动。
- 五列表格继续保留最低可读宽度与横向滚动兜底，不能因视觉精简压缩项目名称或状态列。

### 6.2 信息结构

- 顶部摘要由现有边框卡片网格改为轻量元数据行，展示报告期、执行人、执行时间和基准记录。
- 标签使用弱化文字，值使用较高对比度；空间不足时允许自然换行，不截断基准记录。
- 移除现有“新增、减少、完整结果”三张统计卡，数量直接放入对应分组标题。
- 结果分组顺序调整为：本次完整核对结果、本次新增差异、本次减少差异。
- 继续沿用现有规则：没有数据的差异分组可以不渲染；完整结果按历史数据正常展示。

### 6.3 分组与表格

- 三个分组分别使用绿色、红色、蓝色 3px 色条标识，标题文字保持中性，数量使用弱化颜色。
- 分组取消厚重外框和大面积标题背景，表头使用轻背景，行之间使用细分隔线。
- 表格继续展示项目编号、项目名称、差异金额、差异类型和状态，不增删业务字段。
- 表头和全部单元格保持系统当前的 `text-align: center`；金额继续居中，不使用参考稿的右对齐。
- 状态改为中性胶囊：已解释使用弱填充，未解释使用中性描边；状态语义和文本不变。
- 底部继续显示“恢复到结果页”，保留现有权限、事件绑定和页面跳转行为。

## 7. 实现边界

### 7.1 结构策略

- 采用“统一外壳类 + 保留旧类”的渐进方式。现有 ID 和业务类继续存在，避免改动 JavaScript 查询、事件绑定和测试依赖。
- 为通用与工具弹窗补充共享语义类，或使用明确的选择器分组统一遮罩、容器、标题栏、内容区和底部操作区。
- 不使用宽泛的 `[class*=modal]` 选择器，以免影响状态面板、下拉层或非弹窗组件。
- 专用弹窗尺寸规则放在共享外壳之后，只覆盖宽高、网格或滚动等业务所需属性，不重新定义一套视觉皮肤。

### 7.2 历史详情渲染

- 只调整 `renderHistoryDetailContent()`、摘要/数量/分组辅助渲染和必要状态标记。
- 历史详情 API、历史加载过程、错误处理、`selectedHistory` 状态和恢复按钮事件保持不变。
- 表格行仍使用已有数据字段，不新增派生业务判断。

### 7.3 主题与圆角

- 默认太空主题和沉稳主题共用结构规范，各自通过现有主题变量呈现表面色、文字色、边框色和强调色。
- 暗色模式提供明确的遮罩、表面、表头、分隔线和状态胶囊对比度规则。
- 弹窗新规则必须位于圆角覆盖体系可控范围内；任何新增矩形弹窗元素都必须纳入 `--ui-radius` 选择器清单。
- 不覆盖 `999px` 状态胶囊、圆形进度、头像、开关轨道和滑块手柄。

## 8. 交互与可访问性

- 所有关闭按钮保留可点击区域和现有 ID；视觉弱化不能缩小点击区域。
- 保留各弹窗当前的遮罩点击策略。禁止遮罩关闭的用户编辑、流程编辑和历史详情不得因样式统一恢复遮罩关闭。
- 保留确认/输入弹窗的高层级，避免被业务弹窗遮挡。
- 保留输入弹窗焦点、日期控件、回车确认和取消行为。
- 滚动条只属于内容区，底部操作按钮不得随长内容滚出视口。
- 在 `prefers-reduced-motion` 或系统关闭视觉效果时继续使用现有降级策略。
