# 报表特殊处理操作记录差异展示设计

## 目标

优化“报表特殊处理录入”详情弹窗中的操作记录，使用户能先识别本次操作类型，再清楚比对修改前后值。设计必须同时支持一次变更多个字段和单个值很长的审计记录。

选定交互为“摘要行＋行内展开详情”：审计表默认保持紧凑，点击“查看变更详情”后在当前审计项下方展开完整的字段对照表。

## 范围与边界

- 仅调整 `report_special_processing` 内置模块的操作记录前端呈现、模块文档、模块版本说明和测试。
- 不修改审计表结构、迁移、权限、审计写入逻辑或历史记录内容。
- 不修改公共 `server.py`、`app.js`、`index.html` 或全局样式；模块清单的发布说明由现有宿主自动并入系统更新日志。
- 当前工作区存在公共文件未提交改动，本次不得覆盖或混入这些改动。

## 数据与兼容性

现有审计接口已在每条记录中返回 `action_code`、`action_summary`、`from_status`、`to_status` 与完整 `changed_fields`。`changed_fields` 保留未经截断的旧值和新值，前端直接使用它构建详情，无需新增接口字段或数据库迁移。

前端依据固定字段映射显示中文字段名；对状态、作废理由、重开原因和确认说明按 `action_code` 补充展示名称。无法取得成对改前/改后值的旧审计项、创建项或异常数据仍显示原 `action_summary`，但改为可换行的完整文本，不丢失历史信息。

## 交互与视觉

### 摘要行

- 每条记录显示明确的操作类型文本，避免只用颜色表达语义。
- `update`（修改/更新记录）使用主题蓝文字或浅蓝描边标签，并显示变更项数量。
- `reopen`（重开记录）使用警告色文字或浅橙标签，并显示状态流向；有重开原因时以“重开原因：内容”作为紧随其后的未编号补充说明。
- `void`（作废记录）使用危险红文字或浅红标签，并显示状态流向；有作废理由时以“作废理由：内容”作为紧随其后的未编号补充说明。
- `status_change` 完成操作使用成功绿；创建和保存草稿保持中性样式。
- 有成对改前/改后值时，摘要行优先展示短状态流或“共 N 项变更”，并提供“查看变更详情／收起详情”文字按钮。按钮使用纯主题色，不使用渐变。

### 展开详情

- 展开内容位于摘要行之后的独立表格行，跨越操作时间、操作人、操作内容三列；时间和操作人无需被超长内容撑高。
- 详情表固定为“字段、修改前、修改后”三列。旧值为中性浅底，新值为克制浅蓝底，中央以箭头标示方向。
- 多字段按顺序逐项展示；值保留换行并允许任意长连续字符折行。不得使用省略号截断或固定高度裁剪；字段列固定为较窄宽度，“修改前”“修改后”始终均分剩余空间，不使用横向滚动条。
- 详情随弹窗主体纵向滚动；展开和收起不重新请求接口，不影响翻页和其他审计项。
- 非成对信息（如重开原因、作废理由、确认说明）在详情中以单列、未编号的补充说明项显示，值同样完整换行；它们不计入“共 N 项变更”，也不显示为第 2 项或其他编号变更。

## 前端结构

`record_drawer.js` 新增小型审计展示转换和渲染职责：

1. 将审计项转换为操作类型、语义色类、成对差异项和单值说明项。
2. 使用每页审计项 ID 维护展开集合；点击后只重新渲染当前审计表体。
3. 有差异详情时渲染紧凑摘要行与可切换的详情行；无详情时渲染兼容的多行摘要。
4. 所有内容继续通过现有 DOM helper 的 `text` 写入，禁止拼接不受控 HTML。

`styles.css` 仅在模块根选择器下新增操作类型、摘要行、展开详情和长文本折行样式；沿用 `--ui-radius`、固定亮色主题与语义色，不添加主题光晕或独立色板。

## 验收标准

1. 用户在不展开详情时能识别“修改、重开、作废、完成、创建”中的任一操作及其语义。
2. 修改记录可展开查看全部字段的完整旧值和新值，字段列较窄，修改前、修改后始终等宽；长文本完整换行展示，不出现横向滚动条。
3. 重开、作废和完成记录分别有可读的操作类型与状态流向；理由完整显示为未编号补充说明，不会单独排成第 2 项变更。
4. 旧审计记录、无结构化差异项和加载失败不会导致弹窗崩溃；原摘要仍可阅读。
5. 改动严格限于该模块、模块测试和必要文档，且不影响权限、写入、迁移和历史审计内容。
