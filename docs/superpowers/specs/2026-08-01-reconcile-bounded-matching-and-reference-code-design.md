# 自动对数有界组合匹配与业务代码解析设计

## 背景

生产环境的资产差异候选池可达到 50～100 行以上，但实际命中组合通常为 2～5 行，绝大多数不超过 10 行。现有动态规划会为大量中间金额保留多条路径，候选组达到约 50 行时可能长时间占用 CPU。与此同时，FA 科目代码的业务代码可能包含点号，例如 `1501.03.03.01.JS0508-2.51`，现有“最后一个点后取值”会错误得到 `51`。

## 目标

1. 在每项目 60 秒硬上限内优先找到 2～5 行精确组合，常用深层搜索到 10 行，并兼顾偶发 20～30 行大组合。
2. 候选池较大时不再因为中间状态路径复制而表现为卡死。
3. 保持单行、同科目汇总、较少行数组合优先的现有业务顺序，并稳定报告候选不唯一。
4. 从科目代码中提取完整业务代码，保留业务代码内部的点号。
5. 债券 DM 双边核对只纳入债券分类非空白的证券记录。
6. 诊断日志可定位耗时，但不挤掉任务面板最早的关键日志。

## 匹配设计

### 快速层

- 单行：按仓储层候选顺序扫描，命中后沿用现有逻辑返回。
- 同科目汇总：按科目代码汇总，命中后沿用现有逻辑返回。
- 2 行：补数哈希。
- 3 行：单行加两数和。
- 4 行：两数和加两数和，并校验索引不重叠。
- 5 行：两数和加三数和，并校验索引不重叠。

以上快速层允许候选池超过“组合候选阈值”，因为 100 行规模的两数、三数索引仍可控。只保存真正命中目标的组合，最多保留调用方要求的候选组数。

### 深层与大组合搜索

- 仅在 2～5 行没有命中后搜索 6～10 行常用组合。
- 20～30 行优先检查整组总额，并用 `候选总额-目标金额` 反向搜索较少的排除项；其他大组合只做受状态数和截止时间限制的尽力搜索。
- 候选行数超过系统阈值时，不进行全池深层搜索，沿用按前四段自然分组兜底。
- 候选行数未超过阈值时，使用有界深度搜索、剩余金额上下界剪枝和失败状态记忆。
- 主匹配、负数绝对值重试与自然分组共享同一个项目截止时间，默认 60 秒。
- 超时返回明确的 `combination_timeout`，不得继续无限计算，也不得中断其他项目。

### 顺序与候选兼容性

- 组合内部使用原始稳定索引排序，并保留仓储层候选顺序，避免改变具体原因编号和详情表资产顺序。
- 保持现有实际末级过滤和资产分类规则不变。

## 业务代码解析

新增 `ValuationRow.account_business_code`，保留现有 `account_tail_code` 作为字面意义上的最后一段。

解析规则：

1. 第一段是四位一级科目。
2. 后续最多三个“恰好两位数字”的段视为科目层级。
3. 从第一个非两位数字段开始，余下内容全部属于业务代码并用点号重新连接。
4. 没有可识别业务后缀时回退到现有最后一段。

示例：

| 科目代码 | 业务代码 |
| --- | --- |
| `1501.03.03.01.JS0508-2.51` | `JS0508-2.51` |
| `1101.02.15.01.244733` | `244733` |
| `1303.01.01.DK20260531001` | `DK20260531001` |
| `1541.01.CC8250MX` | `CC8250MX` |

AM 标的代码、证券代码、合同代码匹配和对应详情展示改用业务代码；纯粹展示字面科目尾段的非业务场景可以继续使用旧属性。

## 债券过滤

债券双边核对的 DM 侧查询仅用于构造“DM 有、FA 债券本金没有”的补零差异。FA 侧已经通过债券本金科目代码过滤，DM 侧必须使用债券分类字段过滤，避免基金、信托计划被当作债券。

采用跨 PostgreSQL/MySQL 的空白判断：

```sql
TRIM(COALESCE(sbm_seclas_h2024, '')) <> ''
```

该条件同时排除 `NULL`、空字符串和纯空格，但不影响同表记录继续用于股票、基金和 SPV 的其他核查。

## 日志

- 保留候选数、阈值、总耗时、分组汇总和查询耗时。
- AM 候选组只记录前 5 组、每 20 组一次以及最后一组。
- 超时日志明确记录已搜索到的最大组合行数和耗时。
- 不修改任务日志 200 条的全局上限。
