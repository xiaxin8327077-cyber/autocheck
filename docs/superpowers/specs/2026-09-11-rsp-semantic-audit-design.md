# 报表特殊处理操作记录语义化展示设计

## 目标

操作记录以审计可读性为第一目标，只突出真正发生变化的业务配置；基本信息与特殊处理内容分组，特殊处理内容按处理表隔离，自动生成脚本作为次级证据按需查看。

## 信息架构

一条操作记录由“操作时间与操作人”“变更规模摘要”“基本信息”“特殊处理内容”组成。基本信息采用“变更项 / 修改前 / 修改后”结构。特殊处理内容下每张处理表为独立卡片，并按“表信息、处理范围、修改字段、脚本”固定顺序展示。

## 语义变化

- 已有对象修改：只展示发生变化的属性。
- 新增处理表、条件或修改字段：使用新增语义，展示当前配置，不机械展示空的修改前。
- 删除处理表、条件或修改字段：使用删除语义，默认展示对象身份与规模，删除前完整配置按需展开。
- 处理表条目本身切换数据源或物理表时，稳定条目标识不变，归入表信息变更；明确删除后重新添加时归入删除加新增。
- 条件、修改字段和处理表均保存内部稳定条目标识。历史数据没有标识时采用物理对象与唯一位置的保守匹配，存在歧义时按删除加新增展示。

## 计数规则

- 基本信息一个字段变化计一项。
- 已有表、条件或修改字段的一个属性变化计一项。
- 新增或删除条件、修改字段各整体计一项。
- 新增或删除整张处理表各整体计一项，内部快照不重复计数。
- 自动生成脚本变化不计入业务变更数；手动脚本变化单独提示。

## 展开规则

操作记录默认折叠。展开后，有变化的基本信息和特殊处理内容默认展示。只涉及一张表时展开该表；两张表且总变更不超过八项时展开两张；其余情况仅展开第一张修改表。脚本始终默认折叠。

## 兼容性

历史扁平审计继续使用现有三列 Diff。新审计同时保留现有基础字段变化，并新增结构化特殊处理 Diff；前端优先渲染结构化内容，避免兼容派生串重复展示。保存必填校验、权限、状态流、附件审计与脚本保存行为不变。
