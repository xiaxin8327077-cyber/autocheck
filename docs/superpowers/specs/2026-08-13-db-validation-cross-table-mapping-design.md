# 人行逐笔校验跨表映射设计

## 目标

把逐笔字段与模板纵表 `field_name` 的对应关系从规则代码迁移到应用数据库。一条跨表映射代表一个实际参与模板交叉校验的逐笔字段，人工可查看、修改和恢复，所有操作保留审计记录。

## 设置入口与弹窗

逐笔校验设置区提供三个并列按钮：

1. 查看表映射
2. 查看字段映射
3. 查看跨表映射

三个按钮复用同一个弹窗外壳，但点击后直接打开固定类型，不在弹窗内循环切换。

弹窗标题区下方提供统一筛选框。输入时即时过滤当前视图，忽略大小写，并显示“当前条数 / 总条数”；清空后恢复全部。表映射检索表类型、逻辑表和物理表，字段映射检索逻辑表、中文名和映射字段，跨表映射检索逐笔表、逐笔字段、模板表和模板字段。

### 表映射

固定列为：表类型、逻辑表、物理表、修改。数据包含逐笔表、模板表和公开信息表；物理表展示当前生效值，修改后可恢复自动映射。

### 字段映射

固定列为：逻辑表、中文名、映射字段、修改。仅展示当前字段映射；未映射和缺失状态通过状态摘要及行内样式表达，不再增加横向列。

### 跨表映射

固定列为：逐笔表、逐笔字段、模板表、模板字段、修改。每个参与模板交叉校验的逐笔字段独占一行。初始化覆盖当前 ZG09、ZG10 全部已实现的模板交叉校验关系，包括 ZG09 表2-1的两条特殊关系以及现有 G/H 指标关系。

## 刷新与人工修改差异

刷新映射只更新自动识别值，不覆盖人工修改值；存在人工修改时，当前生效值仍以人工值为准。

当自动识别值与当前人工值不同时，不增加额外数据列，统一按以下方式展示：

- 对应设置入口按钮右上角显示橙色圆点。表映射、字段映射、跨表映射分别独立统计；该类别全部一致后圆点自动消失。
- 整行使用淡黄色背景。
- 当前值旁显示橙色“与自动映射不同”徽标。
- 徽标悬浮提示自动识别值、当前使用值和最后刷新时间。
- 修改区域同时显示“修改”和“恢复自动”按钮。
- 自动识别值缺失但人工值仍可用时，显示红色“自动映射缺失”徽标，人工值继续生效。
- 人工值与自动值相同时不显示差异提示，但仍保留人工覆盖记录和恢复能力。

表映射比较自动物理表与当前物理表；字段映射比较自动字段与当前字段；跨表映射分别比较逐笔表、逐笔字段、模板表和模板字段。跨表映射任一部分不一致即高亮整行，悬浮提示逐项列出具体差异。

橙色圆点仅表示该类映射至少存在一条自动值与人工值不一致，不承载数量。按钮使用可访问文本说明差异状态；进入对应弹窗后查看具体冲突行。

## 数据模型

跨表映射独立保存，不混入中文字段映射：

- 逐笔逻辑表代码
- 逐笔字段代码
- 模板逻辑范围/口径
- 模板物理表映射引用
- 模板 `field_name`
- 自动值、人工覆盖值、当前生效值
- 状态、说明、更新时间

运行时先用表映射解析当前逐笔表和模板表，再读取跨表映射的逐笔字段与模板字段。规则源码不保存具体生产字段对应关系。

人工修改允许调整逐笔字段、模板表和模板字段；保存前校验数据库标识符，写入现有覆盖表和审计日志。恢复后回到初始化关系。

## 表格排版

弹窗使用接近可视区域宽度的响应式最大宽度。表格固定布局且不产生横向滚动条；表名和字段名使用单行省略，鼠标悬浮通过 `title` 显示完整值。操作列固定窄宽，数据列按内容重要性分配宽度。小屏仍保持单行，优先压缩并省略长物理名。

## 校验行为

- ZG09、ZG10 仅遍历数据库中的有效跨表映射执行校验。
- 未配置、被禁用或对应字段不存在的关系跳过，并输出可定位的状态信息。
- 金额单位换算及误差阈值保持现有规则不变。
- 表映射包含全部模板表，模板口径继续由当前表映射决定。

## 测试

- 初始化 SQL 覆盖 ZG09、ZG10 当前全部关系。
- 存储层验证读取、修改、恢复和审计。
- 刷新测试验证自动值变化不会覆盖人工值，并正确生成差异状态。
- 规则测试验证修改映射后无需改代码即可切换逐笔字段或模板字段。
- 静态测试验证三个独立按钮、按钮差异圆点、固定列名、差异徽标、无循环切换和无横向滚动。
- 完整测试集、前端语法检查和硬编码守卫全部通过。
