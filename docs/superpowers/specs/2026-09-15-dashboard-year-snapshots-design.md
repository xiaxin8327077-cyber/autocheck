# 看板年度趋势快照设计

日期：2026-09-15
状态：已实施并验证

## 1. 目标与范围

看板预览接口在被看板页面定时调用时，继续执行实时查询，并把确实需要跨期保留的趋势数据写入 AutoCheck 本地快照。接口对趋势区域只返回当前自然年的快照数据，避免外部数据源只能查询近半年或系统上线较晚造成历史月份丢失。

仅以下四个内置趋势区域启用快照：

- `monthly_trust_projects`：月度信托项目数量。
- `report_reconciliation_completion_time`：报表对账完成时间。
- `report_validation_issue_handling`：报表校验问题处理。
- `quarterly_special_processing`：季度报表特殊处理。

其余六个区域继续实时返回，不保存快照。用户新增区域默认不启用快照。

## 2. 刷新与返回流程

调用 `GET /api/modules/dashboard-management/boards/{board_code}/preview` 时：

1. 按现有配置实时执行当前看板全部启用区域。
2. 四个快照区域查询成功后，解析每行的月份或季度，按“区域 + 自然年 + 周期”覆盖写入快照；明确返回的 `0` 是有效值。并发查询乱序完成时，较早开始的查询不得覆盖更新的快照。
3. 本次查询未返回的旧周期不得删除，以保留外部查询窗口之外的历史数据。
4. 四个快照区域在同一事务中写入并读取当前自然年的全部周期，按月份或季度升序返回；其余区域直接返回本次实时查询结果。返回行严格按当前启用字段投影，旧快照缺少后来新增的字段时该字段返回 `null`。
5. 快照区域实时查询失败但已有当年快照时，仍以成功状态返回快照，并附加 `snapshot_status: "stale"` 与最近更新时间；没有任何当年快照时保持现有错误响应。
6. 实时查询成功时附加 `snapshot_status: "fresh"` 与最近更新时间。现有看板页面可忽略新增元数据，区域字段和 `rows` 结构保持兼容。

不新增后台定时任务。看板现有轮询即为快照刷新触发器，不额外增加外部数据库查询频率。

## 3. 周期规范

- 月度信托项目数量：查询结果 `month` 兼容 `M月`、`MM月` 和 `YYYY-MM`。本地统一保存年份和月份，接口继续返回 `M月`，并仅接受当前月及以前的当年月份，避免年初把外部近半年中的上年月份误记为本年未来月份。
- 报表对账完成时间：`month` 保存为 `YYYY-MM`；接口同时返回 `reconciliation_completed_time`（`HH:mm` 展示时分）与 `reconciliation_completed_at`（完整日期时间或 `null`）两个独立字段，不再让 `reconciliation_completed_at` 兼容两种格式。新数据必须提供完整日期时间；初始化历史仅有既时分时，完整日期保持 `null`。
- 报表校验问题处理：`month` 保存并返回 `YYYY-MM`。
- 季度报表特殊处理：来源必须返回 `month=YYYY-MM`，按记录的 `report_period` 统计。内部保存年份和月份，对外接口仍返回 `quarter=第N季度`，由月度快照汇总；遗留季度格式的自定义 SQL 返回明确配置错误，不能标记为 fresh。

年份以北京时间的当前自然年为准。2026 年初始化数据仅写入 `period_year=2026`，不会在 2027 年重新套用；接口和失败回退也只读取当前年的快照。“报表对账完成时间”在 1 月可以补写上一年 12 月的迟到记录，但仍归属于上一年，不混入当年响应。信托项目的来源若只返回 `N月`，系统会按当前年解释，因此 SQL 必须自行限定业务年份；推荐来源返回含年份的 `YYYY-MM`，接口仍显示 `N月`。快照隔离不会纠正来源 SQL 把旧数据或固定测试值标记为当年月份的情况。

四类区域的对外业务字段如下；初始化值见下方表格：

| 区域 | 字段及含义 | 初始化后的更新方式 |
|---|---|---|
| 月度信托项目数量 | `month` 月份；`single_trust_count` 单一信托数；`collective_trust_count` 集合信托数；`property_trust_count` 财产权信托数 | 自定义 SQL 返回同月时覆盖，未返回的月份保留 |
| 报表对账完成时间 | `month` 报送年月；`reconciliation_completed_time` 展示时分；`reconciliation_completed_at` 完整完成时间 | 系统来源按报送期取总差异为 0 的最早执行时间；也可配置 SQL；返回同月时覆盖 |
| 报表校验问题处理 | `month` 报送年月；`validation_issue_count` 问题数量 | 自定义 SQL 返回同月时覆盖；包括 9 月在内的初始化值不冻结 |
| 季度报表特殊处理 | `quarter` 季度；`special_processing_count` 数量；内部来源与快照用 `month` 保存报送年月 | 2026 年 1—7 月固定；8 月起按报送期更新，再汇总为季度；2027 年没有固定历史月份 |

无效周期行不写入快照；一次查询中同一周期出现多行或查询结果超过 12 个周期视为配置错误，不覆盖已有快照。周期字段被停用时不读取旧快照伪装为本次成功结果。

## 4. 数据存储

新增模块迁移 `002_year_snapshots.sql`，模块 schema 版本升级为 2，并创建 `dashboard_management_year_snapshots`。平台迁移协议只允许模块 DDL，因此迁移负责建表，模块启动在内置区域初始化完成后幂等补充历史基线：

- `id`：主键。
- `region_id`：数据区域 ID，外键指向模块区域表。
- `period_year`：自然年。
- `period_type`：`month` 或 `quarter`。
- `period_value`：月份 1～12 或季度 1～4。
- `row_json`：该周期完整字段结果 JSON。
- `source_refreshed_at`：最后一次实时查询成功并覆盖该周期的时间。
- `created_at`、`updated_at`：记录时间。

唯一键为 `(region_id, period_year, period_type, period_value)`。停用模块、切换数据来源或删除用户新增区域不影响这四个内置区域的历史快照；模块迁移不自动删除历史数据。

## 5. 2026 年初始化基线

根据用户提供的“金融监管报表报送大屏”数据表初始化 2026 年历史基线：“月度信托项目数量”写入 1—7 月，“报表对账完成时间”写入 1—6 月，“报表校验问题处理”写入 1—9 月（9 月为 18 条），“季度报表特殊处理”写入固定 1—7 月。特殊处理的 1—6 月是保证 Q1=31、Q2=34 的历史估分，不是实际月度明细；7 月固定为 8。特殊处理的 2026 年 1—7 月不会被实时来源或补零覆盖；仅 8 月及以后由看板接口按 `report_period` 实时查询后生成或覆盖。2027 年及以后不保留此冻结边界。初始化幂等且不随机。已有同周期快照时不得重复插入或覆盖：

## 6. 模块边界与错误处理

- 只修改 `dashboard_management` 模块、对应测试和文档，不修改公共平台、其他模块或外部数据库。
- JSON 使用确定性序列化；读取失败或 JSON 损坏时只影响对应区域，并返回脱敏错误。
- 快照写入与同区域读取使用事务；唯一键保证多个看板请求同时刷新时不会生成重复周期。
- 外部 SQL、连接串和数据库错误详情不写入快照，也不通过接口返回。

## 7. 测试与验收

- 迁移与模块 schema 注册测试覆盖既有表、唯一键、2026 年信托 1—7 月和对账完成时间 1—6 月、校验问题处理 1—9 月、特殊处理 1—7 月固定基线、默认旧季度种子升级及初始化幂等性。月度表示复用既有快照表，不新增 DDL 迁移。
- 仓储测试覆盖插入、同周期覆盖、保留未返回周期、当前年过滤与排序。
- 周期解析测试覆盖两种月份格式、两种季度格式、跨年过滤、未来月份过滤、重复周期及无效值。
- 服务测试覆盖查询成功更新快照、查询失败回退旧快照、无快照失败、非快照区域保持实时行为。
- API 测试确认只返回当前自然年，且 `rows` 结构兼容现有看板页面。
- 运行模块测试、全量测试和 `git diff --check`；不自动打包、提交或推送。

## 8. 回滚

代码回退后保留 `dashboard_management_year_snapshots` 表，不自动删表或清数据。旧代码会忽略该表并恢复全部区域实时查询；重新启用新代码后可继续使用原快照。
