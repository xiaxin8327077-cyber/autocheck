# 报表特殊处理确认说明与粘贴图片设计

状态：已认可并实施

日期：2026-09-02

## 1. 目标

数据治理负责人在确认报表特殊处理记录时，可在确认弹窗中选填文字说明，并用剪贴板粘贴最多 3 张图片作为附件。确认完成后，操作记录的「完成」条目展示该说明；图片以缩略图显示，点击后查看大图。

系统只保存和展示这些内容，不解析、不改写、不执行图片或说明中的任何内容。

## 2. 已确认需求

- 说明为**选填**：不填文字、不贴图也可以点「源系统已确认」完成确认。
- 入口：现有确认弹窗（点列表「确认」或待办打开的只读详情）。在底部「取消 / 源系统已确认」按钮**上方**增加「确认说明」区域，不再弹出第二层填写框。
- 图片用**粘贴**（`Ctrl+V` / 右键粘贴），不提供文件上传按钮、不走系统文件选择器。
- 最多 **3** 张；确认前提示缩略图，可单张删除。
- 确认后在操作记录展开「完成」详情中查看：有文字则显示「确认说明」；有图则在说明下方显示缩略图，**点击缩略图查看大图**，再点遮罩或按 Escape 关闭。
- 旧确认记录没有说明和图片，保持现有展示，不做回填。

## 3. 方案选择

采用模块自有附件表保存图片二进制，确认接口提交文字和 Base64 图片，操作记录 JSON 只保存说明文字和附件编号。

未采用：

- 把整图写入 `changed_fields_json`：打开操作记录会反复下载全部图片，列表变慢。
- 把文件落到模块临时目录：`temp_root` 可被清理，不能作为长期留痕。
- 平台 multipart 上传：确认方式是粘贴不是上传；且改平台请求体协议需单独评审。本次用现有模块 JSON 接口，仅提高确认接口的 `max_body_bytes`。

## 5. 交互

### 5.1 确认弹窗

确认模式标题仍为「确认特殊处理」，表单只读。底部按钮上方新增一块：

- 标题：确认说明（选填）
- 多行文本框，最多 500 字，右下或提示中显示字数
- 文本框所属区域监听 `paste`：剪贴板含图片则拦截默认粘贴到文本框的行为，改为加入附件；纯文字仍粘贴进文本框
- 已贴图片以缩略图横排显示，每张有删除（×）
- 已满 3 张再贴图：不添加，提示「最多粘贴 3 张图片」
- 单张超过 2 MiB 或格式不支持：不添加，提示具体原因
- 点缩略图可在确认前提前看大图
- 主按钮文案仍为「源系统已确认」；**请求体不再发送写死的「源系统已确认」作为说明**

### 5.2 操作记录

`status_change` 且 `to_status=completed` 时：

- 有说明文字：摘要或详情中以未编号「确认说明：…」展示，规则与现有重开原因/作废理由一致，不计入「共 N 项变更」
- 有附件：详情中在确认说明下方显示最多 3 个缩略图；点击打开模块内大图层（`--ui-radius`，无主题光晕）；点遮罩或 Escape 关闭
- 无文字且无附件：与现在一样只展示完成/状态流

已完成记录的查看/编辑弹窗不提供再次粘贴入口；仅确认模式可新增说明和图片。

### 5.3 视觉

- 输入框、缩略图容器、大图层使用全局 `--ui-radius` 和现有主题色变量
- 删除缩略图为危险语义（红色），确认主按钮仍为主题渐变
- 缩略图悬浮只用描边和轻微位移，不用光晕
- 仅亮色主题

## 6. 数据

新增迁移 `005_confirm_note_attachments.sql`，`schema_version` 升至 5。

表 `report_special_processing_confirm_attachments`：

| 列 | 说明 |
|---|---|
| `id` | 主键 |
| `record_id` | 所属记录 |
| `audit_id` | 所属完成确认审计行 |
| `sequence_no` | 1–3，同一审计内唯一 |
| `content_type` | `image/png` / `image/jpeg` / `image/webp` |
| `byte_size` | 字节数 |
| `content_sha256` | 内容摘要 |
| `content` | `LONGBLOB`，原始图片字节 |
| `created_at` | 写入时间 |

索引：`(record_id)`、`(audit_id, sequence_no)` 唯一。不存用户文件名。删除记录时同步删除该记录全部附件（与现有审计、明细删除同一事务）。

确认审计的 `changed_fields_json`：

- 有文字：`reason: { "present": true, "new": "<trimmed text>" }`
- 无文字：不写 `reason`，或不得把「源系统已确认」当作说明正文
- 有图：`confirm_attachments: { "count": N, "ids": [id, ...] }`，**不含**图片字节
- 状态变化仍写 `status` 的 old/new

主表不新增确认说明列；说明只存在该次完成审计中。重开后再确认，是一条新的完成审计和新的附件，旧说明和旧图仍挂在历史完成条目上。

## 7. 接口与限制

沿用 `POST /records/{id}/status`，`target_status=completed`。

请求增加可选字段：

- `reason`：字符串，trim 后最长 500；空则视为无说明
- `confirm_images`：数组，0–3 项；每项 `{ "content_type": "...", "data_base64": "..." }`

该路由 `max_body_bytes` 提高到 **10 MiB**（3×2 MiB 原图加 Base64 开销和文字），不超过平台 `MAX_UPLOAD_BYTES`（50 MiB）。不修改 `server.py`。

读取：

- `GET /records/{id}/confirm-attachments/{attachment_id}`
- 权限与查看该记录详情相同
- 校验附件属于该 `record_id`
- 响应 `ModuleHttpResponse.bytes`，`content_type` 为存储的图片类型；体积上限落在平台 `MAX_MODULE_RESPONSE_BYTES`（50 MiB）内

服务端校验：

- 仅 `image/png`、`image/jpeg`、`image/webp`
- 用文件头魔数核对，不信任客户端 `content_type`
- 解码后单张 ≤ 2 MiB，总数 ≤ 3
- 不执行、不转码、不生成派生缩略图文件；展示缩小由 CSS 完成

已知平台约束：模块 JSON 读体超时为 5 秒。局域网内 10 MiB 通常可完成；若现场出现超时，记为平台读体超时问题，不得在本需求中改宿主。不为此引入 multipart。

## 8. 权限与安全

- 写入：现有 `can_confirm`（`rsp.confirm` 且为该条数据治理负责人，管理员例外）
- 读取图片：能 `get` 该记录的用户即可；禁止用附件 id 跨记录读取
- 前端图片用 `<img src="模块API">` 或 blob URL，禁止把不受控 HTML/SVG 当 `innerHTML` 插入；不接受 `image/svg+xml`
- 粘贴区域仅确认模式绑定

## 9. 测试、文档与版本

后端测试：

- 无说明无图：确认成功，审计无 `reason.new`，无附件行
- 仅文字：审计「确认说明」为用户原文，不是「源系统已确认」
- 粘贴 1–3 张合法图：附件行与审计 `ids` 一致，读取接口返回原字节
- 第 4 张、超 2 MiB、错误类型/魔数不符：400，不完成确认、不写附件
- 非治理负责人不能确认
- 删除记录后附件与审计均不在
- 重开后再确认：新旧两套完成审计和附件并存

前端静态测试：锁定确认说明区域、无「上传」文案、`paste`、最多 3 张、缩略图、大图层、`确认说明` 展示。

文档：模块 README、`docs/report-special-processing-module.zh-CN.md` 如与操作记录描述冲突则同步、根 README 当前功能与 `v1.2.20`。模块 `manifest` 版本 `1.2.11`，`release_notes` 只写本功能点，不写「系统优化及BUG修复」。应用内更新日志小版本 `v1.2.20`；展示用大版本仍为 `V1.2`。

## 10. 验收标准

1. 治理用户打开确认弹窗，可在按钮上方选填说明并用粘贴加入最多 3 张图；无上传按钮。
2. 不填不贴也能确认成功。
3. 完成后展开该条「完成」操作记录，能看到说明；点击缩略图能看大图并关闭。
4. 旧确认记录外观与行为不变。
5. 改动留在本模块、模块测试和必要 README/更新日志内。
