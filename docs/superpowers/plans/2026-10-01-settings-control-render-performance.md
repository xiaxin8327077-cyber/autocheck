# 系统设置切页延迟二次排查与实施记录

## 用户反馈与范围

- 生产环境进入系统设置后立即点击角色、用户或字典等菜单，旧设置画面仍停留约一秒；等待几秒后再点击没有明显延迟，本地原反馈几乎没有延迟。
- 已有离页取消与过期响应保护仍保留。它无法抢占已经开始的同步 JavaScript、布局与绘制。
- 本方案已获用户明确认可，按下述范围实施；不启动本地环境，不调整服务器，不变更模块生命周期协议。

## 已确认的代码行为

- `switchPage()` 在更新 `data-page` 前仅等待模块宿主 `deactivate()`；目标页的数据请求在属性更新之后发出。
- 模块宿主初始化完成且无活动模块时，停用没有网络调用；初始化仍在队列中时，停用会等待。设置六项加载不进入该队列，角色与能力刷新也不会重新初始化宿主。
- 页面使用 `display: none/flex` 切换，没有约一秒的离页动画；源码静态资源设置了禁止缓存的响应头。
- 设置业务字段表单每次完整重建 20 张表、20 个 select、121 个 input，其中 81 个属于折叠字段。
- 对真实控件增强函数的 Node 合成计数得到 282 次尺寸／样式读取；140 个控件在前一控件写入 DOM 后继续读取布局。菜单捕获点击对 20 个已关闭下拉仍产生 60 次状态写入。
- 上述实验只证明调用次数和执行顺序，没有测量生产约一秒的耗时，不能据此宣称根因已经证实。

## 已认可的改动

1. 控件增强收集当前需要处理的控件，先批量读取布局，再批量写入包装结构；用小批次分帧执行，避免整批长时间占用主线程。
2. 折叠内容暂不增强，展开时补齐；导航离开设置后取消尚未执行的设置批次。已有界面布局、尺寸和主题不变。
3. 菜单点击只关闭实际打开的下拉／日期控件，已关闭状态直接返回；减少 DOM 观察器对无关区域及自身写入的重复扫描。
4. 保留已有请求取消、会话、草稿、保存和全局流程轮询保护。暂不改模块初始化与停用协议，也不做服务器配置或连接池调整。

## 验证与验收

- 先用真实函数行为测试证明读写分批、隐藏字段按需处理、离页取消、打开控件正常关闭与已关闭控件无重复写入。
- 验证字段展开后的控件尺寸、下拉选择、日期选择、重新进入设置，以及角色／用户／字典／工具页的既有控件行为。
- 独立审查、相关静态及行为测试、全量 pytest 和差异检查通过后，仅提交本次源码及对应说明，不打包或推送。
- 最终仍需生产对比立即离页与等待几秒离页；如延迟不消失，用 Performance 录制区分点击开始前阻塞、宿主队列等待及页面属性更新后的绘制。

## 实现与本地证据

- 公共控件按每帧最多 12 个增强，每批先读取全部尺寸与字体快照，再写入包装与浮层。隐藏祖先、折叠区域及非当前核心页面暂不读取布局；展开或进入目标页面时补齐，模块隐藏根节点同样按需处理。
- 设置离页及会话清理复用原取消入口，清除设置待增强控件，并用代次保护首帧尚未收集的设置任务；保留其他页面待执行控件。模块直接导航通过 `data-page` 变化复用此清理，不改宿主生命周期。
- 下拉和日期记录实际打开的控件，捕获菜单点击仅处理打开集合，已关闭控件不再重复写状态。DOM 观察器只收集新增控件所在区域及展开区域，跳过自身包装、浮层与无关更新；原生 select 的局部选项观察器仍保持同步。
- 独立审查发现首次展开隐藏弹窗时，延后包装会重挂已聚焦控件并失焦。增强前记录焦点和可用选区，包装后输入框用 `preventScroll` 恢复焦点与选区，原生 select 转交新可见按钮；事件处理已选择其他焦点时不覆盖。补充模拟 DOM 移除失焦的测试，先失败后修正。
- 新增 `tests/test_custom_control_render_performance.py` 与合成 DOM 测试支撑，覆盖分帧读写顺序、折叠展开、首帧及后续批次取消、核心页面/模块激活、移除清理、选择与日期事件、打开关闭和局部变更。旧实现首次 5 项行为测试失败，基础修复后通过；补充的首帧取消与包装内移除清理也先失败后修正。
- 与真实设置表单同规模的合成测试（20 个 select、121 个 input，其中 81 个折叠）只测量 60 个可见控件，共 120 次尺寸/样式读取，分批期间不存在批内先写 DOM 再读取下一控件布局。该证据没有测量浏览器或生产耗时。
- 本地专项命令：`.runtime/dev-venv/Scripts/python.exe -m pytest -q tests/test_custom_control_render_performance.py tests/test_settings_navigation_lifecycle.py tests/test_web_static.py`。另完成 `node --check src/auto_check/web/app.js` 与 `git diff --check`；全量测试与独立审查由主任务统一收尾。
- 原生表单 HTML 构建仍为同步操作；本次消除其后的批量控件增强重复布局与长整批执行，无法据此保证生产约一秒的延迟已完全消失。生产验收仍遵循上述 Performance 对比。
