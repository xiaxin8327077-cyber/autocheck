# 管理员本地数据库查看器设计方案

本文档说明 Auto Check（监管智核）管理员“本地数据库”功能的页面、接口、安全和导出方案。该功能用于生产迁移后在无法直接连接 SQLite 的环境中，帮助管理员只读查看本地 `auto-check.db` 的表结构、表数据和存储健康状态。

相关文档：

- `docs/local-sqlite-database-design.zh-CN.md`：本地 SQLite 表结构和迁移后的数据模型。
- `docs/production-sqlite-storage-migration.zh-CN.md`：生产环境 SQLite 迁移步骤和核验流程。
- `docs/prototypes/local-database-browser/local-database-browser-prototype.html`：当前页面预览原型。

## 一、目标

1. 管理员可以在系统内查看本地 SQLite 的表清单、表中文名、字段结构和分页数据。
2. 管理员可以执行基础“存储体检”，确认 schema 版本、完整性检查、外键检查、迁移记录和核心表条数。
3. 管理员可以导出所有表结构到一个 Excel 文件，便于生产环境验收、归档和离线比对。
4. 功能只读，不提供 SQL 输入框，不允许用户拼接任意查询条件，避免误查、越权和数据泄露。

## 二、范围

本功能只面向本地应用自身的 SQLite 数据库 `auto-check.db`，不连接、不查询、不导出 DWS 或报表库业务源数据。

包含：

- 本地数据库菜单，且仅管理员可见。
- 存储健康状态展示。
- 表目录、表数据、字段结构、表说明查看。
- JSON 快照字段的明细抽屉展示。
- 敏感字段脱敏。
- 所有表结构 Excel 导出。

不包含：

- 任意 SQL 查询控制台。
- 数据新增、修改、删除。
- SQLite 文件上传、下载或替换。
- 对 DWS、报表库、人行导入源文件的直接数据浏览。
- 绕过现有登录态的外部诊断入口。

## 三、页面设计

新增一级菜单：`本地数据库`。

菜单规则：

- 管理员可见。
- 普通用户隐藏。
- 后端接口仍需校验登录态和角色，前端隐藏不能作为唯一权限控制。

页面布局：

- 顶部操作区：`导出表结构`、`生成备份`、`刷新状态`。
- 存储体检栏：展示结构版本、完整性检查、外键异常、业务表数量、历史运行数量、最近备份。
- 左侧表清单：按分类展示表名、中文名、模拟或真实记录数，支持按表名和中文名筛选。
- 右侧详情区：展示当前表的摘要、数据、字段、说明三个页签。

页签说明：

| 页签 | 内容 |
|------|------|
| 数据 | 当前表分页数据，支持当前页筛选、分页大小切换、基础排序。 |
| 字段 | 字段名、类型、约束、中文说明、展示策略。 |
| 说明 | 表用途、接口路径、安全策略、访问控制说明。 |

交互要求：

- 点击左侧表名后右侧内容即时切换。
- JSON 字段以“查看 JSON”按钮展示，点击后打开右侧抽屉。
- 敏感字段在列表和 JSON 抽屉中都需要脱敏。
- 表格横向滚动，不挤压字段内容。
- 页面兼容默认太空主题和暗色模式。

## 四、接口设计

所有接口统一放在管理员命名空间下，建议路径前缀：

```text
/api/admin/storage
```

### 1. 存储体检

```text
GET /api/admin/storage/health
```

返回内容：

- 当前 schema 版本。
- `PRAGMA integrity_check` 结果。
- `PRAGMA foreign_key_check` 异常数量。
- 数据库文件路径脱敏展示。
- 数据库文件大小。
- 最近备份文件名和时间。
- 核心表条数摘要。
- 最近一次迁移记录。

### 2. 表目录

```text
GET /api/admin/storage/tables
```

返回内容：

- 表名。
- 中文名。
- 分类。
- 主键。
- 字段数。
- 记录数。
- 表用途说明。
- 是否系统内部表。
- 是否允许查看数据。

表名必须来自服务端维护的白名单元数据，不从请求参数动态拼接。

### 3. 字段结构

```text
GET /api/admin/storage/tables/{table_name}/schema
```

返回内容：

- 字段名。
- SQLite 类型。
- 是否主键。
- 是否非空。
- 默认值。
- 中文说明。
- 展示策略。
- 是否敏感字段。

### 4. 分页数据

```text
GET /api/admin/storage/tables/{table_name}/rows?page=1&page_size=50
```

参数规则：

- `table_name` 必须命中白名单。
- `page` 最小值为 1。
- `page_size` 仅允许 10、20、50、100。
- 排序字段只能使用每张表元数据声明的默认字段或主键。
- 不接收任意 `where`、`order by`、表达式或 SQL 片段。

返回内容：

- 当前页数据。
- 总行数。
- 当前页码。
- 每页条数。
- 字段展示策略。

## 五、表结构导出方案

新增按钮：`导出表结构`。

导出目标：

- 一个 Excel 文件。
- 一个工作簿内包含多个 sheet。
- 文件名建议：`本地数据库表结构.xlsx`。

Sheet 设计：

| Sheet | 内容 |
|------|------|
| 表目录 | 所有表的分类、表名、中文名、记录数、字段数、主键、用途。 |
| 每张表一个 Sheet | 当前表的字段序号、字段名、类型、约束、中文说明、展示策略。 |

Sheet 命名规则：

- 优先使用 SQLite 表名。
- Excel sheet 名最长 31 个字符。
- 替换 `[]*/\?:` 等 Excel 不允许字符。
- 如出现重名，追加 `_2`、`_3` 后缀。

正式实现建议：

- 后端使用项目已有依赖 `openpyxl` 生成标准 `.xlsx`。
- 接口建议为：

```text
GET /api/admin/storage/schema-export
```

- 响应头：

```text
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename="local-storage-schema.xlsx"
```

预览原型说明：

- 当前 HTML 原型使用浏览器端 XML Spreadsheet 方式生成 `.xls`，用于快速验证交互和导出内容。
- 正式功能落地时改为后端 `.xlsx`，避免浏览器兼容差异，并便于加入真实 SQLite 元数据和样式。

## 六、安全边界

1. 不提供 SQL 输入框。
2. 不允许用户提交任意过滤表达式或排序字段。
3. 表名、字段名、排序字段全部来自服务端白名单。
4. 所有接口必须检查登录态和管理员角色。
5. 敏感字段默认脱敏，包括但不限于：
   - `password`
   - `password_hash`
   - `password_encrypted`
   - `token`
   - `secret`
   - `host`
   - `username`
   - `source_path`
   - `download_path`
   - 连接串或凭据类字段
6. JSON 快照字段展示前同样执行递归脱敏。
7. 分页查询需要限制每页数量，避免一次性读取大表。
8. 下载导出只导出表结构，不导出表数据。
9. 所有管理员查看和导出操作建议记录审计日志。

## 七、后端实现建议

建议新增模块：

```text
src/auto_check/app/storage_admin.py
```

职责：

- 维护可查看表的元数据白名单。
- 生成存储体检结果。
- 查询表目录。
- 查询字段结构。
- 分页查询表数据。
- 对敏感字段执行脱敏。
- 生成表结构 Excel。

建议在 `server.py` 中只做路由分发，不把查询、脱敏和 Excel 生成逻辑塞进路由处理函数。

元数据结构示例：

```python
{
    "name": "reconcile_runs",
    "cn_name": "自动对数运行表",
    "category": "自动对数",
    "primary_key": ["id"],
    "default_order_by": ["started_at DESC", "id DESC"],
    "allow_rows": True,
    "sensitive_fields": [],
    "fields": [
        {
            "name": "id",
            "type": "TEXT",
            "nullable": False,
            "cn_name": "运行 ID",
            "display": "原文",
        }
    ],
}
```

## 八、前端实现建议

正式页面可沿用当前预览原型结构：

- 左侧表清单容器。
- 右侧表详情容器。
- `数据 / 字段 / 说明` 页签。
- JSON 抽屉。
- 顶部操作按钮。

前端请求流程：

1. 进入页面时请求 `/api/admin/storage/health` 和 `/api/admin/storage/tables`。
2. 默认选中第一张业务表或最近查看表。
3. 选中表后请求 schema 和第一页 rows。
4. 切换分页、分页大小或刷新时重新请求 rows。
5. 点击导出表结构时直接下载 `/api/admin/storage/schema-export`。

错误处理：

- 401：跳转登录或提示登录失效。
- 403：提示当前账号无管理员权限。
- 404：提示表不存在或未开放查看。
- 500：展示存储检查失败信息，并保留刷新入口。

## 九、测试建议

后端测试：

- 普通用户访问管理员接口返回 403。
- 未登录访问管理员接口返回 401。
- 表目录接口返回所有白名单表及中文名。
- 非白名单表名返回 404 或 400。
- `page_size` 超限被拒绝或回退到默认值。
- 敏感字段在 rows 和 JSON 字段中均被脱敏。
- `schema-export` 返回有效 `.xlsx`，且包含 `表目录` 和每张表的 sheet。
- `health` 能正确报告 schema 版本、完整性检查和外键检查结果。

前端静态测试：

- 新菜单仅管理员可见。
- 页面不包含 SQL 输入框。
- 页面包含 `导出表结构` 按钮。
- 表数据、字段结构、说明页签存在。
- JSON 明细抽屉存在。

## 十、验收标准

1. 管理员登录后能看到 `本地数据库` 菜单。
2. 普通用户看不到菜单，直接访问接口也不能获取数据。
3. 管理员能看到本地库健康状态。
4. 管理员能查看所有白名单表的表名、中文名、字段结构和分页数据。
5. 管理员不能输入或执行任意 SQL。
6. 敏感字段不会明文展示。
7. 点击 `导出表结构` 能下载一个 Excel 文件。
8. Excel 中包含 `表目录` sheet，以及每张 SQLite 表独立的字段结构 sheet。
9. 生产迁移后可通过该页面完成基本数据库核验，不要求管理员直接连接 SQLite 文件。
