# 自动对数核心逻辑版本记录

本文档用于记录自动对数核心逻辑的版本演进。

当前可执行规则和页面、历史、Excel 展示口径以 `docs/reconcile-rules.zh-CN.md` 为准；本文档保留历史版本记录，旧版本段落中的文案不代表当前最终实现。

维护要求：

- 每次对数逻辑发生调整时，必须新增一个版本段落。
- 每个版本都要保留当时的完整逻辑，不覆盖历史版本。
- 每个版本都要写清楚“与上一版本的差异逻辑”。
- 若只是页面、样式、导出格式或测试数据调整，不改变对数判断结果，可不新增逻辑版本。
- 若新增数据源、调整判断顺序、调整科目范围、调整金额匹配方式、调整原因类型或调整原因优先级，必须新增逻辑版本。
- 若表名或字段发生调整，需要同步更新系统设置中的“业务设置”字段清单，保证页面展示与当前逻辑一致。

## logic-2026-06-10-v1

### 版本说明

本版本在 `资产缺失` 已命中具体估值表实际末级科目的基础上，继续按资产类型做细分核查，并将 `具体原因` 列改为逐条格式：

```text
①债券缺失：XX债券；原因：XXX
②贷款缺失：XX贷款
```

有最终原因时追加 `；原因：...`，没有最终原因时只展示资产类型和资产名称。多个资产共同命中时按 `①②③` 换行拼接，并在展开详情中新增“资产缺失细分”表格。

### 资产类型范围

- 特定目的载体：FA 科目前四段为 `1101.05.01.01`、`1101.05.02.01`、`1101.05.03.01`、`1101.05.04.01`、`1101.05.05.01`、`1101.05.07.01`，或满足 `1501.03.XX.01`。
- 债券：`1501.01*`、`1101.02*`。
- 股票：`1101.01*`。
- 公募基金：`1101.04*`。
- 私募基金：`1101.05.06*`。
- 逆回购：前四段满足 `1111.xx.xx.01`。
- 贷款：`1303.01.01*` 或 `1501.04.05.01*`。
- 股权投资：`1511.01.01*`。
- 信托计划收益权：`1541.01*` 且科目名称满足 `LIKE '江苏信托%信托产品%'` 或 `LIKE '江苏信托%资金信托计划%'`。
- 资产收益权：`1541.01*` 且不满足信托计划收益权名称条件。
- 其他资产：不做分类，使用 `科目代码 + 科目名称` 展示缺失资产名称。

### 与上一版本的差异逻辑

- `资产缺失` 的具体原因不再只汇总资产类型，而是逐个命中资产生成格式化原因。
- 特定目的载体保留 AM 标的缺失、FA/AM 标的不一致、合同投融资余额为 0 的原判断；投融资余额非 0 后继续查 `dm.am_projinvest_spv_zgxg_dm` 和报表明细表；`1101.05.06*` 仍按私募基金核查。
- 债券、股票、公募基金、私募基金新增 `dm.fa_security_balance_zgxg_dm` 基础信息字段和报表明细表核查。
- 贷款、股权投资新增 `dm.am_projinvest_zgxg_dm` 和报表明细表核查。
- 信托计划收益权新增 `dm.am_projinvest_spv_zgxg_dm` 和特定目的载体明细表核查。
- 资产收益权新增 `zgxg_zhbs.ccqxx` 和其他债权明细表核查；`zgxg_zhbs.ccqxx` 不加日期条件。
- 逆回购新增 `assman_reg.ex_pledge_back` 空值核查，按 `project_code` 过滤项目，`subcode` 以 `7` 开头，不按日期过滤。
- `资产重复` 新增格式化细分原因和“资产重复细分”表；命中 `1101.05.06.01*` 时用 FA 科目尾段匹配 `am_pactasset_dws.c_stockcode`，若 `c_spv_type <> 11` 且 `c_assettype` 属于 `31、32、34、35、37、33、38`，展示“该资产在证券信息表中为私募产品但在AM中不为私募产品”，其他命中资产名称使用 `科目代码 + 科目名称`。
- `资产差异` 只在无法明确命中资产缺失/重复后进入贷款/财产权合同逐一核对；逐项计算 `AM投融资余额 - FA科目余额`，合计等于 `a0001-估值表0004` 时按 `①②③` 展示合同差异并标记“已解释”，合计非 0 但不等于资产合计差额时按实际合同类型展示“暂不明确具体资产差异，但...”，否则展示“暂不明确具体资产差异”。

## logic-2026-06-09-v2

### 版本说明

本版本将自动对数结果的 `difference_reason` 固定为一级原因分类，原先直接写入差异原因的 AM、TA、1541 财产权等更具体原因改为写入详情中的“具体原因”。这样结果列表、筛选、历史统计和 Excel 主原因列保持稳定，后续无法直接命中的资产或负债权益细分对比可以继续追加到详情中。

### 一级原因

- `资产缺失`
- `资产重复`
- `资产差异`
- `负债及权益科目差异`
- `负债及权益科目缺失`
- `负债及权益科目重复`
- `实收本金差异`
- `实收本金缺失`
- `实收本金重复`
- `暂无法确定`

### 与上一版本的差异逻辑

- `a0001 < 0004` 且能命中具体 `1` 开头资产科目时输出 `资产缺失`；不能命中具体资产时输出 `资产差异`。
- `a0001 > 0004` 且能命中具体 `1` 开头资产科目时输出 `资产重复`；不能命中具体资产时输出 `资产差异`。
- 1541 财产权合同投融资差异命中时，一级原因输出 `资产差异`，具体原因输出“财产权合同投融资金额比估值金额多/少”。
- AM 标的缺失、FA 与 AM 标的不一致、合同投融资余额为 0、投资端信息无异常等原资产细分原因不再作为一级原因，统一挂在 `资产缺失` 的详情中。
- 资产端正确后，若 `a0001-d0000 = FA4001`，输出 `实收本金缺失`。
- 资产端正确后，若 `a0001-d0000 = -FA4001`，输出 `实收本金重复`。
- 资产端正确后，若 `a0001-d0000 = FA4001-c1000`，输出 `实收本金差异`；TA 汇总差额或 DM TA 客户类型为空金额能解释本次实收差额时作为具体原因展示，否则仅作为详情核对信息展示，具体原因回退为原“实收信托有误”。
- 只有 `c1000 = FA4001` 时才进入负债及权益科目判断。
- 非 `1` 开头科目能命中且 `d0000 < a0001` 时输出 `负债及权益科目缺失`。
- 非 `1` 开头科目能命中且 `d0000 > a0001` 时输出 `负债及权益科目重复`。
- 非 `1` 开头科目不能命中时输出 `负债及权益科目差异`。
- `c1000 != FA4001` 且不满足实收本金缺失、重复或差异规则时，输出 `暂无法确定`。

## logic-2026-06-09-v1

### 版本说明

本版本在“实收信托有误”命中后追加 TA 细分判断，用于把原本统一展示的实收信托差异进一步拆成 DM/DWS TA 表汇总不一致、DM TA 客户类型为空导致差异，或保留原“实收信托有误”。

### 与上一版本的差异逻辑

- 新增 `dm.ta_pact_survamt_day_zgxg_dm` 参与实收信托细分判断，表名前固定带 `dm` schema，仍使用当前对账 DWS 数据源连接。
- 新增 `ta_pact_detail_dws` 参与实收信托细分判断，使用当前对账 DWS 数据源默认 schema。
- “实收信托有误”命中后不再立即返回单一原因，而是先比较 DM TA 与 DWS TA 的“份额余额+待结转收益”汇总。
- 若 DM TA 汇总与 DWS TA 汇总不一致，输出“DM表TA份额余额错误”。
- 若两个汇总一致，再检查 DM TA 客户类型为空记录；空值口径为 `tpm_clientkind_tusp` 为空，或 `tpm_clientkind_tusp=4` 且 `tpm_clientkindex` 为空，或 `tpm_clientkind_tusp=5` 且 `tpm_spvtype` 为空。
- 若客户类型为空记录的 `tpm_htincome + tpm_shareamt` 合计等于 `FA4001 - c1000`，输出“dm.ta_pact_survamt_day_zgxg_dm表中客户类型为空导致实收信托有误”。
- 若细分规则不能解释差异，仍输出原“实收信托有误”。

### 完整逻辑

#### 1. 读取主差异

从 `zf_detail_2024` 按 `caldate` 读取 `a0001 - d0000 <> 0` 的项目。

- 项目编号：`projinnercode`
- 项目名称：`projname`
- 资产合计：`a0001`
- 负债及权益合计：`d0000`
- 实收本金余额：`c1000`
- 主差异：`a0001 - d0000`

#### 2. 判断资产侧是否正确

到 `fa_valuationreport_dws` 按同日期、同项目读取 `c_accountcode = '0004'` 的 `f_marketvalue`，作为估值表资产合计。

- 找不到 `0004`：输出“暂无法确定”。
- `a0001` 与估值表资产合计不一致：进入资产侧规则。
- `a0001` 与估值表资产合计一致：进入负债及权益侧规则。

#### 3. 资产侧规则

当 `a0001` 与估值表资产合计不一致时，计算 `abs(a0001 - 估值表0004)`：

- `a0001` 小于估值表资产合计：预估方向为“资产缺失”。
- `a0001` 大于估值表资产合计：预估方向为“资产重复”。

资产侧只读取估值表 `1` 开头的实际末级科目，并按金额匹配优先级查找差异：单行命中、同科目汇总命中、多科目组合命中、组合候选过多、未命中。

#### 4. 1541 财产权合同投融资核对

资产侧规则中，如果 `1` 开头实际末级科目存在 `1541` 开头科目，则取科目代码最后一段作为合同代码，到 `am_projinvest_dws` 按同项目、同日期、同合同汇总 `f_acbalance`。

逐行计算 `f_acbalance - f_marketvalue` 并汇总：

- 汇总差异等于主差异且大于 0：输出“财产权合同投融资金额比估值金额多”。
- 汇总差异等于主差异且小于 0：输出“财产权合同投融资金额比估值金额少”。
- 查不到任一合同余额，或汇总差异不等于资产合计差额：本规则不命中，继续保留资产侧原规则判断。

#### 5. FA/AM 标的复核

只有“资产缺失”金额匹配命中后才进入本复核；“资产重复”不进入。

命中科目的四级科目必须为 `1101.05.03.01`。程序读取同项目、同日期 `am_pactasset_dws`，用 FA 科目名称匹配 AM 资产名称：

- 找不到匹配资产名称：输出“AM标的缺失”。
- 名称匹配但 FA 科目末段代码不等于 AM `c_stockcode`：输出“FA与AM标的不一致”。
- 名称和标的代码都一致：继续查 `am_projinvest_dws`。

若对应合同 `f_acbalance = 0`，输出“合同投融资余额为0但FA科目余额不为0”；若 `f_acbalance <> 0`，输出“缺失资产在投资端信息无异常，请核查报表是否正常生成”。

#### 6. 负债及权益侧实收信托判断

只有 `a0001` 与估值表 `0004` 一致时才进入负债及权益侧。先查 `fa_accountbalance_dws` 的 `4001` 科目并汇总 `f_balance`，计算：

```text
FA4001 - c1000
```

如果同时满足：

- `c1000 != FA4001`
- `FA4001 - c1000 == a0001 - d0000`

则进入实收信托细分判断。

#### 7. 实收信托细分判断

先查 `dm.ta_pact_survamt_day_zgxg_dm`：

- 日期字段：`tpm_date`
- 项目字段：`tpm_tcmpcode`
- 金额：`SUM(tpm_htincome + tpm_shareamt)`

再查 `ta_pact_detail_dws`：

- 日期字段：`d_cldate`
- 项目字段：`c_projcode`
- 金额：`SUM(f_shareamt + f_alltincom)`

判断顺序：

1. 若 DM TA 汇总与 DWS TA 汇总不一致，输出“DM表TA份额余额错误”。
2. 若两个汇总一致，继续查 DM TA 中 `tpm_htincome + tpm_shareamt <> 0` 且客户类型为空的记录。
3. 客户类型为空口径：`tpm_clientkind_tusp` 为空；或 `tpm_clientkind_tusp=4` 且 `tpm_clientkindex` 为空；或 `tpm_clientkind_tusp=5` 且 `tpm_spvtype` 为空。
4. 若客户类型为空记录金额合计等于 `FA4001 - c1000`，输出“dm.ta_pact_survamt_day_zgxg_dm表中客户类型为空导致实收信托有误”。
5. 若细分规则都不能解释差异，输出“实收信托有误”。

#### 8. 实收信托无法解释时

如果 `c1000` 与 FA `4001` 规则无法解释主差异，继续查估值表非 `1` 开头科目，不限制末级科目。

- 优先用主差异 `a0001 - d0000` 原金额匹配。
- 如果主差异为负数且未命中，再尝试用主差异绝对值匹配。
- 命中后输出“负债及权益科目差异”。
- 未命中时输出“暂无法确定”。

## logic-2026-05-29-v1

### 版本说明

这是首次建立的完整逻辑基线，内容按当前代码实际执行顺序整理。

### 与上一版本的差异逻辑

无上一版本。本版本作为后续逻辑差异对比基线。

### 完整逻辑

#### 1. 读取主差异

从 `zf_detail_2024` 按 `caldate` 取数，只处理：

```text
a0001 - d0000 <> 0
```

字段含义：

- 项目编号：`projinnercode`
- 项目名称：`projname`
- 资产合计：`a0001`
- 负债及权益合计：`d0000`
- 实收本金余额：`c1000`
- 主差异：`a0001 - d0000`

差异方向：

- `a0001 - d0000 > 0`：资产大于负债及权益。
- `a0001 - d0000 < 0`：资产小于负债及权益。

#### 2. 先判断资产侧是否正确

到 `fa_valuationreport_dws` 按同日期、同项目取：

```text
c_accountcode = '0004'
```

使用该行 `f_marketvalue` 作为估值表资产合计，对比 `zf_detail_2024.a0001`。

如果找不到 `0004`，直接输出：

```text
预估差异原因 = 暂无法确定
```

当前实现注意点：

- 如果同项目同日期存在多行 `0004`，当前代码只取第一条，不做汇总。

#### 3. 若 a0001 与估值表资产合计不一致

进入资产侧规则。

资产侧差异金额：

```text
abs(a0001 - 估值表0004金额)
```

初始原因判断：

- `a0001 < 估值表0004金额`：先预估为 `资产缺失`。
- `a0001 > 估值表0004金额`：先预估为 `资产重复`。

然后按原因查估值表资产科目：

- `资产缺失` 和 `资产重复`：查 `c_accountcode` 以 `1` 开头的实际末级科目，不要求科目代码必须包含 4 个点；存在下级科目时，上级科目不作为候选。
- `资产缺失` 命中后，AM 标的复核仍按命中科目前四段是否为 `1101.05.03.01` 决定是否继续。
- 用 `f_marketvalue` 匹配资产侧差异金额。

估值表金额匹配优先级：

1. 单行 `f_marketvalue` 等于差异金额。
2. 同一科目代码下多行 `f_marketvalue` 汇总等于差异金额。
3. 多个科目组合汇总等于差异金额。
4. 候选行超过 50 行时不继续组合，匹配状态为 `组合候选过多`。
5. 以上都匹配不上时，预估差异原因改为 `暂无法确定`。

#### 4. 资产缺失后的 AM 复核

只有同时满足以下条件时才继续查 AM：

- 当前原因是 `资产缺失`。
- 命中的估值表科目前四段是 `1101.05.03.01`。

否则原因保持 `资产缺失`。

进入 AM 复核后，查 `am_pactasset_dws`：

- 日期字段：`d_cldate`
- 项目字段：`c_projcode`
- 资产名称：`c_udlyasset`
- 标的代码：`c_stockcode`
- 合同代码：`c_pactid`

资产名称匹配规则：

- 先标准化名称：去空白、统一字符形式、忽略末尾 `_XXX` 类后缀；括号中的内容保留并参与匹配。
- 标准化后完全一致，则认为匹配。
- 如果两边括号中的内容不一致，直接认为名称不匹配。
- 不完全一致时，名称相似度大于等于 `0.90` 也认为匹配。
- 如果同一 FA 科目命中多个 AM 资产，使用相似度最高的 AM 资产继续复核。

AM 判断：

- 找不到匹配资产名称：`AM标的缺失`。
- 找到资产名称，但 FA 科目末段代码不等于 AM 标的代码：`FA与AM标的不一致`。
- 名称和标的代码都一致，继续查 `am_projinvest_dws`。

查 `am_projinvest_dws`：

- 日期字段：`d_cldate`
- 项目字段：`c_projcode`
- 合同代码：`c_pactid`

判断：

- `f_acbalance = 0`：`合同投融资余额为0但FA科目余额不为0`。

当前实现注意点：

- 如果查不到 `am_projinvest_dws` 记录，当前代码按 0 处理，也会进入 `合同投融资余额为0但FA科目余额不为0`。

说明资产侧正确，进入负债及权益侧规则。

先查 `fa_accountbalance_dws`：

- 日期字段：`d_balancedate`
- 项目字段：`c_projcode`
- 科目代码：`c_accountcode = '4001'`
- 金额字段：按项目汇总 `SUM(f_balance)`

计算：

```text
FA4001 - c1000
```

如果同时满足：

- `c1000 != FA4001`
- `FA4001 - c1000 == a0001 - d0000`

则输出：

```text
预估差异原因 = 实收信托有误
```

#### 7. 实收信托无法解释时

继续查估值表非资产科目：

- `c_accountcode` 不以 `1` 开头。
- 不限制末级科目。
- 用 `f_marketvalue` 匹配主差异 `a0001 - d0000`。

匹配逻辑仍按估值表金额匹配优先级执行：

1. 单行命中。
2. 同科目多行汇总命中。
3. 多科目组合命中。
4. 候选行超过 50 行时停止组合。
5. 未命中。

补充规则：

- 如果主差异是负数，先按负数匹配。
- 如果负数未命中，再使用主差异绝对值匹配。

命中后输出：


未命中时输出：

```text
预估差异原因 = 暂无法确定
```

代码里仍保留 `currency_report_duration` 的读取接口，但当前核心流程不再使用它做 FA/TA 实收短路判断。

```text

```
