# 自动对数执行链路明细

本文档记录当前自动对数核心逻辑的真实执行顺序，按“先干哪一步、命中后是否继续、下一步干什么”的方式描述。它不同于 `docs/reconcile-rules.zh-CN.md`：后者偏规则总览，本文档偏代码链路和分支顺序。

## 维护要求

- 本文档是自动对数逻辑的同步维护文档。
- 修改 `src/auto_check/engine/reconcile.py` 中的判断顺序、差异类型、匹配状态、具体原因、资产/实收/负债权益细分时，必须同步更新本文档。
- 修改 `src/auto_check/app/repositories.py` 中会影响对数判断的 SQL、过滤字段、金额口径、数据源表名时，必须同步更新本文档。
- 修改结果页、历史页、导出 Excel 中差异类型或具体原因展示口径时，也要同步检查本文档是否需要更新。

## 0. 基础口径

### 0.1 主表入口

1. 程序从 `zf_detail_2024` 读取核对日期下的全部项目。
2. 如果该日期没有任何报表项目，执行结果返回“报表对应日期无数据”，不进入差异判断，也不写入核对历史。
3. 如果该日期存在报表项目，继续筛选 `a0001 - d0000 <> 0` 的项目进入差异判断；存在报表但无差异时展示“数据完全正确”，并写入 0 差异历史。
4. 项目基础字段（字段含义）：
   - 项目编号：`projinnercode`
   - 项目名称：`projname`
   - 资产合计：`a0001`
   - 负债及权益合计：`d0000`
   - 实收本金余额：`c1000`

### 0.2 核心金额变量

- 主差异：`main_diff = a0001 - d0000`
- 估值表资产合计：`fa_asset_total = fa_valuationreport_dws` 中科目 `0004` 的 `f_marketvalue`
- 资产端差额：`asset_total_gap = a0001 - fa_asset_total`
- 资产端绝对差额：`asset_gap = ABS(a0001 - fa_asset_total)`
- 资产差异解释后的剩余差额：`remaining = main_diff - asset_total_gap = fa_asset_total - d0000`
- FA 实收本金：`fa4001 = fa_accountbalance_dws` 中科目 `4001` 的余额汇总
- 实收本金差额：`received_trust_diff = fa4001 - c1000`

字段含义速查：

| 字段/变量 | 来源 | 含义/口径 |
| --- | --- | --- |
| `projinnercode` | `zf_detail_2024` | 项目编号，自动对数按项目逐个判断。 |
| `projname` | `zf_detail_2024` | 项目名称，用于结果展示和明细定位。 |
| `caldate` | 各业务表日期字段 | 核对日期/报表日期；除特别说明外，同一次核对只取该日期数据。 |
| `a0001` | `zf_detail_2024` | 资负报表资产合计。 |
| `d0000` | `zf_detail_2024` | 资负报表负债及权益合计。 |
| `c1000` | `zf_detail_2024` | 资负报表实收本金余额。 |
| `main_diff` | 计算变量 | 主差异，等于 `a0001 - d0000`。 |
| `fa_asset_total` | `fa_valuationreport_dws` | 估值表资产合计，取科目 `0004` 的 `f_marketvalue`。 |
| `asset_total_gap` | 计算变量 | 资产端差额，等于 `a0001 - fa_asset_total`；保留正负方向。 |

| `current_diff` | 计算变量 | 当前分支正在尝试解释的差额；初始通常为 `a0001 - d0000`，资产差异完整解释后可能切换为 `remaining`。 |
| `c_accountcode` | FA 科目表 | FA 科目代码；末级判断基于完整代码，证券、合同和标的关联使用剥离科目层级后的完整业务代码，业务代码内部点号予以保留。 |

| `c_stockcode` | `am_pactasset_dws` | AM 标的代码，用于和 FA 科目尾段代码核对。 |
| `c_pactid` | `am_pactasset_dws` / AM 合同表 | AM 合同代码，用于继续查询投融资余额和 SPV 相关 DM 表。 |
| `d_bdate` / `contract_start_date` | `am_projinvest_dws` | AM 合同开始日，必配字段；同数据源时通过项目编号、核对日期、合同代码三要素关联 `am_pactasset_dws` 取得；跨数据源时先按核对日期查询合同表，再在应用层按项目编号和合同代码回填；多候选标的消歧时按该字段倒序取最新合同。 |

### 0.3 匹配状态

- `已解释`：已经命中明确规则，或细分差额完整解释当前差异。
- `未解释`：只能定位到一级差异类型，但不能完整解释具体明细。
- `组合候选过多`：组合候选、状态数超过上限，或单项目组合计算达到 60 秒硬上限，程序停止枚举，保留该状态。
- `候选不唯一`：多组组合均可解释同一差额时，不自动选择第一组；资产缺失方向可先用 AM 复核唯一确认，不能唯一确认时保留该状态并返回“暂无法确定”。

### 0.4 差异类型

当前主要差异类型包括：

- `资产缺失`
- `资产重复`
- `资产差异`
- `负债及权益科目差异`
- `负债及权益科目缺失`
- `负债及权益科目重复`
- `实收本金差异`
- `实收本金缺失`
- `实收本金重复`
- `暂无法确定`
- 组合类型，例如：
  - `资产差异 + 负债及权益科目差异`
  - `资产差异 + 实收本金差异`
  - `资产差异 + 实收本金差异 + 负债及权益科目差异`

组合类型只在“资产端差异已经被完整解释，但修正资产端后仍存在剩余差额，需要继续进入实收/负债权益链路”时产生。

### 0.5 表名和字段名配置

自动对数仓储层不再直接依赖固定物理表名和字段名，而是先按逻辑表编码解析到实际数据源、表名和字段名，再生成 SQL。生产运行以系统设置页面保存的 `reconcile_schema` 为准；未在页面保存配置时使用当前内置默认值，保持老环境兼容。

配置来源：

1. 自动对数运行时读取系统配置中保存的 `reconcile_schema`。
2. 系统设置页面提供表单化维护入口，可为每张逻辑表选择数据源、填写物理表名、按表读取数据库字段，并按字段英文名和中文备注模糊搜索选择/手工填写业务字段映射；同时提供“根据配置文件初始化配置”按钮，可从应用数据目录下的 `reconcile-schema.yaml` 初始化并保存到系统配置。生产二进制部署时，该文件放在 `/home/autocheck/data/reconcile-schema.yaml`。
3. `reconcile-schema.yaml` 只是初始化来源，不会在启动或执行自动对数时自动覆盖页面配置。
4. 页面保存后的表字段配置按严格模式执行：缺少逻辑表、必填字段、表名或数据源时直接报配置错误，不再自动补默认字段；只有未保存页面配置时才使用内置默认映射。

表名规则：

- `table` 支持单段表名，例如 `zf_detail_2024`，此时使用所选数据源自身的默认 schema/database。
- `table` 支持带前缀表名，例如 `dm.fa_security_balance_zgxg_dm`、`currency_report_24.currency_detail_project_2_1_9`。
- 字段名只支持普通数据库标识符，例如 `c_projcode`、`f_marketvalue`，不支持在字段配置里写表达式；金额加减、汇总和过滤仍由代码规则控制。

数据源规则：

- 每个逻辑表通过 `source_ref.id` 优先匹配系统数据源 ID；ID 不存在时，允许按 `source_ref.name` 唯一匹配数据源名称。
- 兼容内置别名 `dws` 和 `business`，分别表示当前对账 DWS 数据源和当前对账报表/业务数据源。
- AM 标的表与 AM 合同投融资余额表在同一数据源时，仍在 SQL 中关联合同开始日并按最新合同开始日辅助消歧；如果两表配置到不同数据源，则不生成跨数据源 join，但会分别按核对日期查询两张表，并在应用层按项目编号、合同代码回填合同开始日，避免日期字段返回格式不同导致回填失败。

## 1. 读取估值表资产合计

对每个待核对项目，程序第一步读取估值表 `0004`：

1. 查询 `fa_valuationreport_dws`。
2. 过滤项目编号和核对日期。
3. 读取科目代码 `0004` 的 `f_marketvalue`。

字段含义：

- `fa_valuationreport_dws`：FA 估值表，用于取得资产端科目金额。
- `0004`：估值表中的资产合计科目。
- `f_marketvalue`：估值表科目的金额字段。
- `fa_asset_total`：估值表资产合计，即 `0004.f_marketvalue`。

处理结果：

| 条件 | 下一步 | 差异类型 |
| --- | --- | --- |
| 找不到估值表 `0004` | 停止该项目判断 | `暂无法确定` |
| `a0001 != fa_asset_total` | 进入资产端链路 | 待定 |
| `a0001 == fa_asset_total` | 进入实收/负债权益链路 | 待定 |

## 2. 资产端链路入口

触发条件：

- `a0001 != fa_asset_total`

执行顺序：

1. 计算 `asset_gap = ABS(a0001 - fa_asset_total)`。
2. 判断资产方向：
   - `a0001 < fa_asset_total`：预判为 `资产缺失`。
   - `a0001 > fa_asset_total`：预判为 `资产重复`。
3. 读取估值表资产端候选科目：
   - `1` 开头的实际末级科目；
   - `3001.XX` 且 `f_marketvalue > 0` 的共同类科目，资产类型展示为 `应收账款_共同类`。
4. `1` 开头科目不限制四级科目，先读取后再做“实际末级科目”过滤。
5. 实际末级科目含义：如果当前科目存在下级科目，则当前科目不作为候选；例如存在 `1541.01.CC8250MX` 时，`1541.01` 不作为候选。
6. `3001.XX` 只使用这一层级参与匹配，不继续向下取子级；如果不存在 `3001.XX` 这一层，则不额外构造候选。
7. 用 `asset_gap` 去匹配这些资产候选科目的 `f_marketvalue`。
8. 金额组合按有界分层执行：2～5 行使用补数/两数和快速层；6～10 行使用金额上下界剪枝的常用深层；20～30 行额外支持整组总额和“总额减目标”的反向小补集搜索。
9. 候选行超过系统阈值时仍允许执行 2～5 行快速层；快速层未命中，或大候选池快速层出现多解需要保持原分组语义时，再按科目前四段做自然分组组合。
10. 前四段分组组合仍只使用该分组下的实际末级科目；`3001.XX` 仍只按该层级参与，不做上一层聚合。
11. 同一项目的全候选、负数绝对值重试和前四段自然分组共享 60 秒组合计算截止时间；达到截止时间返回 `combination_timeout`，不再继续无限计算。

字段含义：

- `asset_gap`：资产端绝对差额，等于 `ABS(a0001 - fa_asset_total)`，用于匹配具体资产科目金额。
- `a0001`：资负报表资产合计。
- `fa_asset_total`：估值表资产合计，即 `fa_valuationreport_dws` 中科目 `0004` 的 `f_marketvalue`。
- `f_marketvalue`：估值表科目金额；资产候选科目用该金额参与匹配。

组合匹配命中多种可能组合时，不再自动选择第一组。此类场景统一进入“候选不唯一”保护，避免把多解误判为明确资产缺失或资产重复。

资产端金额匹配结果：

| 匹配结果 | 含义 | 是否视为命中具体资产 |
| --- | --- | --- |
| `single` | 单条科目金额等于差额 | 是 |
| `grouped` | 同一类聚合后等于差额 | 是 |
| `combination` | 多条组合后等于差额 | 是 |
| `ambiguous_combination` | 多组组合均可解释 `asset_gap` | 否，进入候选不唯一 |
| `combination_overflow` | 全末级组合及前四段分组组合仍超过上限 | 否 |
| `combination_timeout` | 单项目组合计算达到 60 秒硬上限 | 否 |
| `none` 或未命中 | 找不到具体科目 | 否 |

候选不唯一处理：

| 场景 | 差异类型 | 匹配状态 | 具体原因 | 是否进入资产差异细分 |
| --- | --- | --- | --- | --- |
| `a0001 < fa_asset_total` 且多组资产端候选科目组合均命中 `asset_gap`，且不能通过 AM 复核唯一确认候选组 | `资产缺失 + 暂无法确定` | `候选不唯一` | `候选不唯一` | 否 |
| `a0001 > fa_asset_total` 且多组资产端候选科目组合均命中 `asset_gap` | `资产重复 + 暂无法确定` | `候选不唯一` | `候选不唯一` | 否 |

详情最多展示 5 组候选组合，按组内科目数量从少到多排序，科目数量相同时按组内科目代码列表排序。

资产缺失候选不唯一的 AM 复核确认：

1. 只对 `资产缺失` 方向执行，`资产重复` 不执行。
2. 内部 AM 复核候选组不受详情最多展示 5 组限制。
3. 对每个候选组中的特定目的载体科目执行 AM 标的和合同投融资余额复核。
4. 将 AM 复核异常对应的 FA 科目金额汇总为 `am_abnormal_fa_total`：
   - AM 标的缺失：计入该 FA 科目 `f_marketvalue`
   - FA 与 AM 标的不一致：计入该 FA 科目 `f_marketvalue`
   - 合同投融资余额为 0 但 FA 科目余额不为 0：计入该 FA 科目 `f_marketvalue`
5. 如果且仅有一个候选组满足 `am_abnormal_fa_total == asset_gap`，则确认该候选组：
   - 差异类型：`资产缺失`
   - 匹配状态：`已解释`
   - 继续生成 AM 复核详情和资产缺失细分详情
6. 如果没有候选组满足，或多个候选组满足，仍返回 `资产缺失 + 暂无法确定`。

命中具体资产后：

- 如果方向是 `资产缺失`，进入第 3 节。
- 如果方向是 `资产重复`，进入第 4 节。

未命中具体资产后：

- 进入第 5 节 `资产差异`。

## 3. 资产缺失链路

触发条件：

- `a0001 < fa_asset_total`
- `asset_gap` 能命中估值表资产端候选科目

最终结果：

- 差异类型：`资产缺失`
- 匹配状态：`已解释`
- 具体原因：按命中的每个资产生成 `①②③` 编号

具体原因格式：

```text
①债券缺失：XX债券；原因：XXX
②特定目的载体缺失：XX信托计划；原因：XXX
③贷款缺失：XX贷款
```

如果没有进一步原因，则省略 `；原因：...`。

### 3.1 资产类型识别

资产缺失按估值表科目代码前缀识别资产类型：

| 科目前缀或规则 | 资产类型 |
| --- | --- |
| 四级科目为 `1101.05.01.01` | 特定目的载体 |
| 四级科目为 `1101.05.02.01` | 特定目的载体 |
| 四级科目为 `1101.05.03.01` | 特定目的载体 |
| 四级科目为 `1101.05.04.01` | 特定目的载体 |
| 四级科目为 `1101.05.05.01` | 特定目的载体 |
| 四级科目为 `1101.05.07.01` | 特定目的载体 |
| 四级科目满足 `1501.03.XX.01` | 特定目的载体 |
| `1501.01` 或 `1101.02` 开头 | 债券 |
| `1101.01` 开头 | 股票 |
| `1101.04` 开头 | 公募基金 |
| `1101.05.06` 开头 | 私募基金 |
| `1111.xx.xx.01` 开头 | 逆回购 |
| `1303.01.01` 或 `1501.04.05.01` 开头 | 贷款 |
| `1511.01.01` 开头 | 股权投资 |
| `1541.01` 开头且名称以 `江苏信托` 开头，并包含 `信托产品` 或 `资金信托计划` | 信托计划收益权 |
| 其他 `1541.01` 开头 | 资产收益权 |
| `3001.XX` 且金额大于 0 | 应收账款_共同类 |
| 其他 | 其他资产 |

### 3.2 特定目的载体缺失

对每条命中的特定目的载体估值表科目，按以下顺序检查：

如果一次资产缺失命中包含多条特定目的载体估值表科目，会逐条执行 AM 复核；复核结果优先返回异常结果（AM 标的缺失、FA 与 AM 标的不一致、合同投融资余额为 0 但 FA 科目余额不为 0）。如果所有科目都只得到非异常的合同投融资余额详情，才返回第一条非异常详情，避免前序兜底命中的正常合同提前截断后续异常科目的核对。

1. 用 FA 科目名称 `c_accountname` 匹配 AM 标的信息表 `am_pactasset_dws.c_udlyasset`。

   名称匹配细则：

   - 先分别规范化 FA 科目名称和 AM `c_udlyasset`：NFKC 规范化、去首尾空白、转小写、删除所有空白字符，并删除末尾 `_...` 或 `＿...` 后缀。
   - 规范化后完全一致时优先命中。
   - 没有完全一致时，括号内内容必须一致，且规范化名称最短长度不少于 4；再按相似度匹配，只有相似度 `>= 0.90` 的候选可用。
   - 多个高相似候选时的处理：
     1. 按相似度从高到低排序，保留最高相似度的候选（可能有多个并列最高分）。
     2. 如果仍有多个候选，按 AM 合同开始日 `d_bdate` 倒序排序，取最新合同对应的标的。
     3. 合同开始日通过项目编号、核对日期、合同代码三要素关联 `am_projinvest_dws` 取得。
     4. 后续再用 FA 完整业务代码和 AM `c_stockcode` 判定标的是否一致。
     5. `am_projinvest_dws.d_bdate` 属于必配字段；配置缺失或真实表中不存在时不再静默降级为空，应在配置保存或自动对数执行时暴露错误。

2. 如果原名称匹配不到 AM 标的，先执行 AM 复核兜底：
   - 规则 ①：用 FA 完整业务代码匹配 `am_pactasset_dws.c_stockcode`。命中一条或多条时，关联 `am_projinvest_dws.d_bdate`，按合同开始日倒序取最新合同对应的 AM 标的，继续进入后续标的代码和合同投融资余额复核。
   - 规则 ②：仅当规则 ① 未命中，且 FA 科目名称包含“江苏信托”时启用。FA 名称和 AM 名称必须只有一方含中文括号 `（...）`；将带中文括号的一方去掉括号及括号内内容后，再按基础规范化名称完全相等匹配另一方。若 FA 不带中文括号、AM 候选全部带中文括号，则去括号后可匹配的 AM 标的候选必须只有 1 个；多个带括号候选不放行。候选成立后，还需按核对日期查询报表库 `zf_detail_2024.projname`，同样去中文括号后做模糊包含匹配，命中条数有且仅有 1 条时才视为名称匹配成功。
   - 两边都含中文括号时不走规则 ②；即使括号外名称一致，括号内容不一致也不能通过该兜底。
3. 如果原名称匹配和兜底规则都匹配不到 AM 标的：
   - 原因：`AM标的缺失`
   - 链路结束。
4. 如果能匹配资产名称，但 FA 完整业务代码不等于 AM `c_stockcode`：
   - 原因：`FA和AM标的不一致`
   - 原始详情会保留 AM 合同来源 `am_pactasset_dws.c_datasource`，仅供导出“处理脚本”判断是否生成 SQL；页面展开详情不展示合同来源字段。
   - 链路结束。
5. 如果标的一致，用 AM 合同代码 `c_pactid` 查询 `am_projinvest_dws`。
6. 如果合同投融资余额为空或为 0：
   - 原因：`合同投融资余额为0但FA科目余额不为0`
   - 链路结束。
7. 用同一个合同代码查询 `dm.am_projinvest_spv_zgxg_dm`：
   - `svd_projcode = 项目编号`
   - `svd_cldate = 核对日期`
   - `svd_mpactid = AM合同代码`
   - `svd_balamoney_cost + svd_balamoney_inte + svd_balamoney_fair <> 0`

   - 原因：`该特定目的载体在DM AM SPV 投融资余额表不存在或余额为0`
   - 链路结束。
9. 如果 AM 资产名称包含 `收益凭证`：
   - 查询业务报表 `currency_report_24.currency_detail_project_2_1_9`
   - 只按 `caldate` 过滤。
   - 如果无数据，原因：`该收益凭证在资负数据子系统-其他债权明细表无数据`

   - 如果无数据，原因：`资负数据子系统-特定目的载体明细表无数据`

## 5. 资产差异链路

触发条件：

- `a0001 != fa_asset_total`
- 资产端 `asset_gap` 不能直接命中具体缺失或重复资产

最终差异类型先定为：

- `资产差异`

然后程序做四类细分：

- 债券本金 DM 证券余额
- 贷款合同
- 财产权合同
- 逆回购

### 5.1 债券本金 DM 证券余额差异

触发条件：

- 资产端不能直接命中具体缺失/重复资产，进入 `资产差异` 细分。
- 债券本金科目只包括：
  - `1501.01.XX.01*`
  - `1101.02.XX.01*`

检查顺序：

1. FA 侧取债券本金实际末级科目：
   - 如果前置自然分组已产生超限债券分组，只取这些债券分组下的实际末级科目。
   - 如果没有超限债券分组，则取本项目本次资产差异候选中的全部债券本金实际末级科目。
2. FA 匹配键：
   - 项目编号
   - 核对日期
   - 完整业务代码：剥离一级科目及后续最多三个两位数字科目层级后，保留剩余全部内容；例如 `1501.03.03.01.JS0508-2.51` 取 `JS0508-2.51`
   - 科目名称 `c_accountname`
3. 查询 DWS 数据源 `dm.fa_security_balance_zgxg_dm`：
   - `sbm_projcode = 项目编号`
   - `sbm_cacldate = 核对日期`
   - `TRIM(COALESCE(sbm_seclas_h2024, '')) <> ''`（债券分类字段非空白才算债券；`NULL`、空字符串和纯空格均视为非债券证券）
4. DM 匹配键：
   - `sbm_stockcode`
   - `sbm_sename`
5. DM 金额：
   - `dm_amount = SUM(sbm_balamoney_cost + sbm_balamoney_fair + sbm_balamoney_inte)`
6. FA 金额：
   - `fa_amount = f_marketvalue`
7. 使用 `FA债券集合 ∪ DM债券集合` 做双边补零：
   - DM 缺少某债券时，`dm_amount = 0`
   - FA 缺少某债券时，`fa_amount = 0`
8. 单只债券差异：
   - `bond_diff = dm_amount - fa_amount`
9. 如果 `bond_diff != 0`，加入资产差异细分。

字段含义：

- `sbm_stockcode`：DM 证券代码，用于和 FA 完整业务代码匹配。
- `sbm_sename`：DM 证券名称，用于和 FA 科目名称匹配。
- `sbm_balamoney_cost`：DM 成本余额。
- `sbm_balamoney_fair`：DM 公允价值余额。
- `sbm_balamoney_inte`：DM 应计利息余额。
- `dm_amount`：DM 证券余额合计，等于成本余额、公允价值余额、应计利息余额三项汇总。
- `fa_amount`：FA 估值金额，取对应 FA 科目的 `f_marketvalue`。

具体原因格式：

```text
①XX债券：DM中缺少该债券，债券代码XXX，FA债券本金科目余额XXX
②YY债券：FA估值表缺少该债券，债券代码YYY，DM证券余额XXX
③ZZ债券：FA债券本金科目余额与DM证券余额有差异，债券代码ZZZ，差异值XXX
```

### 5.4 逆回购资产差异

触发条件：

4. 只取 `subcode LIKE '7%'`。

   - `reverse_repo_business_amount = SUM(buyback_money + expenses)`
6. 逆回购差异：
   - `reverse_repo_diff = reverse_repo_business_amount - reverse_repo_fa_total`
7. 如果 `reverse_repo_diff != 0`，加入资产差异细分。

字段含义：

- `expenses`：存续回购业务表中的费用金额。

具体原因格式：

```text
①逆回购：FA科目余额与存续回购业务表逆回购金额有差异，差异值XXX
```

### 5.5 资产差异是否完整解释

程序把债券、贷款、财产权、逆回购四类差异相加：

```text
asset_refinement_total = SUM(DM证券余额、AM投融资余额或存续回购业务表金额 - FA科目余额)
```

然后与 `asset_total_gap = a0001 - fa_asset_total` 比较。

其中：

- `asset_refinement_total`：资产差异细分合计，汇总债券、贷款、财产权、逆回购等细分行的业务侧金额与 FA 科目金额差额。
- `asset_total_gap`：资产端差额，等于资负报表资产合计 `a0001` 减估值表资产合计 `fa_asset_total`。
- `a0001`：资负报表资产合计。
- `fa_asset_total`：估值表资产合计，即估值表 `0004.f_marketvalue`。

| 条件 | 差异类型 | 匹配状态 | 是否继续后续链路 |
| --- | --- | --- | --- |
| `asset_refinement_total == asset_total_gap` 且存在细分行，`remaining == 0` | `资产差异` | `已解释` | 不继续 |
| `asset_refinement_total == asset_total_gap` 且存在细分行，`remaining != 0` | `资产差异 + 后续差异类型` | 以后续链路状态为准 | 继续进入第 6 节 |
| `asset_refinement_total != 0` 但不等于 `asset_total_gap` | `资产差异` | 通常为 `未解释` 或 `组合候选过多` | 不继续 |
| 没有任何债券、贷款、财产权、逆回购差异 | `资产差异` | 通常为 `未解释` 或 `组合候选过多` | 不继续 |

这里的 `remaining` 为：

```text
remaining = (a0001 - d0000) - (a0001 - fa_asset_total)
          = fa_asset_total - d0000
```

其中：

- `remaining`：资产端差异解释完后仍需要继续解释的剩余差额。
- `a0001 - d0000`：主差异，资负报表资产合计减负债及权益合计。
- `a0001 - fa_asset_total`：资产端差额。
- `d0000`：资负报表负债及权益合计。

因此，只有资产端被完整解释后，才认为“资产端修正后可以按估值表 0004 继续往下核对”。如果资产端没解释完整，即使还能看出其他端可能有问题，也不继续进入实收/负债权益链路。

### 5.6 资产差异具体原因

完整解释时：

```text
①XX债券：FA债券本金科目余额与DM证券余额有差异，债券代码XXX，差异值XXX
①多个债券：FA债券本金科目余额与DM证券余额有差异，差异值XXX
②XX贷款合同：FA科目余额与AM投融资余额有差异，差异值XXX
③逆回购：FA科目余额与存续回购业务表逆回购金额有差异，差异值XXX
```

当同一次资产差异细分中存在多只债券时，`具体原因` 主列使用“多个债券”汇总展示，逐债券名称、证券代码、FA 金额、DM 证券余额和差异值放入“资产差异细分”详情表。

部分解释时：

```text
暂不明确具体资产差异，但XX债券，FA债券本金科目余额与DM证券余额有差异，差异值XXX
暂不明确具体资产差异，但多个债券，FA债券本金科目余额与DM证券余额有差异，差异值XXX
暂不明确具体资产差异，但贷款合同，FA科目余额与AM投融资余额有差异，差异值XXX
暂不明确具体资产差异，但财产权合同，FA科目余额与AM投融资余额有差异，差异值XXX
暂不明确具体资产差异，但逆回购，FA科目余额与存续回购业务表逆回购金额有差异，差异值XXX
暂不明确具体资产差异，但贷款/财产权合同，FA科目余额与AM投融资余额有差异，差异值XXX
暂不明确具体资产差异，但贷款合同、逆回购，FA科目余额与AM投融资余额/存续回购业务表金额有差异，差异值XXX
```

完全无法细分时：

```text
暂不明确具体资产差异
```

## 6. 实收/负债权益链路入口

进入本链路有两种情况：

1. 原始资产端正确：
   - `a0001 == fa_asset_total`
   - 当前差异为 `a0001 - d0000`
2. 资产差异已经完整解释，但还有剩余差额：
   - `asset_refinement_total == asset_total_gap`
   - `remaining != 0`
   - 当前差异改为 `fa_asset_total - d0000`

进入后第一步读取 FA `4001` 余额：

- 数据表：`fa_accountbalance_dws`
- 科目：`4001`
- 金额：`f_balance` 汇总

字段含义：

- `FA 4001` / `fa4001`：FA 科目余额表中科目 `4001` 的 `f_balance` 汇总，代表 FA 侧实收本金余额。
- `c1000`：资负报表主表 `zf_detail_2024` 中的实收本金余额。
- `FA 4001 - c1000` / `received_trust_diff`：FA 侧实收本金与资负报表实收本金的差额。
- `current_diff`：当前待解释差额；进入本链路时可能是 `a0001 - d0000`，也可能是资产差异完整解释后的 `remaining`。

然后按以下顺序执行：

1. 先判断整笔实收本金缺失/重复。
2. 再判断 `FA 4001 - c1000` 是否可以解释当前差异。
3. 如果实收本金不能单独解释，则用剩余差额进入负债及权益科目匹配。

## 7. 实收本金缺失/重复

本节先于 `FA 4001 - c1000` 差异判断执行。

### 7.1 实收本金缺失

触发条件：

```text
current_diff == fa4001
c1000 == 0
```

其中：

- `current_diff`：当前待解释差额，进入本节时可能是主差异 `a0001 - d0000`，也可能是资产差异完整解释后的剩余差额。
- `fa4001`：FA 侧实收本金余额，即 `fa_accountbalance_dws` 中科目 `4001` 的 `f_balance` 汇总。
- `c1000`：资负报表主表 `zf_detail_2024` 中的实收本金余额；为 `0` 表示报表侧没有实收本金余额。

结果：

- 差异类型：`实收本金缺失`
- 匹配状态：`已解释`
- 具体原因基础格式：

```text
①实收本金缺失：FA 4001科目余额XXX
```

细分：

1. 查询 `currency_report_24.currency_detail_project_2_1_8`。
2. 只按 `caldate` 过滤。
3. 如果无数据，追加原因：

```text
①实收本金缺失：FA 4001科目余额XXX；原因：资负数据子系统-实收本金明细表无数据
```

### 7.2 实收本金重复

触发条件：

```text
fa4001 > 0
c1000 > fa4001
c1000 / fa4001 是整数
current_diff == fa4001 - c1000
```

其中：

- `fa4001`：FA 侧实收本金余额，即 FA 科目 `4001` 的余额汇总。
- `c1000`：资负报表主表中的实收本金余额。
- `c1000 / fa4001 是整数`：报表侧实收本金是 FA 侧实收本金的整数倍，用于判断是否疑似重复计入。
- `current_diff`：当前待解释差额。
- `fa4001 - c1000`：FA 侧实收本金减去报表侧实收本金；为负数时表示报表侧可能多计。

```text
repeat_count = c1000 / fa4001 - 1
repeat_amount = fa4001 * repeat_count
```

其中：

- `repeat_count`：疑似额外重复计入的次数。
- `repeat_amount`：疑似重复计入的金额。

结果：

- 差异类型：`实收本金重复`
- 匹配状态：`已解释`
- 具体原因：

```text
①实收本金重复：FA 4001科目余额XXX；原因：c1000疑似重复计入N次，重复金额XXX
```

当前实收本金重复不做业务报表 `2_1_8` 无数据细分。

如果 `current_diff == fa4001` 但 `c1000 != 0`，或实收本金重复不满足上述整数倍闸门，不直接判定整笔实收本金缺失/重复，继续进入第 8 节实收本金差异判断。

## 8. 实收本金差异

如果整笔实收本金缺失/重复没有命中，继续计算：

```text
received_trust_diff = fa4001 - c1000
```

其中：

- `received_trust_diff`：实收本金差额。
- `fa4001`：FA 侧实收本金余额，即 FA 科目 `4001` 的余额汇总。
- `c1000`：资负报表主表中的实收本金余额。

### 8.1 实收本金差异单独解释当前差异

触发条件：

```text
c1000 != fa4001
received_trust_diff == current_diff
```

其中：

- `c1000 != fa4001`：报表侧实收本金余额与 FA 侧实收本金余额不一致。
- `received_trust_diff`：实收本金差额，等于 `fa4001 - c1000`。
- `current_diff`：当前待解释差额；二者相等表示实收本金差异可以完整解释当前差异。

结果：

- 差异类型：`实收本金差异`
- 匹配状态：`已解释`
- 基础具体原因：

```text
①实收本金差异：FA 4001与c1000存在差异，差异值XXX
```

然后进入 TA 细分。

### 8.2 TA 汇总细分

先比较 DM TA 和 DWS TA 的份额余额加待结转收益：

DM：

- 表：`dm.ta_pact_survamt_day_zgxg_dm`
- 项目：`tpm_tcmpcode`
- 日期：`tpm_date`
- 金额：`tpm_htincome + tpm_shareamt`

DWS：

- 表：`ta_pact_detail_dws`
- 项目：`c_projcode`
- 日期：`d_cldate`
- 金额：`f_shareamt + f_alltincom`

处理：

1. 如果 DM 汇总不等于 DWS 汇总，计算 `dm_total - dws_total`。
2. 如果 `ABS(dm_total - dws_total) == ABS(received_trust_diff)`：

字段含义：

- `dm_total`：DM TA 表中 `tpm_htincome + tpm_shareamt` 的汇总金额。
- `dws_total`：DWS TA 表中 `f_shareamt + f_alltincom` 的汇总金额。
- `dm_total - dws_total`：DM 与 DWS 两侧 TA 汇总金额的差额。
- `received_trust_diff`：实收本金差额，等于 `fa4001 - c1000`；这里取绝对值比较，是为了判断 TA 汇总差额是否足以解释实收本金差额。

如果满足第 2 条，具体原因改为：

```text
①实收本金差异：FA 4001与c1000存在差异，差异值XXX；原因：DM表TA份额余额错误
```

3. 如果 DM/DWS 汇总差额不等于实收本金差额，则保留基础具体原因。
4. 只要 DM/DWS 汇总不一致，本节结束，不再检查客户类型为空。

### 8.3 DM 客户类型为空细分

只有 DM/DWS TA 汇总一致时，才继续检查客户类型为空。

查询表：

- `dm.ta_pact_survamt_day_zgxg_dm`

过滤：

- `tpm_tcmpcode = 项目编号`
- `tpm_date = 核对日期`
- `tpm_htincome + tpm_shareamt <> 0`

字段含义：

- `tpm_tcmpcode`：DM TA 表中的项目编号。
- `tpm_date`：DM TA 表中的日期。
- `tpm_htincome`：待结转收益。
- `tpm_shareamt`：份额余额。
- `tpm_htincome + tpm_shareamt`：单条 TA 记录参与实收本金核对的金额。
- `tpm_clientkind_tusp`、`tpm_clientkindex`、`tpm_spvtype`：客户类型、客户类型明细和 SPV 类型字段，用于判断客户类型是否缺失。

客户类型为空判定：

1. `tpm_clientkind_tusp` 为空。
2. 或 `tpm_clientkind_tusp = '4'` 且 `tpm_clientkindex` 为空。
3. 或 `tpm_clientkind_tusp = '5'` 且 `tpm_spvtype` 为空。

处理：

1. 汇总这些空客户类型记录的 `tpm_htincome + tpm_shareamt`。
2. 如果汇总值等于 `received_trust_diff`：
   - 具体原因改为：

```text
①实收本金差异：FA 4001与c1000存在差异，差异值XXX；原因：dm.ta_pact_survamt_day_zgxg_dm表中客户类型为空导致实收信托有误
```

3. 详情中列出合同编号 `tpm_pactid`、客户名称 `tpm_clientname`、客户类型相关字段和金额。
4. 如果金额不能解释实收本金差额，则保留基础具体原因。

### 8.4 实收本金差异不能单独解释当前差异

触发条件：

```text
c1000 != fa4001
received_trust_diff != current_diff
```

其中：

- `c1000 != fa4001`：报表侧实收本金余额与 FA 侧实收本金余额不一致。
- `received_trust_diff`：实收本金差额，等于 `fa4001 - c1000`。
- `current_diff`：当前待解释差额。
- `received_trust_diff != current_diff`：实收本金差额不能单独完整解释当前差额，需要把剩余差额继续交给负债及权益链路。

处理：

1. 先生成一条实收本金差异详情：

```text
①实收本金差异：FA 4001与c1000存在差异，差异值XXX
```

2. 计算剩余差额：

```text
residual = current_diff - received_trust_diff
```

其中：

- `residual`：扣除实收本金差额后仍未解释的剩余差额。
- `current_diff`：当前待解释差额。
- `received_trust_diff`：实收本金差额。

3. 用 `residual` 继续进入第 9 节负债及权益科目匹配。

注意：

- 如果这是普通链路，最终差异类型以后续负债权益结果为准，例如 `负债及权益科目重复`。
- 如果这是资产差异完整解释后的后续链路，最终差异类型会组合展示，例如 `资产差异 + 实收本金差异 + 负债及权益科目差异`。

## 9. 负债及权益科目链路

进入条件：

- 资产端正确后，实收本金缺失/重复未命中，且实收本金差异不能单独解释当前差异。
- 或 `c1000 == fa4001`，直接进入负债及权益科目匹配。
- 或资产差异完整解释后，剩余差额继续进入本链路。

字段含义：

- `c1000`：资负报表实收本金余额。
- `fa4001`：FA 侧实收本金余额，即 FA 科目 `4001` 的余额汇总。
- `current_diff`：进入负债及权益链路时仍待解释的差额。
- `residual`：已扣除实收本金差额后的剩余差额；如果第 8.4 命中，本链路优先用它继续匹配。

### 9.1 读取非 1 开头估值表科目

1. 查询 `fa_valuationreport_dws`。
2. 过滤项目编号和核对日期。
3. 排除 `1` 开头科目。
4. 排除 `0` 开头的四位科目，例如 `0001`、`0002`、`0004`、`0033`。这些是估值表汇总或指标类科目，不参与负债及权益科目金额匹配。
5. 处理 `3001.XX` 共同类科目：
   - `3001.XX < 0` 时作为 `应付账款_共同类` 参与负债权益匹配，金额按绝对值计算。
   - `3001.XX > 0` 不进入负债权益端，它在资产端按 `应收账款_共同类` 处理。
   - 多科目匹配时也只使用 `3001.XX` 这一层级，不向下取子级。
6. 单行精确匹配和同科目汇总匹配不限制末级科目，因为负债及权益差异可能体现在上级科目。
7. 多科目组合匹配只使用实际末级科目，并剔除正回购利息科目 `2111.xx.xx.02.*`，避免上级和下级重复参与组合，或用正回购利息凑数。
8. 组合层沿用资产端有界分层：2～5 行快速层、6～10 行常用深层、20～30 行整组/反向小补集；同一项目共享 60 秒组合计算截止时间。
9. 候选超过阈值时快速层仍可命中少数组合；未命中或大候选池多解需要保持原分组语义时，才按科目前四段自然分组组合。
10. 前四段分组组合仍只使用该分组下的实际末级科目；`3001.XX` 仍只按该层级参与，不做上一层聚合。

说明：这里的排除只作用于负债及权益端的非 `1` 科目匹配，不影响第 1 步读取估值表 `0004` 资产合计。

匹配差额：

- 如果实收本金没有残差，匹配 `current_diff`。
- 如果实收本金已解释一部分，匹配 `residual`。
- 如果原差额为负且按原符号匹配不到，会再尝试用绝对值匹配。

候选不唯一保护：

- 只在匹配 `current_diff = a0001-d0000` 时启用。
- 如果已经扣除实收本金差异后匹配 `residual`，不启用本保护。
- 如果资产差异已完整解释 `a0001-fa_asset_total` 后继续核对剩余差额，不启用本保护，继续沿用原负债及权益科目匹配逻辑。
- 单行精确匹配、同科目汇总匹配不受影响。
- 多科目组合匹配时，如果存在多组组合均可解释 `current_diff`，不选第一组，也不返回负债及权益科目缺失/重复。
- 此时最多保留前 5 组候选组合用于详情展示，候选组合按组内科目数量从少到多排序，科目数量相同时按组内科目代码列表排序。

其中：

- `current_diff = a0001-d0000`：当前待解释差额就是主差异，即资负报表资产合计减负债及权益合计。
- `residual`：扣除实收本金差额后的剩余差额；使用它匹配时不进入本候选不唯一保护。

### 9.2 候选不唯一

触发条件：

- 资产端正确。
- 实收本金没有残差，当前待解释差额就是 `current_diff = a0001-d0000`。
- 非 `1` 开头科目多科目组合匹配时，存在多组组合金额均等于 `current_diff`，或 `current_diff` 为负时存在多组组合金额均等于其绝对值。

处理结果：

| 差异类型 | 匹配状态 | 具体原因 |
| --- | --- | --- |
| 原差异类型 + `暂无法确定`，例如 `负债及权益科目缺失 + 暂无法确定` | `候选不唯一` | `候选不唯一` |

详情展示：

```text
候选组合1：合计金额 XXX
① 科目代码：XXX；科目名称：XXX；科目尾段：XXX；金额：XXX
② 科目代码：XXX；科目名称：XXX；科目尾段：XXX；金额：XXX

候选组合2：合计金额 XXX
① 科目代码：XXX；科目名称：XXX；科目尾段：XXX；金额：XXX
② 科目代码：XXX；科目名称：XXX；科目尾段：XXX；金额：XXX
```

### 9.3 命中具体非 1 科目

如果匹配结果为 `single/grouped/combination`：

| 条件 | 差异类型 | 匹配状态 |
| --- | --- | --- |
| 匹配差额大于 0 | `负债及权益科目缺失` | `已解释` |
| 匹配差额小于 0 | `负债及权益科目重复` | `已解释` |

具体原因格式：

```text
①负债及权益科目缺失：XX科目
①负债及权益科目重复：XX科目
```

如果命中的科目满足 `2111.xx.xx.01` 开头，则资产类型展示为正回购，并追加原因：

```text
①正回购缺失：卖出回购金融资产款；原因：正回购差异
①正回购重复：卖出回购金融资产款；原因：正回购差异
```

如果命中的科目为 `3001.XX < 0` 的共同类科目，则按绝对值命中，科目类型展示为 `应付账款_共同类`，并追加原因：

```text
①应付账款_共同类重复：XX科目；原因：3001共同类科目为负数，按绝对值参与负债权益核对
```

如果前面已经有实收本金差异详情，编号顺延：

```text
①实收本金差异：FA 4001与c1000存在差异，差异值XXX
②负债及权益科目重复：XX科目
```

### 9.4 无法命中具体非 1 科目时的正回购金额细分

如果非 1 科目无法直接命中，程序再做正回购金额比对。

触发科目：

- FA 科目满足 `2111.xx.xx.01` 开头。

检查顺序：

1. 汇总估值表中正回购科目的 `f_marketvalue`，得到 `positive_repo_fa_total`。
2. 查询业务报表数据源 `ass_man_reg.ex_pledge_back`。
3. 只按项目编号 `project_code` 过滤，不按日期过滤。
4. 只取 `subcode LIKE '8%'`。
5. 业务表正回购金额：
   - `positive_repo_business_amount = SUM(buyback_money - expenses)`
6. 正回购差异：
   - `positive_repo_diff = positive_repo_fa_total - positive_repo_business_amount`

字段含义：

- `positive_repo_fa_total`：FA 估值表中正回购科目的 `f_marketvalue` 汇总。
- `positive_repo_business_amount`：存续回购业务表中的正回购金额汇总，等于 `buyback_money - expenses`。
- `positive_repo_diff`：正回购差异，等于 FA 正回购金额减业务表正回购金额。
- `buyback_money`：存续回购业务表中的回购金额。
- `expenses`：存续回购业务表中的费用金额。

处理结果：

| 条件 | 差异类型 | 匹配状态 | 具体原因 |
| --- | --- | --- | --- |
| `positive_repo_diff == 0` | `负债及权益科目差异` | 通常为 `未解释` | `暂不明确具体负债及权益科目差异` |
| `positive_repo_diff == 当前待解释差额` | `负债及权益科目差异` | `已解释` | `①正回购：FA科目余额与存续回购业务表正回购金额有差异，差异值XXX` |
| `positive_repo_diff != 0` 但不等于当前待解释差额 | `负债及权益科目差异` | 通常为 `未解释` | `暂不明确具体负债及权益科目差异，但正回购，FA科目余额与存续回购业务表正回购金额有差异，差异值XXX` |

如果前面已经有实收本金差异详情，编号顺延：

```text
①实收本金差异：FA 4001与c1000存在差异，差异值XXX
②正回购：FA科目余额与存续回购业务表正回购金额有差异，差异值XXX
```

### 9.5 仍无法解释

如果非 1 科目不能命中，正回购也不能完整解释：

- 差异类型：`负债及权益科目差异`
- 匹配状态：`未解释` 或 `组合候选过多`
- 具体原因：

```text
暂不明确具体负债及权益科目差异
```

如果有实收本金残差前缀：

```text
①实收本金差异：FA 4001与c1000存在差异，差异值XXX
②暂不明确具体负债及权益科目差异
```

## 10. 资产差异完整解释后的组合链路

这是当前最容易混淆的分支，需要单独说明。

触发条件：

1. `a0001 != fa_asset_total`
2. 资产端不能直接命中具体资产缺失/重复，因此进入 `资产差异`
3. 贷款、财产权、逆回购差异合计正好等于：

```text
asset_total_gap = a0001 - fa_asset_total
```

其中：

- `asset_total_gap`：资产端差额。
- `a0001`：资负报表资产合计。
- `fa_asset_total`：估值表资产合计，即估值表 `0004.f_marketvalue`。

4. 资产端解释后仍有剩余差额：

```text
remaining = fa_asset_total - d0000
remaining != 0
```

其中：

- `remaining`：资产端修正后仍需继续解释的剩余差额。
- `fa_asset_total`：估值表资产合计，组合链路中临时作为修正后的资产合计。
- `d0000`：资负报表负债及权益合计。
- `remaining != 0`：说明资产端差异解释完后，仍需要继续进入实收本金或负债及权益链路。

此时程序会：

1. 保留资产差异详情作为第一段原因。
2. 构造一个“资产端已修正”的临时项目：
   - 资产合计使用 `fa_asset_total`
   - 负债及权益仍使用原 `d0000`
   - c1000 仍使用原 `c1000`
3. 用这个临时项目继续跑第 6 节实收/负债权益链路。
4. 最终差异类型组合展示。
5. 具体原因编号连续顺延。

组合链路里如果资产差异主原因把多条明细汇总成一条“多个债券/多个资产”原因，后续实收或负债权益原因按主原因条数连续编号。例如资产端主原因只有 `①多个债券...` 一条，后续正回购原因应展示为 `②正回购...`，不能因为资产差异明细表有多行而跳到 `③`。

示例：

```text
差异类型：资产差异 + 实收本金差异 + 负债及权益科目差异
匹配状态：已解释
具体原因：
①逆回购：FA科目余额与存续回购业务表逆回购金额有差异，差异值100
②实收本金差异：FA 4001与c1000存在差异，差异值50
③正回购：FA科目余额与存续回购业务表正回购金额有差异，差异值30
```

如果资产端没有完整解释，则不会进入这个组合链路，最终只保留：

```text
差异类型：资产差异
匹配状态：未解释
具体原因：暂不明确具体资产差异...
```

## 11. 暂无法确定

当前主要在以下情况返回：

1. 主表存在差异，但估值表找不到 `0004` 资产合计。
2. 资产缺失/资产重复直接匹配 `asset_gap` 时，多科目组合存在多组候选，返回 `资产缺失/资产重复 + 暂无法确定`，匹配状态为 `候选不唯一`。
3. 负债及权益端直接匹配 `a0001-d0000` 时，多科目组合存在多组候选，返回 `负债及权益科目缺失/重复 + 暂无法确定`，匹配状态为 `候选不唯一`。
4. 后续如果新增兜底规则，也应归入本节并同步补充。

目前资产端、实收端、负债权益端能定位到一级方向但不能完整解释时，通常不返回 `暂无法确定`，而是返回对应的 `资产差异` 或 `负债及权益科目差异`。

## 12. 结果展示和导出

### 12.1 差异类型

- 页面结果列表、历史记录、导出 Excel 均使用 `difference_reason` 作为“差异类型”。
- 组合类型用 ` + ` 拼接，例如 `资产差异 + 负债及权益科目差异`。
- 页面筛选支持组合类型：筛选 `资产差异` 时，会命中包含 `资产差异` 的组合类型。

### 12.2 具体原因

- 具体原因来自结果详情中的最后一个有效 `specific_reason`。
- 导入/导出 Excel 中“具体原因”是单独列，位于“差异类型”之后。
- 具体原因统一尽量使用 `①②③` 编号；导出详情会对已编号原因做连续重排，避免出现 `①` 后直接跳到 `③`。
- 多个原因换行展示。
- 导出 Excel 的“差异原因详情”中，表格型明细统一按多行展示，每行显式写出字段名，不再使用 `/` 把多列值拼成一行。
- 适用范围包括但不限于：
  - 命中科目：`科目代码`、`科目名称`、`科目尾段`、`金额`
  - 资产差异明细：`资产类型`、`资产名称`、`合同代码/证券代码`、`FA科目余额`、`DM证券余额/AM投融资余额/存续回购业务表金额`、`差异值`
  - 财产权合同明细：`科目代码`、`科目名称`、`合同代码`、`估值金额`、`AM合同投融资余额`、`差异值`
  - TA 客户类型明细：`合同编号`、`客户名称`、`客户类型`、`客户类型明细`、`SPV类型`、`金额`

### 12.3 备注

- 导出 Excel 将“备注”列放在最后一列。
- 单一差异类型或没有备注内容时，导出 Excel 填写“无”。
- 组合差异类型按 `difference_reason` 的 ` + ` 分段和 `match_status` 生成备注：
  - 包含 `暂无法确定`：说明当前存在多组候选结果，无法唯一确认具体资产或科目，并提示查看候选组合明细。
  - 包含资产端类型和实收本金类型：说明资产端差额先被资产端类型解释，修正资产端后剩余差额由实收本金类型解释；未解释时说明实收本金类型未能完整解释。
  - 包含资产端类型和负债及权益类型：说明资产端差额先被资产端类型解释，修正资产端后剩余差额由负债及权益类型解释；未解释时说明负债及权益类型未能完整解释。
  - 同时包含资产端类型、实收本金类型、负债及权益类型：按资产端、实收本金、负债及权益三段说明差额被分段解释。
  - 包含实收本金类型和负债及权益类型：说明实收本金差异解释后仍有剩余差额，再由负债及权益类型继续解释。
- 导出 Excel 的“差异原因详情”会展示最终判断中的 `匹配说明`。例如资产缺失候选不唯一但经 AM 复核确认时，会展示 `候选不唯一，经AM复核确认：候选组合X`。

### 12.4 处理脚本

- 仅 FA/AM 标的不一致生成处理脚本内容。
- 生成脚本前先判断原始详情中的 AM 合同来源 `c_datasource`：
  - `trim/lower` 后等于 `am`：生成现有 `data_mangement.data_mangement_dwd` 修正 SQL。
  - 不等于 `am` 或来源为空：不生成 SQL，输出 `衡泰标的不一致请联系衡泰系统处理。`
- 同一项目存在多条 FA/AM 标的不一致时，脚本列按 `①②③` 编号；单条时不额外编号。
- 合同来源只参与导出脚本判断，不作为结果页或历史详情的展示列。

### 12.5 展开详情

- 结果详情列表同一时间只允许展开一行。
- 展开新行时，原已展开行会自动关闭。
- 展开内容由后端 `build_display_details` 统一生成，当前包含以下块：
  - `最终判断结果`：展示差异类型、具体原因、差异金额、差异方向、匹配状态；按命中链路补充资产合计差额、实收本金差额、负债及权益命中方式、资产差异汇总、匹配说明等字段。
  - `具体差异明细`：展示估值表命中的科目代码、科目名称、科目尾段代码、金额。
  - `标的代码核对`：展示 FA 科目、AM 资产名称、AM 标的代码、AM 合同代码和 FA/AM 标的不一致判定结果。
  - `AM标的缺失`：展示 FA 科目、FA 科目尾段、FA 科目余额、需复核四级科目和未找到 AM 标的的判定结果。
  - `合同投融资余额核对`：展示 FA 科目、AM 资产名称、AM 标的代码、AM 合同代码、合同投融资余额和判定结果。
  - `财产权合同投融资核对`：表头为科目代码、科目名称、合同代码、估值金额、AM合同投融资余额、差异。
  - `资产差异细分`：表头为序号、资产类型、资产名称、FA科目编码、合同代码/证券代码、FA科目余额、DM证券余额/AM投融资余额/存续回购业务表金额、差异值、核查表、原因。
  - `资产缺失细分`：表头为序号、资产类型、资产名称、FA科目编码、科目尾段、FA估值金额、核查表、核查结果、关键字段、AM标的代码、AM合同代码、原因。
  - `资产重复细分`：表头为序号、资产类型、资产名称、FA科目编码、科目尾段、FA估值金额、核查表、核查结果、关键字段、AM SPV类型、AM资产类型、原因。
  - `实收本金细分`：表头为序号、类型、FA 4001科目余额、c1000实收本金余额、差异值、核查表、核查结果、原因。
  - `负债及权益科目细分`：表头为序号、科目类型、科目名称、FA科目编码、科目尾段、FA科目金额、存续回购业务表金额、差异方向、核查结果、原因。
  - `候选组合明细`：表头为候选组合、组内合计、科目代码、科目名称、科目尾段、金额。
  - `TA汇总核对`：展示 DM TA 份额余额加待结转收益、DWS TA 份额余额加待结转收益、DM-DWS差异。
  - `DM TA客户类型为空`：展示客户类型为空金额合计；表头为合同编号、客户名称、客户类型、客户类型明细、SPV类型、待结转收益、份额余额、合计。

### 12.6 历史持久化

- 自动对数执行完成后，历史记录写入本地 `auto-check.db`。
- 运行摘要写入 `run_headers` 和 `reconcile_runs`，状态统计、差异类型统计、结果行、详情和新增/减少差异分别写入结构化历史表。
- 完整历史 payload 同时保留在 `run_headers.payload_json`，旧 `history_runs(kind='reconcile')` 也继续写入兼容快照。
- 列表页、统计和后续筛选优先读取结构化热字段；详情页、恢复结果页和导出仍可从兼容 payload 还原完整结果。
- 旧 `history_runs(kind='reconcile')` 和旧 `history.json` 会在首次读取历史时自动迁移，迁移过程不删除旧数据。

### 12.7 执行日志与耗时观测

自动对数执行日志用于在任务卡住或耗时异常时快速定位当前正在执行的步骤。以下日志点在最近一次增强中加入，全部为纯增量日志，不改变任何判断逻辑：

- `金额匹配` 步骤：
  - `匹配估值表资产端候选科目金额，目标=…，候选=N 行`：候选池行数（阈值判断前的规模提示，不代表进入组合穷举的行数）。
  - `本次执行组合候选阈值=N`：本次执行实际生效的组合候选阈值（来自系统设置），用于核对阈值是否按预期传递。
  - `进入2～5条快速组合匹配…`、`进入6～10条剪枝搜索…`、`进入20～30条反向补集搜索…`：搜索层切换时立即输出，最后一条日志可直接定位当前组合层。
  - `组合匹配进行中：…候选=N行，组合状态=S，本次搜索已耗时=X.Xs，项目剩余=Y.Ys`：单个搜索持续期间约每 5 秒输出一次心跳；自然分组兜底使用同一格式。
  - `估值表资产端候选科目匹配结果=…，命中行数=N，命中金额=…，耗时=X.Xs`：匹配（含分组兜底）整体耗时和最终命中规模。
  - `combination_timeout`：本项目全候选、符号重试和分类分组累计达到 60 秒组合计算硬上限；不会阻塞后续项目。
- `分类组合兜底` 步骤（候选行数超过组合候选阈值后进入）：
  - `分类组合兜底：共 N 个四级科目分组，最大组 M 行`：兜底开始。
  - `分类组合兜底 组i/N：四级科目=…，行数=M，结果=…，耗时=X.Xs`：每组匹配结果与耗时。
- `数据加载` 步骤（仓储层首次按日期全表加载，触发点最深、此前无日志）：
  - `开始加载/加载完成 AM投融资余额全表（日期=…，表=…）：N 行，耗时 X.Xs`
  - `开始加载/加载完成 AM合同开始日全表（日期=…，表=…）：N 行，耗时 X.Xs`
  - `开始加载/加载完成 AM资产信息全表（日期=…，表=…）：N 行，耗时 X.Xs`
  - 以上三条通过 `AutoCheckRepository(query_logger=…)` 回调输出，由 `server.py` 创建引擎时从进度日志回调注入，前端日志面板可见。
- 后台 SQL 诊断：
  - 自动对数执行前会把数据源类型、主机、端口、数据库、schema、完整参数化 SQL 和绑定参数写入后台标准输出，统一带 `[auto-check][sql]` 前缀；生产启动脚本将该输出保存到 `auto-check.log` 时，可直接从最后一条 SQL 判断数据库卡点。
  - SQL 诊断不会调用页面进度回调，因此完整 SQL 和参数不进入前端执行日志；页面只保留查询阶段、耗时和行数摘要。
  - 日志不包含数据库用户名或密码。
- `资产差异细分` 步骤：
  - `进入资产差异细分：债券DM核对→合同投融资核对→逆回购核对`：细分开始。
  - `开始查询DM证券余额…` / `DM证券余额查询完成：N 条，耗时 X.Xs`：债券双边对账的 DM 侧查询。
  - `查询{合同类型}投融资余额，合同…（第i/共N个）`：贷款/财产权合同逐行核对进度。
  - `开始核对逆回购存续回购业务表金额`：逆回购核对开始。
  - `资产差异细分完成：差异合计=…，耗时 X.Xs`：细分整体耗时。
- `AM标的复核` 步骤：
  - `AM标的复核：共 N 行待复核`：命中后 AM 复核的待复核行数。
  - `资产缺失候选不唯一，尝试用AM复核确认候选组合`：候选不唯一进入 AM 复核。
  - `AM复核候选组：共 N 组` / `复核候选组合i/N（M 行）`：候选组复核进度。
  - 候选组很多时，组标题和组内逐行日志只保留前 5 组、每 20 组和最后 1 组；所有候选仍完整参与复核，只减少页面日志量，不改变判断。

定位卡顿的方法：任务日志的最后一行即当前正在执行的步骤；结合上述日志中的耗时，可区分是 SQL 查询慢、全表加载慢，还是纯计算步骤耗时。
